# Task 87 — Compress duplicated push-protocol prose in commands to a reference

Target: claude

## Goal
docs/authoring-guide.md's commit-and-push convention section states the
protocol is authored once "so a dependent command references this section
by name rather than re-deriving it." In practice, all 10 commit-capable
commands (everything in Files below) re-derive the same ~6-10 line
failure-handling paragraph verbatim in their commit/push phase: on commit
failure, don't retry/amend/--no-verify, files remain staged; on push
failure or a pre-push conflict, never retry/force-push, tell the user it
needs a manual sync + push. That's ~60-80 duplicated lines with no guard
keeping them in sync (unlike the task-status vocabulary, which has
check-task-parity.sh). Replace the generic failure-handling prose in each
command's commit/push phase with a short reference to
docs/authoring-guide.md's protocol, while keeping each command's
command-specific behavioral details (what to stage, when to skip, its own
commit message format) inline — those genuinely differ per command and
must not be compressed away.

## Acceptance criteria
- In each of the 10 files, the generic failure-handling paragraph (commit
  failure: no retry/amend/--no-verify; push failure/pre-push conflict:
  no retry/force-push, tell user to sync+push manually) is replaced with
  a one- or two-line reference such as "On commit or push failure, follow
  docs/authoring-guide.md's commit-and-push protocol exactly — do not
  retry, amend, or force-push" (exact wording may vary slightly per file
  to fit surrounding prose, but must not restate the failure-handling
  steps themselves).
- Command-specific content is NOT touched: what files each command stages,
  its commit message format, when it skips committing (--no-commit /
  --no-push flags, non-git VCS exemption), and the pull-at-start /
  re-sync ordering already described locally in each command.
- docs/authoring-guide.md's protocol section itself is unchanged (it
  remains the single source of truth being referenced) unless reading the
  10 files during this task reveals the guide's wording needs a small
  clarification to serve as a clean reference target — if so, make that
  edit too and note it in Decisions.
- All 10 files still pass a manual read-through: an LLM executing any one
  of them in isolation (without having read the other 9) still has enough
  local context to know it must not retry/amend/force-push, even though
  the detailed steps now live one hop away in the guide.

## Decisions
- Trade-off: authoring-guide.md's own stated intent (reference, don't
  re-derive) is being followed here at some cost to each command's
  self-containedness for a partial-context LLM read. Keep the reference
  sentence explicit about the *outcome* (no retry, no amend, no
  force-push) even when deferring the *procedure* to the guide, so a
  command executor that skips the guide still can't take a destructive
  shortcut by accident.
