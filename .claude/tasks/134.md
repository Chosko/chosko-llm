# Task 134 — Update documentation for feature session-continuity

Target: claude

## Goal
Tasks 132 and 133 ship `/session-save` and `/session-resume`, and the
documentation describing this repo's shipped feature set does not yet mention
either. Bring the layers back in line with what actually shipped, and reconcile
the `session-continuity` feature document on the points where implementation
diverged from its design.

## Acceptance criteria
- `README.md` gains a subsection under "Claude Code Workflows" covering the two
  commands: the per-project store, the two file forms, the `Work:` line, the
  fact that `/session-resume` briefs and then stops, and the pruning rule (a
  resumed file is deleted when its work finishes, or superseded by the next
  save; an unresumed file is only ever flagged stale). Placed alongside the
  other workflow families, matching their depth and voice. The `task-*` section
  is left alone — this is not a backlog command.
- `.claude/context/features.md` gains a "Currently shipped" entry for each
  command, in the terse register that file uses, covering: command not skill;
  the `.claude/sessions/` store and filename scheme; full vs pointer form and
  the write-every-section rule; artifact detection and what a table entry is;
  the `Work:` line's four values; the three resolution forms and `Work:`-line
  candidacy; the pruning mechanism split across the two commands; and that
  neither command commits or is read by any `chosko-llm` subcommand.
- `docs/authoring-guide.md` § "State that outlives a session belongs in a
  project document" gains a cross-reference noting that `/session-save`'s
  known-artifact table recognises exactly the class of document that section
  defines.
- `.claude/domain/features/session-continuity.md` is reconciled on the points
  listed under Decisions, and only those.
- `docs/cli-help.txt` is deliberately NOT changed — it documents the
  `chosko-llm` CLI and carries no slash commands. Verified: it names none of
  `/task-list`, `/task-add` or `/production-status`.
- `.claude/context/INDEX.md` is deliberately NOT changed — no new context file
  is created, and shipped features are covered by `features.md`.
- Root `VERSION` takes a patch bump (documentation only).

## Decisions
- **Editing `.claude/domain/features/session-continuity.md` is explicitly
  authorised for this task, user decision 2026-08-24, for the listed
  reconciliations only; do not ask at implementation time.** The file is
  normally owned by `/architect` and read-only to `/task-add`. The
  reconciliations are:
  1. **Artifact detection.** Remove the `/task-implement` → `./delegated-runs.md`
     row and the pointer-form example built on it, and define a known-artifact
     table entry as a *project-scoped state document carrying a resume marker*,
     cross-referencing `docs/authoring-guide.md` § "State that outlives a
     session belongs in a project document". Record the reason:
     `skills/task-implement/delegated-runs.md` is a static shipped instruction
     file holding no state, at a path relative to the installed skill folder
     rather than the project, so a pointer form built on it would have
     discarded the whole handoff. `/task-implement` is a feature that writes no
     resume marker; its sessions take the full form. Rewrite the pointer-form
     example against the surviving `/product-design` row.
  2. **Open question "Gitignore by default?"** — resolved to the document's own
     leaning. Move it out of Open questions into the design as a decision.
  3. **Open question "Does /session-save know what skill is running?"** —
     resolved to the document's own fallback (infer from the conversation, ask
     once when unclear). Move it out of Open questions.
  4. **Open question "Pruning"** — resolved, and no longer deferred. Record the
     three-part mechanism as a decision: (i) `/session-resume` ends its
     briefing by telling the resumed session to delete the file it resumed from
     once the `Work:` it describes is finished, deletion being part of
     finishing — an instruction, not an action, so `/session-resume` stays
     read-only; (ii) if the session ends before finishing, the file stays, and
     the next `/session-save` in a session that resumed from a file writes its
     new snapshot and deletes the file it resumed from as superseded, so two
     snapshots of the same work never coexist; (iii) a file that was never
     resumed is never auto-deleted, and the >14-day stale flag is the only
     signal for those. No `--prune` flag. The "grows without bound" note goes
     with the open question.
  5. **`/session-resume` resolution.** Drop the `a task number → newest file
     whose Work: line names that task` row from the resolution table, leaving
     three forms, and record why: `/task-implement` runs are the least likely
     sessions to be paused, being shorter than product-design and architect
     sessions, so a task-number selector is too specific for the actual usage.
     `Work:` keeps `task <n>` as a value. Add that only files carrying a
     `Work:` line are candidates — the store holds companion documents, which
     the document assumed it did not — and that identical timestamp prefixes
     are broken deterministically on the full filename.
  6. **Pointer-form resume** — record that `/session-resume` follows the
     `Resume from:` path and briefs from the artifact, saying so when the path
     no longer resolves.
  7. **Full-form shape** — record the optional one-paragraph preamble between
     the header block and section 1, and the annotated `none` form of the
     `Work:` line (`none — <short explanation>`), both present in the reference
     file and absent from the document.
  With items 2, 3 and 4 landed, no open questions remain. Leave the
  `## Open questions` heading in place with an explicit "none outstanding"
  line rather than deleting it silently — the same honesty rule the feature
  itself applies to empty sections.
- **`docs/cli-help.txt` and `.claude/context/INDEX.md` are named as
  deliberately-unchanged** rather than silently omitted, so a later reader does
  not treat their absence as an oversight.
