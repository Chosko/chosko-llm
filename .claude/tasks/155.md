# Task 155 — Parse each feature's frontmatter once per `ls` row

Target: claude

## Goal
Task 152's REQUIRES column left `chosko-llm ls` about 32% slower, and the
cause is redundant parsing rather than the column itself. Each listing pass
calls `read_frontmatter_field` three times per row — installed version,
source version, and `requires` from inside `_requires_cell` — and every call
is a command substitution running `parse_frontmatter`'s awk plus a second awk
to pick one key out of its output. The source file is therefore parsed twice
for two fields of the same frontmatter block. Restructure how the five passes
read frontmatter so each distinct file is parsed at most once per row and both
fields come out of that one parse.

## Acceptance criteria
- Each of the five listing passes parses any given file's frontmatter at most
  once per row: the source file's `version` and `requires` come from a single
  `parse_frontmatter` result, not two.
- `ls` output is byte-identical to the current implementation for all four
  invocations — no flag, `--installed`, `--available`, and `--local` —
  including colours, padding, the dimmed malformed-entry rendering, and the
  name-ordered emit from task 153.
- Measured `ls` runtime returns to within a few percent of the pre-152
  baseline at commit `a467f67`. Record the before/after numbers in the commit
  body.
- `requires_specs` stays a strict filter over `requires_specs_lenient`, and
  `add` / `rm` still die on a malformed `requires:` entry while `ls` still
  renders it dimmed.
- No new dependency — awk/sed/grep and POSIX-ish bash only.
- Root `VERSION` gets a patch bump with a matching top `CHANGELOG.md` section;
  `./scripts/check-changelog.sh` is silent.

## Decisions
- The exact shape is the implementer's call, but the constraint is
  parse-once-read-many: either a `read_frontmatter_fields <file> <field>…`
  helper in `lib.sh` that runs `parse_frontmatter` once and emits several
  values, or having each pass hold the `parse_frontmatter` output in a
  variable and pick fields out of it. `read_frontmatter_field` itself stays —
  other callers depend on it and are not part of this task.
- Scope is the per-row parsing in `ls` only. `find_replacement` and
  `check_migration_pending` also call `read_frontmatter_field` per candidate
  file, but they run only on rows already computed as local-only or
  not-installed, so they are a different cost path and are out of scope unless
  the restructure makes them free.
- This is a behaviour-preserving change. Byte-identical output is the test,
  since the project has no suite.
