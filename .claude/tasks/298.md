# Task 298 — Update documentation for feature `session-readers`

Target: claude

## Goal
Part of feature `session-readers`. Tasks 295–297 added the slug form to
`/session-resume` and shipped `/session-list` and `/session-describe`; the
documentation describing the session store is now out of date and must
reflect the shipped behaviour.

## Acceptance criteria
- `.claude/context/session-handoff.md` covers all four session commands
  (or a new sibling context file covers the two readers, linked from it):
  the four-form resolution rule held in `/session-resume`, the readers'
  output shapes, read budgets and read-only contracts; the "directory
  listing is the only way an old session is found" clause goes.
- `.claude/context/features.md` and `.claude/context/INDEX.md` name the new
  commands wherever they list the session pair.
- `.claude/domain/features/session-continuity.md` states the agreed design
  change — `/session-resume` resolves four forms (path, date, slug, nothing)
  with the slug no-match stop as the one exception to degradation, and the
  readers make the store findable without opening files — in every passage
  that stated the old one. Nothing else in the document changes.
- `README.md` and `docs/reference.md` are not edited.
- No `VERSION` bump, no `CHANGELOG.md` entry (documentation only).

## Decisions
- **Design change agreed (user decision, 2026-10-07):** § Resolution in
  `/session-resume`: three forms (none/date/path) → four (path/date/slug/none);
  "Three forms, not four" paragraph keeps the dropped task-number selector
  but no longer counts forms that way. § Resolution / failure behaviour: a
  slug with no exact match stops, naming the nearest slugs. § File format
  (`<slug>` paragraph): "the directory listing … is the only way the user
  finds an old session" → `/session-list` and slug resolution find it.
  § Interfaces and contracts: `/session-resume <date|path>` →
  `<path|date|slug>`. `session-continuity.md` is normally `/architect`'s;
  this task updates it for exactly this and for nothing else. A further
  design decision met at implementation time is not covered: leave that
  passage untouched and name it under *Follow-ups* as a precise follow-up.
- README.md and docs/reference.md are excluded: user-facing docs are
  rewritten when the `unmanned` work ships.
