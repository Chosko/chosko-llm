# Task 208 — Add a --steps N flag to /runbook-run that runs a given number of steps, then stops

Target: claude

## Goal
`/runbook-run` can today be limited only by step ids (`--from`, `--to`,
`--only`); there is no way to say "run the next N steps and stop" without
first reading the runbook to find which id is N steps ahead. Add a
`--steps N` flag that runs at most N selected steps in this run and then
stops, composes with `--from` ("start at step X, run N steps"), and is
refused beside `--to` or `--only` — keeping the one selection model the
bounds already share, so dependencies, per-step re-reading and the
bounded-stop-is-not-completion rule all carry over unchanged.

## Acceptance criteria
- `skills/runbook-run/SKILL.md` ARGUMENTS table has a `--steps N` row: run
  at most N steps in this run, then stop. The Usage comment header gains a
  matching line and an example (e.g. `/runbook-run 3 --from 4 --steps 2`),
  and the frontmatter `description:` names the flag.
- The count is of steps **actually executed in this run** — a step counts
  when its subagent was spawned and its result reached step 8 as `DONE`.
  Steps already `[x]` never count (selection never picks them); a resumed
  `[~]` or re-run `[!]` step counts like any other selected step.
- Reaching the count stops the run exactly as reaching a `--to` bound does
  (step 8's bounded branch): stop after committing the N-th step, set the
  index back to `[PENDING]` unless every step in the whole runbook is now
  `[x]`, and report how many steps ran and which steps remain. The body says
  explicitly this is not completion.
- Fewer than N selectable steps is not an error: the existing branches apply
  unchanged — all `[x]` → completion (`[DONE]`), steps remaining but none
  selectable → deadlock report, a failure → halt as today.
- `--steps` composes with `--from`: selection begins at step X, and the count
  limits how many steps run from there.
- Two new argument errors join the existing list, each naming the problem and
  stopping having run nothing, in the same register as the `--only` one:
  - `--steps` together with `--to` or `--only`;
  - `--steps` with a missing value or a value that is not a positive integer
    (e.g. 0, -1, `abc`).
- `--steps` never weakens `Depends on:` — the dependency paragraph and the
  DO NOT bullet about weakening dependencies name it beside
  `--from` / `--to` / `--only`, and the DO NOT bullet forbidding `[DONE]` at a
  `--to` bound also covers reaching the `--steps` count.
- Step 1's `[DONE]`-runbook rule stays correct: `--steps` alone on a `[DONE]`
  runbook says so and stops, as a run with no flags does.
- The skill's `version:` gets a minor bump (0.8.0 → 0.9.0, or the next minor
  from whatever it holds at implementation time); root `VERSION` gets a
  minor bump with a matching `CHANGELOG.md` section on top;
  `./scripts/check-changelog.sh` passes.
- `skills/pipeline-engine/references/routing.md`'s `/runbook-run` row lists
  `[--steps N]` in its argument column, and `./scripts/check-routing.sh`
  passes.
- `docs/reference.md` (the `/runbook-run` bullet) and
  `.claude/context/features.md` (the `skills/runbook-run/SKILL.md` entry)
  describe the flag, its `--from`-only composition and its bounded-stop
  semantics.
- `.claude/domain/features/runbook-suite.md` is reconciled with what shipped
  on exactly these 2 points — editing it is authorised for this task, see
  Decisions:
  1. The usage block (~lines 885–893) gains a `/runbook-run <name> --steps N`
     line (and a `--from X --steps N` line if it reads naturally beside
     `--from X --to Y`).
  2. The selection paragraphs (~lines 904–915) state that `--steps` likewise
     does not weaken dependencies, is an error beside `--to` or `--only`,
     composes with `--from`, and stops a run the way a `--to` bound does
     (back to `[PENDING]` unless the whole runbook is `[x]`).
  Nothing else in the document changes.

## Decisions
- **Name `--steps N`** (recommended by the runbook step, confirmed by the
  user 2026-09-14): says what it counts, collides with no existing
  `/runbook-run` flag.
- **Refused with `--to` / `--only`; composes with `--from` only** (user
  decision, settled). Two different stopping conditions at once would need a
  precedence rule; refusing the pair avoids inventing one, mirroring how
  `--only` beside a bound is refused today.
- **Counts steps executed in this run, not list positions** (user-confirmed).
  Counting positions would make `--steps 2` run nothing on a runbook whose
  next two listed steps are already `[x]`, which reads as "run N steps" only
  by accident.
- **Reaching the count behaves as a `--to` bound, not completion**
  (user-confirmed). One stopping semantics, not two; the index stays
  `[PENDING]` because work is left behind by design.
- **Never weakens dependencies** (user-confirmed), same as the bounds.
- **Invalid values are an argument error** (user decision): `--steps 0`
  would otherwise be a silent do-nothing run, which the skill already treats
  as indistinguishable from a bug.
- **The count is applied against the per-step re-read, like the bounds** — a
  step appended mid-run is selectable and counted; no fixed list is resolved
  up front.
- **Not folded in:** the `--inline` execution mode and id-prefixed body
  filenames. Later runbook steps plan those as separate tasks with a
  `Preconditions:` on this one.
- **`.claude/skills/runbook-run/` is not touched.** It is a tracked installed
  snapshot (0.7.0, commit 822d524 "installed skills and commands locally in
  project"), not the source; only `skills/runbook-run/` is edited.
- **Editing `.claude/domain/features/runbook-suite.md` is explicitly
  authorised for this task (user decision, 2026-09-14), for the 2
  reconciliations listed above and for nothing else. Do not ask for
  permission at implementation time — the permission is already granted.**
  That document is normally `/architect`'s, and anything beyond those points
  still belongs to `/architect`. These are factual reconciliations with
  shipped behaviour, not redesigns; if one turns out to need a design
  decision rather than a wording fix, stop and say so instead of deciding it
  here.
