# Task 248 — Add `/doc-consolidate`: rewrite a document under the editing discipline, with a drops-only ledger and an independent verifier

Target: claude

## Goal
Documents written before the editing discipline carry superseded, historical,
duplicated and restated statements. Ship a skill that rewrites a file or a
folder under `claude-md:editing-discipline`'s rules, preserving meaning, with a
review surface the user can actually read: a ledger of what is dropped or
merged, never of what is kept, and an independent verifier that reports what
the rewrite lost.

## Acceptance criteria
- `skills/doc-consolidate/SKILL.md` exists with full frontmatter (`version:
  0.1.0`), usage `/doc-consolidate <path> [--commit] [--no-push]`, default
  uncommitted; `<path>` is a file or a folder.
- It is semantics-preserving and not a style compressor: it removes
  superseded, historical, duplicated and restated statements and merges
  overlapping ones; wording that carries meaning is kept, terse or not.
- Schema-aware: frontmatter, the body header of a shipped command or skill,
  the six sections of a context file and the sections of the feature-document
  template are kept in place; consolidation happens inside them.
- Plan-first, per section on files above a stated size: the ledger shown
  before a section is rewritten lists only drops and merges; a superseded
  statement is shown as an old/new pair, historical statements are grouped
  under one count, duplicates name the surviving location. The user approves
  per section, or once for the whole file when they say so. Nothing is written
  before approval.
- After the rewrite, a verifier subagent with fresh context and no access to
  the ledger reads the old and the new text and lists every normative
  statement present in the old and absent from the new. Its report, expected
  near-empty, is printed for the user; any item on it is either restored or
  explicitly accepted by the user before the run ends. The verifier's prompt
  lives in `skills/doc-consolidate/verifier.md`.
- On a folder, cross-file duplicates are found with the method of the
  repo-local `rule-overlap` audit (collect normative statements, group
  restatements) and resolved by keeping one statement and citing it by path.
- The closing report gives before/after line counts as an observation, with no
  target and no judgement attached.
- `docs/reference.md`, `README.md`, `docs/cli-help.txt` where skills are
  listed, and `.claude/context/features.md` name the skill; root `VERSION`
  minor bump; `CHANGELOG.md` entry; `./scripts/check-changelog.sh` and
  `./scripts/check-home-paths.sh` silent.

## Decisions
- The verifier, not the ledger, is what the user validates: a full ledger is
  too long to read, and a fresh reader listing lost rules is a cheaper and
  stronger check than re-reading the plan.
- Named `doc-consolidate`, not `doc-compress`: the caveman plugin ships a
  style compressor under that name, and this skill changes what is said, not
  how.
