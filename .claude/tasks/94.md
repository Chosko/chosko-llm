# Task 94 — Run /cavecompress lite on shipped commands and skills, with peer-review before commit

Target: claude

## Goal
Cut input tokens on every shipped command/skill prompt (commands/*.md,
skills/**/*.md, claude-md/tool-usage-policy.md — the .md files only,
not statusline/*.sh) by running caveman-compress lite on all of them.
Unlike task 93 (context/domain reference docs, compressed and committed
directly), these files ARE the executable prompt bodies Claude Code
parses to run each command/skill — a manual experiment on
skills/task-implement/SKILL.md during authoring found the compressor can
silently invert meaning ("fix the production code and rerun" became
"Don't: fix production code, rerun") while still passing the tool's own
structural validation. So this task adds a peer-review gate before
anything is committed.

## Acceptance criteria
- Every listed file has been run through caveman-compress (the
  `caveman-compress` skill/CLI), overwriting the working copy; each
  file's pre-compression original is preserved (the tool already does
  this via its out-of-tree backup dir — do not disable or bypass that).
- For every compressed file, a fresh subagent is spawned that receives
  ONLY the original and compressed text (no other task context) and is
  asked specifically to find meaning shifts — inverted or dropped
  conditionals, changed defaults, altered trigger conditions, lost
  exceptions/caveats — not style opinions. It reports per file: CLEAN,
  or a list of specific meaning-shift findings with the original phrase,
  the compressed phrase, and why the meaning changed.
- Agents run one at a time or in parallel batches — implementer's call —
  but each agent reviews exactly one file and has no visibility into any
  other file's review.
- All agent findings are collected and presented to the user as one
  report, grouped by file, before anything is committed.
- The user is asked, file by file (or in one batch selection), which
  compressed files to keep and which to revert to their pre-compression
  original. Silence/no answer is not approval to keep.
- Files the user chooses to revert are restored byte-for-byte from the
  pre-compression backup; files the user chooses to keep stay compressed.
- Only the files the user approved to keep are staged and committed;
  reverted files produce no diff and are not part of the commit.
- VERSION is bumped (patch) to reflect the shipped doc change, but only
  if at least one file was kept — a run where the user reverts
  everything makes no shipped change and should not bump it.

## Decisions
- Peer review runs one subagent per file rather than one subagent for
  the whole batch, so a review can't be biased by having already seen
  another file's original/compressed pair, and so a bad review on one
  file doesn't need re-running the rest.
- Keep/revert is a per-file user decision, not an automatic gate on
  whether the reviewing agent found something — the agent's report
  informs the decision, it doesn't make it. A CLEAN verdict from the
  agent is not itself sufficient to skip asking the user.
- This task intentionally does not touch CLAUDE.md or .claude/context/ or
  .claude/domain files — those were task 93's scope and are already done.

## Hints
- The caveman-compress skill lives under the caveman plugin
  (`.claude/plugins/marketplaces/caveman/skills/caveman-compress/`); run
  it via `python -m scripts <absolute filepath>` from that directory (per
  file — it does not accept a directory or glob).
- Compressed-file backups land in the tool's own out-of-tree backup dir
  (`%LOCALAPPDATA%\caveman-compress\backups\<parent-dir-name>\<name>.original.md`
  on Windows) — that is the reference the review agents and any revert
  step should read from, not a copy you make yourself.
