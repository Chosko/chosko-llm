# Task 94 — Add an optional claude-council decision gate to /architect

Target: claude

## Goal
Let `/architect` pressure-test its genuinely consequential design forks through
claude-council (https://github.com/TorpedoD/claude-council, MIT) — a five-lens
advisory framework that runs adversarial peer review and produces a synthesis
preserving minority dissent. The integration is optional delegation: when the
user has the claude-council skill installed, `/architect` offers to convene it
at a real trade-off; when they don't, the skill behaves exactly as it does
today. This buys better decisions at the two points where `/architect`'s output
is most expensive to get wrong — the stack choice and the architecture shape —
without adding a dependency or duplicating upstream work.

## Acceptance criteria
- A new `skills/architect/council-gate.md` carries the whole protocol:
  detection, triage, question framing, invocation, fold-back, and artifact
  handling. Nothing about the council is duplicated into `SKILL.md` beyond a
  one-line offer and the pointer to this file.
- `SKILL.md`'s SUPPORTING FILES table gains a `./council-gate.md` row whose
  "exactly when" is precise enough that the file is never read speculatively —
  it loads only when PHASE 2 reaches a genuine fork that passes triage.
- The gate is offered at three PHASE 2 sites: 2a (stack candidates, via
  `tech-stack-selection.md`), 2b step 1 (architecture shape options), and
  2b step 4 (where the low-level feature split falls).
- Detection probes `${CLAUDE_HOME:-$HOME/.claude}/skills/claude-council/SKILL.md`.
  When absent, the run proceeds exactly as today and says nothing.
- Triage precedes every offer. The gate never fires on a missing fact, and never
  when an existing stack or a present `technical-direction.md` already settles
  the question.
- The council is invoked with no mode argument, so claude-council's own mode
  selection and low-confidence escalation apply.
- `SKILL.md`'s DO NOT list gains a second carve-out to its "Write any file
  before PHASE 3" prohibition, covering council artifacts, worded in the same
  register as the existing progress-marker exception.
- Council artifacts are never added to `WRITTEN` and never staged by `--commit`.
- The PHASE 2 progress marker records that the council was convened, on what
  question, and its verdict.
- The closing report states whether the council was convened, the question, the
  run SHA, the verdict, and where the report and transcript landed.
- `tech-stack-selection.md`'s "Then make a recommendation" step points at the
  gate without restating it.
- Frontmatter `version:` bumped 0.4.0 → 0.5.0.
- No shipped body references a `docs/` path — `docs/` is never installed.

## Decisions
- Optional delegation, not vendoring. Reimplementing the five-lens pattern in
  this repo would duplicate MIT-licensed upstream work and drift from it;
  delegating keeps claude-council's `jq` requirement on claude-council's side of
  the line and leaves this repo's "no new dependencies" hard rule intact.
- Auto-offer rather than a `--council` flag. The user chose surfacing the
  capability at the moment it's useful over a flag most people would never
  discover. Triage is what keeps this from becoming a nag.
- Silent when claude-council is absent. An authoring run must not advertise an
  uninstalled optional dependency mid-flight; discoverability is handled in
  README and frontmatter instead (task 96).
- No mode argument. claude-council's step-4 triage weighs stakes better than a
  generic gate can, and Standard auto-escalates to Deep on low confidence —
  hardcoding a mode would suppress that.
- The council informs, never decides. `/architect`'s existing "Advance past
  PHASE 2 without the user confirming the architecture" prohibition is
  unchanged; the verdict feeds the recommendation the user still approves.
- Dissent maps to Open questions. The minority ledger is exactly the material
  the feature document's Open questions section exists to hold, so it lands
  there rather than being flattened into the verdict.
- Council artifacts stay out of `WRITTEN`. They're claude-council's output, not
  this skill's, and committing generated HTML into a user's repo is a side
  effect `/architect` has no mandate for.
- The progress marker records the council result. Re-convening on resume would
  cost another ~15 agent calls for an answer already paid for.
