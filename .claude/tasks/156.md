# Task 156 — Re-sync the domain layer's `/production-status` description with the Next field

Target: claude

## Goal
Task 154 replaced `/production-status`'s Ready column with a five-valued Next
field, made section 4 echo that value instead of recomputing a next step, and
changed the zero-task rollup so a `[DONE]`/`[PLANNED]` feature with no tasks
renders `-` rather than the false `no tasks yet`. The domain layer still
describes the command as it stood before, in two places with the same
wording — `.claude/domain/product-workflow.md` and
`.claude/domain/features/plan-readout.md`. Bring both in line with what
shipped.

## Acceptance criteria
- `.claude/domain/product-workflow.md`'s `/production-status` section
  describes section 2's last field as the Next field, not readiness, and says
  section 4 echoes it rather than deriving its own recommendation.
- `.claude/domain/features/plan-readout.md` is reconciled with what shipped on
  exactly these 3 points — editing it is authorised for this task, see
  Decisions:
  1. Section 2's last field is the Next field, not readiness.
  2. Section 4 echoes that Next value rather than deriving its own.
  3. The zero-task rollup rule: `-` for `[DONE]`/`[PLANNED]`, `no tasks yet`
     kept only for `[NEW]`/`[ITERATED]`.
  Nothing else in the document changes.
- The zero-task rollup rule is stated in both files: `-` for a `[DONE]` or
  `[PLANNED]` feature with no tasks, `no tasks yet` with its `/task-add` gloss
  kept for `[NEW]` and `[ITERATED]`.
- Readiness itself is described as unchanged — task 154 did not touch how it is
  derived, only what section 2 displays.
- No behaviour change and no other file edited; this is a prose re-sync.
- Root `VERSION` gets a patch bump with a matching top `CHANGELOG.md` section;
  `./scripts/check-changelog.sh` is silent.

## Decisions
- Both files are done together because they are one owner's prose, worded
  identically. Splitting them would leave the two halves drifted from each
  other instead of from the code.
- **Editing `.claude/domain/features/plan-readout.md` is explicitly authorised
  for this task (user decision, 2026-08-25), for the 3 reconciliations listed
  above and for nothing else. Do not ask for permission at implementation
  time — the permission is already granted.** That document is normally
  `/architect`'s, and anything beyond those points still belongs to
  `/architect`. These are factual reconciliations with shipped behaviour, not
  redesigns; if one turns out to need a design decision rather than a wording
  fix, stop and say so instead of deciding it here.
