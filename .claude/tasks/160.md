# Task 160 — Make `/task-review` honour the read budget and never run tests

Target: claude

## Goal
The consumer side of feature `task-peer-review`'s cost controls. `/task-review`
currently reads whatever it likes and says nothing about test commands. This
task makes it honour the budget block its caller now sends, declare
`requires: skill:task-engine` so the protocol file is installed alongside it,
and state the rule that it never re-runs the tests the implementer already
ran — the single largest avoidable cost in a review.

## Acceptance criteria
- Frontmatter gains `requires: skill:task-engine`, and `version:` takes a
  minor bump.
- The skill reads
  `${CLAUDE_HOME:-$HOME/.claude}/skills/task-engine/references/review-budget.md`
  when its invocation carries a budget block, honours the tier it names, and
  does not restate the table.
- The navigation layer is read in full and never counted, at every tier; only
  distinct source and test files beyond the diff count against the cap.
- An invocation with no budget block — a manual run, or a spawn whose effort
  resolved to `same` — reads unbounded, exactly as today.
- A cap that actually binds is reported: the skill stops investigating,
  reports the remaining criteria under the existing gates, and says in one
  line that the cap bound.
- Under `shallow`, the skill states plainly that it cannot read callers, so
  Pre-Report Gate question 3 is answered "no" and the finding is demoted or
  dropped by the gate that already exists — no second gate is added.
- A new contract clause: the skill invokes no test command, in any mode, under
  any budget, under any testing policy, and on either invocation path. It is
  part of the read-only contract, not a budget setting, and no tier relaxes
  it. Reading test files as source is unchanged and still required by the
  Pre-Report Gate.
- Where the caller reports skip-tests mode, the skill says nothing ran and
  reports any criterion depending on runtime behaviour as `unverifiable` —
  the verdict the report schema already carries — rather than treating it as
  a reason to run something.
- The DO NOT list gains entries for running a test command and for admitting a
  finding the tier's own limits prevented it from checking.
- The description reflects the budget, the `requires:` and the no-tests rule.
- Root `VERSION` takes a minor bump and `CHANGELOG.md` gains a matching top
  section, which notes that installing `task-review` now pulls in
  `task-engine`. `./scripts/check-changelog.sh` exits zero.

## Decisions
- `requires:` is unconditional here, unlike `/task-implement`'s deliberately
  runtime `--review` availability gate. The difference is real: the budget
  protocol is read on the ordinary spawned path, not on an opt-in one. The
  feature document names this as an accepted change to what installing
  `task-review` alone does.
- No `--review-effort` flag is added to `/task-review` itself. A hand-typed
  run happens in the session the user already chose; the flags belong to
  `/task-implement`.
