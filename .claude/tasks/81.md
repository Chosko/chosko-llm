# Task 81 — Make /task-implement auto-skip TDD phases for documentation-only tasks

Target: claude

## Goal
In full test mode (a project with a real test suite, no skip-tests marker),
/task-implement currently runs Steps 2/4/5 (write tests, run affected
tests, run full suite) for every task, including ones that touch nothing
but documentation. Writing or running tests for a change with no
executable surface is meaningless work. Make the skill detect, per task,
that it is documentation-only and silently skip Steps 2/4/5 for it — no
confirmation prompt — while leaving skip-tests / skip-tests-unattended
mode's existing global skip untouched.

## Acceptance criteria
- A new "DOCUMENTATION-ONLY TASKS" section (or equivalent) in
  skills/task-implement/SKILL.md defines a documentation-only task: every
  path in the task's `Files:` field (already known from PRE-FLIGHT step 2)
  is a documentation artifact (README.md, CHANGELOG.md, docs/**, or
  comparable prose/reference files), and none is a source file, script,
  test file, or a command/skill specification (commands/*.md,
  skills/**/*.md, or the equivalent executable-prompt files in another
  project — these look like markdown but define runtime behavior, so
  editing them is a code change).
- The determination is folded into Step 1 (Mark IN PROGRESS), using data
  already in hand at that point — the `Files:` field noted in PRE-FLIGHT
  and the body just read in Step 1 — not a separate re-read pass.
- If `Files:` is empty, ambiguous, or mixes documentation with any
  non-documentation path, the task is treated as a normal code task; the
  skill never guesses in the direction of skipping tests.
- Steps 2, 4, and 5's bracketed labels are updated to note they are also
  skipped when Step 1 determined the task is documentation-only (in
  addition to the existing skip-tests-mode skip).
- No confirmation prompt is added or required for this skip — it is
  silent and automatic, consistent with how skip-tests-unattended already
  behaves.
- Behavior when skip-tests / skip-tests-unattended mode is already active
  is unchanged (Steps 2/4/5 are already skipped for every task there,
  making the new determination moot).
- `.claude/domain/task-workflow.md`'s "`/task-implement` discipline"
  section is updated to describe this behavior, keeping the domain doc in
  sync with the skill.

## Decisions
- Detection is based on the `Files:` field plus the body already read at
  Step 1 — no extra re-read of anything, since both are already available
  by that point in the per-task workflow (user's explicit call, to avoid
  redundant reads).
- `commands/*.md` and `skills/**/*.md` are excluded from "documentation"
  even though they are markdown files, because in this repo's own
  convention they are executable specifications, not prose — the same
  heuristic should carry to other projects using this skill via the
  analogous "executable-prompt" framing rather than a hardcoded path list.
