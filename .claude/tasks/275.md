# Task 275 — A re-park deletes the leftover park branch first, and the `/task-clean` sweep spares `[IN PROGRESS]` tasks

Target: claude

## Goal
Feature `unattended-parking`: task 272 moved the unpark's branch delete to
after the task's commit, so a resumed task that asks a second question under
`unattended` meets its own `park/task-<N>` still present, and the park
sequence (`skills/task-engine/references/parking.md` § *The branch*, § *The
park sequence* step 1) fails it as "branch exists". The amended design
(`.claude/domain/features/unattended-parking.md` § *Task parking*, § *Data and
state*, § *Interfaces and contracts*) settles it: the park deletes that
leftover first, local and remote — its content is already in the tree via the
unpark's cherry-pick — and a delete that is refused or fails fails the park
as a Step 7 failure. And the `/task-clean` sweep spares a branch whose task is
`[PARKED]` or `[IN PROGRESS]`: an unpark that resumed but stopped before its
commit still needs the branch as rollback source.

## Acceptance criteria
- `parking.md` § *The branch* no longer calls an existing `park/task-<N>` an
  inconsistent state that fails the park; it states the leftover case and the
  delete-first rule. The name stays deterministic — never suffixed, never
  overwritten in place.
- `parking.md` § *The park sequence* step 1: when `park/task-<N>` exists
  (locally and/or on the remote, remote skipped under NO_PUSH as for every
  remote operation), delete it — `git branch -D park/task-<N>`,
  `git push origin --delete park/task-<N>` — before making the new branch. A
  refused or failed delete fails the park as a Step 7 failure: task
  `[IN PROGRESS]`, tree intact, run stopped.
- `skills/task-implement/SKILL.md` FAILURE HANDLING's park-failure sentence
  ("the name already taken, the push refused") names the new cause — a
  leftover branch the park cannot delete — instead of "name taken".
- `skills/task-clean/SKILL.md`: the sweep's *Orphaned* definition and the
  header comment treat a branch as orphaned only when task N has no summary
  block, or its `Status:` is neither `[PARKED]` nor `[IN PROGRESS]`; one
  reason clause names the rollback source.
- `parking.md`'s pointer to the sweep (near "sweeps every `park/task-<N>`
  branch whose task is not `[PARKED]`") and
  `skills/pipeline-engine/references/routing.md`'s `/task-clean` row state
  the same exception; `./scripts/check-routing.sh` passes.
- Feature frontmatter `version:` bumped on `task-engine`, `task-implement`,
  `task-clean`, `pipeline-engine` (patch); root `VERSION` bumped (patch) with a
  matching `CHANGELOG.md` section; `./scripts/check-changelog.sh` and
  `./scripts/check-home-paths.sh` pass.

## Decisions
- **Deterministic name, delete first, halt on failure** (user decision,
  2026-09-30): suffixed names would make unpark and sweep depend on the
  handoff's `Parking Branch:` value — error-prone; a park that proceeded over
  a stale branch would leave the unpark picking an outdated commit.
- The sweep keys on `[IN PROGRESS]` read from `TASKS.md` alone — no body read.
