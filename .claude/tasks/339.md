# Task 339 — Carry the park-branch exception in the subagent contract's remote rule

Target: claude

## Goal
OPERATING RULES in `skills/runbook-run/references/subagent-contract.md`
tells a step agent in a worktree that the remote is the orchestrator's and
that a skill it invokes skips its pull and push "exactly as under
`--no-push`", while `task-engine`'s `parking.md` has a unit's agent push its
own `park/task-<N>` — the branch another machine needs to unpark. A step
running `/task-implement --unattended` in a worktree reads two rules that
disagree. Carry the exception into the contract, as feature
`parallel-runbooks` § Architecture, *Each step in its worktree* now states:
the rule names the base's pull and push as the orchestrator's and
`park/task-<N>` as the one branch an invoked skill still pushes, under
`parking.md`; the rationale bullet in § *Why each rule is in there* says why
that push races nothing. The block stays one verbatim text with its four
placeholders.

## Acceptance criteria
- The OPERATING RULES block's "The remote is the orchestrator's" rule states
  that a skill the agent invokes makes its commits as usual, skips the pull
  at start, the pre-push re-sync and the push of the base exactly as under
  `--no-push` with no flag typed, and still pushes its own `park/task-<N>`
  when it parks, as the `task-engine` skill's `references/parking.md` says —
  named by skill and file, never by a path, since the block lands in a
  prompt. The rest of the rule (integrate before `DONE`, name the tip) is
  unchanged, and the block keeps exactly its four placeholders.
- § *Why each rule is in there* explains the exception in one or two
  sentences beside the remote-rule bullet: the park branch is private to the
  task, deterministic per task and touches no base, so it races no landing,
  and pushing it is what lets another machine unpark.
- Every other passage of the file that restates the never-push rule is
  reconciled; no passage contradicts the exception.
- `runbook-run`'s `version:` is bumped (patch); root `VERSION` is bumped
  (patch) with a matching `CHANGELOG.md` section; `./scripts/check-changelog.sh`
  and `./scripts/check-home-paths.sh` pass.

## Decisions
- The exception is stated in the contract rather than left to `parking.md`
  alone: the contract is what a step agent actually reads, and a rule it
  carries verbatim must not contradict the rule the invoked skill follows.
