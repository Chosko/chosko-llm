# Task 158 — Add the review-budget protocol to `task-engine`

Target: claude

## Goal
Feature `task-peer-review` gives `/task-implement --review` two cost-control
flags, and both the producer of the resolved values and their consumer need
the same table to agree on what they mean. Per the feature's
*Review cost controls* section, that protocol lives in `task-engine` — stated
once, read by `/task-implement`'s `review-rounds.md` to resolve and pass, and
by `/task-review` to honour. This task adds the reference file and registers
it in the engine's map; the two consumers come in tasks 159 and 160.

## Acceptance criteria
- `skills/task-engine/references/review-budget.md` exists and follows the
  house shape of the other reference files: a title, an "Authority for:" line,
  a note on where the rule was extracted from, `---`, the rule, and a
  `Per-consumer notes` section.
- It carries the `auto` tier table verbatim from the feature document —
  heavy / light / standard, first matching row wins, resolving from four
  signals (lines changed, files changed, acceptance-criteria bullet count,
  and whether the diff touches any non-`.md` file) — and states that `auto`
  never selects `haiku`, and that resolution happens per task, not per run.
- It carries the read-budget table verbatim — shallow / standard / deep across
  the navigation layer, source/test files beyond the diff, whole-file reads,
  callers and imports, tests covering the diff, per-criterion verdicts, and
  the test command.
- It states that the navigation layer (`CLAUDE.md` and its chain,
  `.claude/context/INDEX.md` and the rows for the files in the diff, the task
  body, the feature document named by the task's `Feature:` line) is permitted
  in full and never counted at any tier, and why: metering it pushes a capped
  reviewer into source, which is the expensive path.
- It states that only distinct source and test files beyond the diff are
  counted, and that re-opening a counted file is free.
- It records the two reserved words: `same` on model omits `model:` from the
  Agent call so the child inherits the parent; `same` on effort omits the
  budget block so the reviewer reads unbounded.
- It records that model names pass verbatim to the Agent tool with no local
  allow-list, and why.
- It states the shallow/Pre-Report-Gate interaction: a reviewer forbidden to
  read callers answers "no" to gate question 3, which demotes or drops the
  finding — so a cheaper review is automatically more conservative, never more
  confident-and-wrong.
- It states that a cap which actually binds must be reported in one line, and
  why a silent cap cannot be retuned.
- It states that no tier ever permits a test command, under any testing policy
  or invocation path.
- `skills/task-engine/SKILL.md` gains a map row for the new file, its
  description's file count is corrected, and its `version:` takes a minor bump.
- Root `VERSION` takes a minor bump and `CHANGELOG.md` gains a matching top
  section; `./scripts/check-changelog.sh` exits zero.

## Decisions
- The file is written as an authority, not a summary: tasks 159 and 160 cite
  it and state only what they do differently, per the shared-phase-engine rule
  the engine already follows.
- `task-engine` takes a minor bump rather than a patch — a new reference file
  is new surface for its consumers, not a fix.
