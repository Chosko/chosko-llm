# Task 108 — Extract /architect's input resolution into sectioned-input.md

Target: claude

## Goal
Move `/architect`'s existing input-resolution text out of `SKILL.md` and into
a new on-demand supporting file `skills/architect/sectioned-input.md`, with
`SKILL.md` reading it unconditionally. This is the first half of feature
`slice-aware-architecture`: it creates the seam that task 109's slice mode
plugs into, while changing no behaviour at all. Content is MOVED, never
rewritten — that discipline is what makes the feature's central guarantee
("`/architect` behaves exactly as it does today on projects with no roadmap")
verifiable by reading a diff rather than by trusting a claim.

## Acceptance criteria
- `skills/architect/sectioned-input.md` exists and carries the traditional
  resolution mode: resolving the target against `product-design.md` sections
  and existing `FEATURES.md` slugs, and writing
  `Source: product-design.md § <section>` (or the literal `prompt`).
- The moved text is byte-for-byte the current text wherever it can be —
  reflowing and adding the file's own heading is fine; rephrasing the rules
  is not. A reviewer must be able to confirm equivalence from the diff.
- `SKILL.md`'s SUPPORTING FILES table gains a row for `./sectioned-input.md`
  with its "exactly when" — for now, PHASE 0, always.
- PHASE 0's "Resolve the target feature(s)" step points at the new file
  instead of restating the rules inline.
- Only input resolution and the `Source:` format move. The gate, the
  pull-at-start, the read-the-inputs list, stack detection, the existing-entry
  check, the interrupted-session check, PHASE 0b, PHASE 1, PHASE 2, PHASE 3
  and the commit protocol all stay in `SKILL.md` untouched.
- No new flag, no probe, no roadmap reference — those are task 109.
- `skills/architect/SKILL.md` frontmatter `version:` bumped 0.5.0 → 0.5.1
  (patch: internal reorganisation, no behaviour change), and the frontmatter
  `description` left semantically unchanged.
- Root `VERSION` bumped patch.
- `./bin/chosko-llm ls --available` still lists `architect` at the bumped
  version, and `./bin/chosko-llm show architect` still resolves.

## Decisions
- **Extraction shipped as its own task, ahead of slice mode.** Task 109 hard-
  depends on task 106 (the `/product-roadmap` skill and its document schema);
  this extraction does not, so it can land immediately and its zero-behaviour-
  change property stays separately provable.
- **`SKILL.md` reads `sectioned-input.md` unconditionally in this task.** The
  activation probe and the branch arrive with task 109. Landing the branch
  here would point at a `sliced-input.md` that does not yet exist.
- **Patch bump, not minor.** Nothing observable changes for a user of the
  skill; the file split is internal to the skill folder.
