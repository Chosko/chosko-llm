# Task 308 — Move area handoffs in `/session-save` and list them in `/session-resume`

Target: claude

## Goal
Part of feature `orchestrate-mode`. Area handoffs live under
`.claude/sessions/pending/` until the conversation's first save. `/session-save`
moves them into the new session's `<session-file-stem>/` folder and stages
them with the session file; `/session-resume` lists the areas found in the
resolved session's folder, each with its handoff path, so a resumed
orchestrator can hand each area's next agent its file.

## Acceptance criteria
- `/session-save`: when `.claude/sessions/pending/agent-*.md` exist, they
  move to `.claude/sessions/<stem>/` (the stem of the file just written) and
  are staged with it; a later save in the same conversation whose stem folder
  already holds handoffs carries them into the new stem's folder; no pending
  handoffs → nothing changes. `pending/` left empty is removed.
- `/session-resume`: after the briefing, when the resolved file has a
  `<stem>/` folder, lists each `agent-<area>.md` by area name with its path,
  from filenames only — never reads a handoff body; does not turn the mode
  on. Candidacy (top-level files only, subfolders skipped) is unchanged.
- Neither command names a path into the `orchestrate-mode` skill.
- `version:` bumped (minor) on both; root `VERSION` minor-bumped with a
  `CHANGELOG.md` section; `check-changelog.sh`, `check-home-paths.sh` pass.

## Decisions
- `/session-describe` and `/session-list` already list areas (tasks 297,
  296); not touched here.
- Settled here, against `.claude/domain/features/orchestrate-mode.md`
  § Session commands (no conflict): a later save carries the previous stem's
  handoffs forward, so the newest session file always has the current area
  set; `/session-resume` reports handoff paths but leaves the mode off.
