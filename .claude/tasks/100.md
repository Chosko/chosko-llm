# Task 100 — Add the /context-convert skill (flat ↔ nested)

Target: claude

## Goal
A project that outgrows a flat context layer (or shrinks back into one)
should not have to rebuild it from source. Add `/context-convert`, a new
skill that restructures an existing context layer in both directions,
preserving the authored content of every context file.

## Acceptance criteria
- New skill at `skills/context-convert/SKILL.md`, frontmatter `name:
  context-convert`, `type: skill`, `version: 0.1.0`, description matching
  the family's voice.
- Direction is inferred from the current `Layout:` marker and may be forced
  by argument: `to=nested` / `to=flat`. Converting to the layout already in
  place reports "already <layout>" and exits without writing.
- `nested=<unit1>,<unit2>,…` pre-seeds the unit breakdown when converting
  to nested, exactly as in `/context-build`.
- **Plan-first gate.** Phase 1 analyses the existing layer and reports the
  full plan — every file's old and new path, the unit breakdown, what
  happens to each `Last updated` — and stops for approval before any write.
  `-y` / `--yes` skips the gate, consistent with `/context-update`.
- **flat → nested:** propose unit seams from the existing files' content
  and cross-references, move each context file into its unit folder,
  author one leaf INDEX per unit, and rewrite the root INDEX as a router
  (`Layout: nested`, Units table, no `Last updated`). Every leaf inherits
  the flat layer's single `Last updated` date, so no unit looks fresher
  than it is.
- **nested → flat:** move every context file back to `.claude/context/`,
  delete the leaf INDEXes and unit folders, and rewrite the root INDEX as
  a flat index (`Layout: flat`, Files table) whose `Last updated` is the
  **minimum** across all leaf dates — a floor, so the next Mode A run
  re-checks rather than skips.
- A filename collision on nested → flat (same basename in two units) stops
  the run with the colliding paths listed; the user renames and re-runs.
  Nothing is written on a stop.
- Context-file bodies are never rewritten — only moved. Cross-reference
  links inside them are rewritten to stay valid across the depth change,
  and nothing else about their content is touched.
- Domain files, source code, and CLAUDE.md are out of scope, matching the
  rest of the family. CLAUDE.md's navigation instruction already points at
  `.claude/context/INDEX.md` in both layouts and needs no edit; say so in
  the report.
- The result must be a layer that `/context-update` accepts without
  complaint in its new layout — verify by running it after the conversion.
- Same commit family as `/context-build`: uncommitted by default,
  `--commit` to commit and push, `--commit --no-push` to skip the push.
  Staging is explicit paths only, and must cover deletions (`git add --`
  on removed paths, or `git rm`) so the move is a single coherent commit.
- `.claude/domain/context-workflow.md` documents the new skill and the
  date-inheritance rules in both directions.
- Root `VERSION` bumped minor.

## Decisions
- **Leaves inherit the flat date going nested; the router-less flat index
  takes the minimum going back.** Both directions fail safe — the worst
  case is re-checking a unit that had not changed, never skipping one that
  had.
- **A skill, not a command, and no `nested.md` split.** Every run of this
  skill is about the nested layout, so there is no flat path to keep cheap;
  splitting the file would buy nothing.
- **Stop on collision instead of auto-renaming.** A generated name would
  break every cross-reference pointing at the old one, and the user is
  better placed to pick the surviving name.

- .claude/domain/context-workflow.md — layout contract; document the new skill
- docs/authoring-guide.md — skill frontmatter and versioning
