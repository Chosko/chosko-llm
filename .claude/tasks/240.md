# Task 240 — Set the description contract: short what+when in frontmatter, flags in the body header

Target: claude

## Goal
Claude Code injects every installed feature's frontmatter `description` into
the system prompt at session start, as one `- name: description` line per
feature, and truncates each at 1,536 characters ("Put the key use case first:
the combined description and when_to_use text is truncated at 1,536 characters
in the skill listing"). The authoring guide currently licenses paragraph-length
descriptions that document every flag so that `chosko-llm show` has something
to print. The result, measured on the pipeline branch at v1.57.4: 38 features
put ~45,100 chars of description on disk, the model receives ~7,600 tokens of
it every session before the first prompt, and the seven longest descriptions
(`task-implement`, `runbook-run`, `runbook-create`, `architect`,
`pipeline-revise`, `task-add`, `task-review`) lose their tails — which is where
the flags live. `runbook-clean`'s description also contains a literal ` --- `
and the harness cuts it there, so the model sees 145 of its 1,111 chars.

This task replaces that policy with a contract the two rewrite tasks (241,
242) follow. A description says what the feature does and when to use it,
front-loaded and short. Flags, refusal lists, read-only contracts and
commit/push defaults live in the body's leading `#`-comment header — the
`# /name` / `# Usage:` block that 34 of the 38 bodies already open with. And
`chosko-llm show` prints that header under the description, so a human loses
nothing.

## Acceptance criteria
- `docs/authoring-guide.md` § `description` (currently line 59) is rewritten
  to the contract: what + when, front-loaded; manual features ≤ 60 words /
  400 chars; the auto-trigger skills (`claude-council`, `runbook-suggest`,
  `pipeline-suggest`, `unity-mcp-skill`) ≤ 150 words / 1,000 chars, trigger
  phrases first and any "Not for" list last; a hard fail above 1,536 chars;
  ` --- ` never appears inside a description (the harness truncates there);
  a feature that has a pipeline stage carries exactly one clause naming it.
- The guide states where the rest goes: the body's leading `#`-comment header
  (`# /name`, one-paragraph summary, `# Usage:` lines, examples) is the
  authority for flags and contracts at run time, and every shipped body has
  one.
- The guide documents the three loading-control frontmatter keys Claude Code
  recognises and this repo may now use — `disable-model-invocation: true`
  (description out of context, user-only invocation), `user-invocable: false`
  (hidden from the `/` menu, model-only) and `paths:` (skills only; loads only
  when matching files are in play) — including that commands support the
  first two but not `paths:`.
- `scripts/lib.sh`'s `parse_frontmatter` is confirmed to ignore those keys
  (it already "quietly ignores keys it doesn't care about"); no CLI rejection
  path is added, and a one-line note in the guide records that unknown keys
  pass through.
- `scripts/cmd-show.sh` prints the body's leading `#`-comment header block
  (contiguous lines starting with `#` immediately after the frontmatter)
  under the description in every view, by default; `--content` still prints
  the full body. Verified by running `./bin/chosko-llm show task-list` and
  `./bin/chosko-llm show task-add --latest` against the clone. A body with
  no header prints nothing extra.
- `commands/runbook-clean.md`'s description no longer contains ` --- `
  (rewrite the clause; the full rewrite of that description is task 242).
- The four bodies with no `#` header — `skills/claude-council/SKILL.md`,
  `skills/unity-mcp-skill/SKILL.md`, `skills/task-engine/SKILL.md`,
  `skills/pipeline-engine/SKILL.md` — get one; for the two reference
  libraries it is a two-line "read by path by …; not invoked" note.
- `.claude/skills/context-budget/SKILL.md` flags a description over 1,536
  chars (hard cap) and one containing ` --- `, beside its existing 30-word
  signal; its `description:` awk is extended, not replaced.
- Root `VERSION` minor bump (cmd-show behaviour changes), `CHANGELOG.md`
  entry, `./scripts/check-changelog.sh` and `./scripts/check-home-paths.sh`
  silent. The four touched shipped bodies bump their own `version:` (patch).

## Decisions
- **Keep `chosko-llm show`.** Removing it saves no context tokens (it reads
  files on disk and never enters a session) and would be a breaking CLI
  change. Printing the existing header is a ~10-line change that keeps `show
  <feature>` useful without a flag.
- **Reuse the existing `#` header, do not add a Usage section.** 34 bodies
  already carry one; adding a second block would be the redundancy the task
  removes. The header costs nothing per session — bodies load only on
  invocation.
- **Budgets in chars and words, not tokens.** The repo forbids a tokenizer
  dependency; chars are what the harness caps on anyway.
- **Both reference libraries stay listed for humans.** `disable-model-
  invocation` (set in task 241) removes them from the model's context but
  leaves them typeable; nothing further is needed.
