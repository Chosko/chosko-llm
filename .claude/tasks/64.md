# Task 64 — Add a `statusline` feature kind — ship the status bar config, installable via chosko-llm

Target: claude

## Goal
Package the user's current Claude Code status bar (`~/.claude/statusline.sh`,
wired via `settings.json`'s `statusLine` key) as a proper chosko-llm feature,
so it can be installed/updated/removed/listed like any command or skill.
Introduce a new top-level feature kind, `statusline`, mirroring how
`claude-md` is a sibling kind to `command`/`skill` today. Since settings.json
is arbitrary JSON this repo doesn't own the shape of, and the project avoids
adding jq/python as a dependency, installing a statusline feature does not
edit settings.json itself — instead it prints a ready-to-paste prompt for a
Claude Code session to safely merge in the `statusLine` key.

## Acceptance criteria
- `scripts/lib.sh` gains `src_statusline_path` / `inst_statusline_path`
  (installed to `$CLAUDE_HOME/statusline/<name>.sh`), and every existing
  per-script kind resolver (`resolve_feature` in lib.sh, `resolve_installed`
  in cmd-rm.sh, `resolve_show_feature` in cmd-show.sh) recognizes the
  `statusline:<name>` prefix and folds it into the ambiguity count alongside
  command/skill/claude-md.
- `chosko-llm add <name>` / `add --all` installs a statusline feature the
  same way it installs a claude-md artifact (refuses if already installed,
  requires a `version` in frontmatter), then prints a copy-pasteable prompt
  telling the user to open a Claude Code session and have it replace/add the
  top-level `"statusLine"` key in `$CLAUDE_HOME/settings.json` to
  `{"type":"command","command":"<installed path>","padding":1}`, preserving
  every other key — no jq, no automated brace-matching in the shell script.
- `chosko-llm update <name>` / `update --all` re-copies a statusline feature
  using the same version-compare logic as command/skill/claude-md.
- `chosko-llm rm <name>` deletes the installed script and prints a reminder
  to update/remove the `statusLine` key in settings.json if it still points
  at the deleted file.
- `chosko-llm ls` lists statusline features in their own row group (kind
  column `statusline`), same installed/latest/status columns and
  install/update suggestions as the other three kinds.
- `chosko-llm show <name>` inspects a statusline feature (version, status,
  description, path, `--diff`/`--content`) like it does the other kinds.
- A new shipped feature, `statusline/session-statusline.sh`, contains the
  current status line script verbatim (model · cwd · git · context% · cost ·
  5h/7d rate limits), with frontmatter (`name: session-statusline`, `version:
  0.1.0`, `type: statusline`, `description`).
- `docs/cli-help.txt`, `README.md`, `docs/authoring-guide.md`, and the
  context layer (`.claude/context/features.md` plus the cmd-add/cmd-ls/
  cmd-rm/cmd-update/cmd-show context files and `INDEX.md`) document the new
  kind, the frontmatter-in-heredoc convention, and the settings.json wiring
  flow.
- Root `VERSION` bumped (minor).

## Decisions
- Frontmatter lives inside a `: <<'CHOSKO_FRONTMATTER' ... CHOSKO_FRONTMATTER`
  bash no-op heredoc placed right after the shebang, so the shipped script
  stays valid, directly executable/sourceable bash while the existing
  `parse_frontmatter` awk (which just scans for the first `---`/`---` pair,
  regardless of file position) keeps working completely unmodified.
- `statusline` is added as a sibling kind next to `claude-md` rather than
  folded into `feature_kind`/`installed_kind` — those two helpers only ever
  combined command+skill and aren't called by any script today, so there's
  nothing to extend there; every real kind dispatch already lives duplicated
  per-script, and statusline slots into that existing pattern the same way
  claude-md did.
- No automated settings.json editing in shell, per the user's explicit
  choice: cmd-add prints a prompt for a Claude Code session to perform the
  JSON merge safely instead of risking jq/awk brace-counting on a file this
  repo doesn't control the shape of.
- Shipped as a single file (`statusline/session-statusline.sh`), not a
  folder — it needs no supporting files, so it mirrors a plain `command`,
  not a `skill`.
