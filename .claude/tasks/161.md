# Task 161 — Update documentation for feature `task-peer-review`

Target: claude

## Goal
Tasks 158–160 ship feature `task-peer-review`'s review cost controls. The
documentation describing that area — the README's `/task-implement` and
`/task-review` entries and the context layer's rows for both skills and for
`task-engine` — still describes the loop as it was before the flags existed,
so it is now out of date and needs to reflect the shipped behaviour.

## Acceptance criteria
- `README.md`'s `/task-implement` bullet names `--review-model` and
  `--review-effort`, their defaults, and that `auto` picks a cheaper reviewer
  for a light diff; its `/task-review` bullet names the read budget and the
  never-runs-tests rule.
- `.claude/context/features.md` is updated for all three shipped changes: the
  `skills/task-engine/` entry lists the new reference file, the
  `skills/task-implement/` entry covers the two flags and the eight-item spawn
  prompt, and the `skills/task-review/` entry covers the budget, the
  `requires: skill:task-engine` and the no-tests contract.
- `.claude/context/INDEX.md`'s `Last updated:` anchor is refreshed, and its
  `features.md` row still describes that file accurately.
- Root `VERSION` takes a patch bump and `CHANGELOG.md` gains a matching top
  section; `./scripts/check-changelog.sh` exits zero.

## Decisions
- `.claude/domain/features/task-peer-review.md` is deliberately not touched.
  It is `/architect`'s document, tasks 158–160 implement it as written, and no
  concrete point of divergence exists to reconcile.
- Only `README.md` is user-facing, which is why this task takes a patch bump
  rather than a minor one — the context layer ships to nobody.
