# Task 207 — Rework /runbook-describe into a compact one-runbook summary that never reads prompts or task bodies

Target: claude

## Goal
On first real use `/runbook-describe` spent a large number of tokens: it
printed step prompts in full and opened the bodies of the tasks the runbook
mentions. The command should describe ONE runbook with moderately more
information than `/runbook-list`, which gives one line per runbook. It should
be a middle ground, not a dump of the body. The current 0.1.0 body already
says not to print prompt blocks, so the overspend comes from what it does
allow: a full Read of the body (every prompt enters context), guessing
`Needs:` from prompt blocks, printing `Done:` / `Sequencing:` / `Context:` in
full, and no ban on following task ids. This task rewrites the output shape
and the read budget so the command's cost is roughly the lines it prints.

## Acceptance criteria
- `commands/runbook-describe.md` renders exactly this shape and nothing more:
  ```
  3. implement-ecc-import   [RUNNING]   4/7   —   Land the ECC import architecture
     Created: 2026-09-01   Source: /architect ecc-import   Model: sonnet

     [x] 1. Add the requires: field to the frontmatter contract
            done: a1b2c3d — added the field and its cmd-add resolution (+1 wrong premise)
     [!] 2. Wire cmd-rm's dependents guard            deps: 1
            done: FAILED — <first clause of the reason>
     [ ] 3. Update the authoring guide                 deps: 1, 2   needs: agent+human

     7 steps: 4 done, 1 failed, 2 pending.
     Step 3 needs a person present.
  ```
  - Heading line as today (id, name, status, progress, title), with the
    index's `Failed at:` continuation under a `[FAILED]` runbook only.
  - One header line: `Created:`, `Source:`, `Model:`. **`Sequencing:`,
    `Companion:` and the `## Do not re-propose` count are not printed.**
  - One line per step: the marker as the body carries it, number, title;
    `deps:` on the same line only when the step has dependencies (omitted for
    none); `needs:` on the same line only when an authored `Needs:` value is
    not `agent`.
  - For a step with a `Done:` line, at most one `done:` line: the sha(s) and
    a short summary, with wrong premises shown only as a count
    `(+N wrong premise[s])`; a `[!]` step's line opens with `FAILED —` and the
    first clause of its reason.
  - **No `context:` line** and no `Context:` text of any kind.
  - Closing by-marker summary line and the "Step(s) N need a person present."
    line, as today.
- Step prompt blocks are never printed, in whole or in part.
- Read budget: the command reads `.claude/RUNBOOKS.md` and pulls only the
  lines it prints from the one resolved body — header fields, `##` step
  headings, `Depends on:`, `Needs:`, and the first line of each `Done:` —
  by targeted line extraction. It never does a full Read of the body, never
  opens `.claude/tasks/` (archive included), any other runbook body,
  `.claude/domain/` or `.claude/context/`. Task ids appearing in a `Done:`
  line are printed as written and never resolved. The `DO NOT` list states
  each of these bans explicitly.
- The inferred-`Needs:` behaviour is removed entirely (the whole
  "THE `Needs:` ANNOTATION" exception, the `(inferred)` rendering, and the
  related DO NOT bullets). A step without an authored `Needs:` prints nothing.
- Argument resolution, the missing/empty-index line, the unresolved `File:`
  handling, write-nothing / no-shell / correct-nothing rules are unchanged.
- The frontmatter `description:` is rewritten to match (no "in depth", no
  "every step enumerated … Done: line", no inference sentence), and
  `version:` goes 0.1.0 → 0.2.0.
- `.claude/domain/features/runbook-suite.md` is reconciled with what shipped
  on exactly these 3 points — editing it is authorised for this task, see
  Decisions:
  1. The artifact-table row (currently "read-only deep read of **one**
     runbook, body included") describes the compact one-runbook summary.
  2. The `### /runbook-describe — the deep read side` section is rewritten to
     the new contract: the title drops "deep read"; the render is the shape
     above (no `Sequencing:`, `Companion:`, `Context:`, re-propose count;
     `Done:` summarised to one line instead of "rendered, not summarised");
     the "allowed to read it in full" bound becomes the line-extraction
     budget with the no-task-body / no-prompt bans; the inferred-`Needs:`
     paragraph is removed.
  3. The usage line `/runbook-describe <name|id>  print one runbook in depth,
     body included` is reworded to match.
  Nothing else in the document changes.
- `docs/reference.md` (the `/runbook-describe` bullet) and
  `.claude/context/features.md` (the `commands/runbook-describe.md` entry)
  describe the new shape and read budget.
- Root `VERSION` gets a patch bump with a matching top `CHANGELOG.md` section;
  `./scripts/check-changelog.sh` is silent.

## Decisions
- **Output shape settled with the user (2026-09-14 brainstorm):** the
  compact per-step line with a one-line `done:` summary; no `Sequencing:`,
  no `Companion:`, no `context:` line, no `Do not re-propose` count. No
  `--full` flag — a reader who needs the full record opens the file.
- **`deps:` is omitted when a step has none**, reversing today's
  "`depends on:` always, `none` included" rule — on a one-line-per-step
  render the absence is unambiguous and the `none` is noise.
- **Read budget is line extraction from the one body, never a full Read**
  (user choice). A malformed body is reported as found, not compensated by
  reading more. The `pipeline-engine` routing row ("`.claude/RUNBOOKS.md` and
  exactly one body") stays true and is not edited, so no routing-guard run
  is needed.
- **Inferred `Needs:` is dropped** (user choice): it was the only behaviour
  that required reading prompt blocks.
- **Not re-opened:** printing step prompts verbatim, and opening task bodies,
  are both forbidden by the user; "body included" / "deep read" is the
  premise being reversed.
- **Editing `.claude/domain/features/runbook-suite.md` is explicitly
  authorised for this task (user decision, 2026-09-14), for the 3
  reconciliations listed above and for nothing else. Do not ask for
  permission at implementation time — the permission is already granted.**
  That document is normally `/architect`'s, and anything beyond those points
  still belongs to `/architect`. These are factual reconciliations with
  shipped behaviour, not redesigns; if one turns out to need a design
  decision rather than a wording fix, stop and say so instead of deciding it
  here.
- Versioning: feature `version:` 0.2.0 (output contract changes); root
  `VERSION` patch (a fix of the command's cost, no new surface).
