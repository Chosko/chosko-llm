# Task 201 — Update documentation for feature `task-archive`

Target: claude

## Goal
Feature `task-archive` (.claude/domain/features/task-archive.md) turns
`/task-clean` into a skill that archives instead of deleting, leaves feature
`Tasks:` lines alone, puts the archived-and-terminal rule in `task-engine`, and
adds a `--backfill` recovery mode. Every documentation layer that describes the
old behaviour is now wrong: the README's one-line gloss, the reference's
`/task-clean` section and commit-behaviour list, the authoring guide's
message-form templates, both domain workflow documents, and the context layer's
entry for a command file that no longer exists. Bring them up to date with what
tasks 196 and 199 shipped.

## Acceptance criteria
- `README.md`'s backlog paragraph says `/task-clean` archives rather than
  prunes-and-deletes, in the same register as the surrounding text.
- `docs/reference.md` § `/task-clean` describes the skill: the archive
  destination and the frozen header, that feature `Tasks:` lines are left
  alone, that nothing lists or reads the archive, and `--backfill`. Its
  `task-engine` section and § *Stale tasks* are checked for the same drift, and
  its § *Commit behaviour across the suite* still names `/task-clean`
  correctly.
- `docs/authoring-guide.md`'s prescribed-message-form list carries
  `task-clean: archive tasks …` instead of `task-clean: remove tasks …`, and
  its auto-committing-command lists still name `/task-clean` correctly now that
  it is a skill.
- `.claude/domain/task-workflow.md` records: `resolution.md` also owning the
  archive and the archived-and-terminal rule; `/task-clean` as a skill;
  archiving replacing deletion; and any consumer count or list the new
  citations change.
- `.claude/domain/product-workflow.md` is reconciled on the three places that
  key off the old behaviour — the illegal-transition rationale
  (`[PLANNED]`/`[DONE]` → `[NEW]`), the zero-task rollup paragraph, the iterate
  guard's items 4 and 5 — and its who-writes-what row for `.claude/FEATURES.md`
  drops `/task-clean` as a `Tasks:` writer except on `--backfill`.
- `.claude/context/features.md`'s `commands/task-clean.md` entry becomes a
  `skills/task-clean/` entry covering the migration, `replaces:`, the archive
  move, the supporting file read only under `--backfill`, and the removal of
  the `FEATURES.md` write; its `/production-status` and iterate-guard entries
  are reconciled with task 199.
- `.claude/context/INDEX.md`'s `Last updated:` anchor is moved to the date of
  this change.
- `.claude/domain/features/task-archive.md` is reconciled with what shipped on
  exactly these 2 points — editing it is authorised for this task, see
  Decisions:
  1. Dependencies § `pipeline-engine`: the bullet claiming the `Tasks:`-id lint
     finding still needs dropping and that the feature is `[NEW]` is replaced
     by what shipped — `pipeline-engine` is `[PLANNED]` with tasks 175 and 181,
     the finding was dropped at authoring time in task 175, and task 175 states
     in `probes.md`, `graph.md`, `lint.md` and `/pipeline-check` that nothing
     probes `.claude/tasks/archive/`.
  2. Dependencies § "Documentation to update when this lands": add
     `docs/authoring-guide.md` and `.claude/context/INDEX.md`.
  Nothing else in the document changes; its three open questions stay open.
- No root `VERSION` bump and no `CHANGELOG.md` entry: every path in this task
  is project documentation, which `CLAUDE.md` exempts.

## Decisions
- **Editing `.claude/domain/features/task-archive.md` is explicitly authorised
  for this task (user decision, `2026-09-11`), for the 2 reconciliations listed
  above and for nothing else. Do not ask for permission at implementation time
  — the permission is already granted.** That document is normally
  `/architect`'s, and anything beyond those points still belongs to
  `/architect`. These are factual reconciliations with shipped behaviour, not
  redesigns; if one turns out to need a design decision rather than a wording
  fix, stop and say so instead of deciding it here.
- `.claude/domain/product-design.md` is deliberately not in scope. Its § *Task
  backlog* paragraph already describes the archive — "a pruned task is archived
  under `.claude/tasks/`, retained indefinitely, still counted by its feature,
  and read only when the user asks" — so there is nothing to reconcile, and it
  is `/product-design`'s document.
- `claude-md/git-commit-style.md` is task 196's, not this task's: it is a
  shipped `claude-md` artifact, which `CLAUDE.md` classes as product rather
  than documentation, so it moves with the change that alters the message form
  and bumps with it.
- This task takes no `VERSION` bump, matching tasks 174, 181, 186, 193 and 195
  — the documentation tasks of the five features planned before this one.
