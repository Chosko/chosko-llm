# Task 102 — Add install-scope resolution (--local / --global) to lib.sh

Target: claude

## Goal
`chosko-llm` installs features only into the global `$CLAUDE_HOME`
(`~/.claude`). Users want per-repository installs too, so a project can
carry its own commands/skills under `<project>/.claude/`. Every
installed-side path in the CLI already funnels through `$CLAUDE_HOME`
(`scripts/lib.sh:7` and the `inst_*` helpers), so the whole feature reduces
to one primitive: a scope resolver that parses a `--local` / `--global`
flag, validates the local target, and repoints `CLAUDE_HOME`. This task
adds that primitive to `lib.sh` only — no subcommand consumes it yet
(task 103 does the wiring).

## Acceptance criteria
- `scripts/lib.sh` gains `resolve_scope "$@"`, which:
  - Scans every argument for `--local` and `--global`; dies when both appear.
  - Sets global `CHOSKO_LLM_SCOPE` to `local` or `global` (default `global`).
  - Sets global array `SCOPE_ARGS` to the arguments with the scope flag
    removed, preserving order and embedded whitespace.
  - When scope is `local`: requires `$PWD/CLAUDE.md` to exist. If it does
    not, `die`s with a message naming the missing file and suggesting
    `/project-setup` for an empty directory, plus a reminder that `--local`
    must be run from the project root. On success sets
    `CLAUDE_HOME="$PWD/.claude"`, overriding any inherited `CLAUDE_HOME`.
  - When scope is `global`: leaves `CLAUDE_HOME` untouched (env override
    still honoured).
- `scope_is_local` returns 0 in local scope, 1 otherwise.
- `scope_label` prints a human-readable scope for log lines, including the
  resolved home path (e.g. `local (/path/to/repo/.claude)`).
- `scope_supports_kind <kind>` returns 1 for `statusline` in local scope and
  0 for every other kind/scope combination; callers use it to refuse
  statusline work locally.
- `SCOPE_ARGS` is safe to expand under `set -u` when empty — callers can do
  `set -- ${SCOPE_ARGS[@]+"${SCOPE_ARGS[@]}"}` without an unbound error.
- Sourcing `lib.sh` with no `resolve_scope` call changes nothing: existing
  subcommands keep working against global `$CLAUDE_HOME` unmodified.
- `.claude/context/shared-lib.md` documents the new helpers under a
  "Scope resolution" heading, and its **When to read the source** section
  gains an entry for changing scope semantics.
- Root `VERSION` bumped (patch — no user-visible CLI surface yet).

## Decisions
- **Local root is `$PWD`, not a VCS query.** `git rev-parse --show-toplevel`
  was rejected as non-VCS-agnostic (this project supports non-git VCS via
  the `## VCS` CLAUDE.md override). No upward walk either: `--local` is an
  explicit "you are at the project root" contract, and a wrong cwd fails
  loudly instead of installing into a parent repo.
- **`./CLAUDE.md` is the project-root marker.** Cheap, VCS-agnostic, and
  already the file every chosko-llm-managed project has. `.claude/` is not
  used as the marker because `add --local` must be able to create it.
- **`--local` beats the `CLAUDE_HOME` env var.** An explicit flag on the
  command line is a stronger signal than inherited environment; documented
  rather than made an error.
- **Flags parsed positionally-agnostically.** The scope flag may appear
  anywhere in the argument list so `add --all --local` and
  `add --local --all` both work; scripts get a cleaned array back rather
  than having to re-order their own parsing.
- **Statusline is global-only.** It installs an executable and needs a
  `settings.json` `statusLine` wiring step; per-project statusline scripts
  are out of scope. `scope_supports_kind` encodes that in one place.
