# Task 115 — Update documentation for feature plan-readout

Target: claude

## Goal
Feature `plan-readout` ships `/production-status` and gives `/task-list`
milestone grouping — the read side of the planning layer. The documentation
describing the pipeline and the backlog predates both: the README lists no
such command and describes `/task-list` without grouping, the CLI help has no
entry, the context layer's `task-list` entry names the old marker set only,
and `product-workflow.md` documents no read stage over `PLAN.md`. Bring every
layer up to date with the shipped behavior.

## Acceptance criteria
- `README.md` lists `/production-status` with a one-line description matching
  its frontmatter, and its `/task-list` description mentions milestone
  grouping and the blocker flag.
- `docs/cli-help.txt` lists `/production-status` wherever the other pipeline
  commands appear.
- `.claude/context/features.md` gains an entry for
  `commands/production-status.md`, and its `commands/task-list.md` entry is
  updated with the grouping behavior and the blocker flag alongside the
  existing markers.
- `.claude/domain/product-workflow.md` covers the read stage: what
  `/production-status` joins, that it writes nothing, and that readiness and
  coverage are derived on every read rather than stored.
- `.claude/domain/task-workflow.md` notes that `/task-list` now resolves the
  `Feature:` line through `PLAN.md` when one exists.
- `.claude/domain/features/plan-readout.md` is reviewed against what actually
  shipped and its open questions updated where implementation settled them —
  the rollup-granularity question is settled by task 113's
  counts-plus-`--task-ids`. Anything still genuinely open stays open.
- Root `VERSION` bumped patch (documentation-only change).
