# Task 138 — Update documentation for feature repo-local-audits

Target: claude

## Goal
Tasks 135–137 establish a location this repo has never had — repo-local,
unversioned, unshipped tooling under `.claude/skills/` — and put two audits in
it. Three documents still describe a world where every artifact in this repo is
a shipped feature that bumps `VERSION`. Bring them in line, and reconcile the
`repo-local-audits` feature document on the points where implementation settled
its open questions.

## Acceptance criteria
- `README.md` § Development → "Authoring features": the **Versioning**
  paragraph gains the `.claude/skills/` exemption, in that paragraph's own
  register and no longer than a sentence or two.
- `README.md` § Development → "Repo layout": a `.claude/skills/` row is added to
  the table — repo-local audit skills used to develop this repo, unversioned,
  never installed. Placed with the other `.claude/` rows.
- `README.md` § Claude Code Workflows is deliberately NOT changed. That section
  documents what users install; these skills ship to nobody.
- `docs/authoring-guide.md` § Versioning gains the exemption, matching CLAUDE.md
  and stating the same reason.
- `docs/authoring-guide.md` gains a short section — "Repo-local skills are not
  features", beside the existing § Vendored skills — covering: they live under
  `.claude/skills/`, carry no `version:`, are invisible to `ls`, `add`, `update`
  and `rm`, are never installed, and their names must not collide with any
  shipped feature name. The frontmatter-schema preamble notes that the required-
  fields rule governs shipped features, not these.
- The same section records that `select_export_files` in `scripts/cmd-export.sh`
  includes `.claude/**/*.md`, so `chosko-llm export` carries these two skills
  along — **deliberately not excluded**, since an export packages this repo's
  Claude config and repo-local tooling is part of it. Recorded so a later reader
  does not file it as a bug.
- `.claude/context/features.md` gains a short note in its Overview contrasting
  `skills/` (shipped, versioned, walked by `cmd-ls`) with `.claude/skills/`
  (repo-local, unversioned, invisible to every CLI verb). It is NOT a
  "Currently shipped" entry — that list is for artifacts the CLI installs, and
  adding them there would be the exact category error the feature exists to
  prevent.
- `.claude/context/INDEX.md` is deliberately NOT changed — no new context file
  is created.
- `docs/cli-help.txt` is deliberately NOT changed — no CLI surface changed.
- `.claude/domain/INDEX.md` is deliberately NOT changed — its
  `features/repo-local-audits.md` row already exists and is still accurate.
- `.claude/domain/features/repo-local-audits.md` is reconciled on the points
  listed under Decisions, and only those.
- Root `VERSION` takes a patch bump (documentation only), relative to whatever
  is in place when this lands.
- No test suite by design: verify by reading the diff.

## Decisions
- **Editing `.claude/domain/features/repo-local-audits.md` is explicitly
  authorised for this task, user decision 2026-08-24, for the listed
  reconciliations only; do not ask at implementation time.** The file is
  normally owned by `/architect` and read-only to `/task-add`. The
  reconciliations are:
  1. **Open question "Does `.claude/skills/` collide with the installed global
     skills?"** — resolved. Move it out of Open questions and record it as a
     decision: a repo-local skill name must never collide with a shipped feature
     name; both names were verified free on 2026-08-24.
  2. **Open question "Should the collection step be a script or inline
     instructions?"** — resolved to the document's own leaning: inline, with the
     script named as the escape hatch. Move it out of Open questions.
  3. **Open question "Is `words × 1.3` accurate enough?"** — resolved: kept as a
     heuristic, with the report stating that its figures are estimates rather
     than measurements. Move it out of Open questions.
  4. **Add the vendored-skill exclusion** to § `/rule-overlap` — the two vendored
     skills are out of collection scope because their restatements cannot be
     extracted without breaking the vendoring contract — and the scope statement
     that `hooks/*.sh` and `statusline/*.sh` carry no normative prose.
  5. **Record the export interaction** in § Interfaces and contracts: the hard
     contract "neither appears in `chosko-llm ls --available`" holds, and
     `chosko-llm export` does carry them, deliberately.
  With items 1–3 landed, no open questions remain. Leave the `## Open questions`
  heading in place with an explicit "none outstanding" line rather than deleting
  it silently.
- **`docs/cli-help.txt`, `.claude/context/INDEX.md` and `.claude/domain/INDEX.md`
  are named as deliberately-unchanged** rather than silently omitted, so a later
  reader does not treat their absence as an oversight.
- **The context layer gets a contrast note, not an entry.**
  `.claude/context/features.md` is titled "Artifacts this repo *ships*"; the
  whole point of this feature is that these two are not shipped.
