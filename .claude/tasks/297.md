# Task 297 — Add `/session-describe`

Target: claude

## Goal
Part of feature `session-readers`. Add `/session-describe`, a read-only
command that resolves one handoff by `/session-resume`'s path/date/slug rule
and prints a short plain description of it — without loading it into the
conversation or stopping to wait as `/session-resume` does. The pair to
`/runbook-describe`.

## Acceptance criteria
- New `commands/session-describe.md` with frontmatter
  `name: session-describe`, `version: 0.1.0`, `type: command`, a short
  what+when `description:`, and
  `requires: command:session-resume, command:session-save`.
- Resolution applies the rule in `/session-resume` by name (as
  `/task-implement` applies `/follow-ups`); no restatement of the forms
  beyond the usage line `/session-describe [<path|date|slug>]`. The picked
  file is named on the first line.
- Prints about ten lines: what the session is about (preamble or *What we
  are building*); where it stopped and the very next step(s); objectives
  still open; open blockers; orchestrate-mode area handoffs by area name when
  a `<session-file-stem>/` subfolder exists (from filenames only).
- Read budget: the header block and only the sections it summarises,
  extracted by search; *What worked*, *What did not work*, the file table
  and environment notes are not read; an area handoff's body is never read.
  A pointer-form file is described from its header plus the pointed-at
  artifact's resume-marker line only.
- A section too long for one line is summarised, never quoted; no wall of
  text.
- Failure contract matches the feature document: missing store / no
  candidate → one line; missing explicit path → named, stop; slug with no
  exact match → nearest slugs, stop (inherited from the rule); malformed
  file → described as found, never compensated by reading more.
- Does not brief, does not stop-and-wait, writes/deletes/stages/commits
  nothing, runs no shell beyond what the cited rule permits; cites no
  interaction-policy reference.
- Root `VERSION` minor-bumped with a `CHANGELOG.md` section;
  `check-changelog.sh` and `check-home-paths.sh` pass; `./bin/chosko-llm ls
  --available` lists `session-describe` 0.1.0.
