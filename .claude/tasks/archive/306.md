# Task 306 — Add the `/orchestrate-mode` skill and `interaction-engine`'s mode check

Archived: 2026-10-07
Status: [DONE]

Preconditions: 281

Target: claude

## Goal
Part of feature `orchestrate-mode`. Ship `/orchestrate-mode`: a
conversation-scoped mode in which the session never edits code itself and
turns every change request into a batch of per-area subagents with disjoint
file ownership, briefed from the navigation layer and a per-area handoff
file, checked in as one commit per area at the end. Add the one "is the mode
on?" check to `interaction-engine` as a new reference, so every affected
command cites it rather than restating it.

## Acceptance criteria
- `skills/interaction-engine/references/mode.md` states the check once: the
  mode is on when this conversation turned it on with `/orchestrate-mode` and
  has not turned it off, or a context summary carries the line
  `orchestrator mode: on`; what a citing command does with the answer stays
  in that command. `skills/interaction-engine/SKILL.md` lists it beside
  `policy.md`, `gates.md` and `messages.md`, with when it is opened;
  `interaction-engine`'s `version:` gets a minor bump.
- `skills/orchestrate-mode/SKILL.md` at `version: 0.1.0`, full frontmatter,
  `requires: skill:interaction-engine`, usage
  `/orchestrate-mode [<notes>] [--model <m>]` and `/orchestrate-mode --off`;
  on/off/notes-as-first-request each confirmed in one line; conversation-
  scoped, the `orchestrator mode: on` line kept in any context summary.
- The body carries, per the feature document: request triage (change → batch
  whatever its size; question → answered inline, nothing spawned; no
  actionable note → one line, wait); the orchestrator's read limits
  (`CLAUDE.md`, `.claude/context/INDEX.md`, the touched areas' context files
  only) and act limits (no code edits, no single-instance tool, no
  transcripts; asks only when two readings lead to different code);
  splitting into areas (disjoint files or named regions; same region → one
  area in sequence; an unplaceable or two-way note goes to the user while the
  rest launch); launch (independent areas in one message, shared regions
  serialised, at most one single-instance-tool owner per batch; `opus`
  default, `fable` only for hard work with the brief saying why, `--model`
  overrides the batch); after the batch (project's quick check once; proof
  captures only when the owner is away or asks; report per `messages.md`,
  outcome first, one bullet per area; asks once whether to iterate or check
  in when batches converge); check-in (one commit per area, one at a time,
  only the orchestrator stages; a shared file rides with the area that
  changed it most; then `/session-save`; a class 1 gate per `gates.md`); the
  NEVER list; the Option 3 boundary (areas only for free-form requests and
  `/quick-implement`'s implementation step; `/task-implement` runs with
  `--agents`; `/runbook-run` unchanged; `/task-add`, `/architect`,
  `/pipeline-revise` run in one fresh subagent whose questions the
  orchestrator relays; each command keeps its commit rule; `/objective-run`
  is not split into areas).
- `brief.md`: the eight-part brief in the feature document's fixed order,
  including the shared-file discipline and the report shape.
- `handoff.md`: path (`.claude/sessions/pending/agent-<area>.md` before the
  conversation's first `/session-save`, `.claude/sessions/<stem>/agent-<area>.md`
  after), contents, current-state-only rule, ~120-line cap, rewrite-at-end,
  retiring agents, rebuild when missing or stale.
- `failures.md`: the six-row failures table.
- No project, engine, scene, renderer or script names; no check script; no
  VCS discussion beyond the check-in rule; no doc-sync step; no hook.
- Root `VERSION` minor-bumped with a `CHANGELOG.md` section;
  `check-changelog.sh` and `check-home-paths.sh` pass; `./bin/chosko-llm ls
  --available` lists `orchestrate-mode 0.1.0`.

## Decisions
- The mode check and the skill ship together: the check means nothing
  without the mode, and the skill is its first citer.
- Settled here, against `.claude/domain/features/orchestrate-mode.md`
  § Architecture (no conflict): the engine reference is named `mode.md`; the
  supporting files are `brief.md`, `handoff.md`, `failures.md` beside
  `SKILL.md`.
- The conversation commands (`/task-add`, `/architect`, `/pipeline-revise`)
  gain no text: running them in a subagent and relaying their questions is
  the orchestrator's rule, stated in this skill.
- Not a pipeline-engine consumer: no routing row, `check-routing.sh` is
  unaffected.
