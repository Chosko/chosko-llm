# Task 307 — Make `/task-implement`, `/quick-implement` and `pipeline-suggest` honour orchestrate mode

Archived: 2026-10-07
Status: [DONE]
Files: skills/task-implement/SKILL.md, skills/task-implement/delegated-runs.md, skills/quick-implement/SKILL.md, skills/pipeline-suggest/SKILL.md, VERSION, CHANGELOG.md
Preconditions: 300, 302, 306
Feature: orchestrate-mode

Target: claude

## Goal
Part of feature `orchestrate-mode`. Under the mode, `/task-implement`
delegates by default — `--agents` on even for one task — and
`/quick-implement` runs its spec phase in one fresh subagent whose questions
the orchestrator relays and splits its implementation step into areas, still
making one commit; `pipeline-suggest` stays silent, since every change
request under the mode is already a batch. All three learn the mode is on
from `interaction-engine`'s `mode.md`.

## Acceptance criteria
- `/task-implement` cites `mode.md`; when the mode is on, DELEGATE defaults
  to true for any resolved list, a single task included, and the
  delegate-or-not question is not asked; `--no-agents` still turns it off.
  The delegation guard is unchanged: `human`, `claude+human` and explicitly
  requested `[STALE]` tasks stay in the parent. `delegated-runs.md`'s
  "never on a single-task run" condition states the mode exception.
- `/quick-implement` cites `mode.md`; when the mode is on, the spec
  conversation runs in one fresh subagent and the orchestrator relays its
  questions; the implementation step is split into areas by the
  `orchestrate-mode` skill's split, brief and launch rules, named by feature
  (no path to it); the area agents do not commit; the run makes its one
  commit (change + spec) as usual.
- Behaviour with the mode off is byte-for-byte unchanged in effect.
- `pipeline-suggest`'s `description:` Not-for list (and its body, where it
  restates the list) gains "while orchestrate mode is on", citing `mode.md`.
- `version:` bumped (minor) on each touched feature; root `VERSION`
  minor-bumped with a `CHANGELOG.md` section; `check-changelog.sh`,
  `check-home-paths.sh` pass.

## Decisions
- Settled here, against `.claude/domain/features/orchestrate-mode.md`
  § Boundary (no conflict): the delegation guard still keeps human-in-the-
  loop and requested `[STALE]` tasks in the parent under the mode; an
  explicit `--no-agents` wins over the mode default.
- `pipeline-suggest` is silent under the mode (user decision, 2026-10-07):
  the feature document says every change request there is a batch, so a
  routing suggestion would contradict it.
- `/quick-implement` names the `orchestrate-mode` skill rather than citing a
  path into it: the mode is optional and a path picks one install scope.
- `/runbook-run` and `/objective-run` are not touched: the first already
  delegates per step, the second is exempt (and not yet built).
