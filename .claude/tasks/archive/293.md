## Goal
Part of feature `setup-sync`. Nothing ties a feature that starts reading a
per-project fact to the setup that should offer it. Add the optional
`project-policy:` frontmatter key, declare it on each feature that states
the rule for such a fact, teach the parser to return it, and add the
repo-local `scripts/check-setup.sh` guard that fails whenever a declared
fact, or a shipped claude-md or hook feature, is not offered by setup.

## Acceptance criteria
- `_FM_AWK`'s allowlist in `scripts/lib.sh` includes `project-policy`, so
  `read_frontmatter_field` returns it; no CLI verb acts on it and `cmd-add` /
  `cmd-update` behave as before.
- Declarations:
  - `interaction-engine`: `line:Interaction policy=attended|unattended`
  - `task-implement`: `line:Testing policy for /task-implement=skip-tests|full-tdd|skip-tests-unattended`
  - `doc-consolidate`: `section:editing-discipline`
  - `vcs:` ops per Decisions below.
- `scripts/check-setup.sh` is modelled on `check-routing.sh` (header comment
  stating what it proves and cannot, `set -euo pipefail`, sources `lib.sh`,
  repo-local), silent on success, non-zero with one line per violation,
  failing when: a `line:` marker or any of its values is absent from the
  three setup bodies taken together; a `vcs:` op has no `git <op>` row in
  `/project-setup`'s `## VCS` template; a `section:` names no shipped
  claude-md feature or is not offered by `/project-setup`; a shipped
  claude-md or hook feature is not offered by `/project-setup`; a spec is
  malformed (no `kind:`, unknown kind, `line:` without `=`), naming the file.
- `./scripts/check-setup.sh` passes on the tree as landed, and a deliberately
  broken declaration (tried, then reverted) makes it fail.
- `CLAUDE.md` § Versioning registers it beside the other guards: run after
  adding or changing a `project-policy:` declaration, adding a claude-md or
  hook feature, or editing a setup command; guard only, bumps nothing.
- Every declaring feature's `version:` bumped; root `VERSION` minor-bumped
  with a `CHANGELOG.md` section; `check-changelog.sh`,
  `check-home-paths.sh`, `check-routing.sh` pass.

## Decisions
- The testing-policy line is declared on `/task-implement`, which holds its
  resolution today; feature `quick-implement` moves the declaration to
  `task-engine` when it moves the resolution.
- `vcs:` declarations cover the ops a `## VCS` row maps — `git push` /
  `git pull` are handled by the template's no-push prose, not rows, and are
  not declared. `task-engine` declares the commit and tree protocol's ops it
  owns for every committing feature (`add`, `commit`, `status`,
  `rev-parse`, `log`) plus its own `mv`, `show`, `branch`; other features
  declare only `mv` / `rm` / `show` / `branch` where their own bodies run
  them: `task-clean` (mv, show, branch), `context-convert` (mv, rm),
  `session-save` (rm), `task-review` (branch, diff, log), `task-iterate`
  (branch). Settled by the user (2026-10-07).
- Lands after the setup fixes (291, 292) so the guard passes on the commit
  that introduces it; 281 creates `interaction-engine`.
