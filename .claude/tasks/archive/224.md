# Task 224 — Restore the exec bit on this repo's own `.claude/hooks/remote-session-protocol.sh`

Archived: 2026-09-15
Status: [DONE]
Files: .claude/hooks/remote-session-protocol.sh, VERSION, CHANGELOG.md
Preconditions: none

Target: claude

## Goal
`.claude/settings.json` wires `PreToolUse[AskUserQuestion]` to
`$CLAUDE_PROJECT_DIR/.claude/hooks/remote-session-protocol.sh`, but that file is
committed mode `100644` while the shipped copy at `hooks/` is `100755`. Running
it here fails with exit 126, permission denied, and a `PreToolUse` hook that
cannot execute denies nothing — so the hook has never fired from this repo's own
copy in any cloud session. Record the file as executable.

## Acceptance criteria
- `git ls-files -s .claude/hooks/remote-session-protocol.sh` reports mode
  `100755`, matching `hooks/remote-session-protocol.sh`.
- The file's contents are unchanged — this is a mode change only, and the two
  copies stay byte-identical.
- Verified by running `CLAUDE_CODE_REMOTE=true .claude/hooks/remote-session-protocol.sh`
  and seeing the deny JSON on stdout with exit 0.
- No change to `scripts/cmd-add.sh` or `scripts/cmd-update.sh`, which already
  `chmod +x` on install.
- Root `VERSION` and `CHANGELOG.md` bumped per CLAUDE.md § Versioning (patch);
  `./scripts/check-changelog.sh` exits clean.

## Decisions
- **This is a hand-committed-copy defect, not an installer bug.** `cmd-add.sh`
  and `cmd-update.sh` both `chmod +x "$dst"`, and the user's local checkout of
  this same file is `-rwxr-xr-x`; only the mode recorded in git is wrong. No
  installer change is in scope.
- **It bumps `VERSION`.** CLAUDE.md's narrow exemption covers skills under this
  repo's own `.claude/skills/`; this is a hook governing this repository, and its
  behaviour changes for anyone who clones it.
- **The related detection question was investigated and closed** (2026-09-15). A
  probe on a local git-bash CLI session reported `CLAUDE_CODE_REMOTE` and
  `CLAUDE_CODE_REMOTE_ENVIRONMENT_TYPE` both unset, so the hook correctly exits 0
  there; this cloud session reports `true` and `cloud_default`. The hook's
  detection is therefore not what turns local questions into text, and the user
  decided against speculative hardening. `CLAUDE_CODE_SESSION_ATTENDED` reads `1`
  in both and is not a discriminator. If the symptom recurs locally, the two open
  candidates are a spawned subagent — which cannot use `AskUserQuestion` at all,
  and whose `subagent-contract.md` OPERATING RULES mandate the text form — and
  the desktop app, which was never probed.
