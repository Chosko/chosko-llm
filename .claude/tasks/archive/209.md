# Task 209 — Add an --inline mode to /runbook-run that executes selected steps in the orchestrating session

Archived: 2026-09-14
Status: [DONE]
Files: skills/runbook-run/SKILL.md, skills/runbook-run/references/inline-contract.md, skills/pipeline-engine/references/routing.md, VERSION, CHANGELOG.md
Preconditions: 208
Feature: runbook-inline

Target: claude

## Goal
Implement feature `runbook-inline` (.claude/domain/features/runbook-inline.md).
Today `/runbook-run` always starts one fresh subagent per step. For a short run
of small, closely related steps, the cost of orienting a new agent and spawning
it outweighs the benefit of a clean context. Add an opt-in `--inline` flag.
Under it, the orchestrating session carries out each selected step itself.
Selection, step markers, `Done:` lines, the index, fact propagation and the
commit cadence stay exactly as in the default mode. Only who carries out the
step changes. The default mode does not change.

## Acceptance criteria
- `skills/runbook-run/SKILL.md` ARGUMENTS table has a `--inline` row. The Usage
  header gains a matching line and an example
  (e.g. `/runbook-run 3 --inline --from 4 --steps 2`).
- The frontmatter `description:`, the GOAL and WHAT THIS SKILL READS AND WRITES
  are reworded in the same way. Four contracts become default-mode contracts
  that allow this one opt-in exception:
  - one fresh subagent per step;
  - the orchestrator reads only CLAUDE.md, the runbook and the index;
  - it writes only the runbook and the index;
  - it never does a step's work.
- `--inline` works together with `--from`, `--to`, `--only`, `--steps N`,
  `--no-commit` and `--no-push`, and changes nothing about selection or
  committing.
- Two new argument errors join the list, in the same style as the existing
  ones: say what the problem is, stop, run nothing.
  - `--inline` beside `--relay-spawns`: there is no step subagent to relay for.
  - `--inline` beside `--model`: the session's model cannot be changed from
    inside the run.
- THE EXECUTION LOOP steps 5 (Spawn) and 6 (Wait) gain an `--inline` branch.
  An execution phase takes the place of spawn-and-wait, and no other loop step
  changes. The nested-runbook refusal in step 5 still applies under `--inline`.
- The body names the two phases:
  - **Bookkeeping phase** (steps 1–4 and 7–8). It reads only CLAUDE.md, the
    runbook and the index, and writes only the runbook and the index.
  - **Execution phase.** It orients per CLAUDE.md, reads what the step needs,
    and makes the step's changes and commits through whatever skill the prompt
    invokes. It never edits the runbook or the index.
- The execution phase ends with the session writing out its own outcome as a
  separate act, before any bookkeeping is written. The outcome is either a
  `DONE` report naming the commit sha(s), the decisions taken and any premise
  that proved wrong, or a plain statement of failure.
  - Step 7 classifies that outcome using the same four result cases.
  - If the session cannot state the outcome confidently, it counts as a
    failure.
  - Classification never re-inspects the session's own diff.
  - The rule that no step is ticked before its result exists is restated for
    inline mode.
- New `skills/runbook-run/references/inline-contract.md` holds the fixed inline
  rule set, which replaces the subagent contract's OPERATING RULES:
  - The session assembles the same brief a spawned prompt carries (preamble,
    `Companion:`, `## Do not re-propose`, `Context:`, the verbatim prompt block)
    and works through it in that order.
  - **The brief is the authority.** What the session remembers of an earlier
    step is not an instruction.
  - **Records win.** Where memory disagrees with a `Done:` line or a `Context:`
    bullet, the record is right.
  - **Facts are still written down.** Fact propagation into later steps'
    `Context:` happens exactly as in spawned mode.
  - **Questions and approval gates.** A top-level session asks the user
    directly, in the fixed block
    `Step <n> of <total> — <title> — asking (round <r>)`, with any gate draft
    verbatim and unabridged. It never answers its own question, and never skips
    a gate because it "already knows" the answer. A session that is itself a
    subagent ends its turn under `QUESTIONS FOR USER`, as in the default mode.
  - **Children.** A step that wants a child has the session spawn it directly,
    one level down. If the session cannot spawn, it follows its own parent's
    contract (e.g. `SPAWN REQUEST`). Failing that, the step fails `[!]` with a
    `Done:` line naming the child that could not be spawned and saying that
    re-running without `--inline` is the fix. The session never does a child's
    work in its own context.
  - During the execution phase the session never edits the runbook or the
    index.
  - The Stop-hook reply is unchanged.
- The SKILL.md install-path note lists `inline-contract.md` and says it is read
  only when `--inline` is passed, so a default run never loads it.
- An `--inline` run's opening line says that the steps share one context and
  that `--steps N` limits how many run. It also names the header's `Model:` as
  not applied, once.
- THE SPAWN RELAY (including its 8-round cap and `--relay-spawns`), THE
  QUESTION RELAY and THE DEPTH BUDGET each say what they mean under `--inline`:
  - spawn relay: no role;
  - question relay: direct ask, subagent position unchanged;
  - depth budget: the step's work runs at the orchestrator's own level, and
    its children one level down.
- The `--steps N` count definition written by task 208 is broadened from "its
  subagent was spawned and its result reached step 8 as `DONE`" to "it was
  executed and its outcome reached step 8 as `DONE`", which covers both modes
  in one sentence.
- Nothing records the mode. `Done:` lines, markers, `Steps:`, statuses,
  `Failed at:`, the resume signal and COMMIT CADENCE are identical to spawned
  mode. `[~]` is never committed. The bookkeeping commit stages only the
  runbook and the index.
- The DO NOT list:
  - scopes its "never does a step's work", "reads/writes only" and "one fresh
    subagent" bullets to the default mode;
  - adds bullets forbidding: recording the mode in the artifact; applying
    `--model` or the header `Model:` under `--inline`; editing the runbook or
    index during the execution phase; answering the session's own question;
    and doing an unspawnable child's work.
- Not added: an `Inline:` step field, mixing modes within one run, a context
  cap, parallel steps, or lifting the nested-runbook ban.
- `skills/pipeline-engine/references/routing.md`: the `/runbook-run` row lists
  `[--inline]` in its argument column, and `./scripts/check-routing.sh` passes.
- The skill's `version:` gets the next minor bump from whatever it holds at
  implementation time (0.9.0 → 0.10.0 once task 208 has landed). Root `VERSION`
  gets a minor bump with a matching `CHANGELOG.md` section on top, and
  `./scripts/check-changelog.sh` passes.

## Decisions
- **Preconditions: 208** (runbook instruction). Both tasks edit
  `skills/runbook-run/SKILL.md`. The broadened count definition rewords a
  sentence task 208 writes, so 208 must land first.
- **One implementation task, not split.** The flag, its errors, the loop
  branch, the reference file and the routing row ship as one unit under one
  VERSION bump. A reference file with no reader, or a flag with no rule set,
  cannot be delivered on its own.
- **Reference file named `inline-contract.md`** (Claude's choice). It sits
  beside `subagent-contract.md`, whose OPERATING RULES it replaces under the
  flag. The feature document leaves the name open.
- **This task edits no owned document.** `.claude/domain/features/runbook-inline.md`
  is its read-only design source. Updating `runbook-suite.md`, README,
  `docs/reference.md` and the context layer to match belongs to task 210.
- **Opt-in only; the mode is a property of the whole run** (design decisions
  recorded in the feature document). Inline is never the default. There is no
  per-step mode, and the mode is never recorded in the artifact.
- **`.claude/skills/runbook-run/` is not touched.** It is an older installed
  snapshot (0.7.0), not the source. Only `skills/runbook-run/` is edited.
