# Task 313 — Add the `/pipeline-statusline` command that wires, backs up, restores and verifies the status line

Archived: 2026-10-13

Target: claude+human

## Goal
Add `commands/pipeline-statusline.md`, the wiring half of feature `pipeline-statusline` (`.claude/domain/features/pipeline-statusline.md`): a global command declaring `requires: statusline:pipeline-statusline` that sets `statusLine` in the user `settings.json` beside it, asks replace-or-abort over any other status line and backs it up first, refreshes the renderer on a re-run through the CLI when available, restores the previous status line exactly on `uninstall`, and verifies by running the installed renderer against a fixture in the current project and in a directory with no `.claude/`, timed. Must work under git-bash on Windows as well as macOS and Linux.

## Acceptance criteria
- `commands/pipeline-statusline.md` has full frontmatter (`name: pipeline-statusline`, `version: 0.1.0`, `type: command`, `description` per the contract, `requires: statusline:pipeline-statusline`) and opens with the `# /pipeline-statusline` + `# Global command: …` header block carrying summary and `# Usage:` lines for `/pipeline-statusline`, `/pipeline-statusline --no-nerd-font`, `/pipeline-statusline uninstall`; the procedure reads `$ARGUMENTS`.
- **Locate:** the renderer's absolute path and `settings.json` are resolved from the command's own installed location (`../statusline/pipeline-statusline.sh`, `../settings.json`), never from `~/.claude` or `$CLAUDE_HOME`; a missing renderer stops with the `chosko-llm add statusline:pipeline-statusline` remedy. `./scripts/check-home-paths.sh` passes.
- **Install:** `statusLine` is set to `{"type":"command","command":"bash <absolute renderer path>[ --no-nerd-font]","padding":1,"refreshInterval":10}` by a surgical edit of that one key; every other key and the file's formatting survive. An absent `settings.json` is created holding only that key; one that does not parse stops the run untouched.
- **Replace:** when a different `statusLine` is configured, the command shows it and asks replace or abort. Before replacing it writes the backup to `statusline/pipeline-statusline.backup/` beside the renderer: the old `statusLine` value verbatim, and a copy of the script that value points to (resolved from its command string when it names a file) under its original name with that original path recorded. An existing backup is never overwritten.
- **Re-run:** when `statusLine` already points at the renderer, the command runs `chosko-llm update statusline:pipeline-statusline` if `chosko-llm` is on the PATH and reports `already installed, script updated` or `already installed, unchanged` from its outcome; without the CLI it reports the installed `version:` and the update command. A re-run with or without `--no-nerd-font` changes only that flag in the command string.
- **Uninstall:** restores the backed-up `statusLine` value exactly and the backed-up script to its original path (only if that path no longer holds it), or removes the `statusLine` key when no backup exists and the key points at the renderer; deletes the backup folder; leaves the renderer installed and names `chosko-llm rm statusline:pipeline-statusline`. With nothing of ours configured, reports nothing to uninstall.
- **Verify** (after install and re-run): writes a realistic status payload — the shape of `statusline-last-input.json` beside the settings when present, otherwise a fixture embedded in the command — to a temporary file, runs the installed renderer with it on stdin, its `current_dir` pointing at the current project and then at a fresh temporary directory with no `.claude/`, times each run, and prints both outputs and timings. The timing method works under git-bash, macOS and Linux.
- The body never modifies or deletes `statusline-progress.sh`, `statusline-combined.sh` (except copying it into the backup) or `statusline/session-statusline.sh`, and mentions `statusline-last-input.json` as a leftover debug capture the user may delete, without deleting it.
- The body states the command is global-only, because its required statusline is.
- `./bin/chosko-llm ls --available` (with `CHOSKO_LLM_HOME` at the working repo) lists the command at 0.1.0 with `statusline:pipeline-statusline` in REQUIRES.
- Root `VERSION` bumped minor with a matching top `CHANGELOG.md` section; `./scripts/check-changelog.sh` passes.
- The manual interventions below are completed and their outcomes recorded in the closing report.

## Decisions
- **The settings edit is the agent's, not a script's** — the repo takes no jq, and `chosko-llm add` deliberately never edits `settings.json` (feature document § Purpose).
- **The `--no-nerd-font` choice lives in the `statusLine` command string**, never in the installed script, so `chosko-llm update` cannot undo it.
- **The script is refreshed through the CLI, never copied by the command** — the CLI owns the renderer; `uninstall` leaves it installed for the same reason.
- **The backup always holds the status line that predates this feature**: a second replace never overwrites it.
- **Settled here** (feature document leaves it open): the fixture is embedded in the command body, with the leftover capture preferred for its shape when present.
