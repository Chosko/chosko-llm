## Goal
Second slice of feature `unity-mcp-removal`: delete the setup command and
the vendored operator guide, superseded by Unity's official MCP; remove
every passage of `/project-setup` that offers, plans or runs
`/unity-mcp-setup`; update the two repo-local audits that name the vendored
skill; refresh this repo's tracked `--local` install copies so none carries
Unity MCP content; and give users with installed copies the removal
instructions in the `CHANGELOG`.

## Acceptance criteria
- `commands/unity-mcp-setup.md` and `skills/unity-mcp-skill/` (SKILL.md and
  both references) are deleted.
- `/project-setup` no longer offers Unity MCP: the header comment, the
  offer and its user note, the plan's `Unity MCP:` line, step 7 and its
  plan row, the GATHER item it consumed, the delegation clause in Step 5,
  and the DO NOT bullet are removed; the remaining steps read whole. Kept
  unchanged: Unity detection, the test-suite question, the Unity editor
  dirty-tree noise template, the Plastic SCM mapping.
- `rule-overlap` excludes `skills/claude-council/` as the one vendored
  skill (text and `find` exclusion); `context-budget` drops
  `unity-mcp-skill` from its auto-trigger list, its not-a-gate example and
  its sample table row. No `.claude/skills/` change needs a bump on its own.
- `CHANGELOG.md` section tells users to run `chosko-llm rm unity-mcp-setup`
  and `chosko-llm rm unity-mcp-skill` (`--local` where installed locally),
  delete the `Unity MCP for /task-implement:` line from their `CLAUDE.md`
  and `.claude/context/mcp-tools.md` with its `INDEX.md` row, remove the
  `com.coplaydev.unity-mcp` line from `Packages/manifest.json` and the
  machine-local `UnityMCP` server registration, and switch to Unity's
  official MCP.
- This repo's tracked `--local` install copies are refreshed from the
  shipped sources: `.claude/skills/task-implement/` and
  `.claude/skills/task-engine/` match `skills/task-implement/` and
  `skills/task-engine/` as 288 left them, with
  `.claude/skills/task-implement/unity-mcp-checkpoints.md` deleted (a
  refresh that copies files does not remove a dropped one — check). Any
  other tracked copy under `.claude/skills/` or `.claude/commands/` whose
  shipped source changed here is refreshed the same way.
- No file under `commands/`, `skills/`, `.claude/commands/` or
  `.claude/skills/` names `unity-mcp-setup`, `unity-mcp-skill`, the
  `Unity MCP for /task-implement:` marker, `mcp__UnityMCP__`,
  `unity-mcp-checkpoints.md` or `mcp-tools.md`.
- `project-setup` `version:` bumped; root `VERSION` bumped with the
  `CHANGELOG.md` section; `check-changelog.sh`, `check-home-paths.sh` and
  `check-routing.sh` pass.

## Decisions
- The `--local` copy refresh lives here, not in 288, because it must
  follow both slices; it is required by the runbook (user decision,
  2026-10-07).
- No removal mechanism: `ls` shows an installed copy as `local only` and
  the user runs `chosko-llm rm`, per the feature document's non-goals.
- After 288 so no shipped body cites `/unity-mcp-setup` once it is gone.
  Task 286 also edits `commands/project-setup.md` (flags only) and lands
  first by file order; setup-sync, not yet planned, rebases on whichever
  lands first.
