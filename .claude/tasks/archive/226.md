# Task 226 — Make `/pipeline-revise`'s impact walk explicit on continuing from forward-reached tasks

Archived: 2026-09-15
Status: [DONE]
Files: skills/pipeline-revise/amend.md, skills/pipeline-revise/delete.md, skills/pipeline-revise/insert.md, skills/pipeline-revise/SKILL.md, .claude/context/features.md, VERSION, CHANGELOG.md
Preconditions: none

Target: claude

## Goal
In `amend.md`, `delete.md` and `insert.md`, the bottom-up walk goes up from the anchor task (E3b, E2) and forward to its E4 successors, but none of them says whether the walk goes on up from each successor to that successor's own feature document. Only the runbook-step paragraph says "continues from each as above". On job-hunter-cli, 2026-09-15, an amend anchored on task 188 reached task 199 by E4. 199's feature document still stated the old behaviour but was missing from the proposal. The plan under-scoped it, and the task amend arm's check 2 refused partway through, leaving lint warnings open. Write the continuation rule down in each branch so the gate catches this, not the arm.

## Acceptance criteria
- `amend.md` § Impact walk: from each task reached by E4 whose basis changes, the walk continues up to that task's feature document (E3b, then E2). A missing or unresolved `Feature:` stops it, as for the anchor. It then goes forward again from that task (E4), visiting each node once.
- `delete.md` § Impact walk states the same continuation from each successor whose edge is dropped.
- `insert.md` § Impact walk says explicitly that the walk does *not* continue from successors, since gaining an edge changes nothing they deliver.
- `reorder.md` still inherits from delete + insert and needs no text of its own. Confirm this at implementation time.
- The documents reached this way are named from index lines and show up in the proposal's owner sequence as step 2 entries. `SKILL.md` step 4's body scope is not widened.
- `.claude/context/features.md`'s `/pipeline-revise` passage matches the new rule, if it describes the walk.
- The `pipeline-revise` frontmatter version and root `VERSION` get a patch bump, `CHANGELOG.md` gets a section, and `./scripts/check-changelog.sh` passes.

## Decisions
- **Continue, don't stop.** The observed failure is the under-scoping, and the arm refusing partway through is the cost of leaving it implicit.
- **The body scope stays as is.** A reached feature document is named, not opened, and whether it really states the old behaviour is for `/architect amend`'s arm to decide when it opens the document. Widening step 4 would break its "stated here and never widened" rule. The cost is a step at the gate that may turn out to change nothing.
- **Insert doesn't continue.** A successor that gains a wait edge delivers the same thing.
- **Research documents are out of scope** (user decision, 2026-09-15). `.claude/domain/researches/` is a convention of one project, not something chosko-llm handles.
