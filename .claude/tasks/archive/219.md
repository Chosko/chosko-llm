# Task 219 — Cap the runbook `Done:` line to a terse default form

## Goal
`skills/runbook-run/references/runbook-schema.md` § *The `Done:` line* mandates
three things every line records — the commit sha, the decisions taken while
executing, and any premise that proved wrong — so agents treat the line as the
place to narrate their process, and runbook bodies grow unreadable. A real case
ran to four paragraphs of per-round review tallies, resumption narrative and
restated prompt content. Invert the default: one line carrying the date, the
commit and the diffstat, with prose added only where a later reader of this
runbook would be misled without it.

## Acceptance criteria
- The schema's default is the terse form, stated as a template:
  `Done <YYYY-MM-DD>, commit `<sha>` (<N> files, +<X>/-<Y>).`
- The decisions taken and any wrong premise become **conditional**, under a
  stated test: what a future re-reader of this runbook must know in order not to
  be misled — never what the agent did to arrive there.
- The test carries an exclusion list drawn from the observed failure case:
  per-round review tallies, which files were touched, restatements of the step's
  prompt or the task body, and narration of the agent's own resumption. None of
  those belong on the line.
- A `[!]` line still opens with the failure reason, and a struck step's line is
  unchanged — `references/step-amend.md` keeps that rule as it is.
- `references/subagent-contract.md`'s `DONE` report asks for the diffstat beside
  the sha, so the orchestrator can write the terse line without running git.
- `SKILL.md` § *On `DONE`* and the inline outcome path write the new form.
- `.claude/domain/features/runbook-suite.md` is reconciled with what shipped on
  exactly these 2 points — editing it is authorised for this task, see
  Decisions:
  1. The `Done:` paragraph at ~255–258, whose three mandated items become one
     terse default plus two conditional ones.
  2. Its rationale sentence, "the three that were re-read most often", against
     the observed dumping that motivated this change.
  Nothing else in the document changes.
- Root `VERSION` and `CHANGELOG.md` bumped per CLAUDE.md § Versioning (patch — a
  refinement of shipped behaviour, not a new feature);
  `./scripts/check-changelog.sh` exits clean.

## Decisions
- **The diffstat comes from the agent's report, not from the orchestrator.**
  Having the orchestrator run `git show --stat` to compose the line would buy
  accuracy at the cost of the thing this task is protecting — a cheap
  orchestrator — so the subagent contract asks for it instead.
- **`Context:` is deliberately left alone** (user decision, 2026-09-15). The
  observed bloat is in both fields, but only the `Done:` line is in scope here.
- **Existing long lines are not rewritten.** They are the record of what
  happened; a migration pass would edit history for tidiness.
- **Editing `.claude/domain/features/runbook-suite.md` is explicitly authorised
  for this task (user decision, 2026-09-15), for the 2 reconciliations listed
  above and for nothing else. Do not ask for permission at implementation time —
  the permission is already granted.** That document is normally `/architect`'s,
  and anything beyond those points still belongs to `/architect`. These are
  factual reconciliations with shipped behaviour, not redesigns; if one turns out
  to need a design decision rather than a wording fix, stop and say so instead of
  deciding it here.
