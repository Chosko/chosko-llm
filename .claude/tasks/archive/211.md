## Goal
Part of feature `runbook-id-filenames` (.claude/domain/features/runbook-id-filenames.md).
A runbook body file gets its id in front of its name (`3-runbook-slug.md`), so the id
typed on a command line is the one visible on disk. This task lands the authority and
its main consumer, all inside the `runbook-run` skill folder: the schema (new path,
`File:` as the only source of a body path, the three-form resolution rule, the
leading-numeric-segment name restriction, the one-sentence migration check), the new
`body-migration.md` protocol, the subagent contract's `<FILE>` placeholder, the
single-step amend, and `/runbook-run` itself. The other consumers follow in tasks 212
and 213, citing what this task writes.

## Acceptance criteria
- `runbook-schema.md` § The store shows `.claude/runbooks/<id>-<name>.md` and states
  that every command opens a body at the path its index block's `File:` line holds and
  never builds the path from the name; a legacy `<name>.md` value stays correct.
- § The store's single rule ("a bare all-digits argument is an id, anything else a
  name") is replaced by the four ordered checks of the design:
  1. all digits → id;
  2. exact name → that block;
  3. `<digits>-<rest>` where block `<digits>` exists and is named `<rest>` → that
     block. Halves that disagree are an error naming the id's real runbook, never a
     fallback to either half;
  4. anything else → unknown, listing the runbooks that exist.
  The legacy-name ambiguity case is stated, reported naming both candidates.
- § The store states the naming restriction — a new name whose first kebab segment is
  all digits is refused with one suggested alternative — and why it means checks 2 and
  3 never both match for new runbooks.
- The "alias, never a replacement" paragraph keeps its meaning but no longer says the
  body stays `<name>.md`; name remains what errors, reports, relay blocks and
  `# Runbook: <name>` use, and the body carries no id of its own.
- § The store carries the one-sentence migration check: a writing command whose block's
  `File:` file name does not begin with `<id>-` has a body to migrate, per
  `body-migration.md`.
- § The index block's example shows `File: .claude/runbooks/<id>-<name>.md`.
- New `skills/runbook-run/references/body-migration.md` carries the protocol and
  nothing else:
  - `git mv` to `<id>-<name>.md`, then rewrite `File:`;
  - never while the runbook is `[RUNNING]`, and why; a resume never migrates;
  - both old and new paths staged in the writing command's one commit;
  - target path exists → stop and report, never overwrite;
  - the non-git VCS mapping;
  - its readers: only `/runbook-run` and `/runbook-create --append`, only after the
    inline check fires.
- `subagent-contract.md` gains a third placeholder `<FILE>`, filled from `File:`, used
  in the rule forbidding edits to the body. Relay file names stay built from
  `<RUNBOOK>` and `<N>`. The maintainer rationale records why `<FILE>` is acceptable
  where an invented relay path was not. Exactly three placeholders: `<RUNBOOK>`, `<N>`,
  `<FILE>`.
- `step-amend.md` reads and writes the body at `File:`, resolves the runbook by the
  schema's rule, and never migrates.
- `skills/runbook-run/SKILL.md`:
  - the ARGUMENTS row takes `<id|name|id-name>`, citing the schema;
  - step 1 *Resolve* resolves by the schema's rule, reads the body at `File:` (after
    any id backfill), runs the migration check on a non-`[RUNNING]` runbook before
    marking it `[RUNNING]` and reads `body-migration.md` only on a hit, and uses the
    resolved path for the whole run;
  - step 2 *Re-read* re-opens the resolved path, not `.claude/runbooks/<name>.md`;
  - the commit section stages the `File:` path, and both paths on the migrating
    step's commit, so `/runbook-run` still writes only the runbook and the index;
  - WHAT THIS SKILL READS AND WRITES names the body by `File:`;
  - where it fills the subagent contract, it fills `<FILE>`.
- No existing body under `.claude/runbooks/` is renamed by this task's commit, and no
  sweep, script or eager migration ships — in particular, the runbook this feature was
  planned inside keeps its current file name.
- `skills/runbook-run/SKILL.md` `version:` gets the next minor bump from whatever it
  holds at implementation time; root `VERSION` gets a minor bump with a matching
  `CHANGELOG.md` section on top; `./scripts/check-changelog.sh` passes.

## Decisions
- **Schema, migration protocol, subagent contract, step-amend and /runbook-run are one
  task.** They are one skill folder with one `version:` bump, and every other consumer
  cites the schema this task writes, so it goes first.
- **`step-amend.md` is edited here, not with /pipeline-patch and /pipeline-revise** —
  it lives in the `runbook-run` folder, so its change rides this task's version bump.
- **Preconditions 208 and 209** because both edit `skills/runbook-run/SKILL.md`. This
  task changes resolve, re-read and commit, which neither touches, so the edge is
  sequencing, not design.
- **The repo-local snapshot `.claude/skills/runbook-run/` is not edited** — it follows
  through `chosko-llm update`, per the design's Versioning note.
