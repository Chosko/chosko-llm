## Goal
Restructure the skill of feature `pipeline-dashboard` (`.claude/domain/features/pipeline-dashboard.md`, § Architecture › Skill body and › Protocol, § Interfaces and contracts) so that a project that has not opted in pays nothing beyond the skill's short body: `SKILL.md` keeps the opt-in resolution, the text snapshot on request and the pointer; the protocol moves to `references/protocol.md`, read only when the dashboard resolves on; the Artifact `read` happens once per session; every user-visible string of the skill and the page is English. This answers the owner's review of upstream PR #20 (requests 1, 2 and 4).

## Acceptance criteria
- `skills/pipeline-dashboard/SKILL.md`, `version: 0.2.0`:
  - an English `description` that triggers on progress questions ("how far along are we", "progress", "dashboard") and while a pipeline run with the dashboard switched on is in progress, within the auto-trigger budget (≤ 150 words, ≤ 1,000 chars) of docs/authoring-guide.md § The `description` contract; trigger phrases in English;
  - the `# /pipeline-dashboard` header block updated to the opt-in behaviour, its `# Usage:` naming the opt-in line and the flags;
  - the opt-in rule, stated once: `--dashboard` turns it on and `--no-dashboard` off for that run; without either, a line `Pipeline dashboard: on` in the project's `CLAUDE.md` turns it on; anything else leaves it off;
  - the text snapshot on a progress question, whatever the opt-in;
  - one pointer: when the dashboard resolves on, read `./references/protocol.md` and follow it for the run; nothing of the protocol restated.
- `skills/pipeline-dashboard/references/protocol.md` carries, from today's `SKILL.md`: who does it, files, publishing (order, the scratchpad copy, list-by-title reuse), when to refresh with the watcher, pending questions, when something fails — with these changes:
  - with a stored `url`: `read` it once per session, before that session's first publish to it; later updates in the session republish without reading;
  - the chat line after each republish is English ("Dashboard updated: task 221 started."); no rule picking another language;
  - pending-question fields are written in English;
  - it opens with a one-line header naming it as read by path by `SKILL.md` only when the dashboard is on.
- `skills/pipeline-dashboard/assets/index.html`: every visible string English, per the feature document § Page — `Progress <milestone|project>`, `Runbook steps`, `<milestone> tasks done` / `Tasks done`, `<milestone> features closed` / `Features closed`, `No runbook`, `In progress · step N of M`, `No step running`, `All steps done`, `Runbook tracklist`, the legend (`task done`, `in progress`, `to do`, `problem`), chips (`done`, `in progress`, `to do`, `failed`, `waiting`), the subtitle, the unreadable notice, `Data not available`, the banner (`A question is waiting for your answer` / `Read the question`), the modal (`(recommended)`, `Why I recommend it: …`, `Answer in the Claude Code terminal with the option's letter`, `Close`), the footer (`Updated <generated> · data from TASKS.md, FEATURES.md and the runbook`). Design, tokens, fonts and behaviour unchanged.
- No string in `SKILL.md`, `references/` or `assets/` is in a language other than English.
- `./scripts/check-home-paths.sh` passes; the page renders with no console error in Playwright against data from `generate.sh` on the `music-producer-tycoon` clone, banner and modal included.

## Decisions
- **The page is in this task, the generator and the status line in 321**: the page's strings and the chat line describe one contract — what the user reads during a run.
- **The protocol file sits under `references/`**, the repo's place for on-demand supporting files of a skill.
- **No root `VERSION` bump here**: task 321 bumps once to 1.80.0 for 319–321 (user decision, PR #20 revision).
