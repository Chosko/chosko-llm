# Task 218 — Recommend an answer at `/pipeline-revise`'s editorial gate by letting the branch judge the `editorial` tier

## Goal
`editorial` is one of the three tier values in `skills/pipeline-revise/amend.md`
§ Tier, but no branch can ever judge it — that file instructs the branch to judge
local or structural, leaving the value reachable only through the gate's arm A.
Lift that restriction so a branch judges `editorial` under its own stated test
(wording only, nothing downstream changing meaning, A's sequence equal to B's),
and let the tier the gate already renders at item 2 mark the recommended letter.
The gate gains a recommendation without gaining a concept.

## Acceptance criteria
- A branch may judge `editorial`; `amend.md` § Tier's "The branch judges local or
  structural for the proposal" is replaced by the closed test above.
- Step 7's gate marks the letter the judged tier implies — `editorial` marks A,
  any other tier marks B — carrying the evidence from the touched artifacts the
  gate already lists.
- Where a judged `editorial` tier makes A's and B's sequences identical, the gate
  says so and still offers both, so the tier can be overruled.
- `reorder.md` keeps its fixed structural tier and marks B, using the reason it
  already states; `insert.md` and `delete.md` state which letter each of their
  tiers marks.
- The invariant "the tier decides how long the sequence is; it never decides
  whether the question is asked" survives verbatim in both files that state it.
- The question is still asked on every run, whatever the tier; silence, an
  unclear reply or EOF is still Stop; nothing is written before the gate.
- The DO NOT entry "infer, classify, pre-answer or skip the editorial question"
  is rewritten to ban skipping and to ban treating the recommendation as an
  answer, keeping the carried-answer carve-out intact.
- The answer carried into an `/architect amend` step is still the user's reply,
  never the recommendation.
- `skills/pipeline-revise/SKILL.md`'s `description:` states the recommendation;
  frontmatter `version:` 0.3.1 → 0.4.0.
- `.claude/domain/features/pipeline-revision.md` is reconciled with what shipped
  on exactly these 3 points — editing it is authorised for this task, see
  Decisions:
  1. § Architecture, "Tiers, one gate" — "always asked" stays; "never inferred"
     is replaced by the judged-tier recommendation rule.
  2. The same section's tier list — a branch may now judge `editorial`.
  3. § Interfaces, hard contracts — the answer carried into the `/architect
     amend` step is still the user's reply, never the recommendation.
  Nothing else in the document changes.
- Root `VERSION` 1.45.0 → 1.46.0 with a matching top `CHANGELOG.md` section;
  `./scripts/check-changelog.sh` exits clean.

## Decisions
- **The tier is the recommendation.** Reusing the tier line already rendered at
  gate item 2 avoids a second concept, and makes the currently unreachable
  `editorial` value reachable, which is what it was written for (user decision,
  2026-09-15).
- **Task 217 first.** It fixes the rendering form and the evidence-line rule for
  both gates; this task follows it rather than inventing a parallel form.
- **Minor bump** (user decision, 2026-09-15).
- **Editing `.claude/domain/features/pipeline-revision.md` is explicitly
  authorised for this task (user decision, 2026-09-15), for the 3
  reconciliations listed above and for nothing else. Do not ask for permission at
  implementation time — the permission is already granted.** That document is
  normally `/architect`'s, and anything beyond those points still belongs to
  `/architect`. These are factual reconciliations with shipped behaviour, not
  redesigns; if one turns out to need a design decision rather than a wording
  fix, stop and say so instead of deciding it here.
