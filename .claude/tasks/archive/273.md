# Task 273 — `/runbook-run` progress line counts finished steps and reads the index's `Steps:` counter

## Goal
Feature `runbook-suite`'s design (`.claude/domain/features/runbook-suite.md`
§ *The chat contract*) redefines the counters of the progress line
`Step <n> running. Current run progress (<k>/<m>). Total runbook progress (<x>/<y>).`,
and `skills/runbook-run/SKILL.md` § CHAT OUTPUT still carries the old ones.
Today `k` is the step's position among executed steps, `m` counts only
selectable `[ ]` steps — so a resumed `[~]` or re-run `[!]` step can push `k`
past `m` (`1/0`) — and `x/y` is `[x]` steps plus the one starting over "every
step in the runbook", which misses archived ids. The shipped body must state
the design's counters.

## Acceptance criteria
- § CHAT OUTPUT defines `k` as the steps this run has finished (`[x]` in this
  run) plus the one now starting; a step that parked or failed earlier in the
  run adds nothing to it.
- `m` is every selectable `[ ]`, `[~]` or `[!]` step in range, capped by
  `N` of `--steps N` when that is smaller, fixed at launch and never
  recomputed; steps the run will not execute (unmet `Depends on:`, out of
  range) are not in it. `k` never exceeds `m`.
- `x/y` is the `.claude/RUNBOOKS.md` `Steps:` counter as it stood at launch
  (`y` therefore counting archived ids, per `runbook-schema.md`), `x` raised
  by each step this run finishes plus the one now starting; a parked or
  failed step adds nothing to `x`.
- The `--steps N` counting rule (a resumed `[~]` / re-run `[!]` step counts
  like any other selected step) and the new `m` read as one model, with no
  contradiction between the two passages.
- Feature frontmatter `version:` of `runbook-run` bumped (patch); root
  `VERSION` bumped (patch) with a matching `CHANGELOG.md` section;
  `./scripts/check-changelog.sh` and `./scripts/check-home-paths.sh` pass.

## Decisions
- `m` counts `[~]` and `[!]` steps in the same terms as the existing
  `--steps N` rule already does ("counts like any other selected step");
  what execution would skip stays out of the denominator.
- `y` is the index's `Steps:` total so that archived ids count — that is
  `runbook-schema.md`'s definition of the counter, not a new one.
- `k` and `x` both include the step now starting (user decision,
  2026-09-30).
