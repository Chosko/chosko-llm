# Task 281 — Add the `interaction-engine` reference skill

Archived: 2026-10-07
Status: [DONE]
Files: skills/interaction-engine/SKILL.md, skills/interaction-engine/references/policy.md, skills/interaction-engine/references/gates.md, skills/interaction-engine/references/messages.md, VERSION, CHANGELOG.md
Preconditions: none
Feature: interaction-policy

Target: claude

## Goal
Create the non-invocable `interaction-engine` skill that holds, once, every
rule of feature `interaction-policy`: the policy line, flags and precedence
(`policy.md`), the three gate classes and the park-else-stop rule
(`gates.md`), and the output and question rules (`messages.md`). Later tasks
make each interactive feature cite it; this task ships the engine alone so
those citations have a target.

## Acceptance criteria
- `skills/interaction-engine/SKILL.md` exists with frontmatter `name`,
  `version: 0.1.0`, `type: skill`, `description`, `disable-model-invocation: true`,
  and a body shaped like `skills/task-engine/SKILL.md`: not-invocable notice,
  the install-path / relative-citation note (`../interaction-engine/references/<file>.md`
  from a skill root, `../../interaction-engine/…` from a skill's `references/`,
  `../skills/interaction-engine/…` from a command), a map of the three files
  with when each is opened (policy.md at argument parsing; gates.md only when
  the policy resolves to `unattended`; messages.md before the first gate,
  question or closing report).
- `references/policy.md` states: one value per run; precedence flag or
  handed-down parent policy > runbook `Execution policy:` (`/runbook-run`
  only) > CLAUDE.md `Interaction policy: attended|unattended` > `attended`;
  a parent hands its resolved policy down (step preamble states it under both
  values; delegated prompt carries it in its resolved-flag list; the wording
  says attended/unattended, never "non-interactive"); `--attended` with
  `--unattended` is an argument error; a CLAUDE.md value outside the two
  words is an argument error naming it; every interactive feature accepts
  both flags; the testing-policy marker and the `-y` flags are untouched.
- `references/gates.md` states the three classes and the rule for each —
  class 1 passes under `unattended` printing a short summary naming the
  commit (or the uncommitted change on a no-commit / non-git run), each
  auto-passed write its own commit, an auto-passed gate whose commit fails
  stops as that feature's commit failure does; class 2 waits (park where the
  feature parks, else stop ending with summary + question; a new gate is
  class 2 until tagged); class 3 waits under every policy — and the
  real-decisions rule (park, else stop; never pick an option). Membership is
  declared at the gate by a one-word tag citing this file; the file holds no
  catalogue of gates. A parked gate stays unattended-parking's approval-gate
  case.
- `references/messages.md` states the output rules (no verbatim drafts or
  before → after diffs at a gate; plain summary of what changes, why, what it
  affects; `show` prints the draft and asks again; ~8 lines per gate summary,
  ~10 per closing report, soft; SHAs/diffstats/paths only when they matter,
  an auto-passed gate's commit always does; reply shortcuts at most a
  one-line hint) and the question rules (a message that asks ends with its
  questions; plain language first, identifiers last in parentheses, with the
  feature doc's bad/good example; one ask per stop).
- No other feature is edited. Root `VERSION` minor-bumped with a matching
  `CHANGELOG.md` section; `./scripts/check-changelog.sh` and
  `./scripts/check-home-paths.sh` pass; `./bin/chosko-llm ls --available`
  lists `interaction-engine` at 0.1.0.

## Decisions
- The engine ships first and alone: adoption tasks need a citation target,
  and an engine nobody cites yet changes no behaviour.
- The orchestrate-mode check named in the feature doc is not added here; that
  feature extends the engine when it is implemented.
