# Task 337 — Settle the park branch push inside a worktree

Target: claude

## Goal
`parking.md`'s park sequence pushes `park/task-<N>` unless NO_PUSH, while
`worktree.md` states that a unit's agent never pushes; inside a worktree the
two disagree and nothing on disk decides. Settle it in one place: the park
branch is the one push a unit's agent makes — it is private to the task,
touches no base branch and races with no other unit, and pushing it is what
lets another machine unpark — so the park sequence runs unchanged inside a
worktree, and `worktree.md` names `park/task-<N>` as the single exception to
its never-push rule, citing `parking.md`.

## Acceptance criteria
- `skills/task-engine/references/worktree.md` § *The agent integrates* states
  that the agent never pushes the base branch and that the one branch it
  pushes is its own `park/task-<N>`, under `./parking.md` § *The park
  sequence*, unless NO_PUSH; the sentence that the agent never pushes, with
  no exception, is gone, and no other passage of the file contradicts the
  exception (the orchestrator's landing, the invariants and the per-consumer
  notes are read and reconciled).
- `skills/task-engine/references/parking.md`'s in-worktree paragraph after
  § *The park sequence* states that steps 1, 2 and 4 push and delete
  `park/task-<N>` on the remote exactly as outside a worktree — the push of
  that branch is the agent's, named as the exception in `./worktree.md` —
  and that NO_PUSH alone suppresses it.
- `.claude/domain/features/worktree-isolation.md` states the agreed design
  change — the agent never pushes the base branch; the one branch it pushes
  is its own `park/task-<N>`, under `parking.md` — in every passage that
  stated the old one (§ Architecture, *The agent integrates*), and settles
  § Scope and non-goals, *Pushing from inside a worktree*, which already
  names the base branch only. Nothing else in the document changes.
- `task-engine`'s `version:` is bumped (patch); root `VERSION` is bumped
  (patch) with a matching `CHANGELOG.md` section; `./scripts/check-changelog.sh`
  and `./scripts/check-home-paths.sh` pass.

## Decisions
- The agent pushes the park branch itself rather than handing it to the
  orchestrator at landing: a landing happens only on a return, and a parked
  task's work must be recoverable from another machine before that; the
  branch name is deterministic per task, so no two units can push the same
  one.
- **Design change agreed (user decision, `2026-10-12`):**
  `.claude/domain/features/worktree-isolation.md` § Architecture, *The agent
  integrates*: "The agent never pushes" → "The agent never pushes the base
  branch; the one branch it pushes is its own `park/task-<N>`, under
  `parking.md`". Settled here: § Scope and non-goals, *Pushing from inside a
  worktree* — the non-goal already names the base branch only.
  `.claude/domain/features/worktree-isolation.md` is normally `/architect`'s;
  this task updates it for exactly this and for nothing else. A further
  design decision met at implementation time is not covered: leave that
  passage untouched and name it under *Follow-ups* as a precise follow-up.
