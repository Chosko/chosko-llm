# Task 247 — Ship `claude-md:editing-discipline` and cite it from the authoring guide, the feature template and `/task-review`

Target: claude

## Goal
Edits to rules documents tend to stratify: a new rule lands beside the old one,
history creeps into the body, decisions get explained instead of stated, and the
same rule is paraphrased in several files. Ship the editing discipline that
prevents this as a claude-md feature, so every agent editing a document in a
project that installs it reads the rules from `CLAUDE.md`, and make the one copy
in that file the only statement of them in this repository.

## Acceptance criteria
- `claude-md/editing-discipline.md` exists with full frontmatter (`name`,
  `version: 0.1.0`, `type: claude-md`, `description`) and nine rules, each one
  or two sentences: (1) a changed rule edits the sentence that states it, and
  the old sentence goes; (2) a body carries no history: no "previously", "now",
  "no longer", no dates or task ids as provenance, with `CHANGELOG.md`, the task
  archive and session handoffs as the exceptions; (3) state the rule, not the
  decision, with one reason clause only when it changes how the rule applies,
  the rest belonging to the domain layer; (4) one rule lives in one place, and
  everywhere else cites it by path rather than paraphrasing; (5) a rule
  misread once gets clearer wording, not more adjectives nor a second bullet;
  (6) a DO NOT bullet that negates a sentence already in the body is deleted;
  (7) edit the section, not the sentence: read the whole section and rewrite it
  as if written fresh with the new rule in; (8) before finishing an edit, for
  each sentence added, ask whether an existing sentence now overlaps it,
  contradicts it or describes a state that no longer holds, and if so merge the
  two into one sentence carrying the whole current meaning, a sentence whose
  meaning is now fully carried elsewhere going; (9) a change carries its
  consequences: every passage the approved change makes stale is updated in the
  same edit, whoever owns the file, and a new decision is never smuggled in as a
  consequence.
- No rule names a line count, a ratio or any number as a target.
- The section is installed into this repo's `CLAUDE.md` through the claude-md
  mechanism (`chosko-llm add claude-md:editing-discipline --local`), so
  `CLAUDE.md` carries the managed section and nothing hand-written about it.
- `docs/authoring-guide.md`: the "Tool discipline is global — do not restate
  it" and "Commit message shape is global — do not restate it" sections, and
  any other passage stating the cite-do-not-restate rule, collapse into one
  short section that cites the claude-md feature and keeps only what is
  specific to shipped bodies.
- `skills/architect/feature-doc-template.md`: the update-in-place paragraph
  keeps only what is specific to feature documents (keep slug and heading,
  rewrite the changed sections, one document per feature) and cites the
  feature for the rest.
- `skills/task-review/SKILL.md` gains one finding category, *stratification*:
  history in a body, a duplicate statement, a stale sentence left beside a new
  one. It never flags a diff for its size. Severity per the skill's existing
  SEVERITY section.
- `docs/reference.md` and `README.md` list the new claude-md feature where the
  two existing ones are listed; `.claude/context/features.md` names it.
- `skills/task-review/SKILL.md` `version:` minor bump; root `VERSION` minor
  bump; `CHANGELOG.md` entry; `./scripts/check-changelog.sh` and
  `./scripts/check-home-paths.sh` silent.

## Decisions
- The rules ship as a claude-md kind rather than a docs page: `docs/` is never
  installed, and the discipline has to reach agents working in other
  repositories and in cloud sessions that do not see the global `CLAUDE.md`.
- The claude-md body is the single statement; the authoring guide and the
  template cite it. This task is the first one written under rule 4.
