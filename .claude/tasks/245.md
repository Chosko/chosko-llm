# Task 245 — Bind the relay child with a fixed contract block; check the result file exists before replying

Target: claude

## Goal
The spawn relay's one structurally load-bearing agent, the child, has no fixed
contract: its obligations exist only as prose in `SKILL.md` § THE SPAWN RELAY
step 1, which the orchestrator re-words per spawn — the exact failure
`references/subagent-contract.md` says `OPERATING RULES` exists to prevent. Two
failures observed on 2026-09-20 (runbook `m3-tasks-implementation`, cloud
session, five relayed steps): at step 83 the child returned its full report in
its turn and wrote no `-result.md`, leaving the caller suspended on a file that
did not exist; at step 85 it wrote the file but returned
`Result file written: <path>` with no literal `DONE`, which THE FOUR RESULT
CASES classifies as failure. Both were repaired by an improvised round-trip the
skill never asks for. Give the child a verbatim-pasted block under the same
discipline as `OPERATING RULES`, paste it from step 1, and add an existence
check on the orchestrator's side. Rules, not explanation: the shipped bodies
state obligations, and the only place a reason goes is the maintainer section,
briefly.

## Acceptance criteria

  at most eight lines, imperative, no rationale. Read `<PROMPT>`; do exactly
  what it asks; write the full report to `<RESULT>`; check that `<RESULT>`
  exists and is non-empty before ending the turn; do not repeat the report in
  the returned turn; end the turn with the literal line `DONE` and one line
  saying the file is written, nothing else; on failure write what there is to

  this block. Placeholders `<PROMPT>`, `<RESULT>`, `<RUNBOOK>`, `<N>`, `<FILE>`

  `references/subagent-contract.md`, in the form THE EXECUTION LOOP step 6

## Decisions
- **Rules, not explanation.** The pasted block and the `SKILL.md` edits state
  obligations only. Reasons live in the maintainer section, briefly.
- **Existence check adopted as recommended.** Checking a path exists is not
  reading it; the read ban keeps the report out of the orchestrator's
  context, which a stat does not touch.
- **Re-prompt once, then fail.** One repair covers a child that forgot; a
  second is a child that cannot comply. The re-prompt serves no new
  `SPAWN REQUEST`, so it is not a relay round.
- **`<PROMPT>` / `<RESULT>` are fillable placeholders** where a relay-path
  placeholder in `OPERATING RULES` was not: by the time the child is spawned,
  the request has already named both paths, so filling them invents nothing.
- **Preconditions: 244** because both tasks edit `skills/runbook-run/SKILL.md`.
- **Editing `.claude/domain/features/runbook-suite.md` is explicitly
  authorised for this task (user decision, 2026-09-20), for the 2
  reconciliations listed above and for nothing else. Do not ask for
  permission at implementation time — the permission is already granted.**
  That document is normally `/architect`'s, and anything beyond those points
  still belongs to `/architect`. These are factual reconciliations with
  shipped behaviour, not redesigns; if one turns out to need a design
  decision rather than a wording fix, stop and say so instead of deciding it
  here.
