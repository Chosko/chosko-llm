# Task 111 — Add the /production-plan skill and the PLAN.md schema

Target: claude

## Goal
Ship `skills/production-plan/SKILL.md` plus its on-demand `reconciling.md`,
the skill that writes `.claude/PLAN.md` — a third index beside `TASKS.md` and
`FEATURES.md` recording which low-level feature belongs to which milestone,
in what order, and after what. This is the feature-level half of the
pipeline's WHEN layer, from feature `production-plan`: `FEATURES.md` carries
no ordering today and the dependency prose in each feature document is read
by nobody. The skill covers all four responsibilities in one unit — milestone
inheritance from `Source:`, dependency edges confirmed from feature
documents, validation that refuses cycles and later-milestone dependencies,
and reconciliation on re-run — because they share one read pass, one schema,
and one approval gate; splitting them would ship a plan that cannot be
validated or re-run.

## Acceptance criteria
- `skills/production-plan/SKILL.md` exists with complete frontmatter:
  `name: production-plan`, `version: 0.1.0`, `type: skill`, one-line
  `description`. No `replaces:` — new skill, not a kind migration.
- Argument parsing handles `--commit` and `--no-push` exactly as
  `skills/architect/SKILL.md` does; nothing committed without `--commit`,
  `--commit --no-push` commits locally without the sync/push cycle.
- A PHASE 0 gate refuses when `.claude/FEATURES.md` is missing and points at
  `/domain-setup`. A roadmap is NOT required: without one every feature lands
  in `Unscheduled` and dependency ordering still works.
- Read pass takes in `.claude/FEATURES.md` (slugs, `Status:`, `Source:`,
  `Tasks:`), each feature document's `## Dependencies` section,
  `.claude/domain/product-roadmap.md` when present, and `.claude/TASKS.md`
  (statuses, for the `[SHIPPED]` proposal only). All read-only.
- The `PLAN.md` schema is written inline in `SKILL.md`: `Roadmap:` and
  `Last reconciled:` header lines; one block per milestone with `Status:`,
  `Covers:`, ordered `Features:`; an `Unscheduled` block; and one flat
  `## Dependencies` edge list (`- <slug>: depends on <slug>, <slug>`), not a
  `Depends:` line per feature.
- `Features:` order IS the priority — no separate priority axis, no `P0`/`P1`
  labels. `Covers:` is derived, rewritten every run from the roadmap's own
  `Covers:` lines. `Last reconciled:` is informational only.
- Milestone inheritance is a lookup, not an inference: a milestone
  parenthetical on a feature's `Source:` line places it in that milestone.
  Features with no parenthetical and `Source: prompt` features start in
  `Unscheduled`. An explicit placement overrides the parenthetical, is
  reported plainly at the approval gate, and is never gated or refused.
- Dependency edges: the skill proposes the edge set from each document's
  `## Dependencies` prose in machine-readable form, the user confirms, and
  `PLAN.md` stores it. Prose stays the human-facing statement.
- Validation runs before any write, and both invariants refuse rather than
  warn: within a milestone `Features:` must be a topological order of the
  edges restricted to it, a dependency living in a later milestone is refused
  outright, and a cycle is reported as the actual cycle path and refused with
  no override flag.
- Milestone status vocabulary is exactly `[PLANNED]` / `[ACTIVE]` /
  `[SHIPPED]`, with at most one `[ACTIVE]` milestone. `[SHIPPED]` is proposed
  only when every feature in the milestone is `[PLANNED]` in `FEATURES.md`
  and all their tasks are `[DONE]` or `[SKIP]`, is always confirmed by the
  user rather than applied automatically, and can never reopen.
- Exactly one write phase behind one approval gate, writing `.claude/PLAN.md`
  and nothing else. `FEATURES.md`, `TASKS.md`, the feature documents and the
  roadmap are never written.
- `skills/production-plan/reconciling.md` holds the re-run reconciliation
  text, read on demand, and implements the five-situation table: a feature
  absent from the plan is proposed for placement; a plan slug gone from
  `FEATURES.md` is reported and dropped; an `[ITERATED]` feature has its
  document's dependencies re-read and the edge diff proposed; a roadmap
  milestone absent from the plan is added in roadmap order; a plan milestone
  gone from the roadmap is reported, kept and flagged. Everything lands
  behind the same single approval gate.
- Failure contract implemented: no `FEATURES.md` → refuse, point at
  `/domain-setup`; no features at all → write nothing, say so; cycle →
  report path, refuse; later-milestone dependency → report both features and
  their milestones, refuse; more than one `[ACTIVE]` → report and ask; an
  edge slug resolving to no feature → report and drop the edge; `--commit`
  with nothing changed → no commit, say so.
- Nothing plan-aware is added to `/task-add`, `/task-implement`, or the bash
  CLI — explicitly deferred by the feature's open questions.
- Root `VERSION` bumped minor (new skill).
- `./bin/chosko-llm ls --available` lists `production-plan` at `0.1.0`.

## Decisions
- **One task for the whole skill.** The four responsibilities share one read
  pass, one schema, and one approval gate; validation gates the write path
  and reconciliation is the same write path re-entered. Same call as task 106
  for `/product-roadmap`.
- **Reconciliation in a supporting file, the schema inline.**
  `reconciling.md` is re-run-only text, so it follows
  `skills/architect/iterating.md` and is read on demand. The schema is needed
  by every run, so it stays in `SKILL.md` — the same reasoning task 106
  applied to the roadmap schema.
- **`PLAN.md` at `.claude/` root, not inside `domain/`.** It indexes work
  items, like `TASKS.md` and `FEATURES.md`; the knowledge it indexes lives in
  the domain layer.
- **Milestone status lives in `PLAN.md`, not the roadmap.** The roadmap holds
  intent, this index holds state — one writer per artifact.
- **Preconditions 106 and 109, not just 106.** Milestone inheritance reads
  the `Source:` parenthetical that task 109 introduces, and derived `Covers:`
  needs the roadmap schema from task 106.
