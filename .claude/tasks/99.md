# Task 99 — Add nested-layout support to /context-update

Target: claude

## Goal
Make `/context-update` correct on a nested layer: build its file list from
the leaves, scope each subtree's git scan by that subtree's own date, bump
only the leaves it actually touched, and never treat the router as a date
holder. Nested logic lives in a read-on-demand
`skills/context-update/nested.md` opened only when the marker says nested.

## Acceptance criteria
- PREPARATION reads the `Layout:` marker from `.claude/context/INDEX.md`.
  `flat` or absent: the existing path runs unchanged and `nested.md` is
  never opened. `nested`: `nested.md` is read and drives the run.
- Nested P.2 builds the in-scope file list as the union of the leaf INDEX
  entries, recording the owning leaf for each file. That leaf owns the file
  for the rest of the run.
- **MODE A** issues one `git log --after=<that leaf's Last updated>` per
  leaf. No global date, and no code path reads a date from the router —
  the router has none. A leaf whose `Last updated` is missing degrades to a
  full update **of that leaf only**, never a full-layer rebuild; the
  degrade is named in the scope report.
- Mode A's "no commits found" handling (uncommitted-changes probe, then
  "up to date" exit) applies per the union across leaves, so a run exits
  clean only when every leaf is clean.
- **MODE B (`full`)** covers every file in every leaf.
- **MODE C** gains `unit=<name>` (comma-separated), scoping the run to
  those leaves. `files=<names>` resolves within the leaves; when a bare
  name matches a context file in more than one unit and no `unit=` was
  given, stop and ask the user to disambiguate, listing the matching
  `<unit>/<file>` paths. Do not guess and do not silently pick one.
  With `unit=` supplied, the name resolves inside those units only and no
  question is asked. `files=`, `git=`, and `unit=` still take the union.
- **Step 2.4** updates only the leaf INDEXes whose files this run actually
  wrote: their Files-table descriptions, and their `Last updated` stamped
  to today. Leaves this run did not touch are not written at all. No code
  path writes a date onto the router — the router is edited only when a
  whole unit is added or retired.
- Adding or removing a context file edits its owning leaf's INDEX, never
  the router.
- The scope report (P.4) and the Phase 2 final report both state the
  detected layout; for nested they also list the per-leaf dates, which
  leaves are in scope, which were bumped, and which were deliberately left
  alone.
- **PHASE 3 stages** every leaf INDEX bumped plus every context file
  written, and the router only if a unit was added or retired. Leaves that
  were not bumped are not staged. Explicit paths only — never `git add -A`
  / `.` / `-u`.
- `-y` / `--yes`, `--no-commit`, `--no-push` behave identically in both
  layouts.
- The flat path is byte-identical to task 97's. This is global config
  shared across projects, and a flat regression is the main risk of this
  change — verify it explicitly by reading the flat path start to finish.
- Root `VERSION` bumped minor.

## Decisions
- **Per-leaf git scans, not one global scan.** Leaf dates drift apart;
  scoping everything by the newest silently skips real changes in older
  leaves, and that failure is invisible.
- **Leaf-only degrade on a missing date.** A whole-layer rebuild because
  one leaf lost its date is a large, surprising run; degrading one unit is
  proportionate.
- **Ask on an ambiguous `files=` rather than defaulting.** Picking a unit
  by any rule would quietly update the wrong file; `unit=` exists precisely
  so the user can answer once and not be asked again.
