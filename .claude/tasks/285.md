# Task 285 — Add the pipeline-dashboard page

Target: claude

## Goal
Add `skills/pipeline-dashboard/assets/index.html`, the page of feature `pipeline-dashboard` (`.claude/domain/features/pipeline-dashboard.md`): the approved prototype's design made generic, reading everything from `data.js` as task 284 generates it — header, pending banner and modal, three meters, the "In corso" box, the runbook tracklist, legend, footer, and a notice for sources that could not be read.

## Acceptance criteria
- `skills/pipeline-dashboard/assets/index.html` keeps the prototype's design (https://claude.ai/artifact/TcBzzLktetEeji7grdtDbS): Italian UI, Familjen Grotesk / IBM Plex Sans / IBM Plex Mono from Google Fonts, colour tokens on `:root`, the dark variant under `@media (prefers-color-scheme: dark)` guarded by `:root:not([data-theme="light"])` and repeated under `:root[data-theme="dark"]`, explicit `body` background; done green, running amber with pulse (none under `prefers-reduced-motion`), todo grey, failed red.
- `<title>` is `Pipeline <project>`, set from `DASH.project` at load and present as a static fallback `Pipeline`; it is the fixed per-project title the skill looks up.
- Sections in order: header (eyebrow `<project> · milestone <id>` or `<project>` alone, h1 `Avanzamento <milestone id>` or `Avanzamento <project>`, a one-sentence subtitle derived from the data — runbook name, steps done of total, tasks done of total); pending banner; meters "Passi del runbook", "Task <milestone> completati" (segments capped at 47), "Feature <milestone> chiuse" (labels without the milestone when there is none; the runbook meter shows "Nessun runbook" when `runbook` is null); "In corso" box (running step with its tasks and chips fatto / in corso / da fare, or "Nessun passo in esecuzione" / "Tutti i passi completati"); "Tracklist del runbook" rows (number, feature or label, task range and d/t, one square per task with tooltip `#id title — STATUS`, PARTIAL / INCORRECT / STALE red, chip, `Done:` line), using the per-step `tasks` ids from the data; legend; footer "Aggiornato <generated> · dati da TASKS.md, FEATURES.md e dal runbook".
- A non-empty `DASH.unreadable` shows a visible notice naming those files; a missing `window.DASH` shows "Dati non disponibili" — never fabricated zeros.
- Pending modal per the spec: where, title, question, options with the recommended one highlighted and marked "(consigliata)", "Perché la consiglio: …", "Rispondi nel terminale di Claude Code con la lettera dell'opzione"; opens automatically once per `pending.id` (`localStorage` in try/catch), reopens from the banner button, closes on button, backdrop or Esc; focus moves to the close button on open and back to the opener on close.
- All DOM text from data is set with `textContent` (no `innerHTML` with data anywhere).
- Phone width: 16 px gutter, no horizontal scroll at 360 px.
- **Verification** with Playwright on the local Chromium: screenshots at 1200 px and 390 px, light and dark, from data generated by task 284 against the `music-producer-tycoon` clone, plus one with a fake `pending.json` showing banner and modal; a scripted check that `document.scrollingElement.scrollWidth <= innerWidth` at 360 px and that Esc closes the modal and restores focus. Screenshots sent to the user.

## Decisions
- **The design stays as approved**; changes are only what genericity and the spec require: data-driven labels, focus restored to the opener, Esc closing.
- **No root `VERSION` bump** — same reason as task 284.
