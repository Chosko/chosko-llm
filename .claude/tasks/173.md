# Task 173 — Add positional `--before` / `--after` to `/runbook-create --append`

Target: claude

## Goal
Feature `backlog-ordering` gives the runbook store the same insertion operation
it gives the backlog. `/runbook-create --append` puts every new step at the
foot, so a step that belongs between two others is placed by hand or not at all.
This task adds `--before <step>` and `--after <step>` to the append path, and
records in the schema that a step's id is not its position — so a reader never
infers order from numbering.

## Acceptance criteria
- `/runbook-create --append <name|id>` accepts `--before <step>` and
  `--after <step>`; they are mutually exclusive, and an unknown step id is
  reported by listing the runbook's steps.
- The new step takes the next unused id from the existing numbering, but is
  written at the requested list position. `/runbook-run` already walks the body
  top to bottom, so list position is the order and the id carries none.
- `skills/runbook-run/references/runbook-schema.md` states that step ids are
  stable identifiers and not positions, that a body may legally carry step ids
  out of numeric order, and that order is list position — the same rule
  `TASKS.md` uses for tasks.
- Existing steps' `Depends on:` lines are never rewritten. The new step's
  `Depends on:` is authored as part of the append.
- `--from`, `--to` and `--only` on `/runbook-run` keep addressing steps by id;
  nothing about them changes.
- The APPEND RULES section is corrected where it currently implies the foot:
  "Numbering continues from the last existing step" stays true of the id but
  must not imply the position, and "an append adds material after the last step
  and touches nothing above the append point" is restated as the invariant that
  survives — no existing step is ever edited.
- The DO NOT entry forbidding edits "above the append point" is restated in the
  same terms, so inserting above an existing step is not read as forbidden.
- The `[DONE]` → `[PENDING]` flip, the `[FAILED]` and `[RUNNING]` rules, the
  `Sequencing:` extension, the `Steps: <done>/<total>` update and the
  untouched `Last runbook number:` all apply to a positional insert unchanged.
- `commands/runbook-create.md` and `skills/runbook-run/SKILL.md` each take a
  minor `version:` bump.
- Root `VERSION` takes a minor bump and `CHANGELOG.md` gains a matching top
  section; `./scripts/check-changelog.sh` exits zero.

## Decisions
- The id is not renumbered on insert, in either store. A runbook's ids are
  stable identifiers exactly as task ids are, and the schema now says so
  explicitly rather than leaving a reader to infer order from the number.
- Independent of tasks 169–172: nothing in the runbook store reads
  `Preconditions:`, so this task has no precondition of its own.
