# Task 88 — Remove vestigial --no-commit checks from authoring commands

Target: claude

## Goal
Seven authoring commands (uncommitted-by-default, opt into committing via
`--commit` per docs/authoring-guide.md's commit-and-push convention) each
carry an ARGUMENT NOTE checking "`--commit` and `--no-commit` are mutually
exclusive — if both appear, stop with...". This was copy-pasted from the
auto-committing commands' template, but `--no-commit` isn't a documented
flag for these 7 commands — their default state is already uncommitted, so
there's nothing for `--no-commit` to opt out of. Passing `--no-commit`
alone (without `--commit`) is never checked or stripped by these commands,
so it silently leaks into the free-form argument text instead of being
recognized as a flag. Remove the dead check from all 7 files.

## Acceptance criteria
- The `--no-commit` mutual-exclusivity check is removed from the ARGUMENT
  NOTE (or equivalent) section of all 7 files listed under Files.
- Each file's `--commit` flag handling (scan, strip, set COMMIT=true) is
  otherwise unchanged — only the vestigial `--no-commit` check is removed.
- No file gains new `--no-commit` handling as a side effect; the flag
  remains simply undocumented/unhandled for these 7 commands, matching
  their actual (uncommitted-by-default) behavior.
- Each command's Usage/synopsis line, if it mentions `--no-commit`, is
  corrected to not list it as a valid flag for that command.
- docs/authoring-guide.md's commit-and-push convention section is
  cross-checked to confirm it does not claim these 7 commands accept
  `--no-commit` (it currently correctly limits `--no-commit` to the
  auto-committing group only) — no edit expected there, but verify.
