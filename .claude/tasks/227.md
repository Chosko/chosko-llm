# Task 227 — Make `/runbook-create` commit by default

Target: claude

## Goal
`/runbook-create` stops leaving the runbook in the working tree and commits and
pushes it by default, the way `/runbook-run` and `/runbook-clean` already do.
`--no-commit` becomes the way to hold it back; `--commit` stays accepted as a
silent no-op. A runbook is read by the next session, often on another machine,
and its review already happens at the command's own plan gate.

## Acceptance criteria
- ARGUMENT PARSING: COMMIT is true unless `--no-commit` is passed;
  `--no-commit` implies NO_PUSH; `--commit` is an accepted no-op;
  `--commit --no-commit` stops with `--commit and --no-commit cannot be combined. Pick one.`
  The current "authoring command whose default already commits nothing" note
  for `--no-commit` is removed.
- Pull at start runs on every run without `--no-commit`, before PHASE 1.
- PHASE 6 commits by default (same staging, message forms, migration-rename
  handling and push protocol as today); under `--no-commit` it reports the
  paths and reminds the user nothing was committed.
- The usage header, the PHASE 6 heading, the PHASE 3 "uncommitted and open to
  review" sentence and the DO NOT git bullet no longer assert the old default.
- The forwarding rows in `commands/pipeline-patch.md` COMMITTING and
  `skills/pipeline-revise/SKILL.md` COMMITTING move `/runbook-create --append`
  into the commits-by-default row (`--no-commit` when `--commit` was absent),
  so a revision run does not commit unasked between this task and task 229.
- `routing.md`'s `/runbook-create` Args column reads `[--no-commit | --no-push]`.
- Frontmatter `version:` bumped on `runbook-create`, `pipeline-patch`,
  `pipeline-revise`, `pipeline-engine`; root `VERSION` bumped with a matching
  `CHANGELOG.md` section; `./scripts/check-changelog.sh` and
  `./scripts/check-routing.sh` pass.

## Decisions
- The two forwarding rows are fixed here, not in task 229: a default change
  that does not reach its forwarding row makes revision runs commit when the
  user did not ask — the failure `authoring-commit-default` recorded.
- `--commit` stays a silent no-op rather than an error, matching the earlier
  flip of the four design skills, so existing runbook steps and invocations
  keep working.
