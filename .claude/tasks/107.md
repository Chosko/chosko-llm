# Task 107 — Update documentation for feature product-roadmap

Target: claude

## Goal
Feature `product-roadmap` adds a new shipped skill (`/product-roadmap`) and a
new stage to the product pipeline, both delivered by task 106. The
documentation layers that describe the pipeline and the shipped-artifact set
do not mention either, so they are out of date once 106 lands. Bring them up
to the behaviour that actually shipped.

Ground truth for what shipped is `skills/product-roadmap/SKILL.md` itself —
read it before writing anything, and describe what it does rather than what
was planned. The design rationale behind it is
`.claude/domain/features/product-roadmap.md`; read it for the WHY, but do not
edit it — that document belongs to `/architect`.

In one line, what shipped: a skill that writes
`.claude/domain/product-roadmap.md` — ordered milestone blocks with `Goal:`,
`Exit criteria:`, `Rationale:`, and `Covers:` scope slices naming
`product-design.md` sections — gated on `/domain-setup`, one write phase
behind one approval gate, reading `FEATURES.md` but never writing it, and
carrying no milestone state.

## Acceptance criteria
- `.claude/context/features.md` gains a `skills/product-roadmap/` bullet in
  the "Currently shipped" list, placed beside the other pipeline skills
  (`skills/product-design/`, `skills/architect/`) and written in the same
  terse register as its neighbours. It covers: what the skill writes, the
  `/domain-setup` gate, the single write phase behind one approval gate, the
  read-only relationship with `.claude/FEATURES.md` and `product-design.md`,
  the deliberate absence of milestone state, and membership in the authoring
  commit family (nothing committed without `--commit`; `--no-push` skips the
  push).
- `.claude/domain/product-workflow.md` is updated in three places, all of
  which already exist and are the exemplars to match:
  - "The pipeline" table — a roadmap stage ahead of stage 2 (`/architect`),
    with its Consumes and Produces columns filled.
  - "Artifacts" tree — `domain/product-roadmap.md` added.
  - "Who writes what" table — `product-roadmap.md`, writer
    `/product-roadmap`, one writer only.
- `README.md` lists the new skill wherever the shipped feature set is
  enumerated, matching the surrounding entries' length and style.
- `docs/cli-help.txt` reflects the new feature if and only if that file
  enumerates individual features; leave it untouched otherwise.
- Scope is this feature only. The sibling features in `.claude/FEATURES.md`
  (`slice-aware-architecture`, `production-plan`, `plan-readout`) are
  designed but not implemented — do not document them, and do not describe
  `PLAN.md`, `/production-status`, or milestone status as if they exist.
- No new `.claude/context/` file and no `.claude/context/INDEX.md` row — the
  change is a new shipped artifact, which `features.md` already covers, not a
  new area of the codebase.
- The domain `INDEX.md` row for `product-roadmap.md` is written by the skill
  at runtime in target projects — do not add one for this repo.
- Root `VERSION` bumped patch (documentation-only; 106 already took the minor
  bump for the new skill).
