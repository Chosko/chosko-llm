# Task 206 — Ship `hook:remote-stop-exemption`, exempting `/runbook-run`'s in-flight markers from the cloud Stop hook

Target: claude

## Goal
Every Claude Code cloud sandbox registers a Stop hook in
`~/.claude/launcher-settings.json` that runs `~/.claude/stop-hook-git-check.sh`,
which exits 2 on any dirty tree. That hard-blocks `/runbook-run` on every single
turn, because a run deliberately leaves two markers uncommitted for the whole
duration of a step — the step heading at `[~]` in `.claude/runbooks/<name>.md`,
and that runbook's `Status: [RUNNING]` in `.claude/RUNBOOKS.md`. Those two
together are the skill's resume signal, and committing them would publish a
second concurrent run to the remote, so the block is unfixable from inside the
run. Ship a new `hook` feature, `hook:remote-stop-exemption`
(`event: SessionStart`), that patches the sandbox Stop hook in place at session
start with a narrow exemption for exactly that pattern, and dogfood it into this
repo's own `.claude/`.

## Acceptance criteria

**The feature**
- `hooks/remote-stop-exemption.sh` exists, with full frontmatter in a bash no-op
  heredoc after the shebang: `name: remote-stop-exemption`, `version: 0.1.0`,
  `type: hook`, `event: SessionStart`, `description:`. No `matcher:` — a
  `SessionStart` hook takes none.
- The remote gate is **positive-only**, evaluated by the shell: it engages when
  `CLAUDE_CODE_REMOTE` is `true` or `CLAUDE_CODE_REMOTE_ENVIRONMENT_TYPE` is
  non-empty, and is a silent no-op otherwise. `IS_SANDBOX` is not consulted.
- No `set -euo pipefail`; every path ends in an explicit `exit 0`. Nothing the
  hook does can fail the session.
- Stdout stays empty on success (a `SessionStart` hook's stdout becomes session
  context); progress and any failure go to stderr.
- Honours `CLAUDE_HOME` when resolving the target, per this repo's rule — no
  hardcoded `~/.claude`.
- No new dependencies: POSIX-ish bash with awk/sed/grep only.

**The patch it applies**
- Idempotent — re-running does not double-splice. Guard on the predicate
  function's name already being present in the target.
- Fails open — anchored on the target's exact existing text. If the anchor is
  not found byte-for-byte, the patch is skipped and
  `~/.claude/stop-hook-git-check.sh` is left untouched.
- Verified before installing — rendered to a temp file, gated on `bash -n`, and
  only then moved into place. A corrupted hook is never left behind.
- The splice **guards the uncommitted-changes block** rather than exiting the
  script: the untracked-files, unsigned-commit and unpushed-commit checks still
  run on every path, including when the exemption holds.
- The unsigned-commit block, with its SSH-signing and shallow-clone comments, is
  not rewritten or reordered.

**The exemption predicate**
- Holds only when every path in `git diff HEAD --name-only` is
  `.claude/RUNBOOKS.md` or `.claude/runbooks/*.md`.
- Holds only when every changed line is a marker flip: each `-`/`+` pair is
  byte-identical outside its bracketed token, so an edited step title or any
  prose change in a runbook body still trips the hook.
- Step-heading transitions exempt, and only these: `[ ]` → `[~]`, `[!]` → `[~]`,
  `[x]` → `[~]`.
- Index `Status:` transitions exempt, and only these: `[PENDING]` → `[RUNNING]`,
  `[FAILED]` → `[RUNNING]`, `[DONE]` → `[RUNNING]`.
- **No transition out of `[~]` or out of `[RUNNING]` is exempt.** A step reaching
  `[x]` or `[!]`, or an index reaching `[DONE]`, `[FAILED]` or `[PENDING]`, is a
  completed step that `/runbook-run` commits — it must still trip the hook.
- At most one heading moves to `[~]` across the whole diff; two is not an
  in-flight run.
- A `Steps: <done>/<total>` change is not exempt — it only moves on completion,
  which is committed.

**Verified**
- `bash -n` passes on `hooks/remote-stop-exemption.sh` and on the patched
  `~/.claude/stop-hook-git-check.sh`.
- Runbook case: a step heading flipped to `[~]` and that runbook's `Status:`
  flipped to `[RUNNING]`, patched hook run with `{"stop_hook_active":false}` on
  stdin → exits 0.
- Still fires: a prose edit to a runbook body (not a marker) → exits 2.
- Still fires: an unrelated dirty file → exits 2. An untracked file → exits 2.
- Still fires: a step heading flipped `[~]` → `[x]` → exits 2.
- Installer run twice produces a byte-identical target (`diff` is empty).

**Dogfooded and shipped**
- Installed copy at `.claude/hooks/remote-stop-exemption.sh`, registered under
  `SessionStart` in `.claude/settings.json` beside the existing `PreToolUse`
  entry; both committed, since hooks are local-only.
- `docs/reference.md` gains a `### hook:remote-stop-exemption` section in § 6
  alongside `hook:remote-session-protocol`; `README.md` § 6 gains its bullet;
  `.claude/context/features.md` gains its per-artifact entry;
  `.claude/context/INDEX.md` `Last updated` is refreshed.
- `VERSION` 1.37.0 → 1.38.0 (minor — new feature), with a matching
  `## 1.38.0 — <date>` CHANGELOG section. `./scripts/check-changelog.sh` is
  silent. `./scripts/check-routing.sh` is not required (not a pipeline feature,
  no `requires: skill:pipeline-engine`).

## Decisions
- **Shipped as a `hook` feature, not repo-local plumbing.** The problem hits any
  project running `/runbook-run` in a cloud sandbox, and this repo already has
  the exact precedent — `hooks/remote-session-protocol.sh` is a cloud-session
  workaround shipped as a hook, and its three properties (positive-only gate,
  nothing fatal, speaks only on failure) are the ones adopted here. The
  originating prompt targeted a `.claude/hooks/session-start.sh` that exists in a
  different project; chosko-llm has no such file, so a new `SessionStart` hook
  feature is the equivalent vehicle.
- **Named `remote-stop-exemption`** (user decision) — short enough to type at the
  console, and the `remote-` prefix pairs it with `remote-session-protocol`, the
  other cloud-session hook.
- **The splice guards the uncommitted block; it does not `exit 0` the script.**
  The starting snippet in the originating prompt ended with
  `runbook_in_flight_only && exit 0`, which would also skip the untracked,
  unsigned and unpushed checks — and since `git diff HEAD --name-only` never
  reports untracked files, a tree with the runbook markers *plus* a forgotten
  untracked file would have sailed through. Wrapping the uncommitted check in the
  negated predicate keeps the other three live, which is what "leave every other
  check alone" actually requires.
- **The marker and status vocabularies were widened against
  `skills/runbook-run/references/runbook-schema.md`, which the prompt named as
  the authority and told us to verify rather than trust.** Its starting regexes
  (`\[[ ~]\]`, `\[(PENDING|RUNNING)\]`) miss real in-flight cases: `SKILL.md`
  step 4 re-runs a `[!]` step and a `--only N` re-run of a `[x]` step, both
  flipping to `[~]`, and the index goes `[FAILED]` → `[RUNNING]` on a resume and
  `[DONE]` → `[RUNNING]` on a `--from`/`--only` re-run. Left as written the hook
  would still have blocked those sessions.
- **The predicate is directional: transitions *into* the in-flight state only**
  (user decision). Anything leaving `[~]` or `[RUNNING]` is a completed step,
  which `/runbook-run`'s commit cadence commits — those must keep tripping the
  hook rather than being waved through.
- **Paired-line comparison rather than a flat line-shape match.** Matching each
  changed line against a regex independently would exempt a diff that changed a
  step's *title* as well as its marker. Requiring the `-` and `+` lines to be
  identical outside the bracketed token closes that, and keeps a genuinely
  forgotten runbook edit — the loss this hook exists to prevent — blocking.
- **Rejected, not to be re-litigated:** editing
  `~/.claude/launcher-settings.json` (recreated per sandbox, and settings may be
  read once at startup); giving `/runbook-run` a gitignored sidecar for `[~]`
  (changes a global skill in every project and splits runbook state across two
  files); replacing `stop-hook-git-check.sh` wholesale (its unsigned-commit
  detection carries hard-won SSH-signing, `%G?` and shallow-clone detail with
  issue references); and an instruction-based fix in `CLAUDE.md` (the harness
  runs the script after the model stops — it never reads `CLAUDE.md`, and
  instructions cannot clear an exit-2 block).
- **Nothing is being removed.** An exhaustive search of this repo — every body
  under `commands/`, `skills/`, `claude-md/`, `hooks/`, `docs/`,
  `.claude/context/`, `.claude/domain/`, plus `CLAUDE.md`, `AGENTS.md`,
  `.gitignore`, `.claude/settings.json` and the git log on both branches — found
  no prior mitigation for this Stop hook. The earlier attempt referred to in the
  originating prompt was local to that other project (user confirmed).
- **Out of scope:** `/runbook-run` and everything under `skills/`, and
  `~/.claude/launcher-settings.json`.
