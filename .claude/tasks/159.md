# Task 159 — Add `--review-model` and `--review-effort` to `/task-implement`

Target: claude

## Goal
A reviewer spawned with no `model:` inherits the parent, so an Opus
implementer spawns an Opus reviewer for every task in a batch — the review
loop's dominant cost, and one the user cannot currently see or choose.
Feature `task-peer-review` adds two flags on `/task-implement` that resolve a
model and a read budget per task and pass them to the spawned reviewer. This
task is the producer side: parsing, resolution, and the changed spawn.

## Acceptance criteria
- ARGUMENT PARSING accepts `--review-model <name>|same|auto` (default `auto`)
  and `--review-effort shallow|standard|deep|same|auto` (default `auto`), and
  strips both.
- Either flag without `--review` stops the run, in the same shape `--rounds`
  already uses.
- An unrecognised `--review-effort` value stops the run and names the legal
  values. `--review-model` accepts any name verbatim — there is no local
  allow-list, per the protocol file.
- `review-rounds.md` resolves `auto` per task from the round's own diff and
  the task body already read in Step 1, using the tier table in
  `${CLAUDE_HOME:-$HOME/.claude}/skills/task-engine/references/review-budget.md`,
  and does not restate the table.
- The spawn prompt carries eight items instead of six: the existing six, plus
  the test-suite state (green under the project's resolved testing policy, or
  skip-tests so nothing ran) and the budget block — the latter omitted
  entirely when the effort resolved to `same`.
- The Agent call carries `model:` unless the model resolved to `same`, in
  which case it is omitted and the child inherits, as before.
- The resolved pair is reported once per task alongside the round summary, in
  the documented shape — e.g.
  `Review: sonnet / standard (auto — 210 lines, 4 files, code)`.
- `delegated-runs.md` names both flags as run-level resolved flags that ride
  the fixed-size hand-off, and states that `auto` resolves per task from each
  task's own diff so the parent passes two strings and measures nothing. The
  four-field return contract and the rule that the launcher never opens a task
  body are unchanged.
- `SKILL.md`'s description, usage block, examples and DO NOT list reflect the
  two flags; `version:` takes a minor bump.
- Root `VERSION` takes a minor bump and `CHANGELOG.md` gains a matching top
  section. The bullet says in so many words that `--review` now defaults to a
  Sonnet reviewer unless the diff is heavy, that this is a behaviour change to
  an existing flag, and that `--review-model same` restores the old
  behaviour. `./scripts/check-changelog.sh` exits zero.
- A run without `--review` is byte-for-byte the run it is today: no new
  parsing effects, no new prompt, no mention of any of this in its output.

## Decisions
- The tier and budget tables are cited, not copied. Task 158 makes
  `review-budget.md` the single authority and this task is one of its two
  consumers.
- Resolution stays per task rather than per run, which is what keeps a batch
  O(1) in the parent.
