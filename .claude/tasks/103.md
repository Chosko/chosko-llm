# Task 103 — Wire --local / --global into ls, add, rm, update, show

Target: claude

## Goal
Make the five feature-facing subcommands scope-aware so a user can list and
install chosko-llm features into a single repository's `.claude/` instead of
`~/.claude`. Task 102 added the `resolve_scope` primitive to `lib.sh`; this
task makes `ls`, `add`, `rm`, `update`, and `show` consume it, refuses the
statusline kind in local scope, and updates the user-facing docs and the
navigation context layer.

## Acceptance criteria
- Each of `scripts/cmd-ls.sh`, `cmd-add.sh`, `cmd-rm.sh`, `cmd-update.sh`,
  `cmd-show.sh` calls `resolve_scope "$@"` immediately after sourcing
  `lib.sh` and then re-sets its positional parameters from `SCOPE_ARGS`, so
  all existing flag parsing runs unchanged on the cleaned arguments.
- With no scope flag, every one of the five commands behaves byte-identically
  to today against `~/.claude`.
- `--local` from a directory containing `CLAUDE.md` targets `<cwd>/.claude`:
  - `add` creates `<cwd>/.claude/commands/` or `.../skills/` as needed and
    copies there.
  - `claude-md` artifacts inject their managed section into `<cwd>/CLAUDE.md`.
  - `rm`, `update`, `show`, and `ls` read and write that same local tree.
- `--local` from a directory without `CLAUDE.md` fails before any filesystem
  mutation, with the message task 102 defined.
- Statusline in local scope:
  - `add`, `update`, `rm` on a `statusline:<name>` spec (or a bare name that
    resolves to statusline) `die` with a message saying statusline scripts
    are global-only and to re-run without `--local`.
  - `add --all --local` and `update --all --local` skip the statusline pass
    silently (or with one info log) rather than failing the whole run.
  - `ls --local` omits the statusline pass entirely.
  - `show --local` on a statusline feature reports it as global-only.
- Every command that logs an install/removal/update result names the scope,
  so `Installed command 'foo' v0.1.0 -> …` is unambiguous about which home
  was written. `ls` prints the resolved home above or beside its table.
- Each command's `-h`/`--help` text documents `--local` / `--global`.
- `docs/cli-help.txt` documents the flag on `ls`, `show`, `add`, `rm`, and
  `update`, states the `CLAUDE.md`-at-cwd requirement, and notes that
  statusline is global-only.
- `README.md` gains a short section on per-repository installs.
- Context files `cmd-ls.md`, `cmd-add.md`, `cmd-rm.md`, `cmd-update.md`,
  `cmd-show.md` describe the flag in their **Public API** sections and the
  statusline exception where relevant; `INDEX.md`'s `Last updated` anchor is
  refreshed.
- Root `VERSION` bumped (minor — new CLI surface).

## Decisions
- **Only these five subcommands get the flag.** `uninstall`, `export`,
  `channel`, `upgrade`, and `task-impl` are untouched: `uninstall` and
  `upgrade` are about the managed clone and the proxy, not an install
  target, and adding a half-supported flag there is worse than omitting it.
  Local teardown is `rm --local`.
- **`--all` skips statusline locally instead of failing.** A bulk install is
  a "give me everything applicable here" request; aborting it over a kind
  that can never apply locally would be hostile. An explicit single-feature
  statusline request is a user error and does fail.
- **`cmd-rm.sh` and `cmd-show.sh` keep their own prefix parsers.** They
  resolve against what is installed rather than what is in the managed
  clone; scope only changes which home they inspect. Not consolidating them
  with `resolve_feature` here — that is a separate cleanup.
