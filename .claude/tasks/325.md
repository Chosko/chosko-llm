# Task 325 — Add the worktree protocol to task-engine and wire its consumers

Target: claude

## Goal
Write `skills/task-engine/references/worktree.md`, the single authority for
the worktree-isolation protocol of feature `worktree-isolation`, so that both
run-level orchestrators (`/task-implement`, `/runbook-run`) can execute a unit
of work in its own git worktree and land it onto the base branch through one
rule set. The file carries the whole protocol as the feature document
designs it: the unit and its two derived names, creation from the base tip
with the idempotent exclude line, the agent's integration, the
orchestrator's landing, the worktree as the in-flight signal, failure,
parking inside a worktree, and the sweep rule the pruners apply. Register it
in the engine's map, record the deviations in `commit.md` and `parking.md`,
and add `requires: skill:task-engine` to `/runbook-run` so the engine is
installed before either consumer can cite the file.

## Acceptance criteria
- `skills/task-engine/references/worktree.md` exists, opens with the
  "Authority for:" line the other reference files use, and states: the unit
  names `task-<N>` and `runbook-<id>-step-<n>`; the derived worktree path
  `.claude/worktrees/<unit>` and branch `wt/<unit>`, derived and never
  recorded; creation from the current base tip immediately before the spawn,
  with `.claude/worktrees/` added to `.git/info/exclude` idempotently; the
  agent's integration steps — commit on `wt/<unit>`, rebase onto the local
  base tip, resolve a conflict by re-applying the unit's own intent (a
  version counter bumped again, a newest-first log entry added again, a
  status flip re-made) and never by keeping one side whole, re-verify when
  the base moved, return naming the tip rebased onto, never push and never
  leave the worktree; the rule that an invoked skill's pull-at-start,
  re-sync and push are skipped as under `--no-push` while its commits are
  made as usual, said once; the orchestrator's landing — fast-forward only,
  one rebase-again message to the same agent when the base moved, push per
  the commit-and-push protocol unless NO_PUSH, worktree removal and safe
  branch delete whose refusal fails the unit; the two invariants (one writer
  of the base; base tree clean at every landing, bookkeeping committed first
  when a unit touched the same files); the worktree as the in-flight signal
  and the skip-while-present rule with its one-line report; failure keeping
  the worktree and reporting its path; the park and unpark sequences read in
  the worktree unchanged; and the sweep rule (a `wt/<unit>` whose unit is
  `[DONE]`/`[SKIP]` or `[x]` may be removed, an unfinished one never).
- The file's load discipline is stated at its top as `parking.md`'s is: read
  by `/task-implement` and `/runbook-run` only when the run's parallelism is
  above one; a sequential run never opens it.
- The file's per-consumer notes name `/task-implement`, `/runbook-run`,
  `/task-clean` and `/runbook-clean` with what each does differently, in the
  shape the other reference files use.
- `skills/task-engine/SKILL.md`'s map gains one row for `references/worktree.md`
  and the skill's `version:` is bumped.
- `commit.md` records, in its one-commit-per-unit section and its push
  protocol, the two deviations the feature document names: rebasing the
  private `wt/<unit>` branch is this protocol's and not a rewrite of anyone's
  history; the fast-forward landing by the orchestrator is the merge, and the
  push after it follows the protocol's re-sync and push steps. `parking.md`
  states that the park and unpark sequences run in whatever tree the task is
  running in, the base of its bookkeeping commit being `wt/<unit>` inside a
  worktree, landed like any other commit.
- `skills/runbook-run/SKILL.md`'s frontmatter `requires:` line adds
  `skill:task-engine`, its `version:` is bumped, and its body's dependency
  list names the engine for the one file it reads — nothing else in the
  runbook-run body changes in this task.
- `./scripts/check-home-paths.sh` and `./scripts/check-routing.sh` pass;
  root `VERSION` is bumped (minor) with a matching `CHANGELOG.md` section,
  and `./scripts/check-changelog.sh` passes.
- No orchestrator body reads the file yet: `/task-implement`'s and
  `/runbook-run`'s execution rules are unchanged by this task.

## Decisions
- The reference is written before either orchestrator reads it: the two
  parallel features (`parallel-task-runs`, `parallel-runbooks`) are planned
  separately and both cite this file by path, so it must exist first. No
  orchestrator behaviour changes here.
- `/runbook-run`'s `requires: skill:task-engine` lands in this task, not in
  `parallel-runbooks`: it is the consumer wiring the feature document
  assigns to `worktree-isolation`, and `cmd-add` must install the engine
  before the orchestrator from the first version that cites it.
- Settled here, without conflict with the feature document: its first open
  question (how an agent skips an invoked skill's pull and push) is settled
  by the one sentence the protocol states — the remote is the orchestrator's,
  the agent skips those steps as a run under `--no-push` does and says so
  once. Whether a given skill honours that from the conversation alone is
  left to the orchestrator features, which write the prompt line.
