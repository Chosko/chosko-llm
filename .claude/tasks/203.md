# Task 203 — Flip `/product-design`, `/product-roadmap` and `/production-plan` to commit by default

Target: claude

## Goal
The other three skills in the feature `authoring-commit-default` take the
same inversion task 202 applies to `/architect`: `COMMIT` becomes true
unless `--no-commit` is passed. The three are mechanically identical to each
other, so they are done in one pass — that is what keeps their
`COMMIT AND PUSH` sections verifiably the same afterwards.

The design is `.claude/domain/features/authoring-commit-default.md`; read it
first. The flag shape to copy is
`skills/task-engine/references/commit.md` § *The flags*.

## Acceptance criteria
- In each of `skills/product-design/SKILL.md`,
  `skills/product-roadmap/SKILL.md` and `skills/production-plan/SKILL.md`:
  - `COMMIT` is true unless `--no-commit` was passed, and `--no-commit`
    implies `NO_PUSH`.
  - `--commit` is still accepted as a silent no-op, and `--commit` with
    `--no-commit` still stops the run with
    `--commit and --no-commit cannot be combined. Pick one.`
  - Pull-at-start runs on every run that is not `--no-commit`.
  - The `COMMIT AND PUSH` section header and opening sentence no longer say
    "only when `--commit` was passed".
  - The closing report's "nothing was committed" reminder fires under
    `--no-commit`.
  - The `DO NOT` git bullet reads as "run no git/VCS command when
    `--no-commit` was passed", with the rest of the bullet unchanged.
  - The frontmatter `description` states the new default and names
    `--no-commit`.
- `skills/product-design/council-gate.md`'s "never staged by `--commit`"
  becomes "never staged" — same reasoning as `/architect`'s copy in task
  202, and the two files must stay in step per
  `docs/authoring-guide.md`.
- `skills/product-design/resuming.md` stops saying the skill leaves
  everything uncommitted by default.
- Frontmatter `version:` bumps: product-design 0.6.1 → 0.7.0,
  product-roadmap 0.2.1 → 0.3.0, production-plan 0.1.1 → 0.2.0.
- Root `VERSION` is bumped with a matching new top section in
  `CHANGELOG.md` dated the day of the change; `./scripts/check-changelog.sh`
  is silent.
- The three `COMMIT AND PUSH` sections, and `/architect`'s from task 202,
  differ only where they already differed before this feature.
- No change to any write set, to `WRITTEN` membership, or to the
  commit-and-push protocol itself.

## Decisions
- **`--commit` is retained as an accepted no-op** and **pull-at-start stays
  tied to `COMMIT`** — same two user decisions as task 202 (2026-09-12),
  applied identically here.
- **`/product-design` now commits `.claude/domain/design-process.md` on
  every default run.** Its resume state becomes shareable across machines
  and terminals instead of living in one working tree. This is a behaviour
  change nobody asked for and it reads as a gain; it is recorded in the
  feature document so a future reader does not have to rediscover why the
  file started appearing in commits. Do not suppress it or carve it out of
  `WRITTEN`.
- **The three skills keep their own commit blocks** rather than being routed
  through a shared authority (user decision, 2026-09-12). Do not refactor
  toward one in this task.
