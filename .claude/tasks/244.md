# Task 244 — Make `/runbook-run` quiet between steps and exhaustive in its closing report

Target: claude

## Goal
A multi-step `/runbook-run` today narrates spawn, wait, result classification
and commit for every step, and those fragments are hard to read back once the
run is over. A run invoked with the extra instruction "don't write much in
chat in between, make a short but exhaustive report at the end of the run"
was far easier to follow. Make that the default with the smallest edit that
does it: the body already knows how to report; it only needs to be told to
hold the narration and to make the closing report the record of the run.

## Acceptance criteria
- `skills/runbook-run/SKILL.md` gains one short `CHAT OUTPUT` paragraph
  (roughly six to ten lines, no sub-sections): between steps the orchestrator
  prints one line per step at its end — `Step 4 done (abc1234). Starting
  step 5.`, or the failure line — plus relayed `QUESTIONS FOR USER` blocks and
  spawn-relay lines verbatim, exactly as today; it does not narrate spawning,
  waiting, result classification, `Done:` writing or committing. The same
  rule holds under `--inline`.
- The existing closing-report sentences — step 8's completion branch, the
  `--to` / `--only` / `--steps` bound paragraphs and `On failure` — each gain
  one qualifier and no new section: the report is short but exhaustive, one
  entry per step drawn from the `Done:` line and the step report already in
  hand (outcome, commit sha and diffstat, what changed in one line, any
  decision or wrong premise the agent flagged, questions relayed and the
  answers given), followed by what remains outside the range. The
  orchestrator opens no file it does not open today.
- `references/subagent-contract.md` is untouched; `CLOSING THE RUN` and the
  `/follow-ups` call after the report are untouched.
- `docs/reference.md` § `/runbook-run` gains one sentence on the quiet default
  and the closing report; `.claude/domain/features/runbook-suite.md` gains
  the one point granted below; `.claude/context/features.md`'s `runbook-run`
  entry gains one line.
- `skills/runbook-run/SKILL.md` `version:` patch bump; root `VERSION` patch
  bump; `CHANGELOG.md` entry; `./scripts/check-changelog.sh`,
  `./scripts/check-home-paths.sh` and `./scripts/check-routing.sh` silent.

## Decisions
- **Smallest edit.** The behaviour was obtained in the field by one sentence
  in the prompt, so the body needs a paragraph, not a section. No new fixed
  report template.
- **No opt-out flag.** The closing report is the record; a user who wants
  live detail has the per-step commits.
- **Relayed questions are never suppressed.** A run that needs an answer
  asks for it immediately; quiet applies to narration only.
- **Per step, not per file.** File lists are in the commits.
- **`--review` is not a `/runbook-run` flag** and this task adds none; the
  run that motivated this passed it and it was ignored.
- **Editing `.claude/domain/features/runbook-suite.md` is explicitly
  authorised for this task (user decision, 2026-09-20), for the 1
  reconciliation below and for nothing else. Do not ask for permission at
  implementation time — the permission is already granted.** That document
  is normally `/architect`'s, and anything beyond this point still belongs
  to `/architect`. Point: the run's chat contract (quiet between steps) and
  the closing report as the record of the run are part of the runbook-suite
  design. A factual reconciliation with shipped behaviour, not a redesign;
  if it turns out to need a design decision, stop and say so.
