# Task 96 — Spec the nested context-layer layout in the domain layer

Target: claude

## Goal
Tasks 97–101 all implement against one nested-layout contract; without
writing it down first, three separate command bodies would each invent a
slightly different one. Extend `.claude/domain/context-workflow.md` with the
authoritative spec for the nested (router + leaf) context layer, alongside
the existing flat description. No command is changed by this task.

## Acceptance criteria
- A new section documents the **`Layout:` policy marker**: a
  `Layout: flat` or `Layout: nested` line in the header of
  `.claude/context/INDEX.md`, directly under the title. Detection is
  reading that line — never inference from file contents. A missing marker
  means flat, so every pre-existing layer keeps working untouched.
- The **router INDEX schema** is specified: title, `Layout: nested`, the
  canonical-docs block, a Units table mapping each unit to its
  `./<unit>/INDEX.md`, and the Conventions block. The router carries **no**
  `Last updated` field at all — stated explicitly, with the reason: leaves
  are the sole date authority, so no derived value exists to compute,
  stage, or mistake for a scan anchor.
- The **leaf INDEX schema** is specified: title, its own
  `Last updated: YYYY-MM-DD`, and a Files table listing the context files
  that unit owns. Leaf dates drift apart by design.
- **Ownership** is stated: every context file belongs to exactly one leaf.
  Adding or removing a context file edits that leaf's INDEX; the router
  changes only when a whole unit is added or retired.
- **Depth is capped at two levels** (root router + one rank of leaves), and
  the cap is recorded as a deliberate current limit, not an oversight.
- **`unit=<name>` addressing** is specified as the way to scope an
  operation to one leaf, and as the disambiguator when the same context
  filename exists in two units.
- The six-section per-context-file schema, the 150-line cap, and the
  10-line snippet cap are unchanged and apply identically in both layouts.
- The existing flat description stays accurate; nothing about flat
  behaviour is redefined.
- Root `VERSION` bumped patch (docs-only).

## Decisions
- **Marker in `.claude/context/INDEX.md`, not CLAUDE.md.** Detection then
  costs zero extra reads (the command already opens INDEX.md first), the
  marker travels with the layer it describes, and there is one source of
  truth to flip during conversion.
- **Router carries no date.** The alternative — router date as the minimum
  across leaves — is correct but needs re-derivation logic, a non-obvious
  documented semantic, and extra staging rules; having no date removes the
  failure mode instead of managing it.
- **Two levels only.** Nested routers are wanted eventually but multiply
  the work in every consumer; the cap is recorded so a later task can lift
  it knowingly.
