# Task 174 — Update documentation for feature `backlog-ordering`

Target: claude

## Goal
Tasks 169 and 173 ship feature `backlog-ordering`: selection now honours
`Preconditions:`, `/task-add` gained placement flags and a `--single`
attachment path, and `/runbook-create --append` gained positional insertion.
The documentation describing those areas still says tasks are appended, steps
land at the foot, and `/production-status` names the lowest-numbered task, so it
is now out of date and needs to reflect the shipped behaviour.

## Acceptance criteria
- `README.md`'s `/task-add` coverage names `--before` / `--after` and
  `feature=<slug> --single`, and its `/task-implement` line says `next` follows
  `Preconditions:`.
- `docs/reference.md` § `/task-add` documents both placement flags, their mutual
  exclusion, `--single` and its write-back reminder, and the orphan question;
  its `/production-status` and `/runbook-create` entries reflect the Next-column
  rule and the positional append.
- `.claude/domain/task-workflow.md` records that `Preconditions:` is
  load-bearing for `next` and `all`, that `all` is `next` repeated, that
  `/task-add` can insert, and what `--single` does and does not change.
- `.claude/domain/product-workflow.md`'s Next-field paragraph no longer says
  "`<N>` the lowest-numbered one".
- `.claude/domain/features/runbook-suite.md` is reconciled on exactly these 3
  points — editing it is authorised for this task, see Decisions:
  1. § *Append rules*, bullet 1 — the id continues from the last step, the
     position need not.
  2. § *Append rules* bullet 4 and the ownership-by-line follow-on sentence —
     the surviving invariant is "no existing step is edited", not "material is
     added only after the last step".
  3. § *Interfaces and contracts* — the `--append <name|id>` line gains
     `[--before <step> | --after <step>]`.
  Nothing else in the document changes.
- `.claude/domain/features/backlog-ordering.md` is reconciled on exactly these
  2 points — editing it is authorised for this task, see Decisions:
  1. § *Open questions*, bullet 2 — settled: `/task-implement`'s existing
     BETWEEN TASKS re-read of `TASKS.md` is the per-spawn re-evaluation point,
     and no new read was introduced.
  2. § *Architecture → Selection honours preconditions* — `all` is resolved
     once up front by simulating the repeated `next`, which yields the same
     list while preserving the single resolution report and the delegation
     count.
  Nothing else in the document changes.
- `.claude/context/features.md`'s rows for `commands/task-add.md`,
  `commands/production-status.md`, `commands/runbook-create.md`,
  `skills/task-engine/`, `skills/task-implement/` and `skills/runbook-run/`
  describe the shipped behaviour.
- `.claude/context/INDEX.md`'s `Last updated:` anchor is refreshed.
- Root `VERSION` is **not** bumped and `CHANGELOG.md` gets **no** entry; the
  change is confined to `README.md`, `docs/`, `.claude/domain/` and
  `.claude/context/`, which `CLAUDE.md` § Versioning exempts.
  `./scripts/check-changelog.sh` still exits zero.

## Decisions
- **Editing `.claude/domain/features/runbook-suite.md` is explicitly authorised
  for this task (user decision, 2026-09-09), for the 3 reconciliations listed
  above and for nothing else. Do not ask for permission at implementation time
  — the permission is already granted.** That document is normally
  `/architect`'s, and anything beyond those points still belongs to
  `/architect`. These are factual reconciliations with shipped behaviour, not
  redesigns; if one turns out to need a design decision rather than a wording
  fix, stop and say so instead of deciding it here.
- **Editing `.claude/domain/features/backlog-ordering.md` is explicitly
  authorised for this task (user decision, 2026-09-09), for the 2
  reconciliations listed above and for nothing else. Do not ask for permission
  at implementation time — the permission is already granted.** That document is
  normally `/architect`'s, and anything beyond those points still belongs to
  `/architect`. These are factual reconciliations with shipped behaviour, not
  redesigns; if one turns out to need a design decision rather than a wording
  fix, stop and say so instead of deciding it here.
- No `VERSION` bump and no `CHANGELOG` entry — the boundary in `CLAUDE.md`
  § Versioning puts this task entirely on the documentation side, and a bump
  for a change no user receives corrupts the version `install.sh` reports.
- `.claude/domain/features/plan-readout.md` is deliberately untouched: it
  states nothing about how the Next column picks `<N>`, so there is nothing to
  reconcile.
