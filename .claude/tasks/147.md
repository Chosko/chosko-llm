# Task 147 — Add the check-changelog.sh authoring guard

Target: claude

## Goal

The rule task 146 wrote into `CLAUDE.md` — a `VERSION` bump without a matching
`CHANGELOG.md` section is an incomplete change — is only as good as the thing that
notices when it is broken. Add `scripts/check-changelog.sh`, the third part of the
`version-changelog` feature (`.claude/domain/features/version-changelog.md` § 3): a
repo-local, authoring-time guard over four cheap invariants, run by whoever bumps
`VERSION`, in the style `scripts/check-task-parity.sh` established.

## Acceptance criteria

- `scripts/check-changelog.sh` exists, is executable, starts with
  `set -euo pipefail`, sources `scripts/lib.sh`, and resolves the repo root from
  its own location (`SCRIPT_DIR/..`) rather than hardcoding a path.
- It takes no arguments, reads only `VERSION` and `CHANGELOG.md`, writes nothing,
  and never edits the changelog to fix what it found.
- It checks exactly four invariants and `die`s on the **first** one violated,
  naming it:
  1. `CHANGELOG.md` exists and has at least one section.
  2. The **top** section's version token equals the trimmed contents of `VERSION`.
  3. Version headers are strictly descending semver, with no duplicates.
  4. The top section has at least one bullet.
- On success it exits 0 **in silence** — no success line.
- Running it against the tree task 146 left exits 0 with no output. Temporarily
  bumping `VERSION` without adding a section makes it exit non-zero naming
  invariant 2; reverting restores exit 0.
- **It is not a subcommand.** `bin/chosko-llm` is not modified; `chosko-llm
  check-changelog` still exits with the unknown-subcommand message, because the
  proxy dispatches only its known subcommand list.
- **It is standalone with respect to `scripts/check-task-parity.sh`.** It does not
  reference it, source it, or share code with it. Deleting `check-task-parity.sh`
  (task 118) must leave this script working, and landing this script must leave
  that one working — the two features can land in either order.
- No new dependency: bash, awk, sed and grep only. No yq, no jq, no python.
- **Not a consumer-side check.** `install.sh` and `scripts/cmd-upgrade.sh` are not
  modified, and no git hook and no CI config is added.
- `docs/authoring-guide.md` gains a section documenting the guard: the invocation
  (`./scripts/check-changelog.sh`), when to run it (whenever you bump `VERSION`),
  the four invariants, and what it deliberately does not prove — that the bullets
  are *true*.
- `CHANGELOG.md` gains a section for this task's own bump, per the rule task 146
  made live.
- Root `VERSION` takes a patch bump.

## Decisions

- **Authoring-time, not consumer-side.** A check in `install.sh` or
  `cmd-upgrade.sh` fires on the user's machine, long after the bump, at someone who
  cannot fix it — noise pointed at the wrong person. Consumer-side detection exists
  for free anyway: a missing header for the newly-pulled version makes task 148's
  readout say so in one line. The guard belongs where the mistake happens.
- **Run by hand, documented in the authoring guide** — the way this repo has
  historically run its guards. There is no CI and no installed git hook to hang it
  on, and adding either is out of scope.
- **Standalone from `check-task-parity.sh`, deliberately.** It is *modelled on* the
  pattern that script established — small, repo-local, under `scripts/`, with its
  own authoring-guide section — but shares no code with it, because task 118 deletes
  it and the two features must be able to land in either order.
- **Silent on success**, departing from `check-task-parity.sh`'s closing
  `log_success` line. The feature document specifies silence; a guard meant to be
  run on every bump should say nothing when there is nothing to say.
- **Invariant 2 is the one that matters.** The other three are cheap structural
  checks that keep the file parseable for task 148's readout; invariant 2 is the one
  that catches the actual mistake.
- **Patch bump**, matching the precedent set when `check-task-parity.sh` was added
  (commit `7df4341`, 0.7.0 → 0.7.1): a repo-local authoring guard changes nothing a
  user receives.
