# Task 259 — Spawned step agents answer the runbook-WIP dirty-tree prompt themselves

Target: claude

## Goal
First task of feature `unattended-parking`. `/runbook-run` marks the step
`[~]` and the index `[RUNNING]` before spawning, uncommitted by design, so a
spawned step's `/task-implement` meets a dirty tree at pre-flight and — bound
by OPERATING RULES never to answer a question itself — ends its turn under
`QUESTIONS FOR USER` on every step. The inline contract already carries the
answer for the same prompt in the same session; port it into the spawned
OPERATING RULES, unconditionally, so a step agent answers `proceed` when the
only dirty paths are the runbook body and `.claude/RUNBOOKS.md`, and puts the
prompt to the user unchanged when anything else is dirty.

## Acceptance criteria
- `skills/runbook-run/references/subagent-contract.md`'s pasted OPERATING
  RULES block gains one rule, in the inline contract's register: when a
  step command's dirty-tree prompt (`Working tree has uncommitted changes.
  Choose:`) lists only `<FILE>` and `.claude/RUNBOOKS.md`, answer `1` /
  `proceed`, print the one line `dirty-tree prompt answered proceed — only
  runbook WIP is dirty`, and continue; never `include`; anything else dirty
  reaches the user through `QUESTIONS FOR USER` as today.
- The rule is not conditional on any policy — it holds in every spawned step.
- The contract's *Why each rule is in there* section explains it in one
  bullet: the orchestrator's own `[~]` / `[RUNNING]` writes are the dirty
  paths, `proceed` never `include` because COMMIT CADENCE forbids the markers
  riding in the step's commit.
- `inline-contract.md`'s matching rule and its rationale bullet are reworded
  only where they claimed the rule was inline-only; the rule text itself stays
  identical in both files.
- `skills/runbook-run/SKILL.md` COMMIT CADENCE's closing sentence ("Under
  `--inline` the same condition answers one more prompt…") is updated so it
  no longer presents the self-answer as inline-only.
- `runbook-run`'s frontmatter `version:` bumped (patch); root `VERSION` bumped
  (patch) with a matching `CHANGELOG.md` section; `./scripts/check-changelog.sh`
  and `./scripts/check-home-paths.sh` pass.

## Decisions
- Unconditional rather than gated on the execution policy: the prompt fires
  under both policies and its answer is known under both.
