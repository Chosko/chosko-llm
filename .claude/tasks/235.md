# Task 235 — Surface a runbook's archived step ids in `/runbook-describe`

Target: claude

## Goal
Task 233 gave `/runbook-prune` the power to remove `[x]` steps from a runbook
body and keep their ids on the header's `Archive:` line, where an id **counts as
`[x]` everywhere a marker is read**. `/runbook-describe` was never taught about
that line. It extracts `Created:`, `Source:` and `Model:` from the header and
nothing else, so a pruned runbook describes as though the archived steps never
existed: the step list looks complete when it is partial, a surviving
`deps: 1, 2` points at ids the reader cannot see, and the closing by-marker
count disagrees with both the index's `Steps:` and the heading line describe
itself printed a moment earlier. Teach the command to extract and render the
`Archive:` line and to count archived ids toward its closing totals, so the one
command whose job is *what are this runbook's steps* stops lying about a runbook
someone pruned. Raised as an ADVISORY finding in task 233's review.

## Acceptance criteria
- `commands/runbook-describe.md` § THE READ BUDGET adds `Archive:` to the header
  fields pulled from the body. It stays one targeted Grep pass over one body —
  no extra file, no extra runbook, no full Read, and the never-open rules
  (`.claude/tasks/` archive included, `.claude/domain/`, `.claude/context/`,
  another body, prompt text) are unchanged.
- The rendered shape in § WORKFLOW gains **one optional line**, directly under
  the `Created:`/`Source:`/`Model:` header line, printed **only** when the body
  carries an `Archive:` line — the ids as the body holds them, ascending, with a
  short parenthetical saying they were pruned and count as done. Something of
  this shape:

  ```
  3. implement-ecc-import   [PENDING]   3/5   —   Land the ECC import architecture
     Created: 2026-09-01   Source: /architect ecc-import   Model: sonnet
     Archived: 1, 2, 3   (pruned; counted as done)

     [!] 4. Wire cmd-rm's dependents guard            deps: 1
            done: FAILED — <first clause of the reason>
     [ ] 6. Update the authoring guide                deps: 1, 2

     5 steps: 3 done, 1 failed, 1 pending.
  ```

- The closing by-marker count **counts every archived id as done and as
  present** — the schema's § *An archived id counts as `[x]`* and the index's
  `Steps:` accounting, one level down — so describe's own total matches the
  heading line it printed from the index. Only the non-zero counts are named, as
  before.
- **A runbook that has never been pruned renders exactly as it does today**, line
  for line: no `Archived:` line, no changed count, no empty placeholder. The
  `Archive:` line is never written empty and is absent on most runbooks, so this
  is the common case and it must be a no-op.
- A body whose every step has been pruned renders its heading, its header line,
  the `Archived:` line and the count (`7 steps: 7 done.`) — it is a legal body,
  not a malformed one, and it is neither reported as an error nor rendered as an
  empty step list with no explanation.
- A surviving `Depends on:` naming an archived id is still printed **verbatim**
  in `deps:`. Describe does not annotate it, does not mark it satisfied, and does
  not cross-reference it against `Archived:`; the two lines sitting in one render
  is the whole mechanism.
- `Last step number:` is **not** printed, and § DO NOT gains a bullet saying so
  beside the existing `Sequencing:` / `Companion:` / re-propose one, so the
  omission reads as deliberate rather than as the same oversight being fixed
  here.
- Describe is still read-only. Add whatever wording § DO NOT needs to make clear
  that deriving the count from the body's steps **and its `Archive:` line** is
  derivation, not reconciliation: a `Steps:` count in the index that disagrees
  with the derived one is still reported in prose and never corrected, and no
  file is written, no shell is run.
- The command's frontmatter `description:` is updated to name the archived-ids
  line — it enumerates the render shape, so leaving it stale reproduces this bug
  in the place a reader looks first — and its `version:` is minor-bumped
  (`0.2.1` → `0.3.0`; a new capability inside the same task, per
  `docs/authoring-guide.md` § Versioning).
- `docs/reference.md`'s `/runbook-describe` bullet names the archived-ids line
  and the count that includes them.
- `.claude/context/features.md`'s `commands/runbook-describe.md` bullet is
  updated in both halves it already carries — the render shape and the **Read
  budget** enumeration — and `.claude/context/INDEX.md`'s `Last updated:` anchor
  is moved.
- `.claude/domain/features/runbook-suite.md` is reconciled on exactly the three
  points listed under Decisions, and nothing else in it changes.
- Root `VERSION` takes a **patch** bump (a fix to an existing command, not a new
  feature — `CLAUDE.md` § Versioning), with a matching top `CHANGELOG.md`
  section; `./scripts/check-changelog.sh` runs silent. `./scripts/check-routing.sh`
  is not in scope — no pipeline feature is added, renamed, removed or re-kinded
  and `requires:` is untouched.

## Decisions
- **Editing `.claude/domain/features/runbook-suite.md` is explicitly authorised
  for this task (user decision, 2026-09-17), for the 3 reconciliations listed
  below and for nothing else. Do not ask for permission at implementation time —
  the permission is already granted.** That document is normally `/architect`'s,
  and anything beyond those points still belongs to `/architect`. These are
  factual reconciliations with shipped behaviour, not redesigns; if one turns out
  to need a design decision rather than a wording fix, stop and say so instead of
  deciding it here. The three points, all inside its `### /runbook-describe`
  section:
  1. The rendered shape shown there carries no archived-ids line and must gain
     one, with the note that it is printed only on a pruned runbook.
  2. The read-budget paragraph enumerates the extracted header fields as
     `Created:`, `Source:` and `Model:` and must add `Archive:`.
  3. The closing sentence — "corrects no status, count or marker however wrong
     the index looks" — must distinguish deriving the count from the body's steps
     *and* its `Archive:` line (allowed, and now required) from correcting the
     index (still forbidden).
- **The archived ids go in the header region, not beside the closing count.**
  `Archive:` is a header field in the schema, and a reader who meets it after the
  step list has already read that list as complete — which is the exact failure
  this task exists to remove. Printing it directly under the `Created:` line
  means the step list is never read as the whole runbook.
- **`Last step number:` is deliberately not printed.** The evidence decides it
  rather than the user: describe's stated job is *what are this runbook's steps,
  and how did the finished ones go*, and the counter answers neither — it is
  bookkeeping for `/runbook-create --append`, the only thing that assigns from
  it. `Archive:` is the opposite case: without it the render is wrong, not merely
  less informative. So task 232's field is closed out with a DO NOT rather than a
  line of output, which is also what keeps the header region from drifting back
  toward printing everything.
- **No `--full` and no flag of any kind is added.** The pair with
  `/runbook-list` is unchanged, and a reader who wants the archived steps'
  `Done:` lines opens the commits, which is where `/runbook-prune` deliberately
  left them.
- **`README.md` is out of scope.** Its one mention of `/runbook-describe` names
  the command in a list and makes no claim about its render shape, so it is not
  stale. Left out of `Files:` on purpose, not forgotten.
