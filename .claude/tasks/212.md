# Task 212 — Make /runbook-create write `<id>-<name>.md`, refuse leading-numeric names, and migrate the target of `--append`

Target: claude

## Goal
Part of feature `runbook-id-filenames` (.claude/domain/features/runbook-id-filenames.md).
`/runbook-create` is the only writer of new bodies and the only assigner of ids, so it
writes the prefixed name from the start, enforces the naming restriction that keeps the
schema's resolution rule unambiguous, and — on `--append` — is the second of the only
two commands that migrate a legacy body. All of it cites `runbook-schema.md` and
`body-migration.md` as task 211 left them, and restates neither.

## Acceptance criteria
- New runbook: the id is taken from `Last runbook number: + 1` **before** the body is
  written; the body is written at `.claude/runbooks/<id>-<name>.md`; the counter
  advance and the block append still land in one index write; the block's `File:`
  holds the prefixed path.
- The confirmation plan shows the prefixed `File:` (~line 353); the header comment
  (~line 13), staging (~lines 503–507) and the never-write list (~line 570) name the
  `File:` path, not `<name>.md`.
- A new name whose first kebab segment is all digits (e.g. `2026-migration`) is refused
  before any file is written, with one suggested alternative, beside the
  name-collision rule and citing the schema — both for a name the user typed and one
  proposed at the gate from a free-form description.
- PHASE 1 form 1 (`--append <id|name|id-name>`) resolves by the schema's three-form
  rule; its errors follow the schema (unknown lists runbooks, mismatched compound names
  the id's runbook, ambiguity names both).
- Once PHASE 1 has resolved an `--append` target, and before any material is gathered,
  the migration check runs; `body-migration.md` is read only on a hit. A `[RUNNING]`
  target is never migrated and is appended to at its current `File:` path. A migrating
  append stages both paths in its one commit; a taken target path stops the run with
  nothing written.
- Form 2 (append to the running runbook) uses the `File:` path and never migrates,
  since that runbook is `[RUNNING]`.
- `version:` gets the next minor bump; root `VERSION` gets a minor bump with a matching
  `CHANGELOG.md` section; `./scripts/check-changelog.sh` passes.
