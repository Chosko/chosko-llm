# Task 327 — Show in-flight units from the worktree list in the statusline and the dashboard

Target: claude

## Goal
Under the `worktree-isolation` feature a unit in flight is a worktree, and
its `[IN PROGRESS]` flip lives in that worktree's copy of `TASKS.md`, so the
base copy both progress surfaces read never shows it. Give the
`pipeline-statusline` renderer and the dashboard generator one more input —
the output of `git worktree list --porcelain` — from which every
`wt/task-<N>` branch names a task in flight and every
`wt/runbook-<id>-step-<n>` branch a step in flight. A task so named counts
and renders exactly as an `[IN PROGRESS]` one does today; a step so named
exactly as a `[~]` one does. Silent when there are no worktrees, so a
sequential run renders byte-for-byte as before.

## Acceptance criteria
- `statusline/pipeline-statusline.sh` reads the worktree list once per
  render and treats a task whose `wt/task-<N>` worktree exists as
  `[IN PROGRESS]` in the progress counts and in the lines-3+ list, within
  the existing scope rule; a task both `[IN PROGRESS]` on disk and in a
  worktree is counted once.
- `skills/pipeline-dashboard/scripts/generate.sh` does the same for the
  page data and the text snapshot: an in-flight task renders as `in progress`,
  an in-flight step as the running marker, each counted once.
- With no worktree present, both outputs are identical to today's for the
  same inputs.
- The probe follows a worktree's `gitdir:` as the statusline already does
  for `.git/HEAD`, so a render from inside a worktree still finds the list.
- Bash and awk only, no new dependency; a missing or failing `git` leaves
  both surfaces rendering as they do today.
- Both features' `version:` are bumped; root `VERSION` is bumped (patch)
  with a matching `CHANGELOG.md` section; `./scripts/check-changelog.sh`
  passes.

## Decisions
- The worktree list is read rather than the worktree's `TASKS.md`: the
  feature document makes the worktree's existence the in-flight signal, and
  reading a file inside a worktree would couple the renderers to a layout
  the protocol does not promise.
