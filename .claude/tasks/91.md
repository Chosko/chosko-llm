# Task 91 — Document that docs/ is not deployed and must not be a runtime source for authored features

Target: claude

## Goal
Investigation during tasks 83-90 confirmed: scripts/cmd-add.sh only installs
commands/, skills/, claude-md/, and statusline/ into ~/.claude/ — docs/ is
never part of the deployed surface, and a deployed command's working
directory is the user's own project, not this repo. Every existing
"per docs/authoring-guide.md's ..." citation in shipped commands/skills
turned out to be decorative (the full procedure is always duplicated
inline), so nothing is broken today — but nothing currently states this
constraint explicitly, so a future author could easily write a new
command/skill that treats docs/authoring-guide.md (or any other docs/ file)
as something the executing agent reads at runtime, reintroducing a real
dangling reference next time. Make the constraint explicit where authors
will see it.

## Acceptance criteria
- docs/authoring-guide.md gains a clearly-placed note (near the top, or in
  the frontmatter-schema/commit-and-push sections where docs/
  self-references already occur) stating: docs/ is authoring-time-only
  content, never installed to ~/.claude/ by chosko-llm add/update, and a
  command or skill body must NEVER instruct the executing agent to read a
  docs/ path at runtime — any procedural content a command/skill needs
  must be stated inline in that command/skill's own file (or in a
  claude-md feature, which does get merged into the user's global
  CLAUDE.md and is therefore actually reachable).
- The note explains what CAN safely reference docs/ paths: authoring-time
  guidance for humans/Claude editing this repo (e.g. this guide itself,
  README.md, a task's Hints when the task is about improving this repo) —
  contrasted with what CANNOT: any instruction inside a shipped
  commands/*.md or skills/*/SKILL.md body telling the agent executing that
  command/skill (in a deployed, arbitrary target project) to consult a
  docs/ file.
- CLAUDE.md's own "Authoritative references" section (which already points
  at docs/authoring-guide.md) gets a one-line cross-reference to this new
  constraint, so it's discoverable from the entry point Claude reads first.
- The existing "Common mistakes" section in docs/authoring-guide.md gains
  one bullet for this failure mode, matching the style of its other
  entries (mistake, fix).
