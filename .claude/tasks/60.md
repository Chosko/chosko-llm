# Task 60 — Teach /task-clean to prune pruned task IDs from FEATURES.md

Target: claude

## Goal
`/task-clean` removes terminal-status tasks from `.claude/TASKS.md` and deletes their body
files. Once `/task-add` records task IDs on a feature's `Tasks:` line, `/task-clean`
becomes the only other writer that can invalidate it — a cleaned task leaves a dead ID
behind, and `/architect`'s iterate guard would look it up, find nothing, and under-report.
Close the loop.

## Acceptance criteria
- After removing task entries, `/task-clean` reads `.claude/FEATURES.md` (when it exists)
  and removes every pruned ID from any `Tasks:` line containing it.
- A `Tasks:` line left with no IDs becomes `Tasks: none`.
- Feature `Status:` is NOT changed. A feature whose tasks were all cleaned stays
  `[PLANNED]` — the tasks existed and were resolved; reverting to `[NEW]` would be the
  illegal `[PLANNED]→[NEW]` transition from task 53's state machine.
- Projects with no `.claude/FEATURES.md` are unaffected — the step is skipped silently, not
  an error.
- The removal report names each feature whose `Tasks:` line changed, and which IDs were
  dropped from it.
- The commit stages `.claude/FEATURES.md` alongside `.claude/TASKS.md` and the deleted body
  files when it changed. Explicit paths only; `--no-commit` leaves everything uncommitted
  as today.
- `[STALE]` remains non-terminal and is never pruned (landed in task 54; verify it holds).
- Task IDs are still never renumbered and the `Last task number` counter still never
  decreases.
- Frontmatter `version` bumped; `.claude/context/features.md` updated; root `VERSION`
  bumped (minor).

## Decisions
- `/task-clean` prunes rather than `/architect` self-healing. Confirmed by the user: the
  writer that invalidates the data fixes it immediately, so the file is never
  transiently wrong and the guard stays a pure reader.
- Status is deliberately untouched. Pruning is bookkeeping about which tasks still exist,
  not a statement about the design/backlog relationship.
