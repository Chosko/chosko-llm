# Task 281 — Add the `pipeline-statusline` statusline renderer

Target: claude

## Goal
Add `statusline/pipeline-statusline.sh`, the renderer half of feature `pipeline-statusline` (`.claude/domain/features/pipeline-statusline.md`): from Claude Code's status JSON on stdin and the project's pipeline files it prints the session line, the runbook and task progress line with the four-rule task scope, and one line per in-flight task in scope — in a single awk process with no other fork, degrading silently on anything missing. The feature document's § Architecture › Renderer, § Data and state and § Interfaces and contracts are the design; the user's spec, restated there, is authoritative on every output detail.

## Acceptance criteria
- `statusline/pipeline-statusline.sh` exists with statusline frontmatter in the bash no-op heredoc (`name: pipeline-statusline`, `version: 0.1.0`, `type: statusline`, a `description` per the authoring guide's contract), executable, and `./bin/chosko-llm ls --available` (with `CHOSKO_LLM_HOME` pointed at the working repo) lists it at 0.1.0.
- Exactly one process is forked: bash reads nothing itself and `exec`s a single `awk` under `export LC_ALL=C`; no git, grep, sed, cygpath, date, cat or subshell. Verified by tracing (`strace -f -e trace=execve` or equivalent) on a fixture run: one `awk` execve after the script's own.
- **Line 1** prints, separated by a dim `·`, each item omitted when its field is absent: model display name (cyan); folder glyph + basename of `current_dir` (backslashes normalised to `/` first); branch with green branch glyph, or short SHA with yellow commit glyph when `.git/HEAD` is detached — `.git` as a file is followed through `gitdir:`; `used_percentage` + label `ctx` (green < 70, yellow < 90, red ≥ 90); `$` + total cost with 2 decimals; 5h % (green < 50, yellow < 80, red ≥ 80) followed by `(<hourglass> XhYm <until reset>)` only when `resets_at` − now > 0; 7d % with the same colours. Now comes from awk itself (`systime()` where available, otherwise the item's countdown is omitted — never a `date` fork).
- **Line 2** prints only when `.claude/RUNBOOKS.md` or `.claude/TASKS.md` exists under the normalised `current_dir`:
  - runbook part: first `[RUNNING]` block of `RUNBOOKS.md`, else the last block; play glyph (cyan) + name + 10-cell bar + `%` + `d/t` from `Steps:` + `(STATUS)`;
  - tasks part: check glyph (green) + label `task` + 10-cell bar + `%` + `done/total`, plus `(+N <in corso>)` when N in-scope tasks are `[IN PROGRESS]`; done = `[DONE]` or `[SKIP]`.
- **Scope**, first rule that applies: (a) a `tasks A–B` / `tasks A-B` range in the chosen runbook's title; (b) the union of ranges and single ids named in that runbook body's step headings (`## [m] <n>. <title>`, reading stops at `## Do not re-propose`); (c) the tasks of the features on the `Features:` line of the `[ACTIVE]` milestone in `.claude/PLAN.md`, via each feature's `Tasks:` line in `.claude/FEATURES.md`; (d) every task in `TASKS.md`. Under (a)–(c), an id absent from `TASKS.md` whose `.claude/tasks/archive/<id>.md` exists counts as done; an id absent from both is not counted.
- **Lines 3+**: one per `[IN PROGRESS]` task in scope: gear glyph (yellow) + `task <id>` (cyan) + ` · ` + title, cut to 90 bytes at a word boundary followed by `…`, never splitting a UTF-8 multi-byte sequence.
- Bars use eighth-block resolution (`█`, `▏▎▍▌▋▊▉`, `░` for empty); any non-zero value shows at least one eighth.
- All user-visible words (`ctx`, `until reset`, `task`, `in corso`) and both glyph sets sit in one table at the top of the script. Nerd Font glyphs (nf-fa-folder, nf-dev-git_branch, nf-dev-git_commit, nf-fa-hourglass_half, nf-fa-play, nf-fa-check, nf-fa-cog) are written as octal UTF-8 escapes and are all single-cell; the `--no-nerd-font` argument switches to single-width Unicode (`▶ ✔ ↳` for runbook, tasks done, task in progress; plain single-width fallbacks for the rest). No emoji anywhere, never `⚙`.
- Missing files, missing fields, malformed blocks and an empty stdin produce no error text on stdout or stderr, and exit 0.
- Fixture verification on Linux, outputs shown in the task's closing report: a project fixture whose last runbook has no range in its title and step headings naming `(tasks 267–277)` scopes exactly 267–277; plus cases for rule (a), rule (c) with one archived id, rule (d), a worktree `gitdir:`, a detached HEAD, a backslashed `current_dir`, a title with multi-byte characters past 90 bytes, `--no-nerd-font`, and a directory with no `.claude/` (line 1 only). Runtime of each run reported.
- Root `VERSION` bumped minor (1.76.3 → 1.77.0, or the next minor if it moved) with a matching top `CHANGELOG.md` section; `./scripts/check-changelog.sh` passes.

## Decisions
- **No code shared with `session-statusline`.** Line 1 is a deliberate copy of its behaviour, rewritten inside the single awk program; `statusline/session-statusline.sh` is not edited — copy-on-install leaves no way to share, and retiring it is out of scope (feature document § Scope and non-goals).
- **File existence is tested inside awk** by attempting a `getline` read, never with a shell test — each `test -f` would be a fork.
- **The countdown uses awk's own clock.** If the awk in use lacks `systime()`, the `(… until reset)` part is omitted rather than forking `date`; gawk (git-bash's awk) and mawk both provide it.
- **Settled here** (feature document leaves them open): the single-width fallbacks for folder, branch, commit and hourglass under `--no-nerd-font` are the implementer's choice within "single-width Unicode, no emoji"; the trace-based one-fork check stands in for Windows timing, which task 282's manual checkpoint measures.
