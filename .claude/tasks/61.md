# Task 61 — Document the product pipeline end-to-end in README and the authoring guide

Target: claude

## Goal
Tasks 53–60 each add their own entry to `README.md` and `.claude/context/features.md`, but
nothing tells a reader that `/domain-setup` → `/product-design` → `/architect` →
`/task-add` → `/task-implement` is one continuous pipeline, in which order to run it, or
what the two status vocabularies mean together. Write that narrative once, now that every
piece exists, and verify the whole set is internally consistent.

## Acceptance criteria
- `README.md` gains a "Product pipeline" section: the path from idea to merged code, which
  command runs at each stage, what artifact each consumes and produces, and a worked
  one-paragraph example following a single feature from product design to a task ID.
- The section documents the iterate loop as a first-class flow, not a footnote:
  `/architect` on a planned feature → `[ITERATED]` + `[STALE]` tasks → `/task-add
  feature=<slug>` reconciles → `[PLANNED]`. This is the least obvious part of the design
  and the most likely to be misused.
- It states the entry points for the two realistic starting conditions: a brand new product
  (start at `/product-design`) and an existing codebase (start at `/domain-setup` then
  `/architect`, or go straight to `/task-add`).
- The existing per-command list stays the reference material; the new section links into it
  rather than duplicating descriptions.
- `docs/authoring-guide.md` records two patterns for future authors: skills whose phases
  span sessions keep state in a versioned project document rather than conversation (citing
  `design-process.md`), and any change to the task status vocabulary must be mirrored into
  `scripts/check-task-parity.sh` and `scripts/cmd-task-impl.sh` (citing `[STALE]`).
- A consistency pass across all nine tasks' output: every file path, document name, status
  tag, state transition, and argument name in `README.md`,
  `.claude/domain/product-workflow.md`, `.claude/domain/task-workflow.md`,
  `.claude/context/features.md`, and the new/changed feature files agree exactly. Fix any
  drift.
- `scripts/check-task-parity.sh` passes.
- `.claude/context/INDEX.md`'s `Last updated` refreshed. Root `VERSION` bumped (patch).

## Decisions
- Deferred to last rather than folded into each task: the narrative is only writable once
  the pieces exist, and doing it once avoids eight partial rewrites of the same section.
- Includes an explicit cross-file consistency pass — eight tasks each editing `README.md`
  and `.claude/context/features.md`, against two status vocabularies duplicated into shell
  scripts, is the most likely source of drift in this batch.
