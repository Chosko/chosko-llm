# Task 263 — Runbook schema: `[P]` marker, `Parked:` index line, `Execution policy:` header

Target: claude

## Goal
Part of feature `unattended-parking`. Extend the runbook artifact —
`runbook-schema.md` is its single authority — with the three things the
runbook half of the feature stores: a fifth step marker `[P]`, a conditional
`Parked:` line in the index block, and an optional `Execution policy:` header
line. Give `/runbook-create` the ownership rows and the two listing commands
the one line each they need to show a parked runbook without opening its
body. No execution behaviour changes here; that is task 264.

## Acceptance criteria
- `runbook-schema.md` § *The four step markers* becomes five: `[P]` —
  parked; a `Context:` bullet opening `parked:` carries the question
  verbatim. `[P]` counts as not done in `Steps:`, is committed like `[x]` and
  `[!]`, and never appears beside `[~]` on the same step.
- § *The header* table gains `Execution policy:` — `attended` or
  `unattended`, absent means `attended`, authored by `/runbook-create` only
  when asked, overridden per run by `/runbook-run --attended` /
  `--unattended`; any other value is an argument error at run time.
- § *The index block* gains `Parked: steps <ids>` — present only while at
  least one step is `[P]`, ascending ids, removed when none remains; the
  same rule as `Failed at:`, stated once by reference to it.
- The `Context:` bullet forms `- <date> parked: <question>` (multi-line
  allowed, options included, never an approval-gate draft) and
  `- <date> unparked with answer: <text>` are specified beside the existing
  dated-correction form.
- § *Two deliberate absences* stays true: no `[SKIP]`, no `Produces:`; add
  the sentence that `[P]` is not a skip — the step is still to run.
- `commands/runbook-create.md`'s ownership table: `Execution policy:` is
  written only when the user asks for an unattended runbook, never by
  default; the step marker row's never-written list gains `[P]`; the
  `Context:` row's never-written list names the two parking bullets.
- `/runbook-list` renders the `Parked:` line as a continuation exactly as it
  renders `Failed at:`; `/runbook-describe` shows `[P]` in its marker column
  and the `Parked:` continuation; both read-only, correcting nothing.
- Frontmatter `version:` bumped on `runbook-run` (minor), `runbook-create`,
  `runbook-list` and `runbook-describe` (patch); root `VERSION` bumped
  (minor) with a matching `CHANGELOG.md` section;
  `./scripts/check-changelog.sh` and `./scripts/check-home-paths.sh` pass.

## Decisions
- `Parked:` mirrors `Failed at:` rather than a new status: `[PENDING]` is
  still true of a runbook with parked steps, and a fifth index status would
  make every reader learn one more word for a runbook that simply has not
  finished.
- The header line is authored, never inferred: an author who wants a
  runbook to park says so once, and `/runbook-run` never rewrites the header.
