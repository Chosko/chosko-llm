# Task 104 — Surface pending kind migrations in `ls` and `show`

Target: claude

## Goal
Task 95 shipped kind migration (`replaces: <kind>:<name>`), but only the
mutating commands act on it. `chosko-llm ls` still renders a feature
mid-migration as two unrelated rows — the stale installed artifact as
`local only`, its replacement as `not installed` — and the TTY footer tells
the user to `add` the replacement, which would leave both artifacts
installed side by side. `chosko-llm show` has the same blind spot. Teach
both surfaces to detect a pending migration from the `replaces:`
declaration already in the frontmatter and report it, so the user knows
`update --all` is the correct next step.

## Acceptance criteria
- `ls` gains two status values on top of the existing four:
  - `superseded` — replaces `local only` on an installed artifact that has
    no managed-clone source AND for which `find_replacement <kind> <name>`
    finds a feature in the clone declaring `replaces: <kind>:<name>`.
  - `migration pending` — replaces `not installed` on a clone feature
    whose own `replaces:` names an artifact that is currently installed.
- Both new statuses render in `C_YELLOW` (actionable, same as `updatable`).
- A `superseded` row is NOT counted as updatable; a `migration pending` row
  is NOT counted as installable. They feed a separate counter.
- The TTY footer gains, when that counter is non-zero:
  `Run 'chosko-llm update --all' to migrate N feature(s) that changed kind.`
  The always-present `show` hint stays last. `Everything is up to date.`
  is not printed when only migrations are outstanding.
- Footer suppression when stdout is not a terminal is unchanged.
- `--installed` / `--available` filter semantics are unchanged (a
  `superseded` row survives `--installed`; a `migration pending` row
  survives `--available`).
- `show` computes the same two statuses, colors them the same, and prints
  a matching footer tip:
  - `superseded`: this artifact was replaced by `<new-kind> '<name>'`; run
    `chosko-llm update --all` to complete the migration.
  - `migration pending`: installing this will remove the installed
    `<old-kind> '<name>'`; run `chosko-llm update --all`.
- `show <name>` with no kind prefix still dies as ambiguous mid-migration
  (both kinds resolve), but the die message gains one line naming the
  pending migration and the `update --all` fix.
- `find_replacement` is only called on rows that are already installed-with-
  no-source — never on every row.
- Root `VERSION` bumped minor (0.49.1 → 0.50.0).
- `docs/cli-help.txt` `ls` line lists the two new statuses.
- Context files updated: `cmd-ls.md`, `cmd-show.md`, `shared-lib.md`.

## Decisions
- Both rows flagged rather than a footer-only hint: the table itself is the
  misleading part, and a user reading `not installed` next to `local only`
  has no way to connect them.
- Status vocabulary extended in `show` too, keeping the "status vocabulary
  mirrors `cmd-ls` exactly" invariant that `.claude/context/cmd-show.md`
  already records, rather than letting the two surfaces drift.
- Ambiguity in `show <name>` is left as a `die`, not auto-resolved to the
  replacement — silently picking a kind the user did not ask for is worse
  than an error that names the fix. Only the message improves.
- Detection reuses `find_replacement` / `read_frontmatter_field` /
  `artifact_is_installed` from `lib.sh`; no new state, no new lockfile.
- Filter semantics deliberately untouched: `--installed` hides the
  `migration pending` row, `--available` hides the `superseded` row. Each
  filter still shows one half of the pair, so the notice survives both.
- If the four near-identical `ls` listing passes make the change unwieldy,
  factoring the shared per-row status/color logic into one helper is in
  scope — behaviour of the existing four statuses must not change.
