# Task 310 — Add the `/objective-run` skill

Target: claude

## Goal
Part of feature `objective-run`. Ship `/objective-run "<objective>"`: it turns
one stated objective into checkable success criteria (the run's one gate),
then works toward them in rounds — a fresh worker subagent does one piece of
work and commits, a fresh checker subagent marks every criterion met or not
met with evidence, and the round is logged and committed — until every
criterion is met, `--max-time` has passed, or `--max-rounds` consecutive
rounds made no progress. The committed log at `.claude/objectives/<id>.md`
lets `/objective-run <id>` resume a run in a later session, carries the run's
parked questions, and collects the documentation the run made stale for the
closing report to propose as follow-ups.

## Acceptance criteria
- `skills/objective-run/SKILL.md` at `version: 0.1.0` with full frontmatter
  (`name`, `version`, `type: skill`, a what+when `description`) and
  `requires: skill:interaction-engine, skill:runbook-run`; the body's `#`
  header carries the usage
  `/objective-run "<objective>" [--max-time <duration>] [--max-rounds <N>]`
  and `/objective-run <id>`, plus `--attended` / `--unattended` per
  `interaction-engine`'s `policy.md`.
- Criteria: the run first writes a short list of criteria, each with how it
  is checked, and shows it as a plain summary per `messages.md`. The gate is
  tagged class 1 per `gates.md`: under `attended` it waits; under
  `unattended` it passes, printing the summary and the log commit. A
  criterion that needs a user decision is parked in the log under
  `unattended` and waits for the user under `attended`; a parked criterion is
  not worked on until answered.
- Rounds: worker — fresh subagent briefed with the objective, the criteria
  and their latest verdicts and the log's round summaries, doing one piece of
  work toward an unmet criterion and committing it, its brief carrying
  `/runbook-run`'s operating rules (the `DONE` line, the spawn relay, the
  commit report) by citing `../runbook-run/references/subagent-contract.md`;
  checker — fresh subagent, edits nothing, gives every criterion met / not
  met with evidence (a command's output, a file, a test name); log — the
  round's entry and verdicts written and committed. The loop is named as the
  shape of `/task-implement --review`'s review rounds; the run's own loop is
  stated in full here.
- Stopping: all criteria met; `--max-time` passed, checked with `date`
  between rounds (a started round always finishes), counted from this
  invocation's start; `--max-rounds N` consecutive no-progress rounds (no
  criterion moved from not met to met), `N` = 3 by default, the count
  re-derived from the log on resume. The stop reason goes in the log.
- Questions: a worker's question is parked under every policy — recorded in
  the log's parked list verbatim with its options, that work set aside, the
  next round picking other work; parked questions carry `/runbook-run`'s
  `P<n>` handles and are unparked the way its step parking unparks, citing
  `../runbook-run/references/parking.md`. The closing report asks every
  parked question together, last, in plain language, per `messages.md`.
- Docs follow-ups: each round records in the log's *Docs to update* section
  the documents and sections its change made stale; the run edits no
  documentation; the closing report proposes them — `/architect amend` where
  a design changed, `/pipeline-revise --catch-up` for editorial catch-up.
- Resume: `/objective-run <id>` re-reads criteria, verdicts, limits and
  parked questions and starts the next round; a done or stopped log reports
  its outcome and starts nothing; an unknown `<id>` names the existing logs
  and stops.
- Failure contract: a worker that fails to commit, or a checker that gives
  no verdict, ends the round as no progress, recorded; a failed log commit
  stops the run; a malformed duration is an argument error.
- `skills/objective-run/references/log-schema.md` states the log: path
  `.claude/objectives/<YYYY-MM-DD>-<slug>.md` (a same-day slug collision
  takes `-2`, `-3`, …); the objective; the criteria each with check, latest
  verdict and evidence; the limits and start time; one entry per round
  (worker commit and summary, checker verdicts); parked questions; *Docs to
  update*; status `running` / `done` / `stopped: <reason>`. The SKILL.md
  cites it and does not restate it.
- Commits: one per worker round (the worker's), one log commit per round
  (the run's), each log commit pushed per the repo-wide commit-and-push
  protocol as `/runbook-run` pushes; no `TASKS.md` write; no Stop hook; no
  area splitting.
- Root `VERSION` minor-bumped with a `CHANGELOG.md` section;
  `./scripts/check-changelog.sh`, `./scripts/check-home-paths.sh` and
  `./scripts/check-routing.sh` pass; `./bin/chosko-llm ls --available` lists
  `objective-run 0.1.0`.

## Decisions
- One implementation task, not several: the skill is one `SKILL.md` and one
  reference, and every part (gate, rounds, stopping, parking, resume,
  follow-ups) reads and writes the same log.
- Settled here, against `.claude/domain/features/objective-run.md` (no
  conflict): the log reference is `references/log-schema.md`; `--max-time`
  counts from each invocation's start, since elapsed time is in memory only
  and the stored start time would expire a resumed run at once; a resume uses
  the limits stored in the log; parked questions use `/runbook-run`'s
  `P<n>` handles and unparking; a parked criterion is not worked on;
  same-day slug collisions take a numeric suffix; the review-round loop is
  cited by name, not by a path into `task-implement`, because none of its
  review/iterate specifics apply; `--attended` / `--unattended` are accepted
  because `policy.md` requires every interactive feature to accept them.
- Each log commit is pushed: a run must survive the session (and container)
  that started it. No `--no-commit` / `--no-push` flag — the feature's
  interface defines none, and an uncommitted log cannot be resumed.
- Not a pipeline-engine consumer: no routing row. No `project-policy:`
  declaration: the policy line is `interaction-engine`'s, and the run uses no
  git op beyond those `task-engine` declares.
- Orchestrate mode needs no text here: `/orchestrate-mode` already states
  that `/objective-run` is not split into areas (task 306).
- Preconditions: 281 (`interaction-engine` to cite), 283 (`/runbook-run`'s
  subagent contract and parking in their policy-aware form), 303
  (`/pipeline-revise --catch-up`, which the closing report proposes).
