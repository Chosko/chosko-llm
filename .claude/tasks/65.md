# Task 65 — Print a file-count/line-count report at the end of export, before the open-folder prompt

Target: claude

## Goal
`chosko-llm export` currently ends by writing the artifact and then (in a
TTY) asking to open the export folder, with no summary of what was
exported. Add a small report — number of files and total line count —
printed after the artifact is written but before that prompt, so the user
sees the scope of the export at a glance regardless of shape (Markdown or
`--archive`).

## Acceptance criteria
- After either output branch (Markdown or zip) finishes writing, and
  before the "Open the export folder?" prompt, `cmd-export.sh` prints a
  one-line report via `log_success` (or `log_info`) stating the number of
  files and total line count.
- The counts are derived from `$files` (the same selection list already
  used to build both shapes) and each source file's line count — not from
  parsing the generated `.md`/`.zip` output.
- The report appears identically for both the default Markdown shape and
  `--archive`.
- Existing stdout contract is unchanged: the report goes to stderr like
  all other `log_*` output; the only stdout line remains the final
  absolute output path.

## Decisions
- Count lines from the original repo-relative files listed in `$files`
  (read via `$repo/$f`), not from the concatenated Markdown output or the
  zip's staged copies — this keeps the report meaningful for both shapes
  from one shared computation, matching the "one selection function, two
  consumers" pattern the file already follows.
- Place the report after the `if [ "$archive" = true ]; then ... else ...
  fi` block (around what is currently line 121 in `scripts/cmd-export.sh`),
  so it's common to both branches instead of duplicated inside each.
