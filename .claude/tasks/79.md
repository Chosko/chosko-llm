# Task 79 — Simplify /task-implement's strict-TDD sequence — drop the watch-it-fail step

Target: claude

## Goal
The current /task-implement per-task workflow (skills/task-implement/SKILL.md)
and its headless mirror (scripts/cmd-task-impl.sh) run a strict 8-step
red/green TDD sequence: write tests, run them expecting a FAIL, implement,
run them expecting a PASS, then run the full suite. The explicit "watch it
fail" step costs a full test invocation plus a reasoning pass on every task
without adding information the implementer needs — it just confirms the
test file is wired up. Drop that step to cut effort and token consumption
per task while keeping the rest of the sequence (tests-first, affected-test
pass, full-suite pass) intact. This applies to both implementers (Claude via
the skill, the external LLM via the orchestrator) as a straight replacement
of full-tdd's behavior — not a new opt-in policy tier.

## Acceptance criteria
- `skills/task-implement/SKILL.md`'s per-task workflow (Step-by-step
  section and the numbered GOAL summary near the top) has 7 steps instead
  of 8: Mark IN PROGRESS → write/update tests → implement → run affected
  tests (expect pass) → run full suite (expect pass) → mark terminal status
  → commit and push. There is no step that runs tests and expects failure.
- `scripts/cmd-task-impl.sh`'s `implement_one` mirrors the same removal:
  the block that runs `run-affected-tests.sh` and dies if it unexpectedly
  passes (current Step 3) is deleted; aider still writes tests
  (tests-prompt.md) then implements (implement-prompt.md) as two separate
  passes, but nothing checks for a pre-implementation failure in between.
  Comments/log lines renumber Step 4→3, 5→4, 6→5, 7→6, 8→7 accordingly.
- `scripts/check-task-parity.sh`'s `WORKFLOW_STEPS` canonical list is
  updated from `Step 1`..`Step 8` to `Step 1`..`Step 7`, and
  `./scripts/check-task-parity.sh` passes against the updated skill and
  script.
- `skills/task-implement/no-test-suite.md`'s skip-tests-mode step list
  ("Skip Steps 2, 3, 5, and 6") is updated to the new step numbers, and its
  user-facing description of the TDD sequence no longer promises a
  watch-it-fail phase.
- Every other shipped reference to the old "8-step" workflow is updated to
  the new count: `README.md`, `docs/authoring-guide.md`,
  `.claude/domain/task-workflow.md`, `.claude/context/cmd-task-impl.md`,
  `.claude/context/INDEX.md`, `.claude/context/features.md`. Historical,
  already-`[DONE]` task bodies (e.g. `.claude/tasks/39.md`,
  `.claude/tasks/45.md`) are left untouched — they're a record of past
  work, not live documentation.
- `skills/task-implement/SKILL.md`'s frontmatter `version:` is bumped
  (minor), and the repo's root `VERSION` is bumped (minor) per CLAUDE.md's
  versioning rule.

## Decisions
- Removed the fail-watch step outright rather than merging "write tests"
  and "implement" into a single step — smaller diff on both sides of the
  parity-guarded pair, and it still preserves tests-first ordering (tests
  exist before the production edit) while cutting one test run + one
  reasoning pass per task. (User confirmed this framing over the two
  alternatives offered: conditional full-suite skipping, and merging
  affected+full-suite runs.)
- Applied as a straight replacement of full-tdd's behavior everywhere,
  not a new `Testing policy for /task-implement:` marker value — every
  project already on full-tdd gets the leaner sequence with no opt-in
  step. (User's explicit choice.)
- Kept the change mirrored across both implementers (the interactive
  skill and the headless `cmd-task-impl.sh` orchestrator) rather than
  letting them diverge, consistent with the existing parity guard's
  purpose. (User's explicit choice.)
- Left wording of "TDD" vs. a more accurate term (since dropping the
  red/green proof makes "strict TDD" a less accurate label) to the
  implementer's judgment during editing — apply whatever phrasing reads
  naturally in each file rather than a single fixed replacement string.
