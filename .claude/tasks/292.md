# Task 292 — Bring `/project-setup`'s wizard in line with the features it sets up

Target: claude

## Goal
Part of feature `setup-sync`. `/project-setup` asks the testing policy only
on Unity projects and offers one of its three values, never offers the
interaction policy, the claude-md sections or the hook, its `## VCS` template
lacks operations later features run, and it keeps a history aside. Fix every
one of these so a freshly set-up project carries every per-project fact the
shipped features read.

## Acceptance criteria
- The testing-policy question is asked on every project, offering
  `skip-tests`, `full-tdd`, `skip-tests-unattended`, or no line (the
  default: `/task-implement` detects the runner). A chosen value is written
  as `Testing policy for /task-implement: <value>` in a `## Tasks
  implementation` section, created on any project when a value is chosen;
  the Unity subsection keeps only the dirty-tree noise bullets.
- The wizard offers `Interaction policy: attended|unattended`, `attended`
  suggested, the line omitted when the user keeps the default.
- The `## VCS` template gains Plastic rows for `git mv`, `git rm`,
  `git show` and `git branch` beside the existing ones.
- When it injects a `## VCS` section the wizard says, in one line, that a
  non-git VCS disables parking: `--unattended` is refused by the parking
  features and an unattended run stops at a question instead of parking.
- It offers each shipped claude-md section — `editing-discipline` (named as
  required by `/doc-consolidate`), `git-commit-style`, `tool-usage-policy` —
  and the `remote-session-protocol` hook, each installed with
  `chosko-llm add --local`, after CLAUDE.md exists.
- The CONFIRM plan shows every new choice; the final report suggests
  `/product-design` and `/architect` when the domain layer was set up.
- The "it was a command before v0.46.0" aside is gone.
- `project-setup` `version:` bumped; root `VERSION` minor-bumped with a
  `CHANGELOG.md` section; `check-changelog.sh` and `check-home-paths.sh`
  pass.

## Decisions
- The testing-policy marker keeps the `## Tasks implementation` section as
  its home, which now exists on any project that picks a value; the
  interaction-policy line is written as its own line in CLAUDE.md where
  `interaction-engine`'s `references/policy.md` (task 281) says it is read.
- The claude-md / hook installs run in EXECUTE after the wizard's own
  CLAUDE.md work and before the heavy sub-commands, since `--local` needs
  `CLAUDE.md` to exist.
- Preconditions 286 and 289: 286 adds the interaction-engine dependency to
  this body and 289 deletes the Unity MCP offer from the same Unity
  subsection this task restructures; both land first.
