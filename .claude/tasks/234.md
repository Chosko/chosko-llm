# Task 234 — Document `/runbook-prune` and the two new runbook header fields

Target: claude

## Goal
Tasks 232 and 233 ship a seventh runbook artifact and two new optional body
header fields. Every document describing the suite still describes six artifacts,
a max()-derived append rule, and a body schema with neither field. Bring the
README, `docs/reference.md`, the context layer and the `/architect` feature
document up to what shipped.

## Acceptance criteria
- `README.md`'s runbook paragraph names `/runbook-prune` beside `/runbook-list`,
  `/runbook-describe` and `/runbook-clean`, and says in one clause what
  distinguishes it from `/runbook-clean`: prune removes finished **steps** from a
  live runbook, clean removes finished **runbooks**.
- `docs/reference.md` § The `runbook-*` commands gains `/runbook-prune` — its
  argument form, the `[x]`-only rule, the `Archive:` line, the `[RUNNING]`
  refusal, and its commit-by-default behaviour.
- `.claude/context/features.md` lists `commands/runbook-prune.md`, and
  `.claude/context/INDEX.md`'s row for that file is updated if its summary no
  longer covers the folder's contents.
- `.claude/domain/features/runbook-suite.md` is reconciled with what shipped on
  exactly these 4 points — editing it is authorised for this task, see Decisions:
  1. § The six shipped artifacts — the table, the ship order and the `requires:`
     graph become seven, `/runbook-prune` requiring `skill:runbook-run`.
  2. § The body schema — the two new optional header fields, `Last step number:`
     and `Archive:`.
  3. § `/runbook-create` — "Numbering continues from the highest existing step
     id" becomes the stored counter.
  4. § Scope and non-goals' "Deletion on completion", and § Two deliberate
     absences' "a runbook is authored complete" — pruning is a mid-life event
     neither passage anticipates; plus `Steps:` counting archived ids as done.
  Nothing else in the document changes.
- No root `VERSION` bump and no `CHANGELOG.md` entry: every file this task
  touches is documentation or the context layer, both exempt per CLAUDE.md
  § Versioning.

## Decisions
- **Editing `.claude/domain/features/runbook-suite.md` is explicitly authorised
  for this task (user decision, 2026-09-17), for the 4 reconciliations listed
  above and for nothing else. Do not ask for permission at implementation time —
  the permission is already granted.** That document is normally `/architect`'s,
  and anything beyond those points still belongs to `/architect`. These are
  factual reconciliations with shipped behaviour, not redesigns; if one turns out
  to need a design decision rather than a wording fix, stop and say so instead of
  deciding it here.
- **No new feature document.** `/runbook-prune` extends the runbook asset kind
  rather than introducing one, so it is recorded in `runbook-suite.md` rather
  than given a `.claude/domain/features/runbook-prune.md` of its own. A feature
  document is `/architect`'s to create in any case.
