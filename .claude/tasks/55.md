# Task 55 — Add /domain-setup — scaffold the domain knowledge layer and the FEATURES.md index

Target: claude

## Goal
`.claude/domain/` is read by `/task-add` and `/task-enrich`, deliberately never written by
`/context-build` or `/context-update`, and created by nothing at all — every project that
has one grew it by hand, with no index and no CLAUDE.md pointer. `/product-design` and
`/architect` both write into it, so it must become structural first. Add `/domain-setup`,
scaffolding the layer the way `/task-setup` scaffolds the backlog: idempotent, standalone,
re-runnable on projects that already have domain docs.

## Acceptance criteria
- `commands/domain-setup.md` exists with complete frontmatter (`name: domain-setup`,
  `version: 0.1.0`, `type: command`, one-line description).
- Probes each artifact individually, creates only what is missing, never overwrites without
  explicit confirmation. A re-run on an initialized project reports "Domain layer already
  initialized." and writes nothing.
- Creates: `.claude/domain/`, `.claude/domain/features/`, `.claude/domain/INDEX.md` (a
  `| File | Covers |` table matching the shape of `.claude/context/INDEX.md`),
  `.claude/FEATURES.md` (a `# Features` stub with no entries, per task 53's schema), and a
  CLAUDE.md navigation pointer to `.claude/domain/INDEX.md`.
- On a project with pre-existing hand-written docs in `.claude/domain/`, it indexes them
  into the new `INDEX.md` — reading each file's heading and opening paragraph for the
  "Covers" cell — rather than writing an empty index.
- Creates a minimal `CLAUDE.md` carrying just the pointer if none exists, the same fallback
  `/context-build` uses. The pointer composes with an existing `/context-build` navigation
  instruction rather than duplicating or overwriting it.
- Maintains a `WRITTEN` list driving the final report; when non-empty and `--commit` was
  not passed, closes with an explicit "nothing was committed" reminder.
- `--commit` stages EXACTLY the `WRITTEN` paths in one commit. Without it, no git/VCS
  command runs at all. `--commit` with `--no-commit` stops with the standard
  mutual-exclusion message. Empty `WRITTEN` under `--commit` makes no commit. Non-git VCS
  honours the `CLAUDE.md` `## VCS` mapping.
- A `DO NOT` section forbids: creating feature entries or design documents (those belong to
  `/architect` and `/product-design`), clobbering existing domain docs, catch-all staging
  (`git add -A`/`.`/`-u`), and hook-skipping flags.
- `.claude/context/features.md` gains a "Currently shipped" entry; `README.md` lists it.
- Root `VERSION` bumped (minor — new command).

## Decisions
- Standalone command rather than extending `/task-setup` or inlining into `/project-setup`.
  Confirmed by the user: mirrors `/task-setup`, keeps `/project-setup` a thin orchestrator
  per its stated design, and is the only shape runnable on existing projects that already
  have a domain folder but no index.
- `.claude/FEATURES.md` sits at the `.claude/` root as a sibling of `TASKS.md`, not inside
  `domain/`: it indexes work items like `TASKS.md`, while the feature DOCUMENTS it points
  at live under `.claude/domain/features/`.
- Authoring-command semantics (uncommitted by default, `--commit` opts in), matching
  `/task-setup`, `/context-build`, and `/project-setup`.
- Indexes pre-existing domain docs rather than assuming a clean slate — the near-term users
  are existing projects.
