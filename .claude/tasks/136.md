# Task 136 — Add the repo-local /context-budget audit skill

Target: claude

## Goal
Second step of the `repo-local-audits` feature
(`.claude/domain/features/repo-local-audits.md`). This repo ships prompts and
its product thesis is token-lean navigation, but it has no way to check its own
bodies against that thesis: `skills/unity-mcp-skill/references/workflows.md` is
2,109 lines, `commands/task-add.md` is 879, and nothing notices. Add a
repo-local `/context-budget` skill that inventories every shipped body,
estimates its token cost, and reports a ranked table. It is a tool for building
the product, so it is not part of the product: it lives under `.claude/skills/`,
carries no `version:`, and is installed nowhere.

## Acceptance criteria
- `.claude/skills/context-budget/SKILL.md` exists, creating `.claude/skills/`.
  Frontmatter carries `name: context-budget`, `type: skill`, and a one-line
  `description` — and **no `version:` field**. The body states in one line why
  it has none: `version:` exists for `cmd-add` / `cmd-update`, which will never
  see this file.
- Nothing is created under `skills/`, `commands/`, `claude-md/`, `statusline/`
  or `hooks/`. Verify against a clone where `install.sh` has run:
  `./bin/chosko-llm ls --available` does not list `context-budget`.
- **Inventory** — walks `commands/*.md`, `skills/*/SKILL.md`, every supporting
  file under `skills/*/`, `claude-md/*.md`, and the `CLAUDE.md` chain.
- **Estimation** — `words × 1.3` for prose, `chars / 4` for code-heavy content.
  The report states plainly that these are estimates, not measurements; an
  estimate presented as a measurement is the failure mode to avoid.
- **Thresholds**, flagged at: `SKILL.md` > 400 lines; supporting reference file
  > 500 lines; command > 400 lines; `description:` frontmatter > 30 words;
  `CLAUDE.md` chain combined > 300 lines.
- The `description:` check is called out in the body with its reason: a
  description loads whether or not the feature is ever invoked, so a bloated one
  is a permanent per-session cost. `/task-implement`'s description is a
  paragraph and is the live example.
- **Report** — a ranked table of the heaviest bodies, an estimated saving per
  item, and a total. **No recommendations about what to cut.** The numbers are
  the output; the judgement is the author's.
- **Explicitly not a gate.** The body says so: a 2,109-line reference file may
  be correct, since `unity-mcp-skill` covers a large external surface. The
  audit makes cost visible, it does not litigate it.
- `/context-budget --verbose` adds a per-file breakdown. No other arguments.
- **Read-only, always.** Writes nothing, edits nothing, deletes nothing, opens
  no task, offers no `--commit`, installs no hook and no CI gate.
- The body states that a repo-local skill's name must never collide with a
  shipped feature name, and that `context-budget` is free as of 2026-08-24.
- **Root `VERSION` is NOT bumped**, per the exemption task 135 added to
  CLAUDE.md. `VERSION` is deliberately absent from this task's `Files:` line.
- No test suite by design: verify by running `/context-budget` in this repo. It
  should flag `skills/unity-mcp-skill/references/workflows.md` (2,109 lines),
  `references/tools-reference.md` (1,584), `commands/task-add.md` (879),
  `skills/task-implement/SKILL.md` (708), `commands/project-setup.md` (604),
  `commands/task-setup.md` (560) and `skills/context-convert/SKILL.md` (519);
  the `CLAUDE.md` chain at ~62 lines is well under its threshold and must not
  be flagged. **These figures are as of 2026-08-24, before task 118** — that
  task deletes the dual-LLM lane and tasks 125–131 move several of these bodies,
  so a later run reporting different numbers is expected, not a failure. What
  must hold is the shape: the two `unity-mcp-skill` reference files at the top,
  and the `CLAUDE.md` chain unflagged.

## Decisions
- **Adapted from ECC's skill of the same name, cut to this repo's shape.** Its
  thresholds and estimation heuristics are carried over and re-anchored; its
  report format, MCP analysis and agent-description rules are not — they are for
  a different shape of repo.
- **`words × 1.3` kept** rather than calibrated against a real tokenizer, which
  would need a dependency this repo forbids. Mitigated by labelling the output
  as estimates.
- **No `.claude/context/` file and no INDEX row.** The navigation layer maps the
  shipped codebase; a repo-local audit is tooling, and task 138 covers it with a
  short contrast note in `.claude/context/features.md` instead.
