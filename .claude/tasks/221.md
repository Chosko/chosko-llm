# Task 221 — Keep the orchestrator-authored part of a spawned prompt minimal

Target: claude

## Goal
`SKILL.md` § *THE SPAWNED PROMPT* assembles six parts, of which 1–4 are composed
by the orchestrator. Nothing bounds what it writes there, so it restates material
the step's own command will read for itself — a task body that `/task-implement
134` opens anyway, the feature document behind it, context files. That costs
twice: tokens in every spawned prompt, and an orchestrator that had to read those
documents to write the summary. The orchestrator should orchestrate; the spawned
agent does the reading.

## Acceptance criteria
- Parts 1–4 carry an explicit brevity rule: never restate anything the step's own
  prompt will cause the agent to read — task bodies, feature documents, context
  files, or the backlog.
- The orchestrator is forbidden to open a step's task body, or any document the
  step names, in order to compose the preamble. It already may not read them to
  do the step's work; this closes the same door for prompt authoring.
- The preamble keeps exactly what the agent cannot derive: the navigation
  instruction, the runbook name and the step number.
- Part 5 (the fenced prompt block, verbatim) and part 6 (OPERATING RULES, fixed
  text) are untouched — the change bounds only what the orchestrator writes
  around them.
- The one sentence `--relay-spawns` adds to the preamble survives, since it is
  genuinely not in the step and not in part 6.
- `Context:` bullets keep their current rule and are not capped here.
- `.claude/domain/features/runbook-suite.md` is reconciled with what shipped on
  exactly this 1 point — editing it is authorised for this task, see Decisions:
  1. The spawned-prompt assembly at ~386–399, where parts 1–4 gain the brevity
     rule and the orchestrator's no-deep-read constraint.
  Nothing else in the document changes.
- Root `VERSION` and `CHANGELOG.md` bumped per CLAUDE.md § Versioning (patch);
  `./scripts/check-changelog.sh` exits clean.

## Decisions
- **The rule binds the orchestrator, not the author.** A verbose step is the
  runbook author's to fix through `/runbook-create`; what this task bounds is the
  material the orchestrator adds at spawn time.
- **`Context:` is deliberately left alone** (user decision, 2026-09-15), even
  though it is part 4 and is the other place runbook bodies grow.
- **Part 6 stays fixed text.** It is a contract precisely because it is identical
  in every spawn; trimming it per step is what the reference file exists to
  prevent.
- **Editing `.claude/domain/features/runbook-suite.md` is explicitly authorised
  for this task (user decision, 2026-09-15), for the 1 reconciliation listed
  above and for nothing else. Do not ask for permission at implementation time —
  the permission is already granted.** That document is normally `/architect`'s,
  and anything beyond that point still belongs to `/architect`. This is a factual
  reconciliation with shipped behaviour, not a redesign; if it turns out to need
  a design decision rather than a wording fix, stop and say so instead of
  deciding it here.
