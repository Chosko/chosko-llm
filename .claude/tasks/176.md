# Task 176 — Write the pipeline index-graph reference

Target: claude

## Goal
Add `skills/pipeline-engine/references/graph.md`, the second file the engine's
map already names: how the pipeline's indexes point at each other, and nothing
else. It is the impact walk's only input — `/pipeline-revise` traverses it and
`/pipeline-check` evaluates its edges — so it describes only lines that live in
index files. Reading an artifact *body* is a consumer's own decision and is
never required to traverse the graph; the file says so, because a graph that
needs bodies is a graph that costs a read per node.

## Acceptance criteria
- `graph.md` names each edge by the artifact and the exact line it lives on:
  `FEATURES.md` `Source:` → a `product-design.md` section plus the optional
  milestone parenthetical; `FEATURES.md` `Doc:` → the feature document path;
  `FEATURES.md` `Tasks:` ↔ `TASKS.md` `Feature:`; `TASKS.md` `Preconditions:` →
  task ids; `PLAN.md` milestone `Features:` lists and its flat `## Dependencies`
  edge list → `FEATURES.md` slugs; `RUNBOOKS.md` `File:` → the body path;
  runbook steps naming task ids or feature slugs.
- Each edge states its direction, which side is authoritative when the two
  disagree, and which command writes each side.
- The `FEATURES.md` `Tasks:` → `TASKS.md` direction states the resolution rule
  explicitly: **an id on a `Tasks:` line with no summary block in `TASKS.md` is
  archived and terminal, not dangling.** Feature `task-archive` makes that the
  normal state of a cleaned feature — `/task-clean` moves the body to
  `.claude/tasks/archive/<N>.md` and leaves `Tasks:` alone — so the absence
  carries meaning rather than indicating drift.
- That rule is **cited, never restated**:
  `${CLAUDE_HOME:-$HOME/.claude}/skills/task-engine/references/resolution.md` is
  named as its authority, and `graph.md` adds only what the edge does with it.
- The file adds **no probe of `.claude/tasks/archive/`** and states that
  traversing the graph never requires one: an absent id resolves to "archived,
  terminal" from the absence itself, and no reader checks whether the archived
  file is actually there.
- The reverse direction is unchanged and stated separately: a `TASKS.md`
  `Feature:` slug with no entry in `FEATURES.md` is a real inconsistency, since
  nothing archives a feature slug.
- The file states explicitly that no edge requires opening a task body, an
  archived body, a feature document, a runbook body or a design document, and
  that a consumer that opens one is doing so for its own reasons, not to
  traverse the graph.
- It restates no schema owned elsewhere. `TASKS.md`'s block shape cites
  `task-engine/references/resolution.md`; the runbook body, index block and
  `Steps:` counter cite
  `${CLAUDE_HOME:-$HOME/.claude}/skills/runbook-run/references/runbook-schema.md`;
  `PLAN.md`'s schema cites `/production-status`. Each citation adds the edge and
  nothing else.
- Every edge in the file is consumed by at least one lint finding (task 178) or
  one impact-walk step; an edge used by neither is cut, per the design's
  every-line-is-consumed rule.
- The file notes which edges simply do not exist on a project missing that index,
  so a consumer degrades rather than failing — the same contract
  `/production-status` already keeps.
- `skills/pipeline-engine/SKILL.md` takes a **minor** `version:` bump. Its map
  table is not edited — task 175 already wrote this row.
- Root `VERSION` takes a **patch** bump and `CHANGELOG.md` gains a matching top
  section; `./scripts/check-changelog.sh` exits zero.

## Decisions
- The graph is index-only by construction, not by convention. Every edge that
  would need a body is either dropped or re-expressed over an index line — that
  is what keeps the lint's read cost bounded by the number of indexes rather
  than by the size of the backlog.
- The archived-and-terminal rule is cited from `resolution.md` rather than
  written here, per `shared-phase-engine`'s one-authority-per-rule discipline.
  Feature `task-archive` is what puts the rule in that file; at the time this
  task is implemented the rule may not be there yet. Cite it regardless — a
  second copy written here to bridge the gap is the copy that would drift. If
  the file has not gained it yet, say so in the commit rather than restating it.
- The absence of an id is treated as sufficient evidence of archiving, with no
  verification. That is `task-archive`'s own stated non-goal — a hand-deleted
  body and an archived one look identical to every reader, and the difference
  only surfaces when the user asks to read the task.
- Root `VERSION` is patch here while the skill's own `version:` is minor: the
  skill gains a capability, but no new invocable surface reaches the user until
  task 179. The two axes are independent, and `docs/authoring-guide.md`
  § Versioning says so.
- `.claude/domain/features/pipeline-engine.md` is read-only in this task; task
  178 carries the grant that removes the superseded finding from it.
