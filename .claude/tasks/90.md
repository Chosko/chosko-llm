# Task 90 — Add a lightweight resume marker to /architect for interrupted PHASE 2 sessions

Target: claude

## Goal
/architect writes nothing to disk until PHASE 3 (WRITE) — PHASE 2
(ARCHITECT, conversational) can run long, covering stack decisions,
architecture, data/state, interfaces, dependencies, and open questions, all
of which lives only in conversation until confirmed. If a session ends
mid-PHASE-2, everything discussed is lost with no trace, and a later
`/architect <same feature>` run starts over with no acknowledgment that a
prior attempt existed. Contrast with skills/product-design/, explicitly
cited in docs/authoring-guide.md's "State that outlives a session belongs
in a project document" section as the reference pattern: it persists a
Current-stage marker in `.claude/domain/design-process.md`, rewritten
before every phase ends, so a later run detects it, summarizes where the
last session stopped, and offers to resume or start fresh. Add an
analogous, appropriately lighter-weight mechanism for architect — it
designs one feature per run rather than a whole multi-document product, so
the persistence need is smaller, but the current total silence on
interruption is worth closing.

## Acceptance criteria
- A session that ends partway through PHASE 2 for a given feature leaves
  some persisted trace (exact mechanism is an implementation decision, see
  Decisions) that a later `/architect <same feature>` run can detect.
- On detecting a partial-progress trace, the later run summarizes what was
  captured so far and offers to resume from there or start the feature's
  design fresh — mirroring product-design's resuming.md UX (report,
  don't silently guess).
- The marker/trace is rewritten or cleared when PHASE 3 completes normally,
  so a fully-written feature never looks like an interrupted one.
- PHASE 0 / PHASE 0b's existing gate and iterate-guard behavior (including
  the `[IN PROGRESS]` task refusal) is unaffected — this is a separate,
  additive mechanism for architect's own mid-conversation state, not a
  change to the existing feature/task status vocabulary.
- The "never write to any file before PHASE 3" framing in SKILL.md's DO NOT
  section is updated to carve out the new marker mechanism explicitly, so
  it doesn't read as contradicted.

## Decisions
- Left open: whether the marker lives in a new small scratch file (e.g.
  `.claude/domain/features/<slug>.architect-progress.md`), as a `Status:`
  value transition on the FEATURES.md entry, or another mechanism —
  choose whichever is lowest-risk and least likely to be confused with
  the existing FEATURES.md/TASKS.md status vocabularies owned by other
  commands. Document the choice made.
