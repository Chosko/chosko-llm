# Task 82 — Add --short option to /task-add for lightweight tasks

Target: claude

## Goal
Add a `--short` flag to `/task-add` for trivial, low-ambiguity tasks (e.g.
"document the current deployment method") where the normal PHASE 1 deep
codebase/context/domain investigation costs more tokens than the task
itself. `--short` trades pre-implementation grounding for insertion-time
efficiency: the implementer (`/task-implement`) resolves the details at
execution time instead.

## Acceptance criteria
- `/task-add --short <description>` is documented in the command's usage
  line, ARGUMENT NOTE flag-scanning block, and DO NOT list, following the
  same pattern as `--no-split`/`--no-commit`.
- Under `--short`, PHASE 1 is reduced to the minimum needed to fill the
  `Files:` line (light Glob/Grep only) — no reading of CLAUDE.md,
  `.claude/context/`, or `.claude/domain/` files for grounding.
- Under `--short`, PHASE 1.5 (split check) is skipped entirely, same as
  `--no-split` — a short task is never split.
- Under `--short`, PHASE 2 is NOT skipped wholesale: it still asks about
  ambiguity inherent to the user's own description (e.g. the description
  admits multiple plausible interpretations, or names a target that
  doesn't clearly resolve). It does not ask about ambiguity that would
  only have surfaced through the deep investigation `--short` skips — the
  two are different sources of open questions, and only the former
  applies here.
- The written body uses a short-form schema: `## Goal` (1–3 sentences)
  only. `## Acceptance criteria` and `## Hints` are omitted entirely;
  `## Decisions` remains conditional as in the normal schema — present
  only when a genuine non-obvious call was made during the (now minimal)
  authoring pass.
- `--short` is mutually exclusive with `--enrich` and with `feature=<slug>`
  (both imply exactly the deep investigation `--short` exists to skip);
  combining them stops with a clear error, mirroring the existing
  `--commit`/`--no-commit` mutual-exclusion pattern.
- `--short` composes normally with `--no-commit` and `--no-push`.
- `.claude/domain/task-workflow.md` documents the short-form body schema
  alongside the existing thin/enriched schemas.
- `commands/task-add.md`'s frontmatter `version:` and description are
  updated to mention `--short`; the root `VERSION` file is bumped (minor).

## Decisions
- Short-form bodies drop `## Hints` and `## Acceptance criteria` entirely
  rather than keeping placeholders — both would be authored without
  investigation and would likely be wrong or vacuous; the task description
  itself says this resolves "at execution time."
- `--short` forces `--no-split` behavior rather than adding a separate
  split-skip flag — a task specific enough to qualify for `--short` is by
  definition not a bundle of independent deliverables.
- `--short` refuses to combine with `feature=` and `--enrich` rather than
  silently downgrading their behavior, since both modes exist precisely to
  produce deeply-grounded bodies.
