# Task 301 — Define the scheduler's in-flight set as the units this run spawned

Target: claude

## Goal
`delegated-runs.md` § *The scheduler* defines the in-flight set as the whole
worktree list, so a worktree left behind by an earlier failed task counts as
in flight forever and a `--parallel` run can never reach its "nothing in
flight" end. Define it as `/runbook-run` does: the units this run spawned and
not yet landed, held in run memory; the worktree list is what the
skip-while-present rule and the readers consult, not what counts toward N or
decides the end of the run. A leftover worktree then skips its task with one
line and blocks nothing else.

## Acceptance criteria
- `skills/task-implement/delegated-runs.md` § *The scheduler* defines the
  in-flight set as the tasks this run spawned whose return has not yet been
  landed, held in run memory, and uses that set — and nothing read off git —
  for the count against N, for the in-flight clause of eligibility, for the
  overlap rule's "any task in flight", for the barrier's "every task in
  flight lands" and for the end-of-run test "nothing is in flight"; the
  sentence making the worktree list the in-flight set is gone.
- The same section keeps the worktree list as what the skip-while-present
  rule reads: a task whose `wt/task-<N>` worktree exists and that is not in
  this run's in-flight set is skipped with the one line `worktree.md` gives,
  once per task per run, and counts toward nothing.
- `.claude/domain/features/parallel-task-runs.md` states the agreed design
  change — the in-flight set is the tasks this run spawned and not yet
  landed, in run memory; the worktree list is what the skip-while-present
  rule reads — in every passage that stated the old one (§ Data and state,
  and § Architecture, *The scheduler*, where it says what the launcher reads
  at a scheduling point). Nothing else in the document changes.
- `task-implement`'s `version:` is bumped (patch); root `VERSION` is bumped
  (patch) with a matching `CHANGELOG.md` section; `./scripts/check-changelog.sh`,
  `./scripts/check-home-paths.sh` and `./scripts/check-routing.sh` pass.

## Decisions
- The in-flight set is run memory, not derived from the filesystem: it is a
  property of this run, and the one thing the launcher cannot read off git
  is which worktrees are its own.
- **Design change agreed (user decision, `2026-10-12`):**
  `.claude/domain/features/parallel-task-runs.md` § Data and state: "The
  in-flight set is the worktree list" → "The in-flight set is the tasks this
  run spawned and not yet landed, in run memory; the worktree list is what
  the skip-while-present rule reads" — a leftover worktree from an earlier
  run never counts toward N or keeps the run open.
  `.claude/domain/features/parallel-task-runs.md` is normally
  `/architect`'s; this task updates it for exactly this and for nothing
  else. A further design decision met at implementation time is not
  covered: leave that passage untouched and name it under *Follow-ups* as a
  precise follow-up.
