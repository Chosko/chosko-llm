# Task 300 — Move `/task-implement`'s testing-policy resolution, tests-first sequence and closing report into `task-engine`

Target: claude

## Goal
Part of feature `quick-implement`. `/quick-implement` runs `/task-implement`'s
per-task sequence without a backlog entry, so the parts it shares must have one
home. Move RESOLVING THE TEST RUNNER (with its `test-runner.md` and
`no-test-suite.md` supporting files), the tests-first sequence (Steps 2–5) and
THE CLOSING REPORT into `task-engine` references, make `/task-implement` cite
them, and move the testing-policy `project-policy:` declaration with the rule.
Pure restructuring: `/task-implement`'s behaviour does not change.

## Acceptance criteria
- `skills/task-engine/references/testing-policy.md`, `tests-first.md` and
  `closing-report.md` exist, each the single authority for its rule and each
  with a `/task-implement` note; `test-runner.md` and `no-test-suite.md` move
  to `skills/task-engine/references/` (by `git mv`) and their cross-references
  resolve.
- `skills/task-implement/SKILL.md` cites them by relative path
  (`../task-engine/references/<file>.md`) and keeps only its own parts (status
  flips, DOC_ONLY, parking hooks, review rounds, commit); its supporting-file
  table, `delegated-runs.md` and `review-rounds.md` point at the new paths.
- The text inside the moved rules that is task-specific (status flips, task
  ids, `Files:`) is phrased so a run without a task can follow it, or kept as a
  `/task-implement` note; no rule changes meaning.
- The marker line `Testing policy for /task-implement: …` keeps its exact
  text, so every existing `CLAUDE.md` keeps working.
- The `project-policy: line:Testing policy for /task-implement=…` declaration
  moves from `task-implement`'s frontmatter to `task-engine`'s;
  `scripts/check-setup.sh` passes.
- `commands/task-setup.md`'s MIRRORED COPY note names the new `test-runner.md`
  path.
- `task-engine` and `task-implement` `version:` patch-bumped (and
  `task-setup` if its note changed); root `VERSION` patch-bumped with a
  `CHANGELOG.md` section; `check-changelog.sh`, `check-home-paths.sh`,
  `check-routing.sh` and `check-setup.sh` pass.

## Decisions
- `test-runner.md` and `no-test-suite.md` move with the resolution they
  serve, rather than `/quick-implement` reading `task-implement`'s private
  supporting files; a feature citing another non-engine skill's file would
  need a `requires:` it should not have.
- The marker keeps its `/task-implement` wording: renaming it would break
  every project that already declares it.
- Patch bump: no behaviour changes.
- Lands after 282 (interaction policy in `/task-implement`, including the
  closing report), 288 (human-in-the-loop rewrite of the same body) and 293
  (adds the declaration this task moves).
