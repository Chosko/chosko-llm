# Task 260 — `[PARKED]` status and the task parking protocol in `task-engine`

Target: claude

## Goal
Part of feature `unattended-parking`. Give the task half of the feature its
single authority before any consumer is wired: a ninth status tag `[PARKED]`
in `status.md`, and a new reference `skills/task-engine/references/parking.md`
holding the handoff section, the parking branch, the park sequence, the
transactional unpark, the answerer rule and the prompts-with-a-default rule —
everything `/task-implement` (task 261) and the launcher (task 262) will cite
rather than restate. `resolution.md` and `commit.md` gain the lines that
belong to them.

## Acceptance criteria
- `status.md` lists `[PARKED]` as the ninth tag: the task asked a question
  under the `unattended` policy and its work is set aside; non-terminal;
  never in a default prune set; written and cleared only by
  `/task-implement`; its transitions `[IN PROGRESS]` → `[PARKED]` →
  `[IN PROGRESS]` named in § *Transitions*; the tag's meaning pointed at
  `./parking.md` in three lines, not restated. `[IN PROGRESS]` is no longer
  the longest tag by the same count, so the `/task-list` per-consumer note
  is corrected.
- `parking.md` exists, opens with the load rule — read by `/task-implement`
  only when UNATTENDED is true or a resolved task is `[PARKED]` — and
  specifies:
  - **the one event that parks**: a question the agent asked about the work
    (a skill's own blocking question, or `QUESTIONS FOR USER` when the
    session is a step agent); every other gate keeps its existing outcome,
    named (precondition skip, dependency unselectable, failure, prompt with a
    default);
  - **prompts with a default**: a prompt whose silence already resolves to
    a value takes that value under UNATTENDED and is a *For the record* line
    (delegation → no, `[PARTIAL]` surfacing → `[PARTIAL]`, feature flip →
    none, `Proceed?` → yes, pre-flight dirty tree → abort, explicit `[STALE]`
    → skip with one line); the ambiguous test runner aborts the run;
  - **the handoff**: a trailing `## Parking handoff` section in the task
    body, the one body section `/task-implement` writes, with `Parked:`
    (date, step reached, one reason clause, the words `approval gate` when
    the question is one), `Parking Branch:` (`park/task-<N>` or `[none]`),
    `Question:` multi-line verbatim with options, never compressed; an
    `Answer:` line only after an unpark whose merge failed; nothing else —
    no draft, no restated body;
  - **the branch**: `park/task-<N>`, one commit of tracked edits and the
    untracked files the task created, excluding `.claude/TASKS.md` and
    `.claude/tasks/<N>.md`, branched from the current head, pushed unless
    NO_PUSH; a branch of that name already existing fails the park;
  - **the park sequence**: branch commit, checkout back, then one
    bookkeeping commit on the base staging exactly the `Status:` flip and
    the handoff, so the base tree is clean afterwards;
  - **the unpark transaction**: ask first (an `approval gate` cherry-picks
    first and asks with the draft in the tree), `cherry-pick -n` the parking
    commit, delete the branch local and remote, resume at the step named
    with the `[IN PROGRESS]` flip and the handoff removal riding in the
    task's own commit; a cherry-pick conflict aborts the pick, restores the
    tree and leaves `[PARKED]` — under UNATTENDED the answer is recorded in
    the handoff with a new `Parked:` reason, that update is committed as
    bookkeeping, the task is skipped and reported as needing an attended
    unpark; under attended the run halts and asks how to merge;
  - **the answerer rule**: unpark is attempted whenever an answerer exists —
    an attended session when the task is reached, or an UNATTENDED run
    holding an answer from the pre-ask or from chat; with no answer the task
    is skipped with one line and never re-parked;
  - **refusals**: `--unattended` beside `--no-commit`, and on a non-git VCS.
- `resolution.md` § *Eligibility* states that `[PARKED]` is implementable
  for `all` / `next` exactly when an answerer exists, else skipped with one
  line, citing `./parking.md`; § *Opening a per-task body file* / *Where a
  status flip is written* note the handoff as the one section
  `/task-implement` writes in a body.
- `commit.md`'s `/task-implement` note gains the two parking commit forms
  (`Task <N>: parked — <reason>` bookkeeping on the base; the branch commit
  `Task <N>: parked work-in-progress`) as deliberate departures from one
  commit per task, and the unpark's flip riding in the task's own commit.
- `skills/task-engine/SKILL.md`'s reference table lists `parking.md` with
  its read-when.
- `task-engine`'s frontmatter `version:` bumped (minor); root `VERSION`
  bumped (minor) with a matching `CHANGELOG.md` section;
  `./scripts/check-changelog.sh` and `./scripts/check-home-paths.sh` pass.

## Decisions
- Reference before wiring: two consumers cite one authority, no copy drifts.
- The handoff lives in the body, not the summary block: the block schema is
  "nothing else" and the question is multi-line; `resolution.md` records the
  one exception.
- Branch name is deterministic and also recorded — the field for the reader,
  the name as a guard.
