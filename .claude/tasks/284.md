# Task 284 — Add the pipeline-dashboard generator and text snapshot

Target: claude

## Goal
Add `skills/pipeline-dashboard/scripts/generate.sh`, the generator of feature `pipeline-dashboard` (`.claude/domain/features/pipeline-dashboard.md`): run from a project root, one awk pass reads the project's indexes and the per-project `pending.json` and writes `data.js` (`window.DASH = {…}`) into the project's state folder, or with `--text` prints the text snapshot from the same model. The feature document's § Architecture › Generator, § Text snapshot and § Data and state are the design; the user's spec message (data model, text snapshot) is authoritative on details.

## Acceptance criteria
- `skills/pipeline-dashboard/scripts/generate.sh` is executable, starts with a header comment naming its purpose and usage, and uses bash plus a single `awk` process for all parsing (no jq, python, grep, sed or git binary); `export LC_ALL=C`; output stays valid UTF-8.
- **State folder**: `${CLAUDE_HOME:-$HOME/.claude}/pipeline-dashboard/<slug>/`, created if missing. `<slug>` is `<owner>-<repo>` lower-cased from the `origin` URL in `.git/config` (https and ssh forms, `.git` suffix stripped; a worktree's `.git` file followed through `gitdir:` to its common dir), else the project folder's name lower-cased. A `--print-state-dir` mode prints the folder and exits, for the skill body to use.
- **Data model** in `data.js`, all strings JSON-escaped:
  - `project` (repository folder name), `slug`, `generated` (local `YYYY-MM-DD HH:MM`);
  - `milestone`: `{id, title, features: [...]}` from the first `[ACTIVE]` block of `.claude/PLAN.md`, or `null`;
  - `features`: `{<slug>: {status, tasks: [...]}}` for the milestone's features from `.claude/FEATURES.md` (every feature with a `Tasks:` line when there is no milestone);
  - `tasks`: `[{id, title, status, feature}]` — the milestone features' task ids, or every task in `.claude/TASKS.md` when there is no milestone; an id absent from `TASKS.md` but present as `.claude/tasks/archive/<id>.md` is `DONE` with the title from the archive file's first heading when readable;
  - `runbook`: `{name, title, status, steps: [{n, mark, title, done, tasks: [ids]}]}` for the first `[RUNNING]` block of `.claude/RUNBOOKS.md`, else the last, or `null`; steps from `## [m] <n>. <title>` up to `## Do not re-propose`, each with its `Done:` line (last one when several); a step's `tasks` from `(task N)` / `(tasks N–M)` / lists in its title, else the tasks whose `feature` is the slug the title names (a backticked slug or a known feature slug as a word);
  - `pending`: the parsed content of `pending.json` passed through verbatim when it is a JSON object, else `null`;
  - `unreadable`: the list of index files that exist but yielded nothing parseable (empty when all is well).
- Every index may be absent: missing files produce `null` / empty arrays, never an error; exit 0 whenever `data.js` was written.
- **`--text`** prints, from the same model, the prototype's `term.sh` layout generalised: header (project, milestone, runbook name and status), a steps bar and a tasks bar with counts, the last two done steps plus every remaining step each with a mini bar, the running task(s) under their step, and the last three tasks done (by id). Plain text, no ANSI, fits 80 columns.
- **Verification**, outputs shown in the closing report: against the clone of `music-producer-tycoon` (`.claude/` only) `milestone.id` is `m2-mvp` and the runbook is `implement-progressive-unlocks` with steps 1–4 marked `x` (its step titles name no task and no slug, so their `tasks` are empty — `Done:` text is shown, never used for mapping), and runbook 2's steps, picked by marking it `[RUNNING]` in a scratch copy, map to their heading ranges; against chosko-llm (no `PLAN.md`) `milestone` is `null` and `tasks` holds every task; against an empty folder `data.js` is written with nulls; `data.js` parses with `node -e` and `--text` output is shown for the first case; runtime measured.

## Decisions
- **Slug from `.git/config` read in awk**, never `git remote`: one process, works on git-bash without forking git.
- **Per-step task ids are computed here**, so the page never parses titles (the prototype's `tasksFor` / `featureOf` were hardcoded to one project).
- **No root `VERSION` bump**: without `SKILL.md` the folder is not an installable feature and no CLI verb sees it; task 286 bumps.
- **Settled here** (the feature document leaves it open): the state-folder print mode, the archive-title lookup, the `unreadable` list's shape.
