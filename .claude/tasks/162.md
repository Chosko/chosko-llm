# Task 162 — Record the Next field's omission case in the domain layer

Target: claude

## Goal
Task 156 re-synced the domain layer with `/production-status`'s Next field but
wrote the value list as "exactly one of" five values. The shipped command has a
sixth outcome: its failure-contract table (`commands/production-status.md`) says
that with no `.claude/TASKS.md`, section 2 OMITS the Next field on `[PLANNED]`
features — their next action cannot be derived without task statuses — while
every other status keeps its value. Both `.claude/domain/product-workflow.md`
and `.claude/domain/features/plan-readout.md` therefore read as exhaustive and
are wrong on that degradation path. A future session treating the domain layer
as the spec would read the list as closed and reintroduce a derived value on
`[PLANNED]` features in exactly the case whose whole point is that it cannot be
derived. Related: plan-readout's section-4 claim that the recommendation carries
"the same Next value section 2 gave it" has no defined behaviour when section 2
gave none.

## Acceptance criteria
- `.claude/domain/product-workflow.md`'s Next-field paragraph no longer reads as
  an exhaustive five-value list: it states that with no `.claude/TASKS.md` the
  field is omitted on `[PLANNED]` features, and that every other status keeps its
  value.
- `.claude/domain/features/plan-readout.md` is reconciled with what shipped on
  exactly these 2 points — editing it is authorised for this task, see Decisions:
  1. Output item 2's Next field is not always present: with no
     `.claude/TASKS.md` it is omitted on `[PLANNED]` features, every other status
     keeping its value.
  2. Output item 4 states what it echoes when section 2 omitted the field, so
     "the same Next value section 2 gave it" has a defined behaviour in that
     case.
  Nothing else in the document changes.
- The omission is described as a degradation of the failure contract, not a
  sixth derived value — nothing suggests a new value to compute.
- No behaviour change and no file edited beyond the four in `Files:`; this is a
  prose re-sync, and `commands/production-status.md` is correct as it stands.
- Root `VERSION` gets a patch bump with a matching top `CHANGELOG.md` section;
  `./scripts/check-changelog.sh` is silent.

## Decisions
- Both files are done together for the same reason task 156 gave: they are one
  owner's prose, worded in step, and splitting them would leave the two halves
  drifted from each other instead of from the code.
- **Editing `.claude/domain/features/plan-readout.md` is explicitly authorised
  for this task (user decision, 2026-08-25), for the 2 reconciliations listed
  above and for nothing else. Do not ask for permission at implementation time —
  the permission is already granted.** That document is normally `/architect`'s,
  and anything beyond those points still belongs to `/architect`. These are
  factual reconciliations with shipped behaviour, not redesigns; if one turns out
  to need a design decision rather than a wording fix, stop and say so instead of
  deciding it here.
- Found by a code review of commit `5c8ada6` (task 156) on 2026-08-25.
