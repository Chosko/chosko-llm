# Task 152 — Add a REQUIRES column to `ls`

Target: claude

## Goal
`chosko-llm ls` shows NAME / KIND / INSTALLED / LATEST / STATUS but says
nothing about the `requires:` frontmatter field, so a dependency is only
visible by opening a feature file or hitting `rm`'s refusal. Add a sixth
REQUIRES column rendering each row's kind-prefixed specs, so the dependency
graph is readable straight from the listing.

## Acceptance criteria
- `chosko-llm ls` prints a sixth column `REQUIRES` after `STATUS`, in the
  header and in every one of the five listing passes (command, skill,
  claude-md, statusline, hook).
- `STATUS` becomes a padded column (wide enough for `migration pending`);
  `REQUIRES` is the final, unpadded column, so a long value never breaks
  alignment and needs no truncation.
- The cell holds the comma-separated kind-prefixed specs exactly as declared
  (`skill:task-engine`, `skill:a, command:b`), and a dimmed `—` when the
  feature declares none.
- The value is read from the managed-clone source file when it exists,
  falling back to the installed file otherwise — matching the LATEST
  column's bias, and giving a not-installed row its dependencies before
  `add`.
- A malformed entry (no kind prefix) does NOT abort `ls`: the row renders
  the raw offending entry dimmed and the listing continues. `add` and `rm`
  keep their current fatal behaviour, unchanged.
- `ls --installed`, `ls --available`, `ls --local` and `ls --global` all
  carry the column; the TTY-gated suggestions footer is unchanged.
- `docs/cli-help.txt` describes the new column.
- `VERSION` bumped minor (1.15.0 → 1.16.0 — the next minor after task 153's
  bump) with a matching top `CHANGELOG.md` section;
  `./scripts/check-changelog.sh` exits silent.

## Decisions
- **REQUIRES is always on, not behind a flag** (user decision). Only about
  9 of ~50 features declare `requires:`, so the column is mostly `—`, but a
  flag would add parsing, help text and a second output shape for little
  gain.
- **Last position, STATUS padded** (user decision). Avoids truncating a
  multi-spec value and keeps every existing column at its current width.
- **Clone-first source, installed as fallback** (user decision). Same bias
  as the LATEST column: it answers what the feature will require after an
  `update`, and gives a not-installed row a meaningful value.
- **Non-fatal on a malformed entry, raw entry shown dimmed** (user
  decision). `requires_specs` in `lib.sh` `die`s by design so `add` / `rm`
  catch a dangling reference at install time; `ls` is a read-only lister and
  must not be taken down by one typo in one unrelated feature. Implement it
  as a lenient sibling helper (or an opt-in parameter) in `lib.sh` rather
  than weakening `requires_specs` itself — `add` and `rm` must keep dying.
