# Task 95 — Support feature kind migration (command → skill) in the CLI

Target: claude

## Goal
Install is copy-based and never prunes, so a feature that changes kind
(`commands/<n>.md` becomes `skills/<n>/SKILL.md`) leaves a stale installed
command sitting next to the new skill under the same `/<n>` name — two
definitions of one slash command. Today `update --all` reports the stale
artifact as `Skipping command '<n>': no source in managed clone.` and leaves
it forever. Give the CLI a declarative migration path so the context-family
conversion (tasks 97–100) and every future kind change land cleanly on
existing installs.

## Acceptance criteria
- `parse_frontmatter` in `scripts/lib.sh` recognizes a fifth optional key,
  `replaces`, whose value is a kind-prefixed spec (`command:<name>`,
  `skill:<name>`, `claude-md:<name>`, `statusline:<name>`). Unset on every
  existing feature; absence changes nothing.
- `require_versioned_source` is unchanged — `replaces` is never required.
- Single-feature `chosko-llm update <spec>` / `chosko-llm add <spec>`: after
  the feature is installed, if its source frontmatter carries `replaces:`
  and that named artifact is installed, remove it and log one
  `Migrated <old-kind> '<name>' -> <new-kind> '<name>'` line. If it is not
  installed, do nothing and stay silent.
- `chosko-llm update --all`: when an installed artifact has no source in the
  managed clone, scan the managed clone for a feature declaring
  `replaces: <that-kind>:<that-name>` before emitting the existing
  `Skipping … no source in managed clone.` warning. On a hit, install the
  replacement and remove the stale artifact, logging the migration line. On
  no hit, the existing warning is emitted unchanged.
- Removal reuses the same deletion semantics as `cmd-rm` for the artifact's
  kind (`rm -f` command/statusline, `rm -rf` skill, `remove_section`
  claude-md).
- No new dependency, no lockfile, no state file. Bash + awk/sed/grep only.
- Every script touched still opens with `set -euo pipefail` and sources
  `lib.sh`; no `$CLAUDE_HOME` / `$CHOSKO_LLM_HOME` path is hardcoded.
- `docs/authoring-guide.md` documents `replaces:` — when to set it, the
  spec syntax, and that it should be dropped a release or two after the
  migration has propagated.
- Root `VERSION` bumped minor.
- Verified by running the real CLI against a clone: install the old kind,
  add the `replaces:` key to the new kind, run `update --all`, confirm the
  stale artifact is gone and the new one is installed.

## Decisions
- **Declarative frontmatter key, not a rename map or migration script.**
  A `replaces:` line lives with the feature that supersedes the old one, so
  the fact travels in the same git pull that ships the rename. A separate
  map file would be state outside the filesystem, which CLAUDE.md forbids.
- **`--all` resolves the migration from the stale side.** The replacement
  skill is not installed yet, so iterating installed artifacts is the only
  place the stale command is visible. Hooking the existing "no source"
  branch means no new iteration pass.
- **Fifth frontmatter key is accepted deliberately.** `shared-lib.md` notes
  that a fifth field means editing the `parse_frontmatter` awk regex; that
  is the intended cost here, not an accident.
