# Task 144 — Add the /runbook-suggest skill

Target: claude

## Goal

The last artifact of the `runbook-suite` feature
(`.claude/domain/features/runbook-suite.md`), and the one that addresses the
suite's only usability problem: the moment a runbook is worth writing is the
moment nobody thinks of it. A design conversation ends with seven follow-ups,
the session closes, and a week later they are re-derived from scratch — which is
exactly what happened before the reference file was written by hand. This skill
auto-triggers on that moment, emits one or two lines pointing at
`/runbook-create`, and stops.

## Acceptance criteria

- `skills/runbook-suggest/SKILL.md` exists and is the **only** file in the
  folder. Full frontmatter: `name: runbook-suggest`, `version: 0.1.0`, `type:
  skill`, a `description` (below), and `requires: command:runbook-create`.
- The body is small — roughly thirty lines — because its cost is paid whenever it
  loads, and a skill that by design loads on a guess must be cheap to be wrong.
- **The `description` is the trigger mechanism.** Claude Code selects a skill
  from its description, so the description *is* the mechanism: there is no hook,
  no `Stop` handler and no event registration, and the body says so. The
  description is adapted from the design's draft and carries both the trigger
  conditions and the anti-triggers, the way `claude-council`'s description
  already does with its "Not for: …" clause.
- **The threshold is carried in both the description and the body**: suggest
  only when the follow-ups would be **lost with the conversation** — three or
  more actions, or two or more with an ordering constraint, or any prompt that
  depends on decisions not recorded on disk. Never for a two-step list of simple
  prompts.
- **The anti-triggers are named explicitly**: a single next action; a list of
  things already done; a checklist the current session is about to work through;
  an enumeration inside an explanation; and a list of tasks that belong in the
  backlog, which is `/task-add`'s job.
- **It asks nothing.** No `AskUserQuestion`, no gate, no waiting — a question
  from an auto-triggered skill is an interruption at exactly the wrong moment.
- **The suggestion is generic.** It emits one or two lines suggesting
  `/runbook-create` — to turn the proposed follow-up actions into a new runbook,
  or to append them to an existing one — and stops. It **names no runbook**,
  does not say which runbooks exist, and does not say whether one is running.
  `/runbook-create` invoked with no options is what asks new-versus-append and
  lists the choices; that gate belongs to the command the user chose to run.
- **It reads no file, opens nothing, and writes nothing.** It does not look at
  `.claude/RUNBOOKS.md`, does not open a runbook body, creates no runbook, and
  never invokes `/runbook-create` itself. It proposes once.
- The body states that the fire rate is **tuned after observing real sessions**,
  that this is the accepted method for this artifact rather than an open
  question, and that the fix if it proves noisy is a narrower description — never
  a suppression flag.
- Every install path named uses `${CLAUDE_HOME:-$HOME/.claude}`; no path under
  `docs/` appears.
- Root `VERSION` takes a minor bump (new shipped skill), relative to whatever is
  in place when this lands.
- Nothing under `.claude/context/` or `.claude/domain/` is edited here — task
  145 owns both knowledge layers.
- No test suite by design: verify by reading the diff and confirming
  `./bin/chosko-llm ls --available` lists `runbook-suggest  skill  —  0.1.0`
  against a clone where `install.sh` has run.

## Decisions

- **Preconditioned on 141 as well as 140 and 125.** Its `requires:` edge names
  `command:runbook-create`, not the orchestrator, and it is the one judgment
  call in the feature's dependency graph: it cites no shared file and needs no
  schema, but a proposal is useless if the command it names is not installed,
  which is exactly what `requires:` exists to stop. It ships last per the
  document's ship order, so 140 is a precondition too.
- **It depends on the command alone and does not pull the whole suite in.**
  Resolution is one level deep (task 125), so installing this skill installs
  `runbook-create`, which is what the user then runs.
- **The suggestion names no runbook, and the skill reads nothing** — user
  decision 2026-08-24. The feature document's `/runbook-suggest` section asks
  for `--append <name>` to be mentioned when `RUNBOOKS.md` lists non-`[DONE]`
  runbooks and for the current runbook to be named; that is overruled in favour
  of the generic suggestion, which keeps the skill's "reads no file, writes no
  file" property literally true and leaves new-versus-append entirely to
  `/runbook-create`'s own no-argument gate. Task 145 corrects the document.
- **A skill, not a command**, because it must be selectable by Claude Code from
  its description without the user typing anything — which is the entire
  mechanism.
