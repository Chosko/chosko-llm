# Task 142 — Add the /runbook-list command

Target: claude

## Goal

The read side of the `runbook-suite` feature
(`.claude/domain/features/runbook-suite.md`): one pass over
`.claude/RUNBOOKS.md` that prints every runbook with its status, progress,
creation date and source, plus the reason a halted one halted. It never opens a
runbook body — which is why the index carries `Steps:` at all — so its cost is
flat in the number of runbooks rather than in their size.

## Acceptance criteria

- `commands/runbook-list.md` exists with full frontmatter: `name: runbook-list`,
  `version: 0.1.0`, `type: command`, a `description`, and
  `requires: skill:runbook-run`.
- The body cites
  `${CLAUDE_HOME:-$HOME/.claude}/skills/runbook-run/references/runbook-schema.md`
  for the status set and the index block shape, and carries **no second copy of
  either**.
- One pass: read `.claude/RUNBOOKS.md`, parse each block's five fields, apply an
  optional status filter, print. **It never opens a file under
  `.claude/runbooks/`.**
- Output is one line per runbook — status, name, `<done>/<total>` steps, created
  date, source — with a `↳ failed at step <n> — <reason>` continuation printed
  **only** for `[FAILED]` runbooks, and a trailing summary line counting the
  runbooks by status. The body carries the rendered example from the design so
  the shape is unambiguous.
- A missing or empty index is **not an error**: one line saying no runbooks
  exist and naming `/runbook-create`.
- The optional status argument is matched **without brackets and
  case-insensitively**, matching `/task-list`'s existing convention. An unknown
  status names the four valid ones rather than printing nothing — a silent empty
  result is indistinguishable from having no matching runbooks.
- The listing **writes nothing, runs no shell command, and corrects no status
  however wrong it looks.** Reconciliation belongs to the command that already
  has the body open, and the body says so.
- Every install path named uses `${CLAUDE_HOME:-$HOME/.claude}`; no path under
  `docs/` appears.
- Root `VERSION` takes a minor bump (new shipped command), relative to whatever
  is in place when this lands.
- Nothing under `.claude/context/` or `.claude/domain/` is edited here — task
  145 owns both knowledge layers.
- No test suite by design: verify by reading the diff and confirming
  `./bin/chosko-llm ls --available` lists `runbook-list  command  —  0.1.0`
  against a clone where `install.sh` has run.

## Decisions

- **`requires: skill:runbook-run` even though this command parses nothing the
  orchestrator owns.** The edge is about vocabulary, not parsing: the status set
  and the index block shape are specified once, in `runbook-schema.md`, and a
  listing carrying its own copy is the second copy that drifts.
- **Preconditioned on 140 and 125** for the same reason as every other consumer:
  the cited path and the declared requirement are both dangling before those
  land.
- **Never opening a body is a hard rule, not an optimisation** — it is
  `/task-list`'s existing discipline of never opening a file under
  `.claude/tasks/`, and it is the reason the index carries derived fields at
  all.
- **`Failed at:` is printed rather than looked up.** The one thing a reader of a
  halted runbook needs is why it halted, and making them open the file for a
  single sentence is the friction that stops the listing being used.
