# Task 127 — Migrate /task-list onto the task-engine

Target: claude

## Goal

Step 3 of the `shared-phase-engine` migration order
(`.claude/domain/features/shared-phase-engine.md`): the first consumer, and the
proof that the pattern works end to end. `/task-list` is the smallest of the
suite (240 lines) and read-only, so a regression is obvious and harmless — which
is exactly why the design puts it first. Replace its restated rules with
references to `skills/task-engine/references/`, declare `requires:
skill:task-engine`, and change nothing a user can observe.

## Acceptance criteria

- `commands/task-list.md`'s frontmatter carries `requires: skill:task-engine`,
  so `chosko-llm add command:task-list` installs the engine first.
- Its `LOCATING THE BACKLOG` and `STATUS TAGS` sections are replaced by
  references of the form
  `${CLAUDE_HOME:-$HOME/.claude}/skills/task-engine/references/<file>.md`,
  each followed only by what `/task-list` does **differently** from the shared
  rule. Nothing restates a rule the engine now owns.
- `/task-list` cites `resolution.md` and `status.md`. It cites neither
  `tree.md` nor `commit.md` — it is read-only and writes nothing — and the body
  keeps saying so.
- Everything genuinely unique to `/task-list` stays in its body verbatim: the
  usage header and examples, the `<STATUS>` filter, the ⚠ human-in-the-loop
  marker, the `[STALE]` marker, the `Feature:` slug column, and the whole
  `PLAN.md` milestone-grouping path with its blocked-feature flagging.
- **Observable behaviour is unchanged.** Same usage lines, same filter
  argument, same output format with and without a `.claude/PLAN.md`, same
  read-only guarantee that the per-task body files under `.claude/tasks/` are
  never opened.
- Verification is a before/after comparison, not an inspection: run `/task-list`
  and `/task-list MISSING` against this repo's own backlog before and after the
  migration and confirm the output is identical.
- The body is under 150 lines. This is a target, not the criterion — the
  criterion is that every rule the engine owns appears in `/task-list` exactly
  zero times.
- `commands/task-list.md` takes a minor frontmatter `version:` bump
  (expected `0.5.2` → `0.6.0`); root `VERSION` takes a patch bump, relative to
  whatever task 126 leaves in place.
- Nothing under `.claude/context/` or `.claude/domain/` is edited here — task
  131 owns both knowledge layers.

## Decisions

- **Minor frontmatter bump, not patch.** No behaviour changes, but
  `requires: skill:task-engine` means installing this command now installs a
  second feature — a real change to what a user gets, and the kind of thing
  `chosko-llm ls`'s version columns exist to signal.
- **Root `VERSION` patch bump.** No new feature and no CLI surface change; a
  behaviour-preserving restructure is a patch at repo level.
- **The reference path uses `${CLAUDE_HOME:-$HOME/.claude}`**, following the
  precedent the vendored `claude-council` skill already set in this repo, and
  the hard rule against hardcoding `~/.claude`.
- **`/task-list` first, exactly as the document orders it.** Its read-only
  nature bounds the blast radius of getting the reference form wrong on the
  first attempt.
