# Task 229 — Make `/pipeline-patch` and `/pipeline-revise` commit once, at the end

Target: claude

## Goal
Today both commands make no commit of their own and forward flags, so a
revision lands as one commit per owner step, or not at all. Instead they commit
by default and own the commit: every owner step runs uncommitted, and one commit
at the end holds the whole patch or revision.

## Acceptance criteria
- ARGUMENT PARSING in both: COMMIT true unless `--no-commit`; `--no-commit`
  implies NO_PUSH; `--commit` accepted no-op; the `--commit --no-commit` stop.
  Usage lines read `[--no-commit] [--no-push]`.
- Pull at start once per run, after anchor resolution and before the walk,
  unless `--no-commit`. No owner step pulls or pushes.
- Every owner step runs without committing: a command owner (`/task-add`,
  `/product-design`, `/production-plan`, `/runbook-create`, `/architect`)
  always receives `--no-commit`; an arm executed by path is executed with no
  commit. The COMMITTING forwarding table is replaced by this rule.
- After the last step and the closing check, stage exactly the union of the
  paths the owner steps reported writing, by explicit path, and make one
  commit, then re-sync and push per `commit.md` (push skipped under
  `--no-push`). Subject: for `/pipeline-patch` the arm's closing report line;
  for `/pipeline-revise` the `Revised <anchor> — <branch>, <tier>` report line.
  Nothing written → no commit.
- `/pipeline-revise` arm C (hand to `/runbook-create`) follows the same rule:
  `/runbook-create` runs with `--no-commit`, and the revise commits the
  runbook body and index as the one commit.
- A `/pipeline-revise` sequence that stops part-way (an owner refuses, or its
  gate is answered stop) commits nothing: the report lists every path written
  so far and says nothing was committed. A refusal, gate answer D, and a
  `--no-commit` run make no commit; only the pull at start (absent under
  `--no-commit`) touches git.
- WRITE SET / DO NOT / report wording no longer says "no commit of its own";
  "never stages a path no owner step wrote" is kept.
- `skills/pipeline-revise/delete.md`'s provenance sentence names the
  revision's one commit instead of "the commits the owner steps make".
- `routing.md` rows for both show `[--no-commit] [--no-push]`, and
  `/pipeline-revise`'s "earlier writes kept" precondition says they stay
  uncommitted.
- Frontmatter `version:` bumped on `pipeline-patch`, `pipeline-revise`,
  `pipeline-engine`; root `VERSION` + `CHANGELOG.md` section;
  `./scripts/check-changelog.sh` and `./scripts/check-routing.sh` pass.

## Decisions
- **A partial sequence is left uncommitted (user decision, 2026-09-15).**
  Committing half a revision would break the reason for the change — every
  commit holds a complete revision. The closing lint already reports the
  state the stopped sequence left.
- Owners always get `--no-commit` regardless of their own default, so the
  forwarding table no longer depends on each owner's default; a future
  default flip needs no edit here.
- Arm C is handled the same way, even though `/runbook-create` is the only
  writer on that path: one rule, not a special case.
- Pull once at the orchestrator: nested `--no-commit` runs skip their own
  pull, so without this pull a revision would start from a stale tree.
