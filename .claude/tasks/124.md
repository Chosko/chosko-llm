# Task 124 — Update documentation for feature task-peer-review

Target: claude

## Goal

Tasks 121–123 ship the `task-peer-review` feature: two new skills and a new
`--review` / `--rounds` loop inside `/task-implement`. Every layer that
describes the `task-*` suite still describes it without them — README's
backlog section, the authoring guide's commit-behaviour groups, the context
layer's shipped-artifact list, and the domain layer's task workflow — and the
feature document itself still carries open questions that tasks 121–123
settled. Bring the documentation in line with what shipped.

## Acceptance criteria

- `README.md`'s "Work through a backlog — the `task-*` commands" section gains
  `/task-review` and `/task-iterate` in its bullet list, and its
  `/task-implement` bullet mentions `--review [--rounds N]`. The section's
  commit-behaviour paragraph is updated: `/task-iterate` commits and pushes
  automatically when run standalone, and does not commit at all when run inside
  `/task-implement --review`, so a task still produces exactly one commit.
- `docs/authoring-guide.md`'s "Commit-and-push convention" adds `/task-iterate`
  to the auto-committing group, and states that `/task-review` belongs to
  neither group because it never commits anything.
- `.claude/context/features.md` gains entries for `skills/task-review/` and
  `skills/task-iterate/` in the same register as the surrounding entries — the
  three input forms, the confidence and Pre-Report gates, that zero findings is
  a valid review, the three severity tiers, the `remote-diffs.md` supporting
  file and when it is read, mandatory triage with its three verdicts, sticky
  rejections, and `/task-iterate`'s caller-dependent commit rule. Its
  `skills/task-implement/` entry is updated for the `--review` / `--rounds`
  loop, the new `review-rounds.md` supporting file (bringing its supporting-file
  count to the correct number), and the fact that the reviewer runs as a
  subagent while iterate runs in the main session.
- `.claude/context/INDEX.md`'s `Last updated` anchor is current.
- `.claude/domain/task-workflow.md` gains a section on the review loop in its
  own compressed register: the two skills and their division of labour, why the
  reviewer must be a fresh context, mandatory triage as the auditable
  replacement for a silent judgement, sticky rejections, the severity gate and
  the round bound, and — stated as an invariant, not a detail — that
  `/task-iterate` does not commit inside `/task-implement --review` so the
  one-commit-per-task rule survives. Its "Delegated runs" section notes that
  `--review` propagates to each implementor, which spawns its own reviewer, and
  that the parent still sees only the four returned fields.
- `.claude/domain/features/task-peer-review.md` is reconciled with what shipped
  on exactly these four points — editing it is authorised for this task, see
  Decisions:
  1. the branch-mode base open question is resolved as implemented (default to
     the repository's default branch, `base=<ref>` to override);
  2. the `--rounds`-on-`/task-review` open question is resolved as decided (it
     stays a `/task-implement` flag);
  3. the "Hard contracts" read-only bullet is reconciled with the opt-in
     `.claude/reviews/` file, so the document no longer states two things that
     conflict;
  4. the loop's placement is recorded as running before `/task-implement`'s
     Step 6, not between Steps 6 and 7.
  Nothing else in the document changes.
- Root `VERSION` takes a patch bump.
- `docs/cli-help.txt` is not edited: it documents `chosko-llm` subcommands and
  never enumerates individual skills, so nothing in it goes stale.
- No shipped feature body under `commands/` or `skills/` is edited here — tasks
  121–123 own those, and any needed change there is a bug in one of them, not
  this task.

## Decisions

- **Editing `.claude/domain/features/task-peer-review.md` is explicitly
  authorised for this task (user decision, 2026-08-24), for the four
  reconciliations listed above and for nothing else. Do not ask for permission
  at implementation time — the permission is already granted.** That document
  is normally `/architect`'s, and anything beyond those four points still
  belongs to `/architect`. These are factual reconciliations with shipped
  behaviour, not redesigns; if one turns out to need a design decision rather
  than a wording fix, stop and say so instead of deciding it here.
- **Patch bump, not minor.** Documentation-only; no shipped feature's behaviour
  changes in this task.
- **The one-commit-per-task invariant is documented as an invariant.** It is
  the least obvious rule in the feature and the easiest for a future editor to
  "fix" into symmetry, so both `README.md` and `task-workflow.md` state the
  rule together with its reason.
