# Task 303 — Add `/pipeline-revise --catch-up`

Target: claude

## Goal
Part of feature `quick-implement`. Add `/pipeline-revise --catch-up`, the
editorial mode that amends the documentation to match code that has already
landed — from a `/quick-implement` spec, or a free-form description of the
landed change — and deletes the spec in its commit.

## Acceptance criteria
- `/pipeline-revise --catch-up <spec-path | "<landed change>">` is parsed;
  a spec path that does not exist stops the run.
- `skills/pipeline-revise/catch-up.md`: walks impact as the other modes do,
  drives owner amend steps classified editorial (no task marked stale for a
  point the code settled); a point where the code breaks the design is listed
  in the plan as a question — amend the design to accept the code, or keep the
  design and insert a task — and the answer takes the ordinary amend or insert
  path.
- The run's one commit deletes the spec it was given; when a context layer
  exists and the landed change touched files it describes, the plan's last step
  is `/context-update`.
- The `/pipeline-revise` `routing.md` row states the mode (Consumes the spec,
  Argument shape, the spec deletion).
- `pipeline-revise` `version:` minor-bumped; root `VERSION` minor-bumped with
  a `CHANGELOG.md` section; `check-changelog.sh`, `check-home-paths.sh`,
  `check-routing.sh` pass.

## Decisions
- A separate `catch-up.md` branch file beside `amend.md` / `insert.md` /
  `delete.md` / `reorder.md`, loaded only on `--catch-up`.
- Lands after 285 (the gate rewrite in the same body) and 302 (the spec
  format it reads).
