# Task 230 — Update documentation for the new commit defaults

Target: claude

## Goal
Once tasks 227–229 ship, the docs still describe `/runbook-create` as an
uncommitted authoring command, `/session-save` as never committing, and
`/pipeline-patch` /
`/pipeline-revise` as making no commit of their own. Bring every description
into line with the shipped behaviour.

## Acceptance criteria
- `README.md`: the pipeline-revision sentence (one commit per revision,
  `--no-commit`), the runbook and session sections.
- `docs/reference.md`: the opening commit-conventions paragraph, the
  `/pipeline-patch` and `/pipeline-revise` usage and commit paragraphs, the
  runbook commit-behaviour paragraph, the session paragraph ("Neither command
  commits" — now only `/session-resume` commits nothing).
- `docs/authoring-guide.md` § Commit-and-push convention: `/runbook-create`
  and `/session-save` move to the auto-committing group; the
  orchestrator paragraph gains the pipeline pattern (steps run `--no-commit`,
  one commit at the end, partial runs uncommitted) beside `/project-setup`.
- `.claude/domain/product-workflow.md` § Commit and push and the revision
  provenance line.
- `.claude/context/features.md` rows for the four changed commands;
  `.claude/context/INDEX.md` `Last updated` refreshed.
- The owned documents below are reconciled with what shipped on exactly these
  9 points — editing them is authorised for this task, see Decisions:
  1. `.claude/domain/features/authoring-commit-default.md` — *Purpose* and
     *Non-goals* no longer list `/runbook-create` among the commands keeping
     the uncommitted default.
  2. `.claude/domain/features/pipeline-revision.md` — *Data and state*
     provenance names the revision's one commit instead of the commits each
     owner step makes.
  3. `.claude/domain/features/pipeline-revision.md` — *Interfaces* usage lines
     read `[--no-commit] [--no-push]`, and "makes no commit of its own" becomes
     the commit-at-end rule.
  4. `.claude/domain/features/pipeline-revision.md` — a sequence stopped
     part-way is left uncommitted.
  5. `.claude/domain/features/session-continuity.md` — the "Committing"
     non-goal is reversed for `/session-save`, which now commits and pushes
     by default; `/session-resume` stays read-only.
  6. `.claude/domain/features/session-continuity.md` — Pruning part 2:
     the superseded file's deletion rides in the save's commit.
  7. `.claude/domain/features/runbook-suite.md` — the authoring-default
     paragraph for `/runbook-create`.
  8. `.claude/domain/features/runbook-suite.md` — the
     `/runbook-create <args> --commit [--no-push]` usage line.
  9. `.claude/domain/product-design.md` — the "Gates keep the director in the
     reviewer's seat" decision no longer names the runbook-authoring commands
     among those adding a second pause.
  Nothing else in those documents changes.
- No `VERSION` bump and no `CHANGELOG.md` entry — documentation only.

## Decisions
- **Editing `.claude/domain/features/authoring-commit-default.md`,
  `.claude/domain/features/pipeline-revision.md`,
  `.claude/domain/features/session-continuity.md` and
  `.claude/domain/features/runbook-suite.md` (normally `/architect`'s), and
  `.claude/domain/product-design.md` (normally `/product-design`'s), is
  explicitly authorised for this task (user decision, 2026-09-15), for the 9
  reconciliations listed above and for nothing else. Do not ask for permission
  at implementation time — the permission is already granted.** Anything
  beyond those points still belongs to the owning command. These are factual
  reconciliations with shipped behaviour, not redesigns; if one turns out to
  need a design decision rather than a wording fix, stop and say so instead of
  deciding it here.
