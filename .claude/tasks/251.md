# Task 251 — `/architect amend`: a body read classifies, the stricter carried classification wins, several features per run

Target: claude

## Goal
Three sources of friction in the amend arm. A task body read to decide a
touched status makes the whole case ambiguous, so the arm asks even when the
body decided cleanly. A classification carried from `/pipeline-revise` that
disagrees with the arm's own derivation re-asks at a second gate. And one
editorial change mentioned in four feature documents costs four runs. Remove
all three.

## Acceptance criteria
- `skills/architect/amend.md` § 4 *Clear or ambiguous*: a body read that
  decides a task's touched status is a mechanical signal like a summary-block
  decision; only a body that still cannot decide keeps the case ambiguous, and
  that task is classified touched as today. The evidence line names the body
  read (`touched on body: <ids>`).
- § 4 *A classification carried from `/pipeline-revise`*: when the carried
  classification and the arm's own derivation disagree, the stricter one
  applies (not editorial over editorial), the closing line states the
  deviation (`carried: editorial; applied: not editorial — touched: <ids>`),
  and the arm never asks. The confirmation form is gone.
- `amend feature=<slug>,<slug>,... "<change>"` amends several features in one
  run: the change is scoped per feature (§ 2), the guard runs per feature
  (§ 3), one gate renders a section per feature with its own touched set,
  outcome and `Classified:` line, the `product-design.md` upstream edit is
  drafted once, a feature refused on a touched `[IN PROGRESS]` task is dropped
  from the run with one line and the rest proceeds, the write set and the
  closing line are per feature, and the run makes one commit. A slug that does
  not resolve stops the whole run before the gate, listing the slugs that
  exist.
- `skills/architect/SKILL.md` ARGUMENT PARSING accepts the comma-separated
  form and dispatches to the arm once.
- `skills/pipeline-revise/SKILL.md` step 8's paragraph on the carried
  classification describes stricter-wins and no longer mentions a confirmation
  form or an explicit reply.
- `skills/pipeline-engine/references/routing.md` `/architect` row: argument
  shape and preconditions describe the multi-slug form and the classification
  rule.
- `.claude/domain/features/owner-amend-arms.md` is reconciled with what ships
  on exactly these points — editing it is authorised for this task, see
  Decisions: (1) body reads classify; (2) stricter-wins replaces the
  confirmation form; (3) several features per run. Nothing else in the
  document changes.
- `docs/reference.md` § `/architect` and `.claude/context/features.md` describe
  the three changes.
- `skills/architect` `version:` minor bump; `skills/pipeline-revise` patch
  bump; root `VERSION` minor bump; `CHANGELOG.md` entry;
  `./scripts/check-changelog.sh`, `./scripts/check-routing.sh` and
  `./scripts/check-home-paths.sh` silent.

## Decisions
- Stricter wins because staling a surviving task costs one reconciliation
  while not staling a dead one costs a wrong implementation; the arm already
  applies that asymmetry to an undecidable body.
- **Editing `.claude/domain/features/owner-amend-arms.md` is explicitly
  authorised for this task (user decision, 2026-09-21), for the three
  reconciliations listed above and for nothing else. Do not ask for permission
  at implementation time.** The document is normally `/architect`'s; a change
  beyond those points is a design decision and stops the run to say so.
