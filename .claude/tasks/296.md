# Task 296 — Add `/session-list`

Target: claude

## Goal
Part of feature `session-readers`. Add `/session-list`, a read-only command
printing one line per handoff in `.claude/sessions/`, newest first, so the
right handoff can be found without opening files — in the shape of
`/runbook-list`.

## Acceptance criteria
- New `commands/session-list.md` with frontmatter `name: session-list`,
  `version: 0.1.0`, `type: command`, a short what+when `description:`, and
  `requires: command:session-save` (store layout and header schema).
- One line per candidate (top-level file carrying a `Work:` line), newest
  first by full filename descending:
  `<YYYY-MM-DD HH:MM>  <slug>  <Work: value>  — <first sentence of the next step>`.
- A pointer-form file prints `→ <Resume from: path>` in place of the next
  step and is marked as a pointer.
- A handoff with a `<session-file-stem>/` subfolder gets a trailing
  `[areas: <n>]`, n = number of `agent-*.md` files there, counted from
  filenames only; `pending/` and other subfolders are not sessions and are
  skipped silently.
- Read budget: one search (Grep tool) over the store for `Work:`,
  `Resume from:` and the exact-next-step section heading with the line after
  it; never a full read of any file, no shell command.
- Missing or empty store, or no candidate: one line saying so, no error.
- Writes, deletes, stages and commits nothing; corrects no file however
  malformed — a candidate missing a field prints what it has.
- Keeps to plain language; cites no interaction-policy reference.
- Root `VERSION` minor-bumped with a `CHANGELOG.md` section;
  `check-changelog.sh` and `check-home-paths.sh` pass; `./bin/chosko-llm ls
  --available` lists `session-list` 0.1.0.

## Decisions
- No arguments and no filter in this version: a session file carries no
  status (feature non-goal), and a date/slug filter is what `/session-describe`
  and `/session-resume` already resolve.
