# Task 277 — Harden the spawn relay against relay children that reply in-turn

Target: claude

## Goal
A `/runbook-run` run halted at step 101 with: "The review child it relayed
gave its review in its reply, but never wrote the result file and never ended
with DONE". Root cause is an instruction conflict: `/task-implement`'s
reviewer spawn prompt (`skills/task-implement/review-rounds.md` item 6) and
`/task-review` § OUTPUT DESTINATION tell a spawned reviewer to "return the
structured report to the caller and write nothing to disk", while
`RELAY CHILD RULES` tell a relay child to write its report to `<RESULT>` and
end with a bare `DONE`. The child obeyed the more specific skill. Fix it in
two layers: (1) remove the conflict, so the result file is the return channel
whenever the run's rules name one; (2) give the orchestrator a safety net, so
an unmarked relay-child turn gets the same single re-prompt a `DONE` child
with a missing result file already gets, instead of halting the run.

## Acceptance criteria
- `skills/task-review/SKILL.md` § OUTPUT DESTINATION, spawned-by-`/task-implement --review`
  branch: "return the report to the caller" means the return channel the
  run's rules name — when those rules name a result file (a relay child),
  writing the report there is how it is returned and is not the disk state
  "write nothing to disk" forbids. No other branch changes.
- `skills/runbook-run/references/subagent-contract.md` `RELAY CHILD RULES`
  carry one precedence line: `<RESULT>` is the return channel and overrides
  any instruction in the prompt file or the skill it invokes to reply in the
  turn or to write nothing to disk. The block stays verbatim-pasteable fixed
  text with the same placeholders.
- The same file's *Why each rule is in there* section gains a bullet for the
  precedence line, citing the step-101 incident (a reviewer whose skill said
  "write nothing to disk"), in the style of the existing step-83/85 bullets.
- `skills/runbook-run/SKILL.md` THE SPAWN RELAY § *The protocol* step 3: a
  child whose returned turn carries no marker (`DONE`, `QUESTIONS FOR USER`,
  `SPAWN REQUEST`) and is not a plain failure report gets the same single
  re-prompt as a `DONE` child with a missing/empty result file — same wording,
  not a relay round, not counted toward the cap, existence check only, file
  never opened. A plain failure report still fails the step immediately; a
  second miss (still unmarked, or result file still absent/empty) fails the
  step with the `Done:` line naming the relayed child and the missing file.
  The step 3 bullets are rewritten as one coherent set, not patched.
- Step agents' own unmarked turns are unchanged: THE FOUR RESULT CASES and
  "An ambiguous report is a failure" still halt on them.
- `.claude/domain/features/runbook-suite.md` states the agreed design change —
  the single re-prompt also covers a relay child whose turn carries no marker
  and is not a failure report — in every passage that stated the old one, and
  settles that `RELAY CHILD RULES` override an invoked skill's own output
  destination. Nothing else in the document changes.
- `docs/reference.md` (around the relay's existence-check paragraph, ~line
  1409) matches the new behaviour.
- `runbook-run` frontmatter 0.19.1 → 0.19.2, `task-review` 0.4.2 → 0.4.3,
  root `VERSION` 1.75.3 → 1.75.4, new `CHANGELOG.md` section on top.
  `./scripts/check-changelog.sh` and `./scripts/check-home-paths.sh` pass.

## Decisions
- **Design change agreed (user decision, `2026-10-01`):** `runbook-suite.md`
  § spawn relay — "a missing or empty file buys the same child one
  re-prompt" → the re-prompt also covers a child whose turn carries no
  marker and is not a failure report; a second miss fails the step. Settled
  here: `RELAY CHILD RULES` override an invoked skill's own output
  destination. `.claude/domain/features/runbook-suite.md` is normally
  `/architect`'s; this task updates it for exactly this and for nothing else.
  A further design decision met at implementation time is not covered: leave
  that passage untouched and name it under *Follow-ups* as a precise
  follow-up.
- **Both layers, not either.** Layer 1 removes the cause seen in step 101;
  layer 2 catches the next skill whose output rules clash with the relay.
  The relay has broken three times on child output discipline (steps 83, 85,
  101) — stricter wording alone has not held.
- **Explicit failure stays immediate.** Only an unmarked, non-failure turn is
  re-prompted: the child still holds its report in context, so one short turn
  recovers it. Re-prompting a declared failure would just invite a polite
  `DONE` on work that failed.
- **Step agents excluded.** Extending the re-prompt to a step's own agent
  would change the "ambiguous report is a failure" policy — out of scope.
- **Patch bump** — a fix to existing behaviour, no new surface.
