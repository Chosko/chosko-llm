# Task 183 — Add the single-task amend reference to `task-engine`

Target: claude

> Merged into task 182 on 2026-09-11; that body is the authority. This task is `[SKIP]` and awaits `/task-clean`.

## Goal
Feature `owner-amend-arms` gives each artifact owner a standalone amend file in
its own folder. The task suite's artifact is one task, and it has no amend arm
at all today — changing one task body is a command that does not exist. This
task adds `skills/task-engine/references/amend.md` as the eighth reference file
and the single authority for changing one existing task, so a consumer can
execute a targeted task change without loading `/task-add` or reimplementing its
guards.

## Acceptance criteria
- `skills/task-engine/references/amend.md` exists as a peer of the other seven
  reference files, and is complete on its own: it names its inputs, its single
  gate, exactly what it writes and its closing report line.
- It states which body sections may be rewritten and which summary-block fields
  may change.
- It states that `Preconditions:` may be rewritten to add or drop an edge, and
  that a dropped edge is named in the task's `## Decisions` so the removal has a
  written reason.
- It states that deleting a live task means `[SKIP]` with a reason, never
  physical removal — removal is `/task-clean`'s act over terminal statuses. It
  cites `./status.md` for the vocabulary rather than restating it.
- It states that `Feature:` may be added to an orphan task but never changed on
  a feature-derived one, because the feature's `Tasks:` line is the other half
  of that link and would have to move with it.
- It states the two checks a consumer makes before writing: the task is not
  `[IN PROGRESS]`, and the change does not alter what the task's feature
  document promises — the second case routes to `/architect amend` instead.
- It never touches `[DONE]` or `[SKIP]` work; follow-up work is a new task.
- It cites `./resolution.md`, `./status.md` and `./stale.md` by path and
  restates nothing they own, per the engine's one-authority discipline; any
  per-consumer divergence is recorded as a note, not as new shared rule text.
- `skills/task-engine/SKILL.md`'s map table gains a row for the new file, its
  `description:` says eight files rather than seven, and the sentence naming who
  may open the skill is widened to admit the pipeline revision surfaces.
- `skills/task-engine/SKILL.md`'s `version:` is bumped (minor), root `VERSION`
  is bumped, `CHANGELOG.md` gains a matching top section, and
  `./scripts/check-changelog.sh` is silent.

## Decisions
- **No unshipped command is named.** `skills/task-engine/SKILL.md` currently
  says only the five `task-*` features should ever open it; the amend
  reference's real consumers are `/pipeline-patch` and `/pipeline-revise`, which
  do not exist yet. The sentence is widened generically ("the pipeline revision
  surfaces read `references/amend.md` by path") and `pipeline-revision`'s own
  tasks add the names when those commands land — the same rule the
  `pipeline-engine` routing table follows, where rows exist only for shipped
  features.
- **A new peer file, not a section inside `status.md` or `resolution.md`.** The
  amend protocol spans several of those files; putting it inside one of them
  would give it two homes and break the one-authority discipline the engine
  exists to hold.
- **`Preconditions:` is `none`.** Rewriting a `Preconditions:` edge is an
  operation on a field that already exists, so this file does not wait on
  `backlog-ordering`'s selection change (task 169) or its `--before` / `--after`
  placement (task 171).
