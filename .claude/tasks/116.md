# Task 116 — Delete-not-append design-process.md content once a run ends

Target: claude

## Goal
`.claude/domain/design-process.md` (written by `/product-design`) only ever
grows. A real project's file shows why: five dated
`### PHASE N revision — <date>` blocks, `[SUPERSEDED — see ...]` markers
that keep old decision text verbatim instead of deleting it, a
`### Closing record` essay, and a "Current stage" block that ballooned from
the template's 1-2 sentences into a multi-paragraph changelog — none of
this is spec'd anywhere; sessions invented it ad hoc because **no protocol
exists for amending a design after PHASE 7 completes.** Almost all of it
was only useful while that particular round was in flight — the decision
itself is already durably recorded in `product-design.md` /
`technical-direction.md` / `business-model.md`; git history is the record
of how the file got there (the design-process.md content itself already
says this once, for retired product-name candidates: "full list preserved
in git history, not re-listed here" — that instinct just isn't applied
anywhere else). Once a round ends — PHASE 7 finishing the first time, or a
later ad hoc amendment — the surrounding scaffolding should be deleted, not
kept and not merely shortened. Only what is genuinely worth remembering
(durable WHY that would otherwise be lost, one line each) survives.

## Acceptance criteria
- `document-templates.md`'s `design-process.md` template states the rule
  plainly: "Decisions worth keeping" is a flat, undated bullet list of
  terse one-line entries (the call + a brief why) — never dated
  sub-headers, never `[SUPERSEDED]`-tagged verbatim retention, never a
  closing-record essay. A superseded entry is deleted outright when the new
  decision lands, not marked and kept.
- The template states "Current stage" stays 1-2 sentences plus short
  per-document one-liners and a next step, **regardless of how many
  amendment rounds have run** — it is rewritten each time, never grown into
  a changelog.
- `/product-design` PHASE 7 compresses `design-process.md` down to this
  shape — deleting everything that doesn't clear the "worth remembering"
  bar — immediately before writing the process-complete marker, and the
  final report says so.
- `resuming.md` gains the missing entry point: when PHASE 0 finds a
  `design-process.md` already marked process-complete, resuming.md offers a
  third path alongside Resume/Start-fresh — **amend a decision** — for a
  targeted change that doesn't warrant re-running phases. That path edits
  the relevant document(s) directly (`product-design.md` /
  `technical-direction.md` / `business-model.md`), then applies the same
  delete-not-append compression to `design-process.md` before the session
  ends, so an amendment leaves the file the same size shape it found it in,
  not larger.
- `docs/authoring-guide.md`'s generic "state that outlives a session"
  pattern section states the same delete-on-round-end rule, so a future
  resumable skill built on this pattern inherits it.
- `.claude/domain/product-workflow.md` and `.claude/context/features.md`
  descriptions of `design-process.md` mention the compression and the new
  amend path.

## Decisions
- Deletion, not summarization-into-a-ledger: per direct user steer, most
  mid-run detail is not worth keeping in any form once the round ends —
  only durable, otherwise-lost WHY survives, tersely. Everything else
  (alternatives enumerated, meeting narrative, dated headers, verbatim
  superseded text, closing records) is cut; git history is the fallback
  record, matching a convention the file already uses once for product
  names.
- Compression fires at the end of **any** round that touches
  design-process.md — the original PHASE 7, and the new amend path —
  not just the first completion, since the real growth mostly happened
  through undocumented post-completion amendments.
- The amend path lives in `resuming.md` as a third option (Resume /
  Start-fresh / Amend) rather than a new CLI flag, since `design-process.md`'s
  presence is already the sole signal this skill uses to route a re-invocation
  — consistent with "There is no `resume` argument… the document is the
  state."
- Per earlier confirmed choice, the rule also lands in
  `docs/authoring-guide.md`'s generic reusable-pattern section, not just
  product-design's own files.
