# Task 190 — Write the `pipeline-revise` delete branch

Target: claude

> Merged into task 187 on 2026-09-11; that body is the authority. This task is `[SKIP]` and awaits `/task-clean`.

## Goal
Removing planned work is the branch where the temptation to delete is
strongest and most damaging. This task writes
`skills/pipeline-revise/delete.md`, which maps removal onto the vocabularies
that already exist — `[SKIP]` for a task, a struck step for a runbook,
`[SKIP]` plus a `/production-plan` reconciliation for a whole feature — so that
history is never lost from a live index.

## Acceptance criteria
- `skills/pipeline-revise/delete.md` exists and is complete on its own: a
  consumer that has read `./SKILL.md` and this file can execute the branch end
  to end.
- Task removal is `[SKIP]` with a reason recorded in the task body, through
  `task-engine`'s amend reference. Physical removal is never performed here;
  it stays `/task-clean`'s explicit act over terminal statuses, and the file
  says so.
- Runbook-step removal is a strike — `[x]` with a `Done:` line opening
  `struck — <reason>` and no commit sha — through `runbook-run`'s step-amend
  reference. A step is never deleted and never renumbered.
- Feature removal is `[SKIP]` on every one of its live tasks followed by a
  `/production-plan` run, whose reconciliation drops the edges. The feature's
  `FEATURES.md` entry stays, with its ids intact.
- `[DONE]` work is never reopened, re-statused or removed, in any of the three
  shapes.
- Direction rules stated: a deletion walks *forward* to the successors whose
  `Preconditions:` name the removed id — each such edge is dropped through the
  task amend reference, and the drop is named in that task's `## Decisions` —
  and *upward* to the feature document that promised the deleted scope.
- Tier logic stated: deleting a task no other entry names is *local*; a
  deletion that crosses artifacts, or that drops an edge, is *structural*.
- The branch-specific half of the verification bracket is stated: after
  actuation the successor tasks' bodies are read to confirm the sequence still
  reads as a sequence.
- The branch writes nothing itself; every step names the arm it delegates to,
  by path.
- No new status value and no change ledger: `[SKIP]`, struck steps and the
  owners' commits are the provenance, and the file says so explicitly.
- `./SKILL.md`'s SUPPORTING FILES table gains its `./delete.md` row.
- Root `VERSION` bumped, `CHANGELOG.md` top section matches,
  `./scripts/check-changelog.sh` silent.

## Decisions
- **Feature removal keeps the entry.** The feature document's non-goals rule
  out physical deletion; an entry whose tasks are all `[SKIP]` and whose edges
  `/production-plan` has dropped is inert without erasing what was planned or
  why.
- **`/production-plan` is invoked, not imitated.** Dropping an edge by hand
  would make the reviser a writer of `PLAN.md`, which the feature's hard
  contract forbids; the reconciliation the plan already performs on every run
  is the sanctioned path.
- **A dropped edge is always narrated.** `task-engine`'s amend reference
  requires the drop to appear in the successor's `## Decisions`; the branch
  states that the reason names the deletion, so a later reader can see why the
  precondition vanished.
