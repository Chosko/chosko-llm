# Task 188 — Write the `pipeline-revise` amend branch

Target: claude

## Goal
The amend branch is the reviser's most common path: something that already
exists changes, and everything that depends on it has to be brought along.
This task writes `skills/pipeline-revise/amend.md` — the impact walk's
direction rules in both directions, the owner sequence that orders the writes,
and the tier logic, for a change that alters an existing artifact rather than
adding or removing one.

## Acceptance criteria
- `skills/pipeline-revise/amend.md` exists and is complete on its own: a
  consumer that has read `./SKILL.md` and this file can execute the branch end
  to end.
- Top-down rules stated: from a design section or a feature document to the
  tasks carrying that `Feature:`, the `PLAN.md` edges naming the slug, and the
  runbook steps naming the slug or one of its task ids.
- Bottom-up rules stated: from a task to the feature document that promised it,
  when its `Feature:` slug resolves in `FEATURES.md`. A `Feature:` slug that
  resolves to nothing, or an absent one, stops the upward walk and the task is
  treated as free-form — not an error.
- The owner sequence is fixed and stated, upstream first: `/product-design`'s
  amend arm, then `/architect amend`, then task bodies through
  `task-engine`'s amend reference, then runbook steps through `runbook-run`'s
  step-amend reference. No downstream step is written against a state a later
  step changes.
- Tier logic stated: *editorial* — wording only, nothing downstream changes
  meaning; *local* — one artifact plus the entries that merely name it;
  *structural* — scope changes, or a downstream entry's contract changes. The
  tier drives how long the owner sequence is; it never decides whether the gate
  is asked.
- The branch adds no read of its own beyond the anchor scope `./SKILL.md`
  already fixes.
- The branch writes nothing itself. Every step names, by path, the arm it
  delegates to.
- No new status value: the outcomes are `[STALE]`, `[ITERATED]` and the
  owners' existing flips, and the file says so.
- `./SKILL.md`'s SUPPORTING FILES table gains its `./amend.md` row with an
  "exactly when".
- Root `VERSION` is bumped and `CHANGELOG.md` gains a matching top section;
  `./scripts/check-changelog.sh` is silent.

## Decisions
- **The owner sequence runs upstream first.** The feature document fixes the
  set of owners but not their order. Writing a task body before the feature
  document that governs it would have the task amended against a promise about
  to change, which is the drift this feature exists to prevent.
- **A feature document change routes through `/architect amend`, never
  through the full skill.** The precision iterate guard is the whole point of
  task 182; the blanket guard would stale tasks the change does not touch.
- **An orphan task is walked, not refused.** A task with no resolvable
  `Feature:` is common on projects that never ran `/architect`; the branch
  amends it and stops the upward walk rather than treating it as drift.
