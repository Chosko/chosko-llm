# Task 179 — Add the `/pipeline-check` command

Target: claude

## Goal
Add `commands/pipeline-check.md` — the read-only drift report that makes the
silent cost of a mishandled amendment loud. None of the pipeline's indexes reads
the others for consistency, so a task whose `Feature:` names a deleted slug, or
a precondition pointing at a skipped task, sits there until an implementer hits
it. This command probes the project per `probes.md`, reads exactly the indexes
the probe found, evaluates `lint.md`'s catalogue over `graph.md`'s edges, and
prints each finding with the one command that fixes it. It reports; it fixes
nothing.

## Acceptance criteria
- Frontmatter is complete: `name: pipeline-check`, `version: 0.1.0`,
  `type: command`, `requires: skill:pipeline-engine`, and a `description:` that
  states the read-only register and the `feature=<slug>` form.
- The body cites all four reference files as
  `${CLAUDE_HOME:-$HOME/.claude}/skills/pipeline-engine/references/<file>.md`
  and never a `docs/` path — `docs/` is authoring-time-only and is not installed.
  It restates no probe, no edge and no finding; it states only its own
  deviations, the `task-engine` discipline verbatim.
- The read-only register is stated explicitly and in the same register
  `/production-status` uses: writes nothing, creates nothing, commits nothing,
  flips no status, opens no file under `.claude/tasks/` — **`.claude/tasks/archive/`
  named explicitly among them** — `.claude/runbooks/` or
  `.claude/domain/features/`, and runs no shell beyond the probe.
- Every absent index removes its findings rather than failing the run. The only
  stop is a project carrying none of the indexes at all, which is pointed at
  `/task-setup` and `/domain-setup` and stops there.
- A clean project prints exactly one line.
- Findings are grouped by artifact, in a fixed artifact order, each rendered
  from `lint.md`'s output template and each carrying its fix command verbatim.
  The run ends with one summary line counting `ERROR` and `WARNING` findings.
- `feature=<slug>` scopes the walk to that feature and to the tasks, plan edges
  and runbook steps that name it. An unknown slug lists the slugs that do exist
  rather than reporting an empty clean run.
- An unrecognised argument is reported in one line and the default report still
  runs — the command never refuses over its own arguments, matching
  `/production-status`.
- The command is invoked explicitly and by nothing else: the body carries no
  instruction for another feature to call it, and nothing in this task edits
  another feature to do so.
- `./bin/chosko-llm ls --available` lists `command:pipeline-check` at `0.1.0`
  with `skill:pipeline-engine` in the REQUIRES column, and
  `./bin/chosko-llm add command:pipeline-check` into a scratch `CLAUDE_HOME`
  installs `skill:pipeline-engine` first.
- Root `VERSION` takes a **minor** bump and `CHANGELOG.md` gains a matching top
  section; `./scripts/check-changelog.sh` exits zero.

## Decisions
- A command, not a skill: a thin read-only reporter with no conversation and no
  supporting files is exactly the register `/task-list` and `/production-status`
  occupy, and the design names it a command.
- The probe may shell out; nothing else in the run may. That is the one stated
  departure from `/production-status`, which runs no shell at all, and the body
  says so rather than leaving a reader to infer it.
- The archive folder is named in the read prohibition rather than left implied
  by `.claude/tasks/`. It is a subfolder of a path already forbidden, but naming
  it is what stops a later reader treating it as a separate store that the
  prohibition happened not to mention.
- No `--fix`, no `--quiet`, no exit-code contract. The lint reports and every
  fix is the named owner's; an exit code would invite a caller to gate on it,
  which is the auto-running the design rules out. The severity counts are for a
  human's eye, not a gate.
- `.claude/domain/features/pipeline-engine.md` is read-only in this task.
