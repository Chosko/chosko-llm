# Task 85 — Hard-refuse non-claude Target tasks in the unattended task-impl orchestrator

Target: claude

## Goal
scripts/cmd-task-impl.sh's unattended orchestrator (chosko-llm task-impl)
never checks a task's `Target:` field. Interactive /task-implement gates
`claude+human`/`human` tasks behind human-in-loop.md's checkpoint protocol
(pause, explain the manual step, verify before continuing) — but the
unattended path hands such a task straight to aider with no warning,
silently skipping every manual-intervention checkpoint the task's body may
declare. This mirrors the existing `[STALE]` refusal (implement_one's
case statement, scripts/cmd-task-impl.sh ~line 230) in spirit: an
unattended, non-interactive orchestrator cannot make the judgment calls
that gate needs, so it must refuse rather than proceed. Add the same
hard-refuse treatment for any task whose `Target:` is not `claude`.

## Acceptance criteria
- `implement_one()` in scripts/cmd-task-impl.sh refuses (dies with a clear
  message) any task whose Target field is `claude+human`, `human`, or
  `local` — mirroring the existing `[STALE]` case's structure and message
  style (name the task number, state why, point at the interactive path:
  "implement it interactively via /task-implement instead"). Only
  `Target: claude` proceeds.
- The up-front "Validate all targets up front" loop (scripts/cmd-task-impl.sh
  ~lines 177-186) also checks Target for every task in the batch before any
  task starts, so `task-impl all` (or an explicit multi-task run) fails fast
  on the whole batch rather than partway through, consistent with how that
  loop already validates task existence.
- A `task_target` convenience helper is added to scripts/lib-task-external.sh
  alongside the existing task_status/task_files/task_title helpers (task_field
  "$1" Target), since Target is already mirrored into the TASKS.md summary
  block per commands/task-add.md's schema.
- Existing `[STALE]` refusal behavior and all currently-passing
  MISSING/STUBBED/INCORRECT/PARTIAL + Target:claude tasks are unaffected.

## Decisions
- Refuse rather than warn-and-skip (per explicit instruction): a task with
  a non-claude Target left running unattended is a correctness risk (a
  Manual interventions section aider cannot execute), not a soft skip like
  an out-of-scope status.
- `local` (the --enrich schema's Target for local-LLM bodies) is refused
  here too, since chosko-llm task-impl drives aider with the standard
  implement/tests prompts, not the enriched-body flow — treat it as
  out-of-scope for this orchestrator rather than silently mishandling it.
