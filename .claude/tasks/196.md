# Task 196 — Put the archive rule in `resolution.md`, rewrite `/task-clean` as a skill that archives, and add `--backfill`

Target: claude

## Goal
Feature `task-archive` (.claude/domain/features/task-archive.md) stops
`/task-clean` deleting a pruned task's body: it moves to
`.claude/tasks/archive/<N>.md` carrying a frozen header, the feature that
generated the task keeps naming it on its `Tasks:` line, and an id that is
referenced but absent from `TASKS.md` comes to mean "archived and terminal".
This task ships the archive mechanism whole, in three pieces that are one
change:

1. **The rule's single home.** `skills/task-engine/references/resolution.md`
   — which already owns where the backlog lives, the summary-block schema and
   when a body file may be opened — gains the archive location, the
   archived-file form and the archived-and-terminal rule every consumer will
   cite. `pipeline-engine` (task 175) cites this rule and lands after this
   task for that reason.
2. **The migration and the move.** `commands/task-clean.md` becomes
   `skills/task-clean/SKILL.md`, because `--backfill`'s procedure must sit in a
   supporting file the ordinary prune never loads and a command is a single
   file that can carry nothing beside it. The prune moves each body instead of
   removing it and stops touching `.claude/FEATURES.md`.
3. **The recovery mode.** `/task-clean --backfill` reads git history, restores
   each body earlier runs deleted into `.claude/tasks/archive/`, and puts the
   recovered id back on its feature's `Tasks:` line where the slug still
   exists. The procedure lives in `skills/task-clean/backfill.md`.

Written together, `SKILL.md` is authored once against a shape that includes
the flag, `commit.md`'s `/task-clean` note is written once, and the feature
takes one `VERSION` bump. What the *readers* of an absent id do about it is
task 199.

## Acceptance criteria

### `skills/task-engine/references/resolution.md` and `skills/task-engine/SKILL.md`
- `resolution.md` gains a section on the archive stating its location
  (`.claude/tasks/archive/<N>.md`, the task's id as the file name), that the
  folder is created by the archiving run and is append-only, and the archived
  file's form: the original body unchanged, plus a frozen header of the same
  `Key: value` lines the body already uses for `Target:`, directly under the
  title — `Archived:` (`YYYY-MM-DD`), `Status:`, `Files:`, `Preconditions:`,
  and `Feature:` when the task had one. Nothing else is derived or added, and
  the header is written once and never updated.
- The same section states the rule every consumer will cite, in one sentence:
  an id referenced anywhere but absent from `TASKS.md` is archived and
  terminal; no command probes the folder, opens an archived file, or reports
  on its contents, except when the user names a task and asks to read it.
- It states that absence is the whole signal: no reader verifies the file is
  there, and a hand-deleted body is indistinguishable from an archived one by
  design — the difference surfaces only when the user asks to read the task,
  at which point a missing file says so itself.
- § *Opening a per-task body file* is reconciled with that: the paths it
  governs are `.claude/tasks/<N>.md` only, and nothing in it opens a file
  under `archive/`.
- `/task-list`'s per-consumer note is left as it stands — its existing "must
  NOT open any file under `.claude/tasks/`" already covers `archive/`, and a
  second prohibition would be a second copy.
- The `/task-clean` per-consumer note is rewritten for the skill this task
  ships: the single reason it opens a body file is to probe that the file
  exists before planning its **move**, not its deletion, and the prune path
  does not open `.claude/FEATURES.md` at all — the skill's only
  `FEATURES.md` write is the `Tasks:` restoration under `--backfill`.
- The `/task-add` per-consumer note records that reconciliation leaves an
  absent id unclassified and keeps it when the `Tasks:` line is rewritten.
- `skills/task-engine/SKILL.md`'s map row for `references/resolution.md` names
  the archive alongside what it already owns; no rule text is added to
  `SKILL.md`, and its own `version:` is bumped.
- No other file under `references/` restates any part of the rule.

### `skills/task-clean/SKILL.md` (new) and `commands/task-clean.md` (deleted)
- `skills/task-clean/SKILL.md` carries the whole of today's
  `commands/task-clean.md` prune flow, with frontmatter `name: task-clean`,
  `version: 0.9.0`, `type: skill`, `replaces: command:task-clean`,
  `requires: skill:task-engine`, and a description that says the effect is an
  archive, not a deletion, and names the `--backfill` mode.
- `commands/task-clean.md` is deleted in the same commit. `replaces:` is what
  retires an already-installed command copy on `add` / `update`; no script
  changes.
- PHASE 1's plan names the destination `.claude/tasks/archive/<N>.md` for each
  pruned task. A destination that already exists is refused in the plan rather
  than overwritten — ids are unique, so it can only mean a hand-placed file.
- PHASE 2 moves each body rather than removing it, as a VCS rename (`git mv`,
  or the `## VCS` mapping's equivalent), so history follows the file, and
  writes the frozen header into the moved file from the summary block the plan
  already parsed: `Archived:` (the run's date), `Status:`, `Files:`,
  `Preconditions:`, and `Feature:` when the task had one. The form is cited
  from `resolution.md`, never restated.
- The rest of the prune is unchanged: the summary block still leaves
  `TASKS.md`, survivors' `Preconditions:` still drop the pruned ids (an
  archived precondition is a satisfied one), no survivor is renumbered, and
  `Last task number:` is untouched.
- Every step that read or wrote `.claude/FEATURES.md` on a prune is gone —
  PHASE 1 step 4b, PHASE 2 step 4b, the plan's "Feature Tasks: lines to
  update" block, the feature half of PHASE 2's re-check and of the report, and
  the two DO-NOT bullets about feature `Status:`. In their place one explicit
  statement: a prune does not open `.claude/FEATURES.md`, because a feature
  keeps every id it ever generated and `Tasks: none` means what it says.
- A body already missing at prune time is noted in the plan and archived as
  nothing; its summary block still leaves `TASKS.md`.
- A missing `.claude/tasks/archive/` is created, never an error.
- A non-terminal prune set named explicitly archives the same way; the frozen
  `Status:` records that the task was pruned live. The `[STALE]` warning and
  the default terminal pair are unchanged.
- Under `--no-commit` the move is still a rename in the working tree, and the
  report says what moved where.
- The ARGUMENT NOTE accepts `--backfill`, sets the mode and strips it, and
  refuses the flag combined with a status set with a named message.
- `SKILL.md` reads `./backfill.md` exactly when the flag is present, in one
  sentence, and carries none of the procedure itself. An ordinary prune loads
  nothing extra — verify by reading `SKILL.md` end to end for any backfill
  detail that leaked out of the supporting file.
- Nothing from `resolution.md` is copied into the skill: the backlog
  resolution, the archive location, the archived-file form and the
  archived-and-terminal rule are all cited by
  `${CLAUDE_HOME:-$HOME/.claude}/skills/task-engine/references/...` path, and
  the skill states only its own deviations.
- No path under `docs/` is named as something to read at run time.

### `skills/task-clean/backfill.md` (new)
- Carries the whole procedure:
  - **Discovery** — every body under `.claude/tasks/` that git history records
    as deleted, taking the latest deletion per path, dropping ids that are live
    in `TASKS.md` or already in the archive.
  - **Recovery** — the body from the deleting commit's parent, and the frozen
    header from that parent's `TASKS.md` summary block, with `Archived:` set to
    the deleting commit's date so the header tells the truth about when the task
    left the backlog. A body whose block cannot be found — a hand deletion — is
    archived with `Archived:` alone and flagged in the plan.
  - **Feature link** — a recovered block carrying `Feature: <slug>` whose slug
    still exists in `.claude/FEATURES.md` puts the id back on that feature's
    `Tasks:` line, ascending. A slug that no longer exists is reported, not
    written. No other field of `FEATURES.md` is touched, and no feature
    `Status:` changes.
- States that this is the only `.claude/FEATURES.md` write left in the skill
  and that it exists only on this path.
- Backfill runs behind the same plan-and-**"Apply?"** gate as a prune, commits
  per the same protocol, and is never triggered by a prune — it is an explicit
  act, in the register `/pipeline-check` sets for one-off checks.
- A project whose VCS is not git stops, naming the limit; there is no `cm`
  port.
- A second run finds nothing to recover and says so rather than reporting an
  empty success.
- The archived-file form and the archived-and-terminal rule are cited from
  `resolution.md`, not restated.

### `skills/task-engine/references/commit.md` — the `/task-clean` note
- The prune's message form becomes `task-clean: archive tasks <N>[, <M>, …]`,
  staging is `.claude/TASKS.md` plus, per archived task, both the old and the
  new path, `.claude/FEATURES.md` no longer joins it on a prune, and the move
  replaces the `rm` as the one shell use outside PHASE 3.
- The backfill specifics are recorded in the same note: its own message form
  (`task-clean: backfill <N> archived tasks`), the archive paths it stages, and
  that `.claude/FEATURES.md` joins the staged paths on this path and only on
  this path.

### `claude-md/git-commit-style.md`
- Its example list names `task-clean: archive tasks …` instead of
  `task-clean: remove tasks …`, and its own `version:` is bumped.

### Versions
- Root `VERSION` takes **one minor** bump and `CHANGELOG.md` gains **one**
  matching top section naming the kind change, the delete → archive change and
  the `--backfill` mode; `./scripts/check-changelog.sh` is silent afterwards.

## Decisions
- **One task for the archive mechanism.** Planned as three tasks (196–198) and
  merged on 2026-09-11 (user decision). The rule, the skill that produces
  archives and the mode that recovers them are one shape; splitting them had
  `SKILL.md` written at `0.9.0` and rewritten at `0.10.0` within one release,
  and `commit.md`'s note edited twice. The readers (task 199) and the
  documentation (task 201) stay separate.
- `resolution.md` gets exactly one writer in this feature. Its per-consumer
  notes are statements of this rule's shape, so splitting them across the
  tasks that touch each consumer would put several writers on one file for a
  handful of lines. Each consumer still states its own deviation in its own
  body (task 199); this file stays the mirror the engine already keeps.
- The rule ships before anything that cites it. Task 175 (`pipeline-engine`)
  preconditions on this task so `graph.md` and `lint.md` cite a rule that
  exists.
- The skill continues the command's version line (`0.8.0` → `0.9.0`) rather
  than restarting at `0.1.0`, matching the `context-build` / `context-update`
  migrations, which kept theirs across the same `replaces:` path. The feature
  is the same feature; only its kind changed. `--backfill` ships inside that
  same bump rather than as a second one.
- The prune's `FEATURES.md` step is removed outright rather than made
  conditional. Leaving ids on the `Tasks:` line is the whole second half of the
  feature: it is what makes `Tasks: none` mean "never planned" again, and a
  conditional would keep the ambiguity alive on some runs.
- The removed DO-NOT bullets are replaced by one positive statement rather
  than dropped silently. A prohibition that disappears reads as an oversight;
  the reason a prune never opens `FEATURES.md` now is different from the reason
  it never changed a feature's `Status:` before.
- The commit-message form changes to `archive` (user decision at planning
  time): nothing is removed any more, and the two places that echo the template
  by name — `claude-md/git-commit-style.md` here, `docs/authoring-guide.md` in
  task 201 — are both already in this feature's scope.
- The supporting file is referenced relatively (`./backfill.md`) from
  `SKILL.md`, matching `/task-implement`'s `./delegated-runs.md` and
  `/architect`'s supporting files, rather than by a
  `${CLAUDE_HOME:-$HOME/.claude}` path — a skill reading its own folder needs
  no home resolution.
- The `FEATURES.md` write stays inside `backfill.md` rather than in `SKILL.md`.
  The prune's whole point is that it never opens that file; a write described
  in the always-loaded body would invite exactly the read it removed.
- Non-git projects get a plain stop, per the feature's stated non-goal, not a
  best-effort recovery from some other history source.
- Minor on root `VERSION`: the user-visible effect of a shipped command
  changes, the artifact kind changes with it, and a new mode reaches the user.
