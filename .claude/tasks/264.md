# Task 264 — `/runbook-run` parks a step under the `unattended` policy

Target: claude

## Goal
Part of feature `unattended-parking`. Give `/runbook-run` the policy and the
behaviour behind it: `--attended` / `--unattended` / `--skip-parked`, the
one preamble sentence a step agent reads under `unattended`, and a reference
`skills/runbook-run/references/parking.md` — loaded only under `unattended`
or when a `[P]` step is selected or blocks selection — holding the fifth
result row, the no-deadlock end branch, unparking, the launch pre-ask,
mid-run answers and the rejections. Two conditional lines join the
OPERATING RULES, with their inline equivalents. Under `attended` a question
still relays and waits.

## Acceptance criteria
- ARGUMENTS gains `--attended`, `--unattended` (mutually exclusive — both is
  an argument error; either overrides the header's `Execution policy:`) and
  `--skip-parked` (requires `--unattended`); the header value resolves the
  policy when neither flag is passed; a header value outside the two words
  is an argument error naming it. Usage header and examples list them.
- The reference-file table gains `./references/parking.md` — read once when
  the policy resolves to `unattended`, or when step 3 selects a `[P]` step or
  finds one blocking selection; a default attended run that meets no `[P]`
  never loads it.
- THE SPAWNED PROMPT part 1: under `unattended`, and only then, the preamble
  carries one sentence declaring the run unattended, in the slot
  `--relay-spawns` uses; the sentence says *unattended*, not
  *non-interactive*.
- `parking.md` specifies: the **fifth result row**, active only under
  `unattended` — `QUESTIONS FOR USER` → mark `[P]`, append the `parked:`
  bullet with the block's question and options (never a draft), print the
  question in chat with a number handle, write the index `Parked:` line,
  commit, continue; the **selection branch** — steps remain, none
  selectable, at least one `[P]`: not a deadlock, not a failure; the run ends
  with the index `[PENDING]` and the closing report naming the parked steps
  and the steps waiting on them; **unparking** — append `unparked with
  answer:` and set `[ ]`; the step sits above the current one and ordinary
  top-down selection picks it next, stated as a rule; when the step's prompt
  is a `/task-implement` on a `[PARKED]` task the answer is recorded on the
  step only and the task unparks when the step executes; the **pre-ask** at
  launch under `unattended` unless `--skip-parked` — every `[P]` step in
  range, question verbatim, numbered, answered or skipped per item or for
  all, `approval gate` items skip-only, answers written to `Context:` at
  once; **mid-run answers** by number handle or step name, recorded and
  selected next, any other message ordinary conversation; the **rejections**
  — an answer to a question never printed this run, and a second answer to
  an answered step, rejected with one line and recording nothing; a `[P]`
  step under `attended` (parked by an earlier run) asked when reached, in
  the fixed relay block.
- Step 3 (Select) cites the parking branch; step 8 and THE FOUR RESULT CASES
  cite the fifth row; the `[P]` marker is committed per COMMIT CADENCE.
- `subagent-contract.md`'s OPERATING RULES gain two rules conditional on the
  preamble declaring the run unattended: before ending with `QUESTIONS FOR
  USER`, leave the tree clean of your own changes — work a skill parked on a
  branch is not yours — and say so in the block; an answer recorded in your
  `Context:` answers the invoked skill's question — answer it from there,
  never relay it back. Their rationale bullets are added. `inline-contract.md`
  carries the same two for an inline session.
- `--inline` composes with the three flags; `--skip-parked` beside
  `--attended` is an argument error.
- The frontmatter description and the usage header say what the policy does
  in one clause each.
- `runbook-run`'s frontmatter `version:` bumped (minor); root `VERSION`
  bumped (minor) with a matching `CHANGELOG.md` section;
  `./scripts/check-changelog.sh` and `./scripts/check-home-paths.sh` pass.

## Decisions
- No `PARKED` marker from the agent: the orchestrator classifies on policy
  plus the existing `QUESTIONS FOR USER`; the agent's contract stays
  fixed text with conditional rules.
- Runbook steps never save work-in-progress; a task's branch is the task's.
- Attended runs have no pre-ask; they ask when reached.
