# Task 135 — Record the `.claude/skills/` exemption to the VERSION bump rule

Target: claude

## Goal
First step of the `repo-local-audits` feature
(`.claude/domain/features/repo-local-audits.md`). That feature puts two audit
skills under this repo's own `.claude/skills/`, where they are unversioned and
installed nowhere. CLAUDE.md's Versioning section currently says to bump root
`VERSION` on **every** shipped change, with no carve-out — so the next session
to touch one of those files will bump for a file no user receives, which
corrupts the meaning of the version `install.sh` reports. Record the exception
before the files that need it exist.

## Acceptance criteria
- CLAUDE.md's `## Versioning` section gains one bullet recording the exception:
  skills under this repo's own `.claude/skills/` are repo-local development
  tooling — unversioned (no `version:` frontmatter), invisible to every CLI
  verb, installed nowhere — and a change confined to them does not bump root
  `VERSION`. The reason is stated, not just the rule: bumping for a file no
  user receives corrupts the meaning of the version `install.sh` reports.
- The exemption is worded **narrowly**, naming `.claude/skills/` and saying in
  the same bullet that the rest of `.claude/` — context layer, domain layer,
  backlog — is unaffected and bumps as usual. A general "repo-local artifacts
  are exempt" wording is wrong here and must not be used: tasks 131 and 134 bump
  `VERSION` for `.claude/domain/` edits.
- The existing three bullets of the Versioning section are left intact; this is
  an addition, not a rewrite.
- Root `VERSION` takes a patch bump. CLAUDE.md is the repo's governing document
  and every prior task-driven CLAUDE.md edit bumped — the new exemption does not
  cover it, by construction.
- Nothing else is touched. `README.md` and `docs/authoring-guide.md` restate the
  bump rule and will disagree with CLAUDE.md until task 138 lands; that is
  deliberate and recorded under Decisions.
- No file is created under `.claude/skills/` here. This task lands inert; task
  136 is the first consumer.
- No test suite by design: verify by reading the diff.

## Decisions
- **CLAUDE.md only, deliberately.** `README.md` § Development → Authoring
  features and `docs/authoring-guide.md` § Versioning both restate the
  bump-on-every-shipped-change rule and are brought in line by task 138. The
  transient inconsistency spans one feature's task set; widening this task would
  make the cheapest and most losable change in the set the largest one.
- **Narrow wording over general.** Naming `.claude/skills/` and excluding the
  rest of `.claude/` explicitly, because the surrounding directories are
  precisely the ones that do bump.
- **This task bumps `VERSION` itself.** Not a contradiction: the exemption is
  scoped to `.claude/skills/`, and CLAUDE.md is not in it. Stated here so a
  later reader does not read the bump as a mistake.
