# Task 109 — Add slice-aware input resolution to /architect

Target: claude

## Goal
Teach `/architect` its second resolution mode, from feature
`slice-aware-architecture`: when the target project has a roadmap, a target
resolves to a **scope slice** — one milestone's share of a high-level feature
— and the feature documents written are scoped to that slice. Ships
`skills/architect/sliced-input.md`, the activation probe and per-target
dispatch in `SKILL.md`, the `--no-slices` escape hatch, and the optional
` (<milestone-slug>)` suffix on `FEATURES.md`'s `Source:` field. Every
low-level feature then belongs to exactly one slice and every slice to exactly
one milestone, which is the property `production-plan` is built on.

## Acceptance criteria
- `skills/architect/sliced-input.md` exists, carrying slice mode only:
  resolution, disambiguation, exclusions flowing into non-goals, and the
  extended `Source:` format. It duplicates none of `sectioned-input.md`'s
  scaffolding.
- **Activation probe:** slice mode activates on the presence of
  `.claude/domain/product-roadmap.md` carrying at least one milestone with a
  `Covers:` line. No flag file, no settings key, no frontmatter switch.
- **Dispatch is per target feature, not per run.** One invocation may
  architect several targets; each resolves independently, so a section with no
  slice takes the traditional path even on a roadmapped project.
- `SKILL.md`'s SUPPORTING FILES table lists both modes with a branch
  condition, replacing task 108's unconditional `sectioned-input.md` row.
  Neither file is read speculatively.
- **Slice resolution** in `sliced-input.md`, in order: find every slice whose
  section matches the target; one match → architect it; several across
  different milestones → ask which, listing each with its milestone and scope
  statement; the user may name the milestone in the invocation to skip the
  question; take the slice's scope statement as a boundary, with its
  exclusions becoming the feature document's **non-goals**; record the
  milestone in `Source:`.
- The union of several slices is NEVER architected, and a milestone is never
  guessed.
- **`Source:` extension:** `Source: product-design.md § Authentication (m1-mvp)`.
  The parenthetical is optional, absent on traditional-mode features and on
  `Source: prompt` features. Backward compatible — every existing entry stays
  valid and readers ignoring the suffix keep working.
- `skills/architect/feature-doc-template.md` documents the optional suffix in
  both the entry example and the by-line ownership table. `/architect` remains
  the field's only writer.
- **`--no-slices`** parsed alongside `--commit` / `--no-push`, forcing
  traditional mode on a roadmapped project. On a project with no roadmap it is
  a silent no-op.
- **Failure contract, exactly as specified:** no roadmap, or no `Covers:` line
  → traditional mode, silently (not a warning); roadmap present but target
  section unsliced → traditional mode for that target, stated in one line;
  section sliced across several milestones with none named → ask; a slice
  whose section is absent from `product-design.md` → architect it anyway and
  warn once.
- **Nothing else in `/architect` changes.** The gate, PHASE 0b's iterate
  guard, the interrupted-session marker, PHASE 1, PHASE 2's conversation,
  PHASE 3's write rules and the commit protocol are untouched. `PLAN.md` is
  never read. `product-roadmap.md` is never written.
- No new document template section — the feature document's non-goals section
  already exists; only its source of content is new.
- `skills/architect/SKILL.md` frontmatter `version:` bumped minor (0.5.1 →
  0.6.0), and its `description` updated to name slice mode and `--no-slices`.
- Root `VERSION` bumped minor.

## Decisions
- **Preconditions 106 and 108.** 106 ships `/product-roadmap` and the
  milestone/`Covers:` schema this task resolves against — a hard dependency
  per the feature document. 108 creates the `sectioned-input.md` seam this
  task branches from.
- **Slice identity stays the `(milestone, section)` pair.** No fourth
  identifier vocabulary, matching task 106's schema decision.
- **Section-heading matching left to implementation.** The feature document
  flags prose-versus-exact-heading matching as an open question; resolve it in
  `sliced-input.md` and record the choice there rather than deferring it.
- **`--no-slices` is per run, not per target.** Unsliced sections already fall
  back on their own, so no evidence yet justifies the finer grain — recorded
  as an open question in the feature document.
