# Task 258 — `chosko-llm`: a `skills/<dir>` with no `SKILL.md` is unmanaged, not a missing feature

Target: claude

## Goal

Claude Code keeps account-synced skills in `~/.claude/skills/synced/<bucket-id>/`,
a directory that holds no `SKILL.md` of its own. Every enumeration of installed
skills in this CLI tests only that a directory exists, so the bucket is read as
a feature: `ls` prints `synced  skill  —  —  not installed`, `update --all`
warns `Skipping skill 'synced': no source in managed clone.`, `show synced`
dies `No feature named 'synced' found`, and `rm skill synced` would `rm -rf`
the directory with the user's synced skills inside it. Make the installed-skill
test `SKILL.md` presence, hold it in `lib.sh`, and have the four consumers
agree: such a directory is installed but unmanaged — listed, inspectable,
never removed.

## Acceptance criteria

- `scripts/lib.sh` holds one predicate for "this directory is a skill this CLI
  manages" — `SKILL.md` present — and `artifact_is_installed skill` calls it
  instead of testing `[ -d skill-dir ]`, so `apply_replaces` →
  `remove_installed_artifact` can never `rm -rf` an unmanaged directory.
- `chosko-llm ls` renders an unmanaged skill directory as `INSTALLED
  unversioned`, `LATEST —`, `STATUS local only` (cyan). No new status value is
  added. The row is not counted as installable and appears in no footer `add`
  hint.
- `chosko-llm show <name>` reports such a directory instead of dying with
  `No feature named '<name>' found`: the same status and version columns as
  the `ls` row, the directory's path, and one line stating it is not managed by
  this CLI and cannot be removed with it.
- `chosko-llm rm skill <name>` refuses before deleting anything, naming the
  directory unmanaged. `--force` does not override that refusal — the flag
  overrides the dependents guard, not this one.
- `chosko-llm update --all` passes over an unmanaged skill directory in
  silence: no `no source in managed clone` warning.
- Managed features are unaffected in all four commands. On a home with no
  unmanaged directories, `ls` output is byte-identical to before the change.
- `.claude/context/cmd-ls.md`, `.claude/context/cmd-show.md` and
  `.claude/context/shared-lib.md` state the rule and name the predicate.
- Root `VERSION` takes a patch bump with a matching `CHANGELOG.md` section;
  `./scripts/check-changelog.sh` is silent afterwards.

## Decisions

- **The predicate lives in `lib.sh`, not in four scripts.** `cmd-ls`,
  `cmd-show`, `cmd-rm` and `cmd-update` each carry their own installed-skill
  test, and they already disagree: `cmd-rm.sh:113` iterates
  `skills/*/SKILL.md` while `cmd-rm.sh:145` checks `[ -d ]`. One predicate is
  what keeps them from drifting apart again.
- **Rendered, not hidden (user decision, 2026-09-22).** Dropping the row
  entirely was the alternative. A directory Claude Code loads skills from is
  something the user has installed, so `ls` reports it as `local only` /
  `unversioned` rather than pretending the filesystem is empty there.
  `local only` already means "present here, absent from the clone", which is
  exactly true of it, so the status vocabulary does not grow.
- **`show` joins this task (user decision, 2026-09-22).** `ls`'s footer always
  ends with `Run 'chosko-llm show <feature>' to inspect a feature`, so a listed
  row that `show` rejects is a dead end, and the two commands would disagree
  about the same directory.
- **`rm` dies, `update --all` stays quiet.** Removal is destructive and
  explicitly aimed, so it earns an error that names why. `update --all` is a
  sweep over everything installed, where a warning per unmanaged directory is
  noise.
- **The fork budget still binds.** The added per-row test is a bash `[ -f ]`,
  not a `$(...)` — `.claude/context/cmd-ls.md`'s fork-budget rule applies to
  this change like any other.
