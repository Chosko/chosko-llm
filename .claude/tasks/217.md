# Task 217 — Recommend an answer at `/architect amend`'s editorial gate, derived from its own touched set and scope call

Target: claude

## Goal
`skills/architect/amend.md` § 4 asks the editorial question with no guidance, so
the user re-derives an answer the arm has already computed: the gate renders the
touched set and the scope call, and outcome B differs from outcome A only when
the touched set is non-empty or scope was added. Mark the letter those two
findings imply, with a one-line evidence statement, so the user confirms or
switches rather than re-deriving. The recommendation is derived, never judged —
no new inference enters the arm.

## Acceptance criteria
- § 4's gate marks one letter as recommended, in both forms of the question —
  the full question and the `/pipeline-revise` carried-answer confirmation —
  reusing the existing marked-letter mechanism rather than adding a second one.
- The derivation is written as a closed rule, not a judgement: touched set empty
  and no scope added → A; otherwise → B.
- When A is marked on an empty touched set with no scope added, the gate states
  that A and B write the identical set, and still offers both letters so the
  classification can be overruled.
- The evidence line cites only what gate items 2–3 already render — a task id, an
  edited section, or the named scope item — and never an adjective.
- Where a carried answer from `/pipeline-revise` exists it remains the marked
  letter; the arm's own derivation appears only when it differs, as one line.
- The question is still asked on every amendment, a `[NEW]` feature's included;
  items 1–3 still render in full; an explicit reply is still required.
- Silence, an unclear reply or EOF is still C, and no flag pre-answers it.
- The touched-`[IN PROGRESS]` refusal still fires before the gate, unchanged.
- § Never's "Infer whether a change is editorial, or skip the question because
  the answer looks obvious" is rewritten to ban skipping and to ban treating the
  recommendation as an answer, carved out as the carried answer already is.
- `skills/architect/SKILL.md`'s `description:` and the `/architect` guard cell in
  `skills/pipeline-engine/references/routing.md` state the recommendation;
  frontmatter `version:` 0.10.1 → 0.11.0.
- `.claude/domain/features/owner-amend-arms.md` is reconciled with what shipped
  on exactly these 3 points — editing it is authorised for this task, see
  Decisions:
  1. § Non-goals, "Deciding editorial versus semantic" — the arm still asks every
     time, and the non-goal narrows to: no classification is ever *applied*
     without an explicit answer.
  2. § Architecture, the one-gate bullet — the gate also marks the letter its
     touched set and scope call imply, with its evidence line.
  3. § Interfaces, hard contracts — silence is still Stop, and a recommendation
     is never a default.
  Nothing else in the document changes.
- Root `VERSION` 1.44.1 → 1.45.0 with a matching top `CHANGELOG.md` section;
  `./scripts/check-changelog.sh` exits clean.

## Decisions
- **Derived, not judged.** The arm gains no new inference: the marked letter is
  arithmetic on the touched set and the scope call it already computes and
  already shows, which is why it does not breach the standing "never inferred"
  contract.
- **Reuse the shipped mechanism.** Task 216's carried-answer confirmation is
  already a marked letter that requires an explicit reply; this generalises its
  source rather than inventing a second rendering.
- **No `--assume-editorial` flag.** A flag would be pre-answering, and would
  remove the overrule the gate exists for.
- **Minor bump** (user decision, 2026-09-15) — new user-visible gate behaviour,
  not a fix.
- **Editing `.claude/domain/features/owner-amend-arms.md` is explicitly
  authorised for this task (user decision, 2026-09-15), for the 3
  reconciliations listed above and for nothing else. Do not ask for permission at
  implementation time — the permission is already granted.** That document is
  normally `/architect`'s, and anything beyond those points still belongs to
  `/architect`. These are factual reconciliations with shipped behaviour, not
  redesigns; if one turns out to need a design decision rather than a wording
  fix, stop and say so instead of deciding it here.
