# Task 267 — Update documentation for feature `unattended-parking`

Target: claude

## Goal
Feature `unattended-parking` is shipped once tasks 259–266 land, and the
documentation describing `/runbook-run`, `/task-implement`, the task status
vocabulary, the runbook schema and the closing reports is then out of date:
it still describes a question as halting the run, four step markers, eight
status tags, and a *Needs you* group followed by a `/follow-ups` call. Bring
the user-facing docs, the context layer, the domain workflow document and the
owned feature documents named below into line with the shipped behaviour.

## Acceptance criteria
- `README.md` and `docs/reference.md` describe the `attended` / `unattended`
  policy, the `--unattended`, `--attended` and `--skip-parked` flags on both
  skills, `[PARKED]` and `[P]`, the pre-ask, answering by number, and the
  closing report as For the record then Follow-ups; `docs/cli-help.txt` is
  untouched unless it lists skill flags.
- `.claude/domain/task-workflow.md` § closing report and its *Needs you*
  mentions read Follow-ups; the status vocabulary paragraph lists `[PARKED]`
  with a pointer to `parking.md`.
- `.claude/context/features.md` entries for `runbook-run`, `task-implement`,
  `task-engine`, `task-list`, `task-clean`, `pipeline-check`,
  `runbook-create`, `runbook-list`, `runbook-describe` and `follow-ups`
  reflect the new files, flags, markers and report shape; `INDEX.md`'s
  `Last updated` anchor is advanced.
- The agreed design change is written into every passage of the four owned
  feature documents that stated the old design, and nothing else in them
  changes:
  - `.claude/domain/features/runbook-suite.md` states five markers, the
    `Parked:` line, the `Execution policy:` header, the unattended fifth
    result row, and one Follow-ups list;
  - `.claude/domain/features/task-implement-launcher.md` states the attended
    relay, the `[PARKED]` return and UNATTENDED in the flag list;
  - `.claude/domain/features/runbook-inline.md` § The question relay gains
    the inline equivalents of the two contract lines, and its closing-report
    sentence reads For the record then Follow-ups;
  - `.claude/domain/features/task-peer-review.md`'s *Needs you* mention
    reads Follow-ups.
  Each passage cites `unattended-parking.md` rather than restating it.
- No `VERSION` bump and no `CHANGELOG.md` entry: the change is confined to
  project documentation and the domain and context layers.

## Decisions
- **Design change agreed (user decision, 2026-09-23):** `runbook-suite.md`
  four markers / four statuses / relay-and-wait / *Needs you* → five markers,
  `Parked:` line, `Execution policy:`, the unattended fifth result row, one
  Follow-ups list; `task-implement-launcher.md` stop-and-report and six
  fields → attended relay, `[PARKED]` return, UNATTENDED in the flag list;
  `runbook-inline.md` question relay and report order → the inline contract
  lines and For the record then Follow-ups; `task-peer-review.md` *Needs
  you* → Follow-ups. Those documents are normally `/architect`'s; this task
  updates them for exactly this and for nothing else. A further design
  decision met at implementation time is not covered: leave that passage
  untouched and name it under *Follow-ups* as a precise follow-up
  (`/architect amend feature=<slug> "…"`).
