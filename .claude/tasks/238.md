# Task 238 — Document `/follow-ups` and the runners' closing call

Target: claude

## Goal
Bring the documentation layers up to date with tasks 236 and 237: the new
`/follow-ups` command, and the closing call both runners now make. Nothing
user-facing behaves differently as a result, so this task is documentation
under CLAUDE.md § Versioning and bumps no `VERSION` and writes no
`CHANGELOG` entry.

## Acceptance criteria
- `README.md` names `/follow-ups` where the command set is introduced, in
  the register the surrounding entries use.
- `docs/reference.md` gains a `/follow-ups` entry, and its `/runbook-run`
  and `/task-implement` sections say the run ends with the closing call.
- `.claude/context/features.md` gains `commands/follow-ups.md`, records its
  `requires:` relationship from the two runners' side, and notes the
  routing row.
- `.claude/context/INDEX.md`'s `Last updated:` anchor moves.
- `.claude/domain/features/runbook-suite.md` is reconciled with what shipped
  on exactly these 2 points — editing it is authorised for this task, see
  Decisions:
  1. Its run-end description (`when no [ ] steps remain, set the index to
     [DONE] and report`, and the bound cases beside it) does not mention the
     closing `/follow-ups` call, nor that it fires at a bound, at a
     user-requested mid-run stop and at a failure halt as well as on
     completion.
  2. Its statement of the orchestrator's job — reads only CLAUDE.md, the
     runbook and the index; never reads a child's report — needs the one
     carve-out that at run end the orchestrator does read the step reports,
     for follow-ups.

  Nothing else in the document changes.
- `.claude/domain/features/task-implement-launcher.md` is reconciled with
  what shipped on exactly these 2 points — editing it is authorised for this
  task, see Decisions:
  1. Its list of what still happens in the parent at the end of the run
     (alongside the batched feature-completion proposal) does not include the
     closing `/follow-ups` call.
  2. It does not record that under `--agents` the parent's follow-up reading
     draws on the per-agent result reports, nor that a listed follow-up may
     be forwarded back to its originating agent.

  Nothing else in the document changes.
- No `VERSION` bump and no `CHANGELOG.md` section — this task is confined to
  documentation, and CLAUDE.md § Versioning exempts it.
