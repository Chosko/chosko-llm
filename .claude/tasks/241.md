# Task 241 — Rewrite the pipeline-core descriptions to the contract; hide the two reference libraries

Target: claude

## Goal
Apply the description contract task 240 wrote into `docs/authoring-guide.md`
to the 20 pipeline-core features: the `task-*` suite, the `pipeline-*`
surfaces, `follow-ups`, `production-status`, the stage skills
(`domain-setup`, `product-design`, `product-roadmap`, `architect`,
`production-plan`) and the two reference libraries. Every flag, refusal,
read-only contract or commit default removed from a description must already
be, or be moved to, that body's leading `#`-comment header, so the agent loses
nothing at run time. The two reference libraries (`task-engine`,
`pipeline-engine`) are read by path and never invoked, so they leave the
model's context entirely.

## Acceptance criteria
- Every `description:` in the Files list is within the contract's budget:
  ≤ 60 words / 400 chars for the manual features; `pipeline-suggest` ≤ 150
  words / 1,000 chars with its trigger phrases first and "Not for" last.
  None contains ` --- `.
- Each stage feature carries exactly one clause placing it in the pipeline,
  in the form the guide fixes (e.g. "Stage 3 of the pipeline: turns a design
  section into feature documents; its output is /task-add's input"). The
  multi-sentence "sits between X and Y" prose currently repeated across
  `architect`, `product-design`, `product-roadmap`, `production-plan`,
  `task-add` and `production-status` appears nowhere.
- `skills/task-engine/SKILL.md` and `skills/pipeline-engine/SKILL.md` carry
  `disable-model-invocation: true`; their descriptions drop the "NOT a skill
  the user invokes and never a skill to suggest" prose and its consumer list,
  keeping one line saying what they are and who reads them.
- `commands/domain-setup.md` carries `disable-model-invocation: true`.
- `skills/task-review/SKILL.md` and `skills/task-iterate/SKILL.md` carry no
  `disable-model-invocation`; `task-implement --review` spawns them by name
  through the Skill tool (`skills/task-implement/review-rounds.md`).
- For every feature, each flag or argument named in the old description is
  present in the body's `#` header after the change (diff the old
  description's `--flag` / `key=<value>` / backticked-word set against the
  new header).
- Each touched feature bumps its own `version:` (patch); root `VERSION` patch
  bump with a `CHANGELOG.md` entry; `./scripts/check-changelog.sh`,
  `./scripts/check-home-paths.sh` and `./scripts/check-routing.sh` silent.

## Decisions
- **Per-stage clause only; no `claude-md` pipeline-map artifact.** The user
  wants the agent to keep a map of the whole pipeline without paying for it
  six times over. One clause per stage feature gives the map at ~20 tokens
  each; a shared artifact stays a follow-up if the map still feels thin.
- **`domain-setup` joins the hidden set.** It is a one-shot scaffold and the
  stage-1 skills already say "requires /domain-setup", so the map keeps it.
- **`task-review` / `task-iterate` stay model-invocable** even though their
  descriptions shrink; the invoking prompt is explicit, so a one-liner is
  enough for the Skill tool to find them.
- **Descriptions are a patch bump per feature.** No behaviour changes; the
  frontmatter key on the libraries is the one new behaviour and rides the
  same patch.
