# Task 204 — Move `/product-design` and `/production-plan` into the commits-by-default row of both forwarding tables

Target: claude

## Goal
`/pipeline-patch` and `/pipeline-revise` each carry a forwarding table whose
rows are grouped by the owner's commit default — the one place in the
product where a command records another command's default on its behalf.
Tasks 202 and 203 change four of those defaults, so the tables must move
`/product-design` and `/production-plan` out of the "commits nothing by
default" row and into `/task-add`'s row. A default that changes without its
forwarding row changing produces exactly the failure the tables exist to
prevent: a revision run committing when the user did not ask.

The design is `.claude/domain/features/authoring-commit-default.md`; read it
first, in particular § *The two consumers* and § *The by-path arm keeps no
default*.

## Acceptance criteria
- In `skills/pipeline-revise/SKILL.md` § COMMITTING, `/product-design` and
  `/production-plan` are no longer in the row headed "A command that commits
  nothing by default". They are in the row with `/task-add`: without
  `--commit` the step is forwarded `--no-commit`; with `--commit` it is
  forwarded no flag, plus `--no-push` when given.
- `/runbook-create --append` stays in the commits-nothing-by-default row —
  its default is unchanged by this feature.
- In `commands/pipeline-patch.md` § COMMITTING, the table's column headings
  and rows no longer assert that an owner whose default changed commits
  nothing without `--commit`.
- The **arm executed by path** row is unchanged in both files. An arm —
  `architect/amend.md`, `task-engine/references/amend.md`,
  `runbook-run/references/step-amend.md` — asserts no default of its own and
  leaves the commit to whoever executes it. That is what lets the patcher
  run an arm without inheriting a command's habits, and this task must not
  disturb it.
- Both files still state that they make no commit of their own and stage no
  path an owner step did not write.
- Both frontmatter `version:` fields bump.
- Root `VERSION` is bumped with a matching new top section in
  `CHANGELOG.md` dated the day of the change; `./scripts/check-changelog.sh`
  is silent.
- `./scripts/check-routing.sh` is silent — no feature is added, renamed,
  removed or re-kinded, and no `requires:` line changes.

## Decisions
- **This task waits on 202 and 203** (`Preconditions:`). Shipped content
  never states a default that has not shipped, so the tables are corrected
  only once the owners actually commit by default.
- **`/architect` gets no row of its own.** The two consumers reach it only
  through its amend arm, which is executed by path and is therefore already
  covered by the unchanged arm row.
- The forwarding tables are the contract, not a description: correcting them
  is part of this feature rather than follow-up documentation.
