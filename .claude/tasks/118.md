# Task 118 — Delete the dead dual-LLM local-model implementation lane

Target: claude

## Goal

`chosko-llm` ships a second implementation lane that drives a local model
(aider + Ollama, `qwen2.5-coder:14b`) through the task backlog, alongside the
Claude lane. It has never been used. Verified 2026-08-24 across the full git
history of four repositories: this repo has 109 `Target:` lines under
`.claude/tasks/` (108 `claude`, 1 `claude+human`, 0 local), and factotum (55),
job-hunter-cli (48) and IsThisFreedom (3) contribute another 165, again 0 local
— roughly 274 task authorings in 110 days with the lane never invoked once. It
costs ~1,700 lines spread across shell scripts, three shipped feature bodies,
the CLI surface, the docs and both knowledge layers, and it is the largest
single obstacle to the `task-*` restructuring work queued behind it. Delete it,
keeping the `Target:` field and its three live values intact.

## Acceptance criteria

- These files no longer exist: `scripts/cmd-task-impl.sh`,
  `scripts/lib-task-external.sh`, `scripts/check-task-parity.sh`,
  `commands/task-enrich.md`, `.claude/context/cmd-task-impl.md`,
  `.claude/context/lib-task-external.md`,
  `.claude/external/implement-prompt.md`, `.claude/external/tests-prompt.md`.
- `bin/chosko-llm` has no `task-impl` case; `chosko-llm task-impl 1` exits 2
  with the unknown-subcommand message. Neither `docs/cli-help.txt` nor
  `scripts/cmd-help.sh`'s fallback heredoc mentions it.
- `chosko-llm ls --available` no longer lists `task-enrich`, and lists every
  other feature at its correct version.
- `/task-add` has no `--enrich` flag: the flag parsing, the PHASE 0
  `commands/task-enrich.md` existence gate, the enriched-body schema section,
  the `--enrich` PHASE 1 step, and every `--enrich` mention in its usage header
  and frontmatter `description` are gone. Its `Target:` value list reads exactly
  `claude`, `claude+human`, `human`.
- `Target: local` appears nowhere under `commands/`, `skills/`, `scripts/`,
  `docs/`, `README.md`, `CLAUDE.md`, `.claude/context/` or `.claude/domain/`.
  `skills/task-implement/SKILL.md`'s `Target: local` warning block and its
  frontmatter sentence "Warns (but proceeds) when implementing a target:local
  task" are removed.
- **The `Target:` field itself survives unchanged**, with `claude` /
  `claude+human` / `human`. `/task-implement` still handles all three; the
  `## Manual interventions` section, the `claude+human` checkpoint flow, the
  `human` guided walkthrough and the Unity MCP path are untouched and still
  documented.
- `/task-setup` creates `.claude/TASKS.md`, `.claude/tasks/`, and
  `.claude/external/run-affected-tests.sh` + `run-full-tests.sh` — and nothing
  else. It no longer writes or embeds the two aider prompt templates (~180 lines
  of heredoc in `commands/task-setup.md`).
- The surviving wrappers are described as the project's test-dispatch
  convention, not external-LLM wiring, in `commands/task-setup.md` (frontmatter
  `description` and body) and `.claude/context/features.md`. The

- `commands/task-setup.md`'s claim that `/task-implement` reads the wrappers is
  corrected — it does not, and never did.
- `docs/authoring-guide.md` no longer contains the section "Keeping
  `/task-implement` and `task-impl` in step", and `/task-enrich` is gone from
  its authoring-commands and `--no-push` lists. The same removal is applied to
  the `/task-enrich` mentions in `commands/domain-setup.md`,
  `commands/project-setup.md` and `commands/unity-mcp-setup.md`.
- `README.md` has no "[Experimental] Implementing tasks with a local LLM"

- `CLAUDE.md`'s task-workflow reference no longer describes a "dual-LLM

- `.claude/context/INDEX.md` has no rows for the two deleted context files and

## Decisions

- **One task, not split, despite ~1,700 lines.** The seam between the runner and
  the authoring path that fed it is clean, but splitting manufactures a shipped
  intermediate state that is worse than either endpoint — `/task-enrich` still
  producing `Target: local` bodies for a runner that no longer exists — and it
  forces either two major VERSION bumps for one coherent removal or an
  inconsistent bump on the second half. This is a deletion verified by
  grep-for-absence, so verification effort does not scale with line count.
- **The whole enrich apparatus goes, not just the runner.** `/task-enrich`,
  `/task-add --enrich`, `Target: local` and the enriched-body schema exist
  solely to feed the local implementer. `Target: local` has 0 uses in 274
  authorings. This makes the release breaking, which is accepted: `VERSION`
  0.62.0 → 1.0.0.
- **`run-affected-tests.sh` / `run-full-tests.sh` are kept and re-described.**
  The claim that all of `.claude/external/` is inert is true of the two aider
  prompt files everywhere, and true of all four files in factotum and
  IsThisFreedom (both carry stub wrappers), but **false in job-hunter-cli**,
  where the wrappers are the project's real two-stack test dispatcher (pytest
  for `legacy/cli/...`, vitest for `web/`/`worker/`/`contracts/`/`site/`),
  referenced by its root `CLAUDE.md`, `.claude/context/shared/testing.md` and
  `.claude/tasks/manual-checks.md`. `scripts/cmd-export.sh` also bundles them
  and stays unchanged.
- **`scripts/check-task-parity.sh` is deleted.** Its only job was keeping the
  `/task-implement` prompt and the bash orchestrator in agreement; with the bash
  side gone there is no second encoding. Note it currently *asserts* that
  `local` is mentioned on both sides, so it must be deleted before or with the
  `Target: local` removal or its own guard fails.
- **`task-impl` is a substring of `task-implement`.** A naive
  `grep -l task-impl | xargs sed` will mutilate the surviving skill, which is
  referenced ~90 times across the repo. Match on `task-impl\b`,
  `cmd-task-impl`, or `chosko-llm task-impl`.
- **Nothing downstream is modified.** Deleting `/task-setup`'s emission does not
  touch `.claude/external/` directories already on disk in factotum,
  IsThisFreedom or job-hunter-cli; all three keep working. job-hunter-cli's
  hand-written `.claude/external/score-with-local.sh` was checked and is
  **independent of this lane** — it scores a job description (system-prompt path
  as argv[1], JD JSON on stdin, `qwen2.5:14b-instruct` via `ollama run`), shares
  only the word "local" and the Ollama dependency, and is already recorded in
  that project's own context layer as a stale artifact because
  `scorer.py::_score_via_local` now calls Ollama's HTTP API directly. Cleaning
  it up is job-hunter-cli's business, not this task's.
- **`/architect`-owned documents under `.claude/domain/features/` are out of
  scope.** `shared-phase-engine.md` names `task-enrich` in its migration order
  (lines 13, 152) and `check-task-parity.sh` among its validation ideas (line
  202); both references go stale when this lands. Do not edit that document here
  — it belongs to `/architect`, and the staleness is resolved when
  `/task-add feature=shared-phase-engine` runs.
- **Historical records are left alone.** `Target:`/aider mentions inside
  `.claude/tasks/*.md` and `.claude/sessions/*.md` are the record of what was
  done and are not rewritten.
