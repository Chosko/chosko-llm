# Task 287 — Update documentation for feature `interaction-policy`

Target: claude

## Goal
Feature `interaction-policy` changes how every interactive feature gates,
reports and asks; this repo's `CLAUDE.md`, context layer and domain layer
must describe the shipped behaviour. User-facing docs (`README.md`,
`docs/reference.md`) are out of scope until the experiment ships.

## Acceptance criteria
- `CLAUDE.md` names the policy and points at the engine / feature doc
  (Authoritative references); it does not add an `Interaction policy:` line.
- `.claude/context/` gains an `interaction-engine.md` file indexed in
  `INDEX.md`; `features.md` and the hub/leaf files for the task, runbook and
  pipeline families describe the dependency, flags and gate classes where
  they describe the passages tasks 282–286 changed.
- `.claude/domain/task-workflow.md` and `product-workflow.md` (`/pipeline-revise`'s
  "one gate, and it always waits") reflect the policy.
- `.claude/domain/features/unattended-parking.md`, `runbook-suite.md`,
  `runbook-inline.md`, `pipeline-revision.md` and `owner-amend-arms.md` state
  the agreed design change — the interaction policy's precedence, gate
  classes and summary-not-draft gates replace the policy carriers, the
  feature-flip default, the verbatim-draft relays, the always-waiting
  revision and amend gates — in every passage that stated the old one.
  Nothing else in those documents changes.
- No `VERSION` bump, no `CHANGELOG` entry (documentation exemption).

## Decisions
- **Design change agreed (user decision, 2026-10-06):**
  1. `unattended-parking.md` § The policy and its carriers: `/task-implement`
     takes the policy from its flag only and the step preamble carries it only
     under `unattended` → one precedence (flag or handed-down policy, runbook
     header, `CLAUDE.md` line, `attended`); the preamble states it under both
     values.
  2. `unattended-parking.md` § Prompts with a default: the feature-flip
     proposal defaults to *none* under `unattended` → it is class 1 and
     passes, flipping the feature.
  3. `runbook-suite.md` § the question relay and the relay in the subagent
     position: an approval gate carries the full draft verbatim and
     unabridged → a plain summary; `show` prints the draft.
  4. `runbook-inline.md` § asking directly: approval-gate draft verbatim and
     a gate never skipped because the session already knows → plain summary;
     a class 1 gate passing on its own under `unattended` is not a skipped
     gate.
  5. `pipeline-revision.md` § the plan gate: owner-step table, headless /
     GATED tokens and before → after shown, the gate always waits → verdict
     line, one plain sentence per change, then the questions; class 1 when
     the plan has no open questions.
  6. `owner-amend-arms.md` § the single gate and the "Amended …" line: the
     gate shows the difference and always waits → plain summary, class 1;
     the report line plain-language-first.
  Each of these paths is normally `/architect`'s; this task updates it for
  exactly this and for nothing else. A further design decision met at
  implementation time is not covered: leave that passage untouched and name
  it under *Follow-ups* as a precise follow-up.
- This repo's `CLAUDE.md` describes the policy and points at it but sets no
  `Interaction policy:` line (user decision): the repo stays `attended` by
  default, and the runbook passes `--unattended` where it wants it.
- A separate `interaction-engine.md` context file rather than folding into
  `task-engine.md`: the engine serves every family.
