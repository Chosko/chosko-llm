# Task 228 — Make `/session-save` commit by default

Target: claude

## Goal
Handoff files exist to cross the gap between sessions, which is usually a gap
between machines — the one place an untracked file helps nobody.
`/session-save` commits and pushes the handoff it writes, and takes
`--no-commit` and `--no-push`. `/session-resume` is unchanged.

## Acceptance criteria
- `/session-save` gains the flag surface: COMMIT true unless `--no-commit`;
  `--no-commit` implies NO_PUSH; `--commit` accepted no-op; the
  `--commit --no-commit` stop. It still never refuses over any other
  unrecognized argument.
- It pulls at start per `commit.md` unless `--no-commit` (or a `## VCS`
  override). The "only shell command is the clock read, never `git`" rule is
  narrowed to: the clock read plus the commit-and-push protocol's git commands.
- It stages exactly the new session file, plus the superseded file's deletion
  when SUPERSESSION DELETE removed a tracked file, in one commit
  `Save session <slug>`, then re-syncs and pushes. An untracked superseded file
  is deleted with nothing to stage for it.
- The "The file is untracked — commit it if you want it to travel" report line
  is replaced by the commit hash; under `--no-commit` a one-line
  nothing-committed reminder replaces it.
- The description, GOAL, REPORTING and DO NOT list no longer claim "never
  commits" / "no `--commit`".
- `commands/session-resume.md` is not modified.
- Frontmatter `version:` bumped on `session-save`; root `VERSION` +
  `CHANGELOG.md` section; `./scripts/check-changelog.sh` passes.

## Decisions
- **`/session-resume` stays read-only, behaviour unchanged (user decision,
  2026-09-15).** It writes, deletes and commits nothing, and still hands the
  deletion over as an instruction; pruning keeps its current three-part design.
- The superseded file's deletion rides in the save's one commit rather than a
  commit of its own: the new snapshot and the removal of the one it replaces
  are one unit of work.
