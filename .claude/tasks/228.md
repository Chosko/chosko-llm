# Task 228 — Make `/session-save` and `/session-resume` commit by default

Target: claude

## Goal
Handoff files exist to cross the gap between sessions, which is usually a gap
between machines — the one place an untracked file helps nobody. `/session-save`
commits and pushes the handoff it writes; `/session-resume` pulls first (so a
handoff saved elsewhere is found), briefs, then deletes the file it resumed from
and commits that deletion. Both take `--no-commit` and `--no-push`.

## Acceptance criteria
- Both commands gain the flag surface: COMMIT true unless `--no-commit`;
  `--no-commit` implies NO_PUSH; `--commit` accepted no-op; the
  `--commit --no-commit` stop. Both still never refuse over any other
  unrecognized argument.
- Both pull at start per `commit.md` unless `--no-commit` (or a `## VCS`
  override). The "only shell command is the clock read, never `git`" rules
  are narrowed to: the clock read plus the commit-and-push protocol's git
  commands.
- `/session-save`: stages exactly the new session file, plus the superseded
  file's deletion when that file was tracked, in one commit
  `Save session <slug>`, then re-sync and push. The "The file is untracked —
  commit it if you want it to travel" report line is replaced by the commit
  hash; under `--no-commit` a one-line nothing-committed reminder replaces it.
- `/session-save` SUPERSESSION DELETE treats an already-absent resumed-from
  file (deleted by `/session-resume`) as nothing to delete, silently.
- `/session-resume`: after the briefing and before "Stopping here.", deletes
  the file it briefed from and — when that file was tracked — commits the
  deletion alone as `Remove resumed session <filename>` and pushes. An
  untracked file is deleted with no commit (never an empty commit). Under
  `--no-commit` it deletes and runs no git command. A pointer file's
  `Resume from:` artifact is still never deleted.
- `/session-resume`'s closing handover sentence says the file was removed and
  where its content survives (this conversation, and git history when it was
  committed) instead of instructing a later deletion.
- Descriptions, GOALs, READ-ONLY THROUGHOUT and both DO NOT lists no longer
  claim "never commits" / "writes nothing, deletes nothing"; THEN STOP still
  forbids starting the handed-off work.
- Frontmatter `version:` bumped on both; root `VERSION` + `CHANGELOG.md`
  section; `./scripts/check-changelog.sh` passes.

## Decisions
- **`/session-resume` deletes at resume time and commits the deletion (user
  decision, 2026-09-15).** This ends its read-only contract and moves pruning
  from "delete when the work is finished" to "delete once briefed". The
  handoff's content lives on in the conversation and, for a committed file, in
  git history. Consequence: `/session-save`'s supersession delete will usually
  find nothing left to delete; it is kept for resumed files that outlived a
  `--no-commit` resume.
- The deletion is its own commit, never folded into a later work commit — one
  unit of work, per `commit.md`.
- Pulling at start is a side gain for `/session-resume`: the newest candidate
  now includes handoffs saved on another machine.
