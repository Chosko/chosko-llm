# Task 189 — Write the `pipeline-revise` insert branch

Target: claude

## Goal
"Insert a task at a specific moment" is the feature's motivating example:
attach the task, place it, write back the feature document, insert the runbook
step, and confirm the lint is clean, in one run. This task writes
`skills/pipeline-revise/insert.md`, which composes the insertion primitives
`backlog-ordering` shipped (tasks 171–173) into that single ordered sequence,
with its own direction rules and tier logic.

## Acceptance criteria
- `skills/pipeline-revise/insert.md` exists and is complete on its own: a
  consumer that has read `./SKILL.md` and this file can execute the branch end
  to end.
- The composition is named explicitly, by primitive:
  `/task-add feature=<slug> --single` attaches exactly one task to a planned
  feature; `--before <N>` / `--after <N>` place it; the orphan-task prompt
  covers a task belonging to no feature;
  `/runbook-create --append --before <n>` / `--after <n>` inserts a step.
- Direction rules stated: an insertion walks *forward* to the successor tasks
  whose `Preconditions:` must gain the new id, and *upward* to the feature
  document that must promise the new scope.
- The owner sequence for the worked example is given in order: `/architect
  amend` for the scope, then `/task-add feature=<slug> --single --after <N>`,
  then each successor's `Preconditions:` through `task-engine`'s amend
  reference, then the runbook step insert, then the scoped lint.
- Tier logic stated: an insert adding scope no existing task covers is
  *structural* and flips the feature `[ITERATED]` through `/architect amend`;
  an insert of something the feature document already promises is *local* and
  leaves the feature status alone.
- The branch-specific half of the verification bracket is stated: after
  actuation the successor tasks' bodies are read to confirm the sequence still
  reads as a sequence.
- A `[RUNNING]` runbook accepts an insert after the current step and nothing
  before it — cited from `runbook-run`'s step-amend reference, not restated as
  a rule of this file's own.
- The branch writes nothing itself; every step names the primitive or arm it
  delegates to, by path or by command name.
- `./SKILL.md`'s SUPPORTING FILES table gains its `./insert.md` row.
- Root `VERSION` bumped, `CHANGELOG.md` top section matches,
  `./scripts/check-changelog.sh` silent.

## Decisions
- **`--single` is the attachment primitive, not a full `/task-add
  feature=<slug>` run.** A whole-feature re-plan reconciles every existing task
  — a far larger revision than the user proposed, and one the gate never
  showed them.
- **A successor's `Preconditions:` is never written directly.** It changes
  through `task-engine`'s single-task amend reference, which owns that field's
  rules, including naming a dropped edge in the task's `## Decisions`.
- **Scope first, task second.** `/architect amend` runs before `/task-add` so
  the new task is drafted against a feature document that already promises it;
  the reverse order produces a task whose `Feature:` points at a document that
  does not mention it, which is a lint finding on its own.
