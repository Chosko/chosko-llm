# Task 149 — Update documentation for feature version-changelog

Target: claude

## Goal

Tasks 146–148 ship the `version-changelog` feature
(`.claude/domain/features/version-changelog.md`): a root `CHANGELOG.md` and the
maintenance rule, the `check-changelog.sh` guard, and a coloured range readout in
`chosko-llm upgrade` backed by three new `scripts/lib.sh` helpers. The user-facing
README, the CLI help text and the navigation context layer describe none of it.
Bring them back in line with what shipped.

## Acceptance criteria

- `README.md` § "Keeping up to date" says that `upgrade` prints what changed for
  exactly the versions just pulled, read from the repo's `CHANGELOG.md`, and that
  the commit list appears instead when the version did not move.
- `README.md` § Development → the **Versioning** paragraph gains the rule — a
  `VERSION` bump without a matching `CHANGELOG.md` section is an incomplete change —
  and points at `./scripts/check-changelog.sh`.
- `README.md` § Repo layout gains a `CHANGELOG.md` row and a
  `scripts/check-changelog.sh` row (the existing `scripts/cmd-*.sh` row does not
  cover a non-subcommand script).
- `docs/cli-help.txt`'s `chosko-llm upgrade` entry gains one line noting it prints
  what changed for the versions just pulled. No flag is added to the help text —
  there is no `--changelog` and no `--no-changelog`.
- `.claude/context/shared-lib.md` documents the three new helpers in its Public API:
  the raw version reader (and that `resolve_version` now reads through it, keeping
  its output format), the changelog path helper in the "Path resolution" family, and
  the changelog range printer — including that it writes to stderr and gates colour
  on `_use_color` rather than the stdout-gated `C_*` variables, which is why it
  lives in `lib.sh` at all.
- `.claude/context/cmd-upgrade.md` records the readout under Side effects and
  Internal patterns: the two raw `VERSION` reads bracketing the pull, the two-sided
  descending-semver range, the rule that the `git log --oneline` dump is suppressed
  exactly when a range printed, the degrade-never-fail contract, and a
  "When to read source" entry for changing the readout.
- `.claude/context/INDEX.md`'s canonical-docs list gains `../../CHANGELOG.md`, and
  its `Last updated` anchor is current.
- **No new context file is created for `scripts/check-changelog.sh`**, and no row
  is added to the `## Files` table for it — deliberate, and stated as such in the
  commit. `scripts/check-task-parity.sh` set the precedent: a repo-local guard is
  documented in `docs/authoring-guide.md` and in the README's repo-layout table,
  not in the navigation context layer, which covers the CLI's own source units.
- `docs/authoring-guide.md` is deliberately NOT changed — task 146 put the rule and
  the schema in § Versioning and task 147 added the guard's section.
- `CLAUDE.md` is deliberately NOT changed — task 146 put the rule in § Versioning.
- `.claude/domain/INDEX.md` is deliberately NOT changed — its
  `features/version-changelog.md` row already exists and stays accurate.
- `.claude/domain/features/version-changelog.md` is deliberately NOT changed. It is
  `/architect`-owned, nothing in it diverged from what shipped, and its
  `## Open questions` correctly reads "None outstanding".
- `scripts/cmd-help.sh`'s fallback heredoc is deliberately NOT changed — it lists
  `chosko-llm upgrade` bare, with no description to update.
- `CHANGELOG.md` gains a section for this task's own bump.
- Root `VERSION` takes a patch bump (documentation only), relative to whatever is in
  place when this lands.

## Decisions

- **The deliberately-unchanged files are named rather than silently omitted**, so a
  later reader does not treat their absence as an oversight.
- **No context file for the guard.** A third home for material already in the
  authoring guide is the copy that drifts, and the context layer's own convention is
  that it covers the CLI's source units — `bin/`, `install.sh`, `lib.sh` and the
  `cmd-*.sh` subcommands — not repo-local authoring tooling.
- **`docs/cli-help.txt` is in scope even though no flag changed.** The readout is
  unconditional new behaviour of a documented subcommand, and the help text is the
  only place a user who never opens the README will see it.
- **Patch bump** — documentation only.
