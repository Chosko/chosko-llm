# Task 151 — Add a `git-commit-style` claude-md snippet and cap task-engine's commit body

Target: claude

## Goal
Commit messages Claude writes today drift into wall-of-text bodies that make
`git log` impossible to scan visually. Ship a second claude-md artifact,
`claude-md/git-commit-style.md`, that injects a global commit-message shape
policy into `$CLAUDE_HOME/CLAUDE.md` the same way `tool-usage-policy` does:
a short imperative subject line, an OPTIONAL body of at most 2–3 lines used
only when it carries information the subject cannot, and
`Co-Authored-By:` / `Claude-Session:` trailers permitted **only on big
commits**, where "big" is defined by an explicit, checkable size threshold
rather than by judgement. The policy is shape-only and yields to local style. In the same task, fix the
one place in this repo that currently mandates the offending shape:
`skills/task-engine/references/commit.md`'s `/task-implement` message
template, whose `<one-paragraph summary of what changed>` line is exactly the
wall of text the snippet is meant to end.

## Acceptance criteria
- `claude-md/git-commit-style.md` exists with full frontmatter — `name:
  git-commit-style` (matching the filename), `version: 0.1.0`, `type:
  claude-md`, and a one-line `description:`.
- Its body states the shape: subject in imperative mood, one line, kept short
  enough to read in `git log --oneline`; body OPTIONAL and capped at 2–3
  lines; body explains why, never restates the diff; no body at all on a
  trivial commit.
- Its body states the precedence rule explicitly: a repo's own convention
  (CONTRIBUTING, CLAUDE.md, or the shape visible in `git log`) and any
  command's own prescribed message form — e.g. task-engine's `Task <N>: …`,
  `Add task <N>: …`, `task-clean: remove tasks …` — override this policy.
- Its body states that `Co-Authored-By: <model>` and `Claude-Session: <url>`
  trailers are added **only on big commits**, and states the threshold
  literally so it can be checked without judgement: a commit qualifies when it
  changes **5 or more files** or **200 or more lines** (insertions +
  deletions). Below that, both trailers are omitted — not "optional", omitted.
- Its body states where the numbers come from, in one line: they are roughly
  this repo's 75th-percentile commit (median 3 files / 82 changed lines; p75
  6 files / 250 changed lines over the last 200 commits), i.e. the top quarter
  of commits by size.
- Its body says the threshold is a default a repo may override, and that a
  repo's own trailer convention (an existing `Co-Authored-By` habit visible in
  `git log`, or a CONTRIBUTING rule) wins over it — same precedence rule as
  the shape.
- The snippet mandates no type-prefix vocabulary (no `feat:` / `fix:`
  requirement); prefix convention is left to whatever the repo already uses.
- The snippet carries no staging, atomicity, or push guidance — those stay in
  `skills/task-engine/references/commit.md`, which is not edited on that
  point.
- `skills/task-engine/references/commit.md`'s `/task-implement` template no
  longer says `<one-paragraph summary of what changed>`; it names an optional
  body of at most 2–3 lines, consistent with the new snippet. The skip-tests
  `(no tests — manual verification pending)` note still has a defined place.
- `skills/task-engine/SKILL.md` `version:` bumped (patch) for that reference
  change.
- `docs/authoring-guide.md` gains a short note, parallel to its existing
  "Tool discipline is global — do not restate it" section, saying commit
  message shape ships as `claude-md:git-commit-style` and must not be
  restated in a command or skill body.
- `.claude/context/features.md` inventory gains an entry for
  `claude-md/git-commit-style.md`; `.claude/context/INDEX.md` `Last updated`
  anchor refreshed.
- Root `VERSION` bumped minor (new shipped feature) and `CHANGELOG.md` gains
  a matching top section; `./scripts/check-changelog.sh` exits silent.
- `./bin/chosko-llm ls --available` lists `git-commit-style` at `0.1.0` under
  the claude-md kind.

## Decisions
- **Shape is a short imperative subject plus an optional 2–3 line body — not
  Conventional Commits** (user decision). The problem being solved is visual
  scannability of `git log`; a mandated type vocabulary does not address it
  and would fight the repo's own `Task <N>:` history.
- **Local style wins** (user decision). A global snippet that overrode a
  command's prescribed message form would contradict task-engine's own three
  message forms in this very repo, so the precedence rule is stated in the
  snippet body rather than left implicit.
- **Shape only — no commit hygiene.** Staging by explicit path, one commit per
  unit of work, and the push protocol already live in
  `skills/task-engine/references/commit.md`; restating them in a globally
  resident snippet is exactly the duplication `/rule-overlap` flags.
- **Amending `commit.md` is in scope for this task, not a follow-up** (user
  decision). Shipping the snippet while the repo's own template still
  prescribes a paragraph body would ship a contradiction.
- **Trailers only on big commits, with a numeric threshold** (user decision).
  "Non-trivial" was too vague to act on, so the snippet names a size test
  instead: 5+ files changed or 200+ changed lines. Under the threshold the
  trailers are omitted, not left to taste.
- **Threshold calibrated on this repo's own history** (user decision). Over
  the last 200 non-merge commits: files changed p25 2 / median 3 / p75 6 /
  p90 8; changed lines p25 13 / median 82 / p75 250 / p90 516. The chosen
  5 files / 200 lines sits just under p75, so trailers land on roughly the
  top quarter of commits and stay off the many small doc/version/task
  commits that dominate `git log` here.
