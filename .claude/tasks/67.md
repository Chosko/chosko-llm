# Task 67 — Add exported repo Version and Created date to the export manifest

Target: claude

## Goal
`chosko-llm export`'s manifest (the Markdown header and the zip's
`MANIFEST.md`) currently records Repo, Commit, and Generated. Add two more
fields: `Version:` — the contents of a root `VERSION` file, when the
exported repo has one — and `Created:` — the date (`YYYY-MM-DD`) of the
repo's first commit/changeset, so a hand-off artifact carries basic
provenance (what version this config is, and how old the repo is) without
the reader having to dig it out themselves.

Computing `Created:` for a non-git repo requires detecting Plastic SCM,
which `cmd-export.sh` doesn't currently do (it only distinguishes "git
repo" from "not a git repo", the latter warning and prompting). Extend that
into a real three-way branch — git / Plastic / neither — so `Commit:` also
becomes meaningful on a Plastic repo instead of showing "not a git
repository" next to an otherwise-accurate `Created:` date.

## Acceptance criteria
- Both manifest locations (the Markdown header block and the zip's
  `MANIFEST.md`) gain the same two fields, in the same relative position:
  `Version:` right after `Repo:`, `Created:` right after `Commit:`.
- `Version:` is emitted only when `<repo>/VERSION` exists; its value is the
  file's trimmed contents. When the file is absent, the line is omitted
  entirely (not written as empty or "none") — matching how missing optional
  root files are already skipped silently elsewhere in this script.
- VCS detection becomes three-way:
  - **git** (existing `git -C "$repo" rev-parse --git-dir` check): `Commit:`
    unchanged (`git rev-parse --short HEAD`, `-dirty` suffix). `Created:` is
    the earliest commit's date reachable from `HEAD`, `YYYY-MM-DD`, UTC.
  - **Plastic** (new: `.plastic/` present under `<repo>`, or a `cm` binary
    resolves and `cm status` succeeds from `<repo>` — same detection
    `/project-setup` PHASE 1a uses): `Commit:` is the current changeset,
    via `cm log --limit=1` (per the mapping already documented in
    `commands/project-setup.md`'s `## VCS` snippet:
    `git rev-parse --short HEAD -> cm log --limit=1`). `Created:` is the
    earliest changeset's checkin date, `YYYY-MM-DD`. No warn/prompt for a
    detected Plastic repo — it's a valid VCS, not a missing one.
  - **Neither**: unchanged existing behavior — warn, prompt to continue
    (TTY) or `die` (non-TTY), `Commit: not a git repository` on "yes".
    `Created:` is omitted in this case.
- Existing stdout contract, exit codes, and the git-branch's `-dirty`
  detection are otherwise unchanged.
- `.claude/context/cmd-export.md` documents the new fields and the
  three-way VCS detection.

## Decisions
- **Full three-way VCS branch, not a narrow ad-hoc Plastic probe for
  Created: only** (user's choice) — computing Created: for Plastic requires
  detecting it anyway, and leaving Commit: at "not a git repository" next
  to a real Created: date would read as a bug in the manifest.
- **VERSION bump: minor, not patch** (user's choice) — this is cmd-export's
  first real Plastic-repo support (a meaningful new capability), not a
  cosmetic tweak to existing output like tasks 63/65.
- **Exact `cm`-based "earliest changeset date" invocation is TBD at
  implementation time** — Plastic's `cm log`/`cm find` flags vary by
  version. A plausible starting point, per task 36's precedent: `cm find
  revision "where date <= 'now'" --order-ascending --format="{date}"
  --limit=1` (or equivalent), verified against whatever Plastic CLI is
  actually available before shipping.
- **Missing VERSION file → line omitted, not written as empty/"none"** —
  consistent with the script's existing "missing optional root files are
  skipped silently" rule for `CLAUDE.md`/`AGENTS.md`/`README.md`.
- **`Created:` uses UTC date formatting**, matching the existing
  `Generated:` field's `date -u` convention, for consistency within one
  manifest.
