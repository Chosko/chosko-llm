# Task 272 — Unpark deletes the parking branch after the task's commit, and `/task-clean` sweeps orphaned park branches

Target: claude

## Goal
The unpark transaction (`skills/task-engine/references/parking.md`
§ *The unpark transaction*) deletes `park/task-<N>` at step 3, before the
resumed task does any work. The parking commit is never merged — it is
cherry-picked with `-n` — so the delete needs `git branch -D` and
`git push origin --delete`, which Claude Code's auto-mode permission
classifier blocks as "Git Destructive". On a downstream project this has
twice left an unparked task unclosed during a `/runbook-run`. Move the
deletion to the last act of the task — after its Step 7 commit (and push)
has landed — and make it non-fatal: a refused or failed delete leaves the
task `[DONE]` and becomes a Follow-ups item naming the branch. This also
makes the transaction safer, since the branch now survives until its content
is committed on the base. `/task-clean` then sweeps every `park/task-<N>`
branch, local and on origin, whose task is not `[PARKED]` — listed in its
plan and confirmed at its existing gate, so the delete runs in a session
where the user can approve the permission prompt.

## Acceptance criteria
- `parking.md` § *The unpark transaction* no longer deletes the branch
  between the cherry-pick and the resume. The deletion is a final step run
  after the task's Step 7 commit and push (after the commit alone under
  `--no-push`); under `--no-commit` the branch is kept. Its "nothing
  destructive happens until the last step" framing still holds.
- A refused or failed delete (local or remote) does not halt the run, does
  not change the task's status and is not retried: it becomes one
  *Follow-ups* item in the closing report naming the branch and the two
  commands. A delegated agent returns it in its fifth field
  (`skills/task-implement/delegated-runs.md`), which still counts toward its
  three-item cap.
- `skills/task-implement/SKILL.md` Step 7 (or Step 1's unpark paragraph,
  whichever states when the transaction completes) cites the post-commit
  deletion by pointing at `parking.md`, restating nothing.
- `skills/task-clean/SKILL.md` gains the sweep: it lists `park/task-<N>`
  branches via `git branch --list 'park/task-*'` and
  `git ls-remote --heads origin 'refs/heads/park/task-*'`, treats one as
  orphaned when task N has no summary block in `.claude/TASKS.md` or has one
  whose `Status:` is not `[PARKED]`, lists the orphans in the plan (one line
  each, naming local/remote), and on approval deletes them at the same
  single gate. No orphans → no plan section, nothing said. A delete that
  fails is reported, not fatal. Under the skill's `--no-commit`/`--no-push`
  semantics, follow what `commit.md` says for remote operations (no remote
  delete under `--no-push`).
- `skills/task-engine/references/status.md`'s `[PARKED]` prune warning no
  longer says the orphaned branch is one "which nothing then deletes"; it
  names the `/task-clean` sweep. `task-clean`'s own `[PARKED]` warning
  paragraph agrees.
- `skills/pipeline-engine/references/routing.md`'s `/task-clean` row names
  the park-branch sweep among what it writes; `./scripts/check-routing.sh`
  passes.
- `.claude/domain/features/unattended-parking.md` states the agreed design
  change — branch deletion moves after the task's commit and is
  best-effort, with `/task-clean` sweeping what is left — in every passage
  that stated the old one (§ *Task unparking* step 3, and the branch
  lifecycle passage near "deleted as the last step of a"). Nothing else in
  the document changes.
- `docs/reference.md` (the unpark description near "deletes it, and resumes
  the task") and `.claude/context/features.md` (the unpark sequence near
  "cherry-pick without committing, delete the branch, resume") describe the
  new order and the sweep.
- Feature frontmatter `version:` bumped on every shipped body edited
  (`task-engine`, `task-implement`, `task-clean`, `pipeline-engine`); root
  `VERSION` bumped (minor — `/task-clean` gains behavior) with a matching
  `CHANGELOG.md` section; `./scripts/check-changelog.sh` and

## Decisions
- **Design change agreed (user decision, 2026-09-30):** unpark step 3
  "Delete the branch, local and remote" moves after the task's Step 7 commit
  and becomes non-fatal (failure → Follow-ups item); the branch lifecycle
  passage states deletion is best-effort after commit and `/task-clean`
  sweeps what is left. `.claude/domain/features/unattended-parking.md` is
  normally `/architect`'s; this task updates it for exactly this and for
  nothing else. A further design decision met at implementation time is not
  covered: leave that passage untouched and name it under *Follow-ups* as a
  precise follow-up.
- **Move the deletion, don't only tolerate it.** A blocked delete in the
  middle of the transaction stops the work even when tolerated; after the
  commit a failure costs only cleanup, and the branch is a rollback source
  until then.
- **Failed delete → Follow-ups item, never a halt, never a retry.**
- **The sweep runs on every `/task-clean`, not behind a flag.** It adds a
  plan section only when orphans exist and rides the one existing gate —
  `/task-clean` is user-invoked, so the permission prompt reaches a person.
- `/task-add`'s skip-and-replace deletion (`stale.md` § *Clearing it*)
  stays as it is: it is already interactive, and a blocked one is caught by
  the next sweep.
- Runbook step parking is unaffected — a generic step has no branch.
