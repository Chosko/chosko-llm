# Task 98 — Add nested-layout support to /context-build

Target: claude

## Goal
Let `/context-build` produce a nested (router + leaf) context layer when
asked, per the task-96 spec, while flat stays the default and the flat path
stays untouched. Nested instructions live in a read-on-demand
`skills/context-build/nested.md` opened only when the nested argument is
present.

## Acceptance criteria
- New arguments: `nested` (the skill proposes the unit seams) and
  `nested=<unit1>,<unit2>,…` (the user names them). Both compose with the
  existing structure hint, `--commit`, and `--no-push`.
- With neither argument, the run is flat and byte-identical to task 97's
  output. `SKILL.md` does not open `nested.md` at all on a flat run.
- Phase 1's analysis report **may suggest** nesting when the repo has
  obvious unit seams, phrased as a suggestion the user can act on by
  re-running with `nested`. It never switches layout on its own, and it
  never asks a question that gates the flat run.
- On a nested run, Phase 1 proposes the unit breakdown — which units, which
  context files land in each — and stops at the existing approval gate.
  `nested=<units>` pre-seeds the unit list but still proposes the per-unit
  file assignment.
- Phase 2 writes: a router `.claude/context/INDEX.md` (`Layout: nested`,
  Units table, no `Last updated`), one `.claude/context/<unit>/INDEX.md`
  per unit (own `Last updated`, Files table), and each context file under
  its owning unit folder. All schemas exactly as specced in task 96.
- The six-section per-file schema, the 150-line cap, and the 10-line
  snippet cap apply unchanged inside units.
- Cross-references between context files in different units resolve
  correctly (`../<other-unit>/<file>.md`); the convention is stated in the
  router's Conventions block.
- Depth is capped at two levels. A proposed breakdown that would need a
  third level is reported as such and flattened into two.
- Phase 3's CLAUDE.md navigation instruction still points at
  `.claude/context/INDEX.md` — the router is the entry point, and the
  instruction tells the reader to follow the Units table to the relevant
  leaf.
- Phase 4 staging on `--commit` covers the router, every leaf INDEX, and
  every context file written. Explicit paths only.
- Root `VERSION` bumped minor.

## Decisions
- **Explicit argument only.** Auto-selecting nested would put a
  reasoning-based judgment back at build time, which is exactly what the
  cheap marker is meant to avoid. The Phase 1 suggestion is how users
  discover the option without the tool deciding for them.
- **`nested` proposes seams, `nested=` accepts them.** Naming units is the
  one thing the user usually knows better than the tool; assigning files to
  named units is the one thing the tool does better.
