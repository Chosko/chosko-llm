# Task 62 — Add `chosko-llm export` — package a repo's Claude config as Markdown or a zip

Target: claude

## Goal
Add a new CLI subcommand `chosko-llm export [<repo>] [--archive]` that collects a
repo's Claude configuration (CLAUDE.md, AGENTS.md, README.md, and the curated
subset of `.claude/`) into a single hand-off artifact. The default shape is one
concatenated Markdown file for uploading to a Claude Project knowledge base; the
`--archive` shape is a zip for uploading to a Claude chat, where the assistant
reads members selectively instead of ingesting everything at once. Both shapes
draw from one shared file-selection function so the two artifacts can never
disagree about what a repo's config is.

## Acceptance criteria
- `bin/chosko-llm` routes `export` to `scripts/cmd-export.sh` (added to the
  existing `ls|add|rm|update|upgrade|channel|show|uninstall` case arm).
- `scripts/cmd-export.sh` starts with `set -euo pipefail` and sources `lib.sh`,
  matching every other `cmd-*.sh`.
- `<repo>` defaults to `$PWD` when omitted. A `<repo>` argument that does not
  resolve to a directory is a hard error via `die` (exit 1).
- One selection function (e.g. `select_export_files <repo_dir>`) emits
  repo-relative paths on stdout and is the only place selection rules live.
  Both output shapes consume it.
  - Includes: `CLAUDE.md`, `AGENTS.md`, `README.md` at the repo root, plus files
    under `.claude/` matching `*.md`, `*.json`, `*.toml` (recursively).
  - Excludes: any `settings.local.json`, and everything under
    `.claude/projects/`, `.claude/history/`, `.claude/todos/`.
  - Missing optional files are skipped silently; an empty selection is a hard
    error (nothing to export).
- Output directory is `$CHOSKO_LLM_EXPORT_DIR`, defaulting to
  `$HOME/claude-exports`, resolved by a helper in `scripts/lib.sh` alongside the
  other path helpers. The directory is created if absent (`mkdir -p`). No new
  path is concatenated inline in `cmd-export.sh`.
- Default shape writes `<export_dir>/<repo>-claude-config.md` containing, in
  order: a header block (repo name, commit SHA, generation date), a manifest
  listing every included repo-relative path, then each file verbatim, each
  preceded by a bare `FILE: <path>` delimiter line. File contents are NOT
  wrapped in code fences.
- `--archive` writes `<export_dir>/<repo>-claude-config.zip` containing the
  selected files under a top-level `<repo>/` directory plus a root
  `MANIFEST.md` recording repo name, commit SHA, and generation date.
- Zip creation prefers `zip -r` when available on `PATH`; otherwise falls back
  to `powershell.exe -NoProfile -Command Compress-Archive`. If neither is
  available, `die` with a message naming both.
- The commit SHA is `git -C <repo> rev-parse --short HEAD`, with `-dirty`
  appended when `git status --porcelain` is non-empty. When `<repo>` is not a
  git repo (or `git` is unavailable), the command warns the user and asks
  whether to proceed; on "yes" the SHA field records `not a git repository`, on
  "no" it exits 0 without writing anything. When stdin is not a TTY the prompt
  cannot be answered — exit 1 with a message explaining why.
- On success the resulting absolute path is printed on **stdout** (the only
  stdout output in the success path; all progress/log lines go through
  `log_*`, which write to stderr).
- `docs/cli-help.txt` documents both forms under a new `chosko-llm export`
  block and adds `CHOSKO_LLM_EXPORT_DIR` to the `Environment:` section.
- `README.md` documents the subcommand where the other subcommands are covered.
- A new `.claude/context/cmd-export.md` follows the six-section context-file
  schema; `.claude/context/INDEX.md` gains a row for it and its
  `Last updated:` anchor is refreshed. `.claude/context/cli-entry.md` gains
  `export` in the routing list; `.claude/context/shared-lib.md` documents the
  new export-dir helper.
- Root `VERSION` bumped `0.21.1` → `0.22.0` (minor — new CLI surface).
- No new runtime dependency beyond bash/awk/sed/grep/find plus the already-
  conditional zip/PowerShell branch.

## Decisions
- **Not a shipped "feature".** This is CLI logic under `scripts/`, not a
  command or skill under `commands/`/`skills/`, so it has no YAML frontmatter
  and no per-feature `version:`. It ships to users via `chosko-llm upgrade`
  (git pull of the managed clone), not via `cmd-add`/`cmd-update`. The user's
  description mentioned "frontmatter version"; the repo convention that
  actually applies here is the root `VERSION` bump.
- **`bin/chosko-llm` changes**, so users whose proxy predates this need one
  `chosko-llm upgrade` (which refreshes the proxy) before `export` resolves.
  Note this in the commit message per CLAUDE.md.
- **Zip via `zip` with a PowerShell fallback** (user's choice). Git Bash on
  Windows ships `zipinfo`/`zipgrep` but no `zip`, so a zip-only implementation
  would be dead on the primary dev machine; `Compress-Archive` covers it
  without adding a dependency.
- **`CHOSKO_LLM_EXPORT_DIR` env override** (user's choice) rather than a
  hardcoded `~/claude-exports`, consistent with the CLAUDE.md rule that
  `$HOME`-relative paths are resolved by `lib.sh` helpers.
- **Non-git repos prompt rather than fail or silently degrade** (user's
  choice). The non-TTY case exits 1 because the prompt is unanswerable and
  silently guessing either way would be wrong.
- **Existing output files are overwritten** without prompting. The filename is
  deterministic per repo, and an export is a regenerable artifact — a prompt
  would just be friction on the common re-export path.
- **`export` is NOT added to the auto-upgrade skip list** in
  `scripts/auto-upgrade.sh`. That list exists for commands that must not pull
  (upgrade/channel/uninstall) or are read-only fast paths (version/help);
  export is neither.
