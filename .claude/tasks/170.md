# Task 170 — Derive `/production-status`'s Next task by the same precondition rule

Target: claude

## Goal
Feature `backlog-ordering` requires one selection rule, not two. Task 169 makes
`next` and `all` honour `Preconditions:`; `/production-status`'s Next column
still names the lowest-numbered open task, so the report can point at a task
`/task-implement next` would refuse to start. This task changes that one
derivation so the read side and the run side agree.

## Acceptance criteria
- In `commands/production-status.md` § READINESS, **The Next field**'s
  `/task-implement <N>` bullet no longer says "the lowest-numbered such task".
  `<N>` is the first task in appearance order that is not `[DONE]`/`[SKIP]`
  and whose `Preconditions:` are all `[DONE]` or `[SKIP]`, with an id resolving
  to no task ignored.
- The bullet names `task-engine`'s `resolution.md` § *Selectors* as the
  authority for the eligibility clause rather than restating it in full — the
  one-authority-per-rule discipline the `task-*` suite already follows.
- A `[PLANNED]`, unblocked feature whose every open task has unmet
  preconditions gets a stated value rather than an undefined one; whichever
  value is chosen is written into the field's enumerated list, so the field
  still has a closed set of values.
- No new read is introduced: `Preconditions:` already comes from the summary
  blocks the command opens, and the never-open-a-file-under-`.claude/tasks/`
  contract in the frontmatter and the DO NOT list still holds.
- Section 4 still echoes section 2's value rather than re-deriving it, and the
  DO NOT list's "Store or cache readiness, the Next field…" line is unchanged.
- `commands/production-status.md` takes a minor `version:` bump.
- Root `VERSION` takes a patch bump and `CHANGELOG.md` gains a matching top
  section; `./scripts/check-changelog.sh` exits zero.

## Decisions
- This repository has no `.claude/PLAN.md` and no
  `.claude/domain/product-roadmap.md` by design, so the change is specified and
  verified against the command body alone. Neither document is created here to
  exercise it.
- Root `VERSION` takes a patch bump, not a minor one: no new surface, one
  derivation corrected. The command's own `version:` takes a minor bump because
  its visible output changes.
- `.claude/domain/features/plan-readout.md` — which owns the read side's design
  — is deliberately untouched: it predates the Next column and states nothing
  about how `<N>` is picked, so there is no drift to reconcile.
