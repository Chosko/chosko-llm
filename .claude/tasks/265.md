# Task 265 — Closing reports end with one Follow-ups list

Target: claude

## Goal
Part of feature `unattended-parking`. `/runbook-run` and `/task-implement`
both close with *Needs you* then *For the record*, then invoke `/follow-ups`,
whose list overlaps the first group without being a superset of it: *Needs
you* holds on-disk pointers `/follow-ups` excludes by rule, `/follow-ups`
holds unrecorded conversation facts *Needs you* never held. Replace the pair
with one list: **For the record** first, then **Follow-ups** — the run's own
items and the items `/follow-ups`' rules yield when applied to the run's
reading, de-duplicated by action, under one numbering that is the reply
handle. Parked items appear there with their question verbatim.

## Acceptance criteria
- In both skills' THE CLOSING REPORT the groups are, in order, **For the
  record** (unchanged in content and shape) and **Follow-ups**: every item
  the old *Needs you* held (flip question, failed step or task, `[~]` step,
  items left outside the range, unresolved `BLOCKING` findings, declined
  slugs) plus every item the `/follow-ups` command body's rules yield when
  applied to the run's reading — the body read by name and applied, never
  invoked; two items naming the same action merge, command form kept; one
  numbering starting at 1; parked steps and tasks listed with their question
  verbatim and multi-line.
- CLOSING THE RUN in both skills no longer invokes `/follow-ups` after the
  report; it states that the rules are applied inside the report's second
  group, that `requires: command:follow-ups` stays because the rules must be
  installed to read, and that an absent command yields the run's own items
  silently. The delegated agent's fifth return field is unchanged and feeds
  the same group.
- `delegated-runs.md` and `review-rounds.md` references to *Needs you* are
  updated to *Follow-ups*; `/task-implement`'s USING THE TASK BODY sentence
  naming *Needs you* as where a precise follow-up goes now names
  *Follow-ups*.
- `commands/follow-ups.md` states, in one sentence, that a run-closing skill
  may apply its rules as the second group of its own closing report under
  the same heading, and that the standalone command is unchanged.
- The reply handle semantics are stated once per skill: replying by number
  is ordinary conversation; a number that names a parked item's question is
  its answer (the post-report unpark path of tasks 261 and 264).
- Frontmatter `version:` bumped on `runbook-run`, `task-implement` (minor)
  and `follow-ups` (patch); root `VERSION` bumped (minor) with a matching
  `CHANGELOG.md` section; `./scripts/check-changelog.sh` and
  `./scripts/check-home-paths.sh` pass.

## Decisions
- Single heading `Follow-ups`, shared with the standalone command, so one
  rule set has one name wherever it renders.
- Follow-ups last: its numbers are the reply handle and sit nearest the
  prompt.
- The rules are applied, not the command invoked — the pattern delegated
  agents already use, and the only way to fold the result into one list.
