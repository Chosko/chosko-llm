# Task 220 — Make `Sequencing:` optional and one line, and stop appends extending it

Target: claude

## Goal
`Sequencing:` was designed when a runbook's order lived only in prose. Now list
position *is* the run order and `Depends on:` carries the edges, so the field's
remaining job is narrow: the *why* that neither of those can show. Meanwhile
`references/step-amend.md` § *Never changed* has an insert **extend** it, and
`/runbook-create --append` does the same, so the field grows without bound — one
real runbook's header reached a full page of dated append narration. Make it
optional, cap it at one line, and stop appends writing to it.

## Acceptance criteria
- The schema's header table marks `Sequencing:` **optional**, absent by default,
  and one line when present.
- Its stated job narrows to *why* this is the order, in the cases list position
  and `Depends on:` cannot express — e.g. "1–4 all edit the same file". What the
  order *is* is no longer its content.
- `/runbook-create --append` and `references/step-amend.md` no longer extend it.
  A dated fact about an inserted or struck step goes into that step's `Context:`,
  which already takes dated facts.
- `step-amend.md` § *Never changed* lists `Sequencing:` without the extension
  parenthetical, so the field is genuinely never changed after authoring.
- The one-line cap states the failure it prevents, so a later author does not
  reintroduce the growth.
- Existing over-long `Sequencing:` fields are left exactly as they are — no
  migration, no rewrite, no warning at run time.
- `.claude/domain/features/runbook-suite.md` is reconciled with what shipped on
  exactly this 1 point — editing it is authorised for this task, see Decisions:
  1. The header-fields paragraph at ~235, which describes `Sequencing:` as always
     present and as stating the order and why it is the order.
  Nothing else in the document changes.
- Root `VERSION` and `CHANGELOG.md` bumped per CLAUDE.md § Versioning (patch);
  `./scripts/check-changelog.sh` exits clean.

## Decisions
- **Kept, not dropped** (user decision, 2026-09-15). The field still carries what
  a dependency graph cannot — "these four touch the same file" — so the fix is
  the cap and the append rule, not removal.
- **Appends write to `Context:` instead.** That is where dated facts already go,
  it is per-step rather than global, and it keeps the header a fixed size.
- **No migration.** Rewriting existing headers would edit the record of runbooks
  that are mid-run or finished, for tidiness alone.
- **Editing `.claude/domain/features/runbook-suite.md` is explicitly authorised
  for this task (user decision, 2026-09-15), for the 1 reconciliation listed
  above and for nothing else. Do not ask for permission at implementation time —
  the permission is already granted.** That document is normally `/architect`'s,
  and anything beyond that point still belongs to `/architect`. This is a factual
  reconciliation with shipped behaviour, not a redesign; if it turns out to need
  a design decision rather than a wording fix, stop and say so instead of
  deciding it here.
