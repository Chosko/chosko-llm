# Task 117 — Vendor the claude-council skill as a shipped chosko-llm feature

Target: claude

## Goal
Import the `claude-council` skill from
`https://github.com/TorpedoD/claude-council/tree/main/skills/claude-council`
into this repo under `skills/claude-council/`, so it ships and updates like
any other chosko-llm feature instead of requiring `npx skills add`. The
council gate in `/product-design` and `/architect` already detects the skill
at `${CLAUDE_HOME:-$HOME/.claude}/skills/claude-council/SKILL.md` — the exact
path `chosko-llm add skill:claude-council` writes to — so vendoring makes the
gate reachable through the CLI without changing gate behaviour. The import is
not verbatim: upstream frontmatter is incompatible with `parse_frontmatter`,
and upstream hardcodes `~/.claude` in three places. The repo currently
documents claude-council as externally installed in seven files; that prose
becomes false the moment this lands and is rewritten as part of this task.

## Decisions
- **Frontmatter is pinned, not re-derived.** Upstream's `description:` is a
  `|` block scalar; `parse_frontmatter` splits on each line's first colon and
  would read `description=|`. Upstream also lacks the required `version:` and
  `type:`. Write exactly:

  ```yaml
  ---
  name: claude-council
  version: 0.1.0
  type: skill
  description: 'Pressure-test a high-stakes decision with a structured LLM Council — five thinking-lens advisors (Red Team, First Principles, Expansionist, Outsider, Executor), anonymised peer review, forced debate when consensus looks too clean, and a dual-chairman synthesis that preserves dissent. Triggers: /claude-council, "convene the council", "run this by the council", "council this", "pressure-test this", "stress-test this", "war room this", "debate this", "torn between two options", "this is a big decision", "I need outside perspectives". Not for factual questions, coding help, debugging, quick yes/no calls, or emotional support. Suffixes: "with codex", "deep", "quick". Secondary: /claude-council outcome <sha1> <note>, /claude-council meta.'
  allowed-tools: Read, Write, Edit, Glob, Grep, Bash, Agent, AskUserQuestion
  ---
  ```

  Single-quoted so upstream's double-quoted trigger phrases survive intact
  and `parse_frontmatter`'s quote-strip still fires. No apostrophe appears in
  the value — a YAML single-quoted scalar escapes `'` as `''`, which the
  naive strip would leave visible — which is why upstream's "I'm torn between
  X and Y" and "should I X or Y" became "torn between two options". All
  mandatory triggers, the anti-trigger list, the three suffixes and both
  secondary invocations are kept; only upstream's connective prose was cut.
- **Ship, don't strip, the jq dependency.** CLAUDE.md's "no new dependencies"
  rule governs this repo's own shell code under `scripts/`; it does not
  govern a vendored skill's runtime. Rewriting Step 10's `jq -n` JSON
  construction in POSIX awk is large and injection-prone for no gain.
- **`evals/evals.json` ships too** (user's call). Authoring-time artifact,
  never read at run time, ~8KB in every install; kept for fidelity with
  upstream and to keep future re-syncs a clean diff.
- **`journal/.gitkeep` ships**, so `journal_append.sh` has a target directory
  on first run without a `mkdir -p`.
- **`${CLAUDE_HOME:-$HOME/.claude}` over verbatim `~/.claude`** (user's call).
  Makes re-syncs noisier, but the repo's hard rule wins and the existing gate
  detection already uses exactly this form.
- **One task, not two.** The doc rewrite is not separable collateral: a
  commit that ships the skill while README still says chosko-llm "never
  installs it for you" leaves the repo self-contradictory.
- **Vendored, not submoduled.** Matches the repo's copy-not-symlink,
  no-lockfile posture; upstream drift is a future manual re-sync.
