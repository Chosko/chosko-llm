# Task 165 — Give runbooks incremental IDs and show them in `/runbook-list`

Target: claude

## Goal
Runbooks are referred to only by kebab-case name, which is long to type and
awkward to quote in a command line. Give each one a stable incremental ID the
way `.claude/TASKS.md` gives tasks one, accepted as an argument wherever a name
is accepted, and displayed by the read side. `/runbook-list` already exists and
is already index-only and token-frugal — this task extends it with an ID column
and the one-line title it currently parses but never prints, and does not
change its cost model.

## Acceptance criteria
- `.claude/RUNBOOKS.md` carries `Last runbook number: <N>` beneath its title,
  mirroring `TASKS.md`'s counter. It only ever increases; a pruned ID is never
  reused and survivors are never renumbered.
- An index block's heading becomes `## <id>. <name> — <one-line title>`. The ID
  is the only addition; `Status:`, `File:`, `Created:`, `Source:`, `Steps:` and
  the conditional `Failed at:` are unchanged.
- `runbook-schema.md` is the single place the counter, the ID and the new
  heading shape are specified. No command body restates them — the existing
  "a second copy is the copy that drifts" rule holds.
- `/runbook-run`, `/runbook-create --append` and `/runbook-clean` accept an ID
  anywhere they accept a name. A bare all-digits argument is an ID; anything
  else is a name. An unknown ID reports the available runbooks exactly as an
  unknown name already does.
- `/runbook-create` assigns the next ID at write time and advances the counter
  in the same write. `/runbook-clean` removes a block without renumbering or
  decrementing.
- Backfill: an index with no counter, or blocks with no IDs, is upgraded in
  place by the first *writing* command that touches it — IDs assigned in index
  order, counter set to the highest. Read-only commands never write.
- `/runbook-list` prints an ID column and the one-line title, keeps index order,
  keeps its padding-from-widest-value rule, and still never opens a file under
  `.claude/runbooks/`. A block with no ID yet prints `-` in that column; the
  listing does not correct it.
- Each shipped body touched gets its frontmatter `version:` bumped; root
  `VERSION` takes a minor bump with a matching `CHANGELOG.md` section, and
  `./scripts/check-changelog.sh` passes.

## Decisions
- **The ID coexists with the name; the name stays canonical** (user decision,
  2026-09-02). The file stays `.claude/runbooks/<name>.md`, the name stays the
  identifier in the heading and in every error message, and the ID is a
  shorthand for the command line. Making the ID primary would break every
  existing invocation form, the `--append <name>` resolution and the
  name-collision rule for no gain.
- **A bare integer is an ID, anything else a name** — unambiguous because names
  are kebab-case and can never be all digits, so no disambiguation prompt is
  needed.
- **The counter is stored, not derived from `max()`** — the same reason
  `TASKS.md` stores it: a derived counter reuses the ID of a pruned runbook.
- **Backfill happens on write, never on read.** `/runbook-list` correcting the
  index would break its own standing rule that it "corrects no status however
  wrong it looks"; reconciliation belongs to the command that is already
  writing.
- **This reverses a recorded decision.** `runbook-schema.md` currently states
  "There is no counter and no numeric id — names are the identifiers, exactly as
  in `.claude/FEATURES.md`." That sentence is replaced, not merely contradicted,
  and the reason for the reversal is recorded in its place.
- `.claude/domain/features/runbook-suite.md` also carries that decision and is
  deliberately left to task 168 — see that task.
