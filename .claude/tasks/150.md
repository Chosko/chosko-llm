# Task 150 — Add a `changelog` subcommand and point `--version` and `upgrade` at it

Target: claude

## Goal
Extends the `version-changelog` feature
(`.claude/domain/features/version-changelog.md`). Today `CHANGELOG.md` is only
ever surfaced by `chosko-llm upgrade`, and only for the exact versions a pull
just moved through — a user who wants the whole file, or wants to catch up from
a point of their own choosing, has to go find it in the managed clone. Add a
`chosko-llm changelog` subcommand: no argument opens the full `CHANGELOG.md` in
the user's editor; `--since <value>` prints the sections from that point
forward, where `<value>` is a version, a date, or a duration. Then make
`chosko-llm --version` and `chosko-llm upgrade` mention it, so it is
discoverable from where users already are.

## Acceptance criteria
- `chosko-llm changelog` with no arguments opens `$CHOSKO_LLM_HOME/CHANGELOG.md`
  in `$VISUAL`, else `$EDITOR`, else `git var GIT_EDITOR`; when none resolves,
  falls back to `less -R` on a TTY and to `cat` otherwise. Never fails merely
  because no editor is configured.
- `chosko-llm changelog --print` always writes the full changelog to stdout and
  never spawns an editor or a pager. It composes with `--since`, where it is the
  way to force unpaged plain output.
- `chosko-llm changelog --since <value>` accepts three disjoint forms,
  auto-detected — no separate flag per form:
    - version, `1.10.0` — sections from the newest down to and **including**
      `1.10.0`;
    - date, `2026-08-01` — every section whose header date is on or after it;
    - duration, `30d` / `2w` / `6mo` / `1y` — same as the date form, computed
      from today.
- An unparseable `--since` value dies with a message naming all three accepted
  forms. A value that matches no section is not an error: it reports that
  nothing matched and exits 0.
- `--since` output goes to **stdout** (greppable, pipeable), unlike `upgrade`'s
  stderr readout.
- **`--since` output is paged only when it does not fit one screen.** The
  rendered block is measured against the terminal height (`LINES`, else
  `tput lines`, else 24); when it fits, it is written straight to stdout with no
  child process. When it does not, it is piped to `$PAGER`, else `less -R`, else
  written straight out. Paging happens only when stdout is a TTY and `--print`
  was not passed: a pipe or a redirect never spawns a pager, so
  `chosko-llm changelog --since 30d | grep …` behaves the same whatever the
  content's length.
- **Colour survives the pager.** The colour decision is made from whether the
  command's *original* stdout is a TTY, not from the fd the renderer ends up
  writing to — piping into a pager would otherwise silently strip every escape.
  The default pager invocation is `less -R` so the escapes pass through.
- **The printed block is visually identical to `upgrade`'s**: same two-space
  version indent and four-space bullet indent, same blank line between sections
  and after the block, same bold version / dim ` — <date>` / accent-coloured
  ASCII `- ` marker with default-coloured bullet text, same pass-through of a
  non-header non-bullet line. The only difference is the colour gate — stdout
  output gates on the stdout predicate (`C_*` / `_use_color_stdout`), stderr
  output keeps `_use_color`, so the escapes are correct for the stream each is
  written to. Both remain clean plain text under `NO_COLOR` or a non-TTY.
- The section-selection and rendering logic lives in `scripts/lib.sh`, with the
  renderer parameterised by output stream and colour gate;
  `print_changelog_range` is refactored to call it, and its existing behaviour on
  `upgrade` is unchanged (same two-sided range, same stderr, same return-code
  contract, same degrade-never-fail rule).
- `bin/chosko-llm` routes `changelog` to `scripts/cmd-changelog.sh`, and the
  daily auto-upgrade hook skips it exactly as it skips `version` and `help` — a
  read-only local view should not trigger a pull.
- `chosko-llm --version` prints its version line on stdout unchanged, then a
  TTY-gated stderr tip pointing at `chosko-llm changelog`.
- `chosko-llm upgrade` gains a TTY-gated stderr tip — `Run 'chosko-llm
  changelog' to see the full changelog` — alongside the existing
  `ls --available` / `update --all` tips.
- `docs/cli-help.txt` documents `changelog`, its `--since` forms and `--print`.
- `README.md` covers the subcommand where it describes staying up to date.
- Root `VERSION` gets a **minor** bump with a matching new top section in
  `CHANGELOG.md`; `./scripts/check-changelog.sh` is silent afterwards.
- A new `.claude/context/cmd-changelog.md` follows the six-section schema, is
  listed in `.claude/context/INDEX.md`, and `cli-entry.md`, `cmd-upgrade.md` and
  `shared-lib.md` are updated where they now understate the surface.
- `.claude/domain/features/version-changelog.md` is reconciled with what ships
  on exactly these 5 points — editing it is authorised for this task, see
  Decisions:
    1. § Scope and non-goals: "No new CLI flag and no new subcommand" is
       falsified — `changelog`, `--since` and `--print` now exist and are in
       scope.
    2. § Scope and non-goals: "No line wrapping and no pager" — the pager half is
       falsified, for both the no-arg view (editor fallback is `less -R`) and
       `--since` (paged when it does not fit one screen); the no-wrapping half
       stands.
    3. § Architecture 5–6: the range printer is no longer the only consumer of
       the formatter; the renderer is shared and parameterised by output stream
       and colour gate, so § 6's flat "gated by `_use_color`, `C_*` are the wrong
       tool" statement now holds only for the stderr caller.
    4. § Interfaces and contracts gains a `chosko-llm changelog` subsection: the
       three `--since` forms, the inclusive version bound (against `upgrade`'s
       exclusive one), the editor chain, the pager rule, and exit 0 on no match.
    5. § Interfaces' "unchanged surface" for `upgrade` no longer holds as written
       — it now prints one more TTY-gated tip, and `--version` prints one too.
  Nothing else in the document changes.

## Decisions
- **One auto-detecting `--since`, not three flags** (user decision). The three
  value shapes are disjoint — `1.2.3`, `2026-08-01`, `30d` — so detection is
  unambiguous and the help stays one line instead of three.
- **Editor chain degrades rather than refusing** (user decision). A bare
  git-bash on Windows commonly has neither `$VISUAL` nor `$EDITOR`; erroring
  there would make the first run fail on the repo's own primary platform.
  `--print` exists for scripts that must not spawn anything.
- **`--since` pages only on overflow, and only on a TTY** (user decision). A
  short range — the common case — should not push the user into `less` for four
  lines, and a piped or redirected run must stay a plain stream whatever its
  length. Measuring the rendered block before choosing is what buys both.
- **Colour is decided from the original stdout, not the write fd.** Otherwise
  the pager case loses every escape, since stdout is then a pipe. This is the one
  place the renderer's gate cannot be read off the fd it writes to.
- **Same presentation as `upgrade`, different colour gate** (user decision).
  Style is single-sourced through one renderer so the two can never drift; the
  gate is not, because `C_*` is stdout-gated and `_use_color` is stderr-gated,
  and using either on the wrong stream produces escapes in redirected output.
- **Filtered output on stdout, full-changelog view through an editor/pager.**
  `--since` output is the command's product and must pipe into `grep`;
  `upgrade`'s readout stays on stderr because it is commentary on another action.
- **Version filtering is inclusive of the named version**, unlike
  `print_changelog_range`, which excludes the old bound. "Since 1.10.0" reads as
  "1.10.0 and everything after"; the exclusive bound in `upgrade` is right there
  because the user already had that version.
- **Both new tips are TTY-gated stderr** (user decision on the `upgrade` one),
  matching the existing auto-upgrade tip, so `chosko-llm --version` stays clean
  when captured in scripts.
- **No new dependency for date maths or height detection.** Durations resolve via
  `date` arithmetic with a POSIX-ish fallback; string comparison of `YYYY-MM-DD`
  is enough for the filter itself; terminal height falls back to a constant when
  `tput` is unavailable.
- **Editing `.claude/domain/features/version-changelog.md` is explicitly
  authorised for this task (user decision, 2026-08-25), for the 5
  reconciliations listed above and for nothing else. Do not ask for permission at
  implementation time — the permission is already granted.** That document is
  normally `/architect`'s, and anything beyond those points still belongs to
  `/architect`. These are factual reconciliations with shipped behaviour, not
  redesigns; if one turns out to need a design decision rather than a wording
  fix, stop and say so instead of deciding it here.
