# Task 309 — Update documentation for feature `orchestrate-mode`

Target: claude

## Goal
Part of feature `orchestrate-mode`. Tasks 306–308 shipped `/orchestrate-mode`,
the mode check, and the mode's effect on `/task-implement`,
`/quick-implement` and the session commands; the documentation describing
those areas is now out of date and must reflect the shipped behaviour.

## Acceptance criteria
- A context file for `orchestrate-mode` (new `.claude/context/orchestrate-mode.md`,
  linked from `features.md` and `INDEX.md`); `interaction-engine.md` names
  `mode.md`; `task-implement-delegation.md`, `quick-implement.md` and
  `session-handoff.md` describe the mode's effect.
- `.claude/domain/features/task-implement-launcher.md` states the agreed
  design change — under orchestrate mode a single-task run delegates too — in
  every passage that stated the old one. Nothing else in the document changes.
- `.claude/domain/features/session-continuity.md` states the agreed design
  change — the store holds, besides one file per save, a `<stem>/` folder of
  area handoffs (and `pending/` before the first save) that `/session-save`
  moves and stages and `/session-resume` lists — in every passage that stated
  the old one. Nothing else in the document changes.
- `README.md` and `docs/reference.md` are not edited.
- No `VERSION` bump, no `CHANGELOG.md` entry (documentation only).

## Decisions
- **Design change agreed (user decision, 2026-10-07):**
  `task-implement-launcher.md` § Scope and non-goals: "single-task runs … no
  agent" → except under orchestrate mode, where `--agents` is on by default.
  `session-continuity.md` § The store: "one file per save" → plus an
  optional `<stem>/` folder of area handoffs and `pending/` before the first
  save, moved and staged by `/session-save`, listed by `/session-resume`.
  Both documents are normally `/architect`'s; this task updates them for
  exactly this and for nothing else. A further design decision met at
  implementation time is not covered: leave that passage untouched and name
  it under *Follow-ups* as a precise follow-up.
- README.md and docs/reference.md are excluded: user-facing docs are
  rewritten when the `unmanned` work ships.
