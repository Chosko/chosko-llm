# Task 195 — Update documentation for feature `pipeline-suggest`

Target: claude

## Goal
Feature `pipeline-suggest` gives the pipeline its first auto-triggered entry
point: a skill nobody invokes that points a free-form request at the command
that fits it. Nothing in the user-facing reference, the domain layer or the
context layer describes such an entry point today — the pipeline is documented
as a sequence of commands the director types. Bring all three up to date with
what task 194 shipped.

## Acceptance criteria
- `README.md` records, beside the revision path task 193 describes, that a
  free-form request may earn a one-line pointer at the pipeline command that
  fits, from a skill nobody invokes — in the register of the existing
  `runbook-suggest` sentence, which is the only other artifact of this kind.
- `docs/reference.md` § 4 gains a `### pipeline-suggest` section beside the
  `/pipeline-patch` and `/pipeline-revise` sections task 193 adds: the trigger
  and its anti-triggers, the two probes, the table's rows, the two-line output
  cap, and that it never invokes, never asks and never writes.
- `.claude/domain/product-workflow.md` records that the pipeline has an
  auto-suggested entry point — a request that arrives as prose may be pointed
  at the stage that owns it — and that the skill owns no line in any artifact
  and enters no stage.
- `.claude/context/features.md` reflects the new `skills/pipeline-suggest/`
  folder, and its note that `skills/runbook-suggest/` is "the only artifact
  nobody invokes" is corrected — there are now two.
- `.claude/context/INDEX.md`'s `Last updated:` anchor is refreshed.
- `.claude/domain/features/pipeline-suggest.md` is reconciled on exactly these
  3 points — editing it is authorised for this task, see Decisions:
  1. § *Interfaces and contracts*, first bullet — it records
     `requires: skill:pipeline-engine` alone, while the same sentence's "and
     the two revision surfaces" clause needs them named, `requires:` being
     flat and non-transitive. The bullet records the shipped frontmatter and
     the commands deliberately left out of it.
  2. § *Architecture* — the document does not mention that this feature ships
     a row in `skills/pipeline-engine/references/routing.md`; declaring
     `requires: skill:pipeline-engine` makes `scripts/check-routing.sh`'s
     completeness invariant demand one. The row is recorded as part of what
     the feature ships.
  3. § *Architecture*, *The shape table* — the abstract bullet list and the
     "ten rows at most" cap are replaced by the rows that shipped, in the
     order they ship.
  Nothing else in the document changes. In particular both open questions —
  whether it nags, and whether the bug row survives — are left open; only use
  answers them, and the document already says so.
- No `VERSION` bump and no `CHANGELOG.md` entry — every path above is
  documentation or the navigation/domain layer, which `CLAUDE.md` § Versioning
  exempts. `./scripts/check-changelog.sh` must still exit zero.

## Decisions
- **Editing `.claude/domain/features/pipeline-suggest.md` is explicitly
  authorised for this task (user decision, 2026-09-10), for the 3
  reconciliations listed above and for nothing else. Do not ask for permission
  at implementation time — the permission is already granted.** That document
  is normally `/architect`'s, and anything beyond those points still belongs
  to `/architect`. These are factual reconciliations with shipped behaviour,
  not redesigns; if one turns out to need a design decision rather than a
  wording fix, stop and say so instead of deciding it here.
- **Task 193 is a precondition as well as task 194.** This task writes into
  the `README.md` paragraph and the `docs/reference.md` § 4 subsections that
  task 193 creates for `/pipeline-patch` and `/pipeline-revise`; landing first
  would mean writing beside sections that do not exist yet, then rewriting
  them.
- **No `VERSION` bump.** `CLAUDE.md` § Versioning exempts `README.md`,
  `docs/`, `.claude/domain/` and `.claude/context/`. The shipped body changed
  in task 194, which bumped for itself; bumping again for a change no user
  receives would corrupt the version `install.sh` reports.
- **`docs/authoring-guide.md` and `CLAUDE.md` are deliberately untouched.**
  This feature adds one skill of an established kind, with no new frontmatter
  field, no new asset kind and no new hard rule, so neither document has
  anything to reconcile.
- **`.claude/domain/features/pipeline-engine.md` and
  `pipeline-revision.md` are deliberately untouched.** The routing row and the
  two surfaces this skill points at are exactly what those documents already
  anticipate; both belong to `/architect` and to their own features' planning
  runs.
