# Task 202 — Flip `/architect` to commit by default

Target: claude

## Goal
`/architect` is one of four skills in the feature `authoring-commit-default`
that stop leaving their output in the working tree and start committing and
pushing it. Invert the skill's `COMMIT` boolean so it is true unless
`--no-commit` is passed, and repair every sentence in the skill's folder that
asserts the old default. `/architect` carries every edge case the other three
do not — the by-path amend arm, the council staging exclusion, and the
progress-marker staging condition — which is why it is a task of its own.

The design is `.claude/domain/features/authoring-commit-default.md`; read it
first. The flag shape to copy is
`skills/task-engine/references/commit.md` § *The flags*, which already
defines it for `/task-add`.

## Acceptance criteria
- In `skills/architect/SKILL.md`, `COMMIT` is true unless `--no-commit` was
  passed. `--no-commit` implies `NO_PUSH`.
- `--commit` is still accepted and is a silent no-op, and passing
  `--commit` together with `--no-commit` still stops the run with
  `--commit and --no-commit cannot be combined. Pick one.`
- Pull-at-start in PHASE 0 runs on every run that is not `--no-commit`.
- The `COMMIT AND PUSH` section header and its opening sentence no longer
  say "only when `--commit` was passed"; the section runs unless
  `--no-commit` was passed.
- The closing report's "nothing was committed" reminder fires under
  `--no-commit` instead of under the absence of `--commit`.
- PHASE 3's progress-marker step stages a previously-committed marker when
  `COMMIT` is true, not when "`--commit` was passed".
- The `DO NOT` git bullet reads as "run no git/VCS command when
  `--no-commit` was passed". The rest of that bullet — stage only explicit
  `WRITTEN` paths, never a catch-all, never force-push, never `--no-verify`
  / `--no-gpg-sign` / `--amend` — is unchanged.
- The frontmatter `description` states the new default and names
  `--no-commit`.
- `skills/architect/amend.md` keeps **no default of its own**. Executed by
  path by `/pipeline-patch` or `/pipeline-revise` it behaves exactly as it
  does today; only `/architect amend` run as `/architect` inherits the new
  default. Its prose stops asserting the old one.
- `skills/architect/council-gate.md`'s "never staged by `--commit`" becomes
  "never staged" — the exclusion is about `WRITTEN` membership, not about a
  flag, and must survive the flip unchanged in meaning.
- `skills/architect/iterating.md`'s "under `--commit`" wording no longer
  names the flag as the condition.
- Frontmatter `version:` goes 0.8.1 → 0.9.0.
- Root `VERSION` goes 1.34.1 → 1.35.0, with a matching new top section in
  `CHANGELOG.md` dated the day of the change. `./scripts/check-changelog.sh`
  is silent.
- No change to any write set, to `WRITTEN` membership, or to the
  commit-and-push protocol itself.

## Decisions
- **`--commit` is retained as an accepted no-op, not removed.** Existing
  runbook steps, documented invocations and the two forwarding tables in
  `/pipeline-patch` and `/pipeline-revise` all pass it today. This is the
  same treatment `/task-add` already gives it (user decision, 2026-09-12).
- **Pull-at-start stays tied to `COMMIT`, so it now runs on every default
  run.** It matches `/task-add`, and a pull conflict stopping the run before
  any work is done is the point of it (user decision, 2026-09-12).
- **The four skills keep four near-identical commit blocks.** Collapsing
  them onto one authority — `task-engine`'s `commit.md`, or a new
  `pipeline-engine` reference — was weighed at architecture time and
  declined for now (user decision, 2026-09-12). Do not refactor toward it in
  this task.
- `/architect` is split from the other three because its folder carries the
  amend arm, the council gate and the progress marker, and those are what a
  reviewer needs to look at closely.
