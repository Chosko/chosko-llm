# Task 262 — Delegated runs relay questions when attended and return `[PARKED]` when not

Target: claude

## Goal
Part of feature `unattended-parking`. A delegated agent today is told it
cannot ask the user and must stop and report on a human decision — a choice
of `delegated-runs.md`, not a limit of the Agent tool, which `/runbook-run`
relays over. Make the launcher relay under `attended` and let the agent park
under `unattended`: UNATTENDED rides in the fixed-size prompt's resolved-flag
list, the launcher gains a result case that relays the agent's question in
the runbook's fixed block and sends the answer back to the same agent, and a
parked task comes back as `[PARKED]` in the six-field return.

## Acceptance criteria
- `delegated-runs.md` § *The agent prompt*: the resolved-flag list carries
  UNATTENDED; the non-interactive notice is rewritten — under attended, a
  question that genuinely needs the user ends the agent's turn under
  `QUESTIONS FOR USER` with options and a recommendation, and the answer
  comes back in the same conversation; under UNATTENDED the agent parks the
  task per `../task-engine/references/parking.md` and returns.
- § *What the agent returns*: the terminal status may be `[PARKED]`; the
  launcher records it, prints one progress line, and spawns the next agent —
  a parked task is not a failure and does not halt the run.
- A new subsection *The question relay*: on a `QUESTIONS FOR USER` return
  the launcher renders the question in the fixed relay block (`Task <N> —
  <title> — the agent is asking (round <r>)`, options, recommendation, any
  approval-gate draft verbatim), collects the answer, sends it to the same
  agent, and repeats; it never answers on the user's behalf and adds no fact
  it does not hold. Under UNATTENDED this case does not occur, since the
  agent parks instead.
- § *Between delegated tasks* step 2 accepts a `[PARKED]` status with a
  clean tree as consistent; the parent re-reads `TASKS.md` as today.
- Mid-run answers by number for a delegated run are handled by the parent
  exactly as SKILL.md's BETWEEN TASKS says for an in-context run (task 261);
  the answered task's agent is spawned next.
- `targets.md` § *The delegation guard*'s per-consumer note names the relay
  and that a `[PARKED]` return is a delegated outcome; the guard itself is
  unchanged.
- SKILL.md's FAILURE HANDLING and CLOSING sections say a `[PARKED]` return is
  not a failure.
- `task-implement`'s frontmatter `version:` bumped (patch); root `VERSION`
  bumped (patch) with a matching `CHANGELOG.md` section;
  `./scripts/check-changelog.sh` and `./scripts/check-home-paths.sh` pass.

## Decisions
- Attended delegated runs relay rather than halt: parking exists only where
  no answer can come, and the launcher can carry an answer.
- The relay block reuses `/runbook-run`'s shape with a task heading, so the
  user reads one form of question from every run-level skill.
