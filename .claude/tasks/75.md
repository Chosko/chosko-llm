# Task 75 — Add per-task push to /task-implement (skill + script), with --no-push

Target: claude

## Goal
Apply the commit-and-push protocol from task 68 to /task-implement, which
commits once per implemented task (Step 8 in skills/task-implement/SKILL.md,
mirrored by scripts/cmd-task-impl.sh's `git commit` for the local-LLM
path). Unlike the other tasks, this run can process several tasks in one
invocation ("all"), so the push granularity must be decided explicitly.

## Acceptance criteria
- Push happens once per task, immediately after that task's commit —
  mirroring "each task gets exactly one commit" (SKILL.md ~line 409) with
  "each task gets exactly one push." Not deferred to end-of-run.
- The start-of-run pull (task 68's step 1) runs once, before the first
  task's work begins, not once per task — re-syncing per commit already
  covers drift between tasks.
- `--no-push` flag added, parsed alongside the existing `--no-commit` (SKILL.md
  ~line 71-77); `--no-commit` implies `--no-push` since nothing is
  committed to push.
- scripts/cmd-task-impl.sh's `git commit` call (~line 348) gets the
  matching pull/re-sync/push logic, kept in lock-step with the skill per
  scripts/check-task-parity.sh's existing parity guard — run
  check-task-parity.sh after editing and fix any reported drift.
- `.claude/domain/task-workflow.md` gets a brief pointer to the authoring
  guide's protocol near its discussion of the implementer's commit.
- README.md's task-implement entry mentions push / `--no-push`.
- Root VERSION bumped (minor).

## Decisions
- Per-task push (not end-of-run) chosen for symmetry with the existing
  one-commit-per-task rule, and so a partial multi-task run ("all" halted
  by a failing task) has already synced everything it did complete.
- The dirty-tree pre-flight commit described in skills/task-implement/
  dirty-tree.md (committing the user's pre-existing uncommitted changes
  before implementation starts) is NOT in scope — it commits work that
  predates this run and isn't "a feature ending with a commit" in the
  sense this change addresses.
