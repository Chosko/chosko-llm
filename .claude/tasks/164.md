# Task 164 — Rewrite CHANGELOG to terse one-liner bullets and stop bumping VERSION for doc-only changes

Target: claude

## Goal
CHANGELOG.md's bullets are multi-line prose paragraphs nobody reads on
upgrade. Switch to a "what's new" style: one terse line per bullet, a bold
Subject naming the shipped command/CLI-subcommand/skill/script a user
recognizes, then a short user-facing clause. Rewrite the full history to
this shape. Also narrow what triggers a VERSION bump: project documentation
(README.md, docs/, .claude/domain/, .claude/context/, CLAUDE.md itself) no
longer bumps VERSION or gets a CHANGELOG entry — only shipped, user-facing
behavior does. A shipped feature's own file (commands/*.md, skills/*/SKILL.md,
claude-md/*.md, statusline/*.sh, hooks/*.sh) is not "documentation" under this
rule — it's the product, and still bumps as before.

## Acceptance criteria
- `CLAUDE.md` § Versioning: the bump-trigger bullet drops "docs" — only
  features, CLI behavior and scripts bump VERSION. A new line states the
  documentation exemption and its boundary (a shipped feature's own body is
  not exempt).
- `docs/authoring-guide.md` § Versioning: bump table and "The changelog rule"
  / "Section schema" updated to match — same exemption, plus the new bullet
  schema: `- **Subject** terse user-facing clause`, one line, no sub-headings,
  no prose paragraphs. Several small/uninteresting changes to shipped
  features compress into one bullet naming only the affected shipped
  features — never an internal dev doc, `.claude/domain/*` or
  `.claude/context/*` file.
- `scripts/lib.sh`'s `_render_changelog_sections` renders a `**Subject**`
  marker inside a bullet in bold/accent color instead of printing literal
  asterisks, on both the `changelog --since` stdout path and the `upgrade`
  stderr path, gated by the existing color predicate. With color off, the
  Subject prints plain with the asterisks stripped, not literal `**`.
- Every existing `CHANGELOG.md` section (`0.1.0` through the current top
  version) is rewritten to the new bullet style. Version headers, dates and
  descending-semver order are unchanged — only bullet content changes. A
  section whose original content was purely internal/doc catch-up gets one
  neutral bullet saying no user-facing change, naming no internal file.
- `./scripts/check-changelog.sh` passes.
- This change is itself a shipped behavior change (renderer + policy), so it
  gets its own VERSION bump and a new top CHANGELOG section written in the
  new style.

## Decisions
- **Single task, not split** (user choice) — the rule change and the full
  rewrite ship together even though the rewrite alone touches ~65 sections.
- **Bump-policy change accepted**: doc-only changes stop bumping VERSION and
  stop getting a CHANGELOG entry going forward. Historical sections keep
  their actual recorded VERSION values (git/VERSION history can't be
  rewritten) — only their bullet text is rewritten.
- **Bullet shape**: `- **Subject** clause` (no colon after Subject). Subject
  is the bold-marked, user-recognizable name — a CLI subcommand, a slash
  command, a script. The bold marker is meant to render as an actual color
  in the terminal (see lib.sh criterion), not stay literal `**` text.
- **Compression rule**: bundled small/boring changes get one generic bullet
  naming only shipped features — never internal documentation, dev tooling,
  or the domain/context navigation layers.

## Hints
- README.md — if it quotes the old multi-line CHANGELOG bullet style anywhere
  as an example, update it.
- `.claude/context/shared-lib.md` — describes `_render_changelog_sections`;
  update if it documents the current no-markdown-interpretation behavior.
