# Task 299 — Move `/task-add`'s design-change check, reconciliation and orphan question into `task-engine`

Target: claude

## Goal
Part of feature `quick-implement`. `/quick-implement` needs the checks
`/task-add` holds inline, and a second copy would drift. Move `/task-add`'s
DESIGN-CHANGE CHECK (the owner table, *settles* vs *diverges*, the question,
agreement and disagreement, the hard rules), its RECONCILIATION application
rules and THE ORPHAN QUESTION into `task-engine` references, and make
`/task-add` cite them. Pure restructuring: `/task-add`'s behaviour, prompts and
output do not change.

## Acceptance criteria
- `skills/task-engine/references/design-change.md`, `reconciliation.md` and
  `orphan-question.md` exist, each the single authority for its rule, each
  with a `/task-add` note stating only what that command does differently, in
  the shape the other references use.
- `commands/task-add.md` replaces each moved section with a citation by
  relative path (`../skills/task-engine/references/<file>.md`) and keeps only
  what is its own (where the check runs in its phases, the gate rendering
  order); every other phase reads unchanged.
- `skills/task-engine/references/amend.md` and
  `skills/pipeline-engine/references/routing.md`, which cite "`/task-add`'s
  DESIGN-CHANGE CHECK", cite `design-change.md` instead.
- `task-engine`'s `SKILL.md` map gains one row per new file, and its reader
  list names `/quick-implement` as a future reader only once it exists (not in
  this task).
- A `/task-add feature=<slug>` and a free-form `/task-add` run produce the
  same gate and the same written files as before (verified by reading the
  diff: no rule text lost, none added).
- `task-engine` and `task-add` `version:` patch-bumped; root `VERSION`
  patch-bumped with a `CHANGELOG.md` section; `check-changelog.sh`,
  `check-home-paths.sh` and `check-routing.sh` pass.

## Decisions
- One reference file per check (three files), matching `task-engine`'s
  one-authority-per-rule shape, rather than one combined "drafting" file.
- The reconciliation reference holds the application rules (classify every
  task, render with a reason each, apply nothing beyond the approved plan);
  the four-way classification itself stays in `stale.md` § *Clearing it* and
  is cited, not copied.
- Patch bump: no behaviour changes.
- Lands after 282, which rewrites `/task-add`'s gate to the interaction
  policy; the moved text is the post-282 text.
