# Task 175 — Add the `pipeline-engine` skill and its probe reference

Target: claude

## Goal
Feature `pipeline-engine` gives the revision suite one home for what every
pipeline feature needs to know about the pipeline as a whole. A shared file can
only ship inside a skill folder, so the engine is a skill — non-invocable in
exactly the way `task-engine` is. This task creates the folder, its versioned
`SKILL.md`, and the first of the four reference files the map will name:
`references/probes.md`, which fixes how a consumer describes a project's
pipeline setup, the one-line verdict every consumer prints identically, and the
rule for reusing a verdict already in the conversation. It is the prerequisite
of every other task in the feature — nothing can be cited by path until the
folder exists.

## Acceptance criteria
- `skills/pipeline-engine/SKILL.md` exists with complete frontmatter: `name:
  pipeline-engine`, `version: 0.1.0`, `type: skill`, and a `description:` that
  states plainly that it is not invocable, takes no arguments, produces no
  output, and must never be suggested — the wording `task-engine`'s description
  already uses for the same property.
- `SKILL.md` carries **no rule text**. It holds only: the not-directly-invocable
  notice, the install-path assumption naming
  `${CLAUDE_HOME:-$HOME/.claude}/skills/pipeline-engine/references/<file>.md`
  and never a hardcoded home path, the map table, and a short note on how a
  reference file is read. Adding rule text here recreates the duplication the
  engine exists to remove, and the file says so.
- The map table carries all four rows — `references/probes.md`,
  `references/graph.md`, `references/routing.md`, `references/lint.md` — each
  stating what that file owns, even though only `probes.md` exists at the end of
  this task. Tasks 176–178 add a file; none of them edits the map.
- `references/probes.md` fixes the probe set: `.claude/FEATURES.md` present;
  `.claude/TASKS.md` and `.claude/tasks/` present; `.claude/domain/product-roadmap.md`
  present and whether its milestones carry scope slices; `.claude/PLAN.md`
  present; `.claude/RUNBOOKS.md` present; the `claude-council` skill installed
  under `CLAUDE_HOME`; the `Testing policy for /task-implement:` marker in
  `CLAUDE.md` and its value; and which pipeline features are installed under
  `CLAUDE_HOME`. Each probe is a cheap filesystem check with a stated result
  shape.
- The probe set contains **no probe of `.claude/tasks/archive/`**, and the file
  says so explicitly: an archive folder no command traverses costs the same as
  one that is not there, and adding a probe here would be the first traversal.
- The file fixes exactly one verdict line — a literal template with a fixed
  field order, plus at least one worked example — and states that every consumer
  prints it identically, in that order, with no per-consumer wording.
- The reuse rule is stated: a verdict already in the conversation is reused
  unless a pipeline writer has run since; the file **names those writers
  explicitly** rather than describing them; a subagent always re-probes, because
  it shares no conversation.
- The file states what the probe is for — one round-trip and one definition, not
  a token saving — so a later reader does not try to optimise it further.
- The file states no rule that `task-engine`'s reference files, `/production-status`
  or `runbook-run`'s `runbook-schema.md` already state; where one of those is
  authoritative it is cited by installed path and only the deviation is written.
- `./bin/chosko-llm ls --available` lists `skill:pipeline-engine` at `0.1.0`.
- Root `VERSION` takes a **minor** bump and `CHANGELOG.md` gains a matching top
  section; `./scripts/check-changelog.sh` exits zero.

## Decisions
- The map table is written complete in this task, ahead of the three files it
  names. The alternative — each reference-file task adding its own row — has
  four tasks editing one table for no gain, and leaves the map temporarily
  disagreeing with the design.
- The probe list is fixed here rather than grown per consumer. A consumer that
  needs a fact the probe does not carry adds it to this file; it does not probe
  privately, or the verdict stops being one line.
- No archive probe, stated as a rule rather than left as an omission. Feature
  `task-archive` makes `.claude/tasks/archive/` a folder no command traverses;
  a probe added here later, "just to check", is exactly how that guarantee
  would be lost.
- `.claude/domain/features/pipeline-engine.md` is read-only in this task.
  Editing it is not authorised; `/architect` owns it, and tasks 178 and 181
  carry the only grants in this run.
