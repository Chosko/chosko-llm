# Task 185 — Record each owner's amend entry in the pipeline routing table

Target: claude

## Goal
Feature `owner-amend-arms` states that the routing table "records where each
owner's amend entry is" — that is how a revision surface finds an owner's cheap
path without loading the owner. The routing table is written by task 177 of
feature `pipeline-engine`, and rows there exist only for shipped features. Once
the three arms of tasks 182–184 have shipped, this task fills their entries in.

## Acceptance criteria
- `skills/pipeline-engine/references/routing.md` records, for every owner that
  has an amend entry, the path to it:
  - `/architect` → `skills/architect/amend.md`
  - the task suite → `skills/task-engine/references/amend.md`
  - the runbook suite → `skills/runbook-run/references/step-amend.md`
  - `/product-design` → its existing arm in `skills/product-design/resuming.md`
    § 6, which shipped long before this feature.
- Owners with no amend arm — `/production-plan` and `/product-roadmap` — are
  recorded as having none, with the one-clause reason (both are
  diff-and-propose on every run), so a reader does not go looking for a file
  that was never meant to exist.
- The entries are added in whatever shape task 177 shipped — a column, or a
  documented per-row field. No new column is invented and no new file is
  created.
- Only shipped features are named. Nothing here names `/pipeline-patch`,
  `/pipeline-revise` or `/pipeline-suggest`; those add their own rows when they
  land.
- `scripts/check-routing.sh` (task 180) still exits clean, if it exists in the
  tree at implementation time.
- Root `VERSION` is bumped, `CHANGELOG.md` gains a matching top section, and
  `./scripts/check-changelog.sh` is silent.
  `skills/pipeline-engine/SKILL.md`'s `version:` is bumped too if its
  `description:` enumerates what `routing.md` carries.

## Decisions
- **A separate task rather than a fold into 182–184.** The routing table does
  not exist until task 177 lands. Folding these entries into the three arm tasks
  would put a cross-feature block on each of them; keeping the bookkeeping
  separate lets all three arms be written the moment they are ready, and lets
  this one wait.
- **`Preconditions:` names the arms as well as 177.** An amend entry that points
  at a file which does not exist yet is precisely the drift `/pipeline-check`
  exists to catch, so this task lands after the files it points at.
- **The table's shape is task 177's to decide.** This task is a filler, not a
  designer; if 177's shape has no place for an amend entry, add the smallest
  field that fits its existing convention and say so in the commit.
