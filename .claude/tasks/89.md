# Task 89 — Trim oversized frontmatter descriptions to match the authoring guide's spec

Target: claude

## Goal
docs/authoring-guide.md's frontmatter schema table specifies `description`
as "One short line." task-add.md, project-setup.md, and unity-mcp-setup.md
each carry a multi-sentence, ~500-700 character description paragraph
instead — functionally useful for `chosko-llm ls` discoverability (they
document flags and modes), but they contradict the guide's own stated
spec. Resolve the contradiction: either trim the three descriptions to
genuinely one-line summaries with detail moved into the command body, or
amend the guide's wording to explicitly permit longer descriptions for
commands with many flags/modes — pick whichever reads better in
`chosko-llm ls` output and is least disruptive, and apply it consistently.

## Acceptance criteria
- Exactly one of the two resolutions is applied consistently across all
  three files plus the guide:
  - Trim path: task-add.md, project-setup.md, and unity-mcp-setup.md's
    `description:` frontmatter fields become single, short sentences (in
    the spirit of the guide's existing short examples); any detail that
    was only in the description (flag behavior, mode explanations) and
    isn't already stated in the command body is moved into the body so
    nothing is lost.
  - Or, guide-amendment path: docs/authoring-guide.md's frontmatter schema
    table description row is reworded to explicitly allow longer,
    multi-clause descriptions for commands with several flags/modes, and
    the three files are left as-is.
- Whichever path is chosen, `chosko-llm ls --available` output (verify by
  reading scripts/cmd-ls.sh's rendering, or running it in a clone with
  install.sh already run) still reads cleanly — no column overflow or
  truncation regression from the chosen approach.
- No other frontmatter field (name/version/type) is touched on any file.

## Decisions
- Left open which of the two resolutions to take — judge from how
  `chosko-llm ls` actually renders `description` and pick whichever keeps
  the CLI output readable; document the choice made in the commit.
